## فصل ۸۶: Agentهای خودمختار

### مقدمه

فصل ۳۱ اصول Agent را توضیح داد. این فصل به **وضعیت فعلی و مسیر** می‌پردازد: چه چیزی امروز واقعاً کار می‌کند، چه چیزی هنوز تبلیغ است، و چه چیزی برای سازمان مهم است.

### مفاهیم اساسی

**سه نسل Agent**

| نسل | ویژگی | وضعیت |
|---|---|---|
| **۱. تک‌ابزاری** | یک ابزار، یک هدف | ✅ بالغ |
| **۲. چندابزاری** | چند ابزار، برنامه‌ریزی ساده | ⚠️ در حال بلوغ |
| **۳. خودمختار** | هدف بلندمدت، خودتصحیح | 🔬 پژوهشی/محدود |

**چهار قابلیت که امروز واقعاً کار می‌کند**

| قابلیت | مثال | محدودیت |
|---|---|---|
| **جست‌وجو + خلاصه** | تحقیق سریع | کیفیت منبع |
| **اجرای کد** | تحلیل داده | محیط محدود |
| **فراخوانی API** | واکشی وضعیت سفارش | نیاز به تعریف دقیق |
| **تولید + بازبینی** | نوشتن و نقد | نیاز به معیار |

**چهار قابلیتی که هنوز ناپایدار است**

| قابلیت | چرا |
|---|---|
| **برنامه‌ریزی بلندمدت** | انحراف از هدف |
| **خودتصحیح قابل اعتماد** | نمی‌داند چه چیزی نمی‌داند |
| **هماهنگی چند Agent** | خطاهای انباشته |
| **اقدام برگشت‌ناپذیر** | ریسک بالا |

**مفهوم «درجهٔ خودمختاری»**

| درجه | چه کسی تصمیم می‌گیرد | مناسب |
|---|---|---|
| **۰** | انسان همه‌چیز | کار حساس |
| **۱** | AI پیشنهاد، انسان اجرا | اکثر کارها |
| **۲** | AI اجرا، انسان تأیید | کار تکراری |
| **۳** | AI اجرا، انسان پایش | کم‌ریسک، پرتکرار |
| **۴** | AI تصمیم | 🔴 هنوز نه |

**نکتهٔ عملی:** درجهٔ ۴ در محیط کاری، فعلاً توصیه نمی‌شود. حتی در درجهٔ ۳، پایش و مسیر توقف الزامی است.

**مفهوم «قابلیت اطمینان ترکیبی»**

اگر هر مرحله ۹۵٪ درست باشد، ۱۰ مرحله = ۰٫۹۵¹⁰ ≈ ۶۰٪.

| تعداد مرحله | قابلیت اطمینان (۹۵٪ هر مرحله) |
|---|---|
| ۱ | ۹۵٪ |
| ۳ | ۸۶٪ |
| ۵ | ۷۷٪ |
| ۱۰ | ۶۰٪ |
| ۲۰ | ۳۶٪ |

**پیامد:** Agent چندمرحله‌ای، نیازمند قابلیت اطمینان **بسیار بالاتر** در هر مرحله است، یا بازبینی میانی.

### مثال‌های عملی

**Lab Scenario 86-A: طراحی یک Agent واقع‌بینانه**

هدف: «هر دوشنبه، گزارش فروش را از سه سیستم جمع کن و بفرست.»

```markdown
# طراحی

## مراحل
۱. واکشی داده از سیستم A (API خواندنی)
۲. واکشی داده از سیستم B (فایل CSV)
۳. واکشی داده از سیستم C (ایمیل)
۴. ترکیب و محاسبه
۵. تولید گزارش
۶. ارسال

## نقاط شکست
| مرحله | احتمال شکست | کنترل |
|---|---|---|
| ۱ | کم | تلاش مجدد |
| ۲ | متوسط (فایل نباشد) | هشدار |
| ۳ | بالا (ایمیل تغییر کند) | مسیر جایگزین |
| ۴ | متوسط (محاسبه) | اعتبارسنجی |
| ۵ | کم | قالب ثابت |
| ۶ | کم | تأیید انسانی |

## تصمیم
مراحل ۱–۵ خودکار. مرحلهٔ ۶: پیش‌نویس + تأیید انسانی.
```

**درس:** به‌جای «Agent کامل»، یک **Workflow با نقاط تأیید** طراحی کن.

**Lab Scenario 86-B: چهار سؤال قبل از ساخت Agent**

```text
۱) آیا مسیر کار از قبل قابل پیش‌بینی است؟
   → اگر بله: Workflow بساز، نه Agent.
۲) آیا اقدامات برگشت‌پذیرند؟
   → اگر نه: تأیید انسانی اجباری.
۳) آیا می‌توانم خطا را در هر مرحله تشخیص بدهم؟
   → اگر نه: بازبینی میانی بگذار.
۴) آیا هزینهٔ خطا کمتر از ارزش صرفه‌جویی است؟
   → اگر نه: نساز.
```

### مقایسه و الگوهای مختلف

**Agent در برابر Workflow**

| | Agent | Workflow |
|---|---|---|
| مسیر | پویا | ثابت |
| قابل پیش‌بینی | کم | بالا |
| هزینه | بالا | کم |
| مناسب | کار متغیر | کار تکراری |

**توصیه:** ۸۰٪ کارها با Workflow. Agent فقط وقتی مسیر واقعاً متغیر است.

**مقایسهٔ سه معماری**

| معماری | مزیت | عیب |
|---|---|---|
| **تک‌عامل** | ساده | محدود |
| **چندعامل** | تخصص | خطای انباشته |
| **عامل + ابزار** ⭐ | تعادل | نیاز به طراحی |

### اشکال شایع

**اشتباه ۱: Agent برای مسئلهٔ ثابت**
اگر مسیر مشخص است، Agent پیچیدگی بی‌دلیل است.

**اشتباه ۲: خودمختاری بالا بدون پایش**
بدون لاگ و توقف، Agent می‌تواند فاجعه بسازد.

**اشتباه ۳: نادیده گرفتن قابلیت اطمینان ترکیبی**
۱۰ مرحله با ۹۵٪ = ۶۰٪.

**اشتباه ۴: اعتماد به «خودتصحیح»**
Agent نمی‌داند چه چیزی نمی‌داند.

**اشتباه ۵: نداشتن سقف هزینه**
Agent چندمرحله‌ای می‌تواند ۱۰ برابر گران‌تر باشد.

### نکات مهم (Tips & Tricks)

- **Workflow را به Agent ترجیح بده.**
- **تأیید انسانی برای اقدام برگشت‌ناپذیر.**
- **سقف مرحله، هزینه و زمان.**
- **لاگ کامل تصمیم‌ها.**
- **قابلیت اطمینان ترکیبی را حساب کن.**

### خلاصه فصل

- سه نسل؛ **نسل ۱ بالغ**، نسل ۳ محدود.
- چهار قابلیت کارآمد، چهار قابلیت ناپایدار.
- **قابلیت اطمینان ترکیبی**، محدودیت اصلی است.
- درجهٔ ۴ خودمختاری، فعلاً توصیه نمی‌شود.
- **Workflow + نقاط تأیید**، طراحی واقع‌بینانه است.

## فصل ۸۷: چندوجهی و بلادرنگ

### مقدمه

مدل‌های امروز فقط متن نمی‌بینند: تصویر، صدا، ویدئو. و به‌طور فزاینده‌ای **بلادرنگ** کار می‌کنند: صحبت می‌کنی، پاسخ می‌شنوی.

این فصل دربارهٔ کاربردهای واقعی و محدودیت‌های باقی‌مانده است.

### مفاهیم اساسی

**چهار ترکیب وجهی**

| ترکیب | کاربرد | بلوغ |
|---|---|---|
| **متن → تصویر** | تولید محتوا | ✅ بالغ |
| **تصویر → متن** | تحلیل، OCR | ✅ بالغ (با محدودیت) |
| **صدا → متن** | رونویسی | ✅ بالغ |
| **متن → صدا** | پادکست، دستیار | ✅ بالغ |
| **ویدئو → متن** | تحلیل جلسه | ⚠️ در حال بلوغ |
| **متن → ویدئو** | تبلیغات | 🔬 محدود |

**سه کاربرد سازمانی**

| کاربرد | مثال | ریسک |
|---|---|---|
| **تحلیل سند تصویری** | فاکتور، قرارداد اسکن‌شده | خطای OCR |
| **رونویسی جلسه** | صورت‌جلسه خودکار | دقت در فارسی |
| **دستیار صوتی** | پشتیبانی تلفنی | لحن، خطا |

**مفهوم «تأخیر» (Latency)**

| نوع | معنا | اهمیت |
|---|---|---|
| **Time to first token** | زمان تا اولین کلمه | مکالمه |
| **Total latency** | زمان کل | پردازش |
| **Real-time** | < ۳۰۰ms | مکالمهٔ طبیعی |

**نکته:** بلادرنگ بودن، هزینهٔ محاسباتی بیشتری دارد. برای هر کاربرد، «چقدر سریع کافی است؟» را بپرس.

**مفهوم «چندوجهی واقعی» در برابر «ترکیب ابزار»**

| | چندوجهی واقعی | ترکیب ابزار |
|---|---|---|
| مثال | یک مدل، متن+تصویر | OCR + LLM |
| مزیت | یکپارچگی | تخصص |
| عیب | خطای مشترک | پیچیدگی |

**توصیهٔ عملی:** برای OCR دقیق، ابزار تخصصی + مدل برای تفسیر. ترکیب، اغلب بهتر از یک مدل است.

### مثال‌های عملی

**Lab Scenario 87-A: رونویسی جلسه**

```markdown
# گردش‌کار رونویسی

## ورودی
فایل صوتی جلسه (۴۵ دقیقه، ۴ نفر)

## مراحل
۱. رونویسی خودکار (ابزار تخصصی)
۲. برچسب‌گذاری گویندگان (دستی یا خودکار)
۳. پاکسازی (حذف پرکننده‌ها: «اِ...»، «خب»)
۴. خلاصه با پرامپت ساختاریافته
۵. بازبینی انسانی (حداقل ۵ نقطه)

## ریسک
- نام‌های خاص اشتباه رونویسی می‌شوند
- اعداد (مبالغ، تاریخ) خطا دارند
- لهجه، دقت را کم می‌کند

## کنترل
□ فهرست شرکت‌کنندگان برای تطبیق نام
□ اعداد کلیدی با یادداشت دستی چک شود
□ رضایت شرکت‌کنندگان برای ضبط
```

**Lab Scenario 87-B: تحلیل فاکتور تصویری**

```text
این تصویر فاکتور را به JSON تبدیل کن.

ساختار:
{"vendor": "", "date": "YYYY-MM-DD", "items": [{"name": "", "qty": 0, "price": 0}], "total": 0}

قواعد:
- اگر عددی خوانا نیست، null بگذار. حدس نزن.
- جمع را دوباره محاسبه کن و اگر با total نمی‌خواند، فیلد "warning" اضافه کن.
- فقط JSON.
```

**بازبینی:** هر فیلد `null` و هر `warning` را دستی چک کن. این‌ها نقاط شکست هستند.

**Lab Scenario 87-C: دستیار صوتی پشتیبانی**

| مرحله | چه اتفاقی | کنترل |
|---|---|---|
| ورود تماس | تشخیص موضوع | مسیر جایگزین |
| پاسخ | تولید گفتار | لحن، سرعت |
| انتقال | به انسان | همیشه ممکن |
| ثبت | خلاصهٔ تماس | بازبینی |

**قاعدهٔ طلایی:** در دستیار صوتی، **مسیر «صحبت با انسان»** باید همیشه در دسترس باشد.

### مقایسه و الگوهای مختلف

**سه سطح بلوغ چندوجهی**

| سطح | کاربرد | آمادگی |
|---|---|---|
| **خواندن** | تحلیل تصویر/صدا | ✅ |
| **تولید** | ساخت محتوا | ✅ با بازبینی |
| **بلادرنگ** | مکالمه | ⚠️ محدود |

**مقایسهٔ دو رویکرد OCR**

| | مدل چندوجهی | ابزار تخصصی |
|---|---|---|
| دقت در متن ریز | متوسط | بالا |
| درک زمینه | بالا | کم |
| هزینه | بالا | کم |
| توصیه | تفسیر | استخراج |

### اشکال شایع

**اشتباه ۱: اعتماد به OCR مدل**
اعداد و متن ریز، خطا دارند.

**اشتباه ۲: نادیده گرفتن رضایت ضبط**
ضبط جلسه، نیاز به اطلاع و رضایت دارد.

**اشتباه ۳: انتظار بلادرنگ ارزان**
تأخیر کم = هزینهٔ بالا.

**اشتباه ۴: استفاده از ویدئو تولیدی در ارتباط رسمی**
ریسک حقوقی و اعتماد.

**اشتباه ۵: نبود مسیر انسانی**
دستیار صوتی بدون مسیر انسان، تجربهٔ بد می‌سازد.

### نکات مهم (Tips & Tricks)

- **برای استخراج دقیق، ابزار تخصصی + مدل برای تفسیر.**
- **اعداد را همیشه دستی چک کن.**
- **رضایت ضبط را بگیر.**
- **در دستیار صوتی، مسیر انسان را همیشه بگذار.**
- **«چقدر سریع کافی است؟» را قبل از «چقدر سریع ممکن است؟» بپرس.**

### خلاصه فصل

- شش ترکیب وجهی؛ **متن↔تصویر، صدا** بالغ‌ترند.
- سه کاربرد سازمانی: **سند، رونویسی، دستیار صوتی**.
- **بلادرنگ** هزینه دارد؛ کفایت را بسنج.
- ترکیب ابزار تخصصی + مدل، اغلب بهتر است.
- مسیر انسانی، الزامی.

## فصل ۸۸: مدل‌های کوچک، روی‌دستگاه و AI PC

### مقدمه

هم‌زمان با بزرگ‌تر شدن مدل‌ها، جریان دیگری هم قوی شده: **مدل‌های کوچک** که روی دستگاه اجرا می‌شوند. این جریان، پیامدهای مهمی برای حریم خصوصی، هزینه و معماری محصول دارد.

### مفاهیم اساسی

**سه اندازهٔ مدل**

| اندازه | پارامتر | اجرا | مناسب |
|---|---|---|---|
| **بزرگ** | ۱۰۰B+ | ابر | کار پیچیده |
| **متوسط** | ۷B–۷۰B | ابر/سرور | اکثر کارها |
| **کوچک** | ۰.۵B–۷B | دستگاه/لبه | کار محدود |

**مفهوم «فشرده‌سازی» (Quantization)**

کاهش دقت اعداد مدل (مثلاً از ۱۶ بیت به ۴ بیت) تا در حافظهٔ کمتر جا شود:

| دقت | حجم | کیفیت |
|---|---|---|
| FP16 | پایه | مرجع |
| INT8 | ~۵۰٪ | نزدیک |
| INT4 | ~۲۵٪ | افت محسوس در کارهای پیچیده |

**مزایای مدل کوچک/روی‌دستگاه**

| مزیت | توضیح |
|---|---|
| **حریم خصوصی** | داده از دستگاه خارج نمی‌شود |
| **تأخیر** | بدون رفت‌وبرگشت شبکه |
| **هزینه** | بدون هزینهٔ توکن |
| **آفلاین** | کار بدون اینترنت |
| **کنترل** | نسخهٔ ثابت، بدون تغییر ناگهانی |

**محدودیت‌ها**

| محدودیت | توضیح |
|---|---|
| **دانش محدود** | بدون دانش به‌روز |
| **توان استدلال** | ضعیف‌تر در مسائل پیچیده |
| **حافظه** | نیاز به RAM/VRAM |
| **به‌روزرسانی** | مدیریت نسخه |
| **کیفیت زبان** | ممکن است در فارسی ضعیف باشد |

**مفهوم «معماری ترکیبی»**

```
درخواست ساده → مدل کوچک روی دستگاه
درخواست پیچیده → مدل بزرگ در ابر
دادهٔ حساس → فقط دستگاه
```

این معماری، بهترین تعادل بین هزینه، حریم خصوصی و کیفیت است.

**مفهوم «AI PC»**

| ویژگی | معنا |
|---|---|
| **NPU** | پردازندهٔ عصبی اختصاصی |
| **حافظهٔ کافی** | اجرای مدل محلی |
| **نرم‌افزار یکپارچه** | دستیار در سیستم‌عامل |

**هشدار بازاریابی:** «AI PC» یک برچسب است، نه یک استاندارد عملکرد. مشخصات واقعی (حافظه، NPU، مدل پشتیبانی‌شده) مهم است.

### مثال‌های عملی

**Lab Scenario 88-A: تصمیم ابر در برابر دستگاه**

| معیار | ابر | دستگاه |
|---|---|---|
| دادهٔ حساس | ⚠️ نیاز به قرارداد | ✅ |
| کیفیت | بالا | متوسط |
| هزینهٔ ثابت | اشتراک | سخت‌افزار |
| هزینهٔ متغیر | توکن | تقریباً صفر |
| به‌روز بودن | ✅ | ⚠️ |
| آفلاین | ❌ | ✅ |

**قاعدهٔ تصمیم:**

```text
اگر دادهٔ حساس + حجم بالا + کار ساده → دستگاه
اگر کار پیچیده + نیاز به دانش به‌روز → ابر
اگر هر دو → معماری ترکیبی
```

**Lab Scenario 88-B: ارزیابی یک مدل کوچک**

```markdown
# ارزیابی مدل محلی — چک‌لیست
```

**Lab Scenario 88-C: معماری ترکیبی**

```python
"""
مسیریابی ساده: محلی یا ابری؟
"""
def route(task: dict) -> str:
    # دادهٔ حساس → همیشه محلی
    if task["data_class"] in ("confidential", "restricted"):
        return "local"

    # کار ساده → محلی
    if task["complexity"] == "low" and task["needs_fresh_knowledge"] is False:
        return "local"

    # نیاز به دانش به‌روز یا استدلال پیچیده → ابر
    if task["needs_fresh_knowledge"] or task["complexity"] == "high":
        return "cloud"

    return "local"

cases = [
    {"data_class": "public",   "complexity": "low",  "needs_fresh_knowledge": False},
    {"data_class": "restricted","complexity": "high","needs_fresh_knowledge": True},
    {"data_class": "internal", "complexity": "high","needs_fresh_knowledge": False},
    {"data_class": "public",   "complexity": "low",  "needs_fresh_knowledge": True},
]

for c in cases:
    print(c, "→", route(c))
```

### مقایسه و الگوهای مختلف

**سه معماری استقرار**

| معماری | حریم خصوصی | کیفیت | هزینه |
|---|---|---|---|
| **ابری** | متوسط | بالا | متغیر |
| **محلی** | بالا | متوسط | ثابت |
| **ترکیبی** ⭐ | بالا | بالا | بهینه |

**مقایسهٔ دو نوع مدل کوچک**

| | مدل عمومی کوچک | مدل تخصصی |
|---|---|---|
| دامنه | گسترده | باریک |
| کیفیت در دامنه | متوسط | بالا |
| اندازه | بزرگ‌تر | کوچک‌تر |

### اشکال شایع

**اشتباه ۱: «مدل کوچک = کیفیت کم»**
برای کارهای باریک، مدل کوچک تخصصی می‌تواند بهتر باشد.

**اشتباه ۲: نادیده گرفتن مجوز مدل**
بعضی مدل‌های باز، استفادهٔ تجاری محدود دارند.

**اشتباه ۳: فرض «محلی = امن»**
مدل محلی امن است، ولی مدیریت نسخه و آسیب‌پذیری هم لازم است.

**اشتباه ۴: خرید سخت‌افزار بر اساس برچسب**
«AI PC» بدون مشخصات کافی، بی‌معناست.

**اشتباه ۵: نبود معماری ترکیبی**
همه‌چیز محلی یا همه‌چیز ابری، معمولاً بهینه نیست.

### نکات مهم (Tips & Tricks)

- **معماری ترکیبی را از ابتدا طراحی کن.**
- **برای دادهٔ حساس، محلی.**
- **مجوز مدل را چک کن.**
- **۱۰ پرامپت واقعی، حداقل ارزیابی.**
- **«AI PC» را با مشخصات بسنج، نه برچسب.**

### خلاصه فصل

- سه اندازه: **بزرگ، متوسط، کوچک**.
- مزایای محلی: **حریم خصوصی، تأخیر، هزینه، آفلاین**.
- محدودیت: **دانش، استدلال، حافظه**.
- **معماری ترکیبی**، بهترین تعادل.
- «AI PC» یک برچسب است، نه استاندارد.

## فصل ۸۹: آیندهٔ کار و مهارت‌های دوام‌آور

### مقدمه

این فصل، جمع‌بندی کتاب است از منظر **تو**: چه مهارت‌هایی دوام می‌آورند، چه مهارت‌هایی کمرنگ می‌شوند، و چطور خودت را موقعیت‌یابی کنی.

**هشدار:** پیش‌بینی شغلی، پر از خطاست. هر کس که «۹۰٪ مشاغل حذف می‌شوند» می‌گوید، معمولاً داده ندارد. این فصل، محافظه‌کار است.

### مفاهیم اساسی

**سه دستهٔ مهارت**

| دسته | مثال | دوام |
|---|---|---|
| **مکانیکی** | تولید متن اولیه، خلاصه‌سازی، تبدیل قالب | 🔻 کاهش |
| **قضاوتی** | تصمیم، اولویت‌بندی، مذاکره | 🔺 افزایش ارزش |
| **رابطه‌ای** | اعتماد، رهبری، آموزش | 🔺 افزایش ارزش |

**مفهوم «جابه‌جایی، نه حذف»**

| نقش | قبل | بعد |
|---|---|---|
| نویسنده | تولید متن | ویرایش، استراتژی |
| تحلیلگر | ساخت گزارش | تفسیر، تصمیم |
| پشتیبان | پاسخ دادن | حل مسائل پیچیده |
| برنامه‌نویس | نوشتن کد | طراحی، بازبینی |

**هفت مهارت دوام‌آور**

| # | مهارت | چرا |
|---|---|---|
| ۱ | **صورت‌بندی مسئله** | AI مسئله را برایت تعریف نمی‌کند |
| ۲ | **قضاوت** | تصمیم، مسئولیت دارد |
| ۳ | **راستی‌آزمایی** | تشخیص خطا، مهارت است |
| ۴ | **ارتباط** | توضیح، متقاعدسازی، مذاکره |
| ۵ | **دامنهٔ تخصصی** | دانش عمیق، مزیت |
| ۶ | **تفکر سیستمی** | دیدن کل، نه قطعه |
| ۷ | **یادگیری مداوم** | ابزار عوض می‌شود |

**مفهوم «مزیت ترکیبی»**

ارزش، در **ترکیب** است، نه در یک مهارت:

```
AI + دامنهٔ تخصصی = ارزش بالا
AI تنها = کالای عمومی
دامنهٔ تخصصی تنها = محدود
```

**مثال:** کسی که AI را می‌شناسد و **حقوق قرارداد** را هم می‌داند، از کسی که فقط AI می‌داند، ارزشمندتر است.

**مفهوم «کار خالی از معنا»**

خطر پنهان: اگر AI بخش معنادار کار را بگیرد و انسان فقط تأیید کند، انگیزه و رضایت افت می‌کند.

| نشانه | پاسخ |
|---|---|
| «فقط دکمه می‌زنم» | افزودن تصمیم واقعی |
| «کارم بی‌معنا شده» | بازطراحی نقش |
| «یاد نمی‌گیرم» | چرخش وظایف |

### مقایسه و الگوهای مختلف

**سه نگرش به آینده**

| نگرش | رفتار | پیامد |
|---|---|---|
| **انکار** | «تغییری نمی‌آید» | عقب‌ماندگی |
| **اضطراب** | «همه‌چیز از دست می‌رود» | فلج |

**مقایسهٔ دو استراتژی شغلی**

| استراتژی | مزیت | عیب |
|---|---|---|
| **عمق** | تخصص، تمایز | وابستگی به یک حوزه |
| **پهنا** | انعطاف | سطحی بودن |
| **T شکل** ⭐ | عمق + آشنایی | نیاز به مدیریت زمان |

### اشکال شایع

**اشتباه ۱: یادگیری ابزار به‌جای مهارت**
نام ابزار عوض می‌شود؛ مهارت می‌ماند.

**اشتباه ۲: انکار اهمیت AI**
«کار من خلاقانه است» — بخشی از آن خلاقانه نیست.

**اشتباه ۳: اضطراب فلج‌کننده**
اضطراب، یادگیری را متوقف می‌کند.

**اشتباه ۴: اتکا به یک ابزار**
وابستگی به یک محصول، ریسک است.

**اشتباه ۵: نادیده گرفتن «معنای کار»**
اگر کارت خالی از معنا شد، تغییر نقش لازم است، نه تحمل.

### نکات مهم (Tips & Tricks)

- **روی مهارت‌های قضاوتی و رابطه‌ای سرمایه‌گذاری کن.**
- **مزیت ترکیبی بساز:** AI + دامنهٔ تخصصی.
- **هر سه ماه، نقشهٔ مهارت را بازبینی کن.**
- **به یک همکار آموزش بده.** عمیق‌ترین یادگیری.
- **نام ابزار را در رزومه ننویس؛ توانایی را بنویس.**

### خلاصه فصل

- سه دسته: **مکانیکی (کاهش)، قضاوتی (افزایش)، رابطه‌ای (افزایش)**.
- جابه‌جایی نقش، نه حذف.
- هفت مهارت دوام‌آور؛ **صورت‌بندی مسئله** و **قضاوت** در صدر.
- **مزیت ترکیبی**: AI + دامنه.
- در هر سه سناریو، **یادگیری** جواب است.
