## فصل ۵: راه‌اندازی VirtualBox / VMware

### مقدمه

قبل از هر چیز، به یک **محیط امن برای آزمایش** نیاز دارید. تصور کنید می‌خواهید یاد بگیرید چطور یک دیسک را پارتیشن‌بندی کنید یا رمز ریشه را بازیابی کنید. اگر این کارها را روی سیستم اصلی خود انجام دهید، ممکن است آن را خراب کنید و داده‌هایتان را از دست بدهید. راه‌حل: **ماشین مجازی (Virtual Machine)**.

یک ماشین مجازی، یک کامپیوتر کامل و مستقل است که داخل کامپیوتر شما اجرا می‌شود. هر کاری در آن بکنید — حتی پاک کردن کل دیسک — به سیستم اصلی شما آسیبی نمی‌رسد. این دقیقاً همان محیطی است که برای تمرین LPIC نیاز دارید.

در این فصل، VirtualBox (رایگان و متن‌باز) را نصب می‌کنیم و اولین ماشین مجازی را می‌سازیم. همچنین با VMware به‌عنوان جایگزین آشنا می‌شویم.

### مفاهیم اساسی

**ماشین مجازی چیست؟**

یک ماشین مجازی (VM) یک نرم‌افزار شبیه‌ساز است که یک کامپیوتر مجازی کامل می‌سازد — با CPU مجازی، رم مجازی، دیسک مجازی و شبکهٔ مجازی. سیستم‌عامل مهمان (guest) داخل آن اجرا می‌شود و از سیستم میزبان (host) جدا است. این جداسازی باعث می‌شود هر آزمایشی ایمن باشد.

**نرم‌افزار Hypervisor:**

نرم‌افزاری که ماشین‌های مجازی را مدیریت می‌کند، **Hypervisor** نام دارد. دو نوع دارد:

| نوع | توضیح | مثال |
|---|---|---|
| **Type 1 (Bare-metal)** | مستقیم روی سخت‌افزار | VMware ESXi, KVM, Xen |
| **Type 2 (Hosted)** | روی سیستم‌عامل | VirtualBox, VMware Workstation |

برای مطالعه، Type 2 کافی است چون روی سیستم شخصی شما اجرا می‌شود.

**دو نرم‌افزار محبوب:**

| نرم‌افزار | رایگان؟ | مزیت | معایب |
|---|---|---|---|
| **VirtualBox** | بله | ساده، متن‌باز، همه‌جا | کمی کندتر |
| **VMware Workstation Player** | بله (شخصی) | سریع‌تر، پایدارتر | رایگان فقط برای استفادهٔ شخصی |

**مفاهیم کلیدی:**

- **Host (میزبان):** کامپیوتر واقعی شما.
- **Guest (مهمان):** سیستم‌عامل داخل ماشین مجازی.
- **Snapshot (اسنپ‌شات):** ذخیرهٔ وضعیت ماشین در یک لحظه (مثل عکس فوری). می‌توانید بعداً به آن برگردید.
- **ISO:** فایل نصب سیستم‌عامل (تصویر دیسک).
- **VDI/VMDK:** فرمت فایل دیسک مجازی.
- **Guest Additions / VMware Tools:** افزونه‌هایی که کارایی و راحتی را بهبود می‌دهند.

**حداقل سیستم موردنیاز:**

| منبع | حداقل | توصیه‌شده |
|---|---|---|
| RAM (سیستم) | ۸ GB | ۱۶ GB |
| RAM (هر VM) | ۲ GB | ۴ GB |
| فضای دیسک | ۵۰ GB | ۱۰۰ GB+ |
| CPU | دو هسته | چهار هسته |
| Virtualization | فعال در BIOS | فعال |

### مثال‌های عملی

**گام ۱: نصب VirtualBox**

```
۱. به virtualbox.org بروید.
۲. نسخهٔ مناسب سیستم‌عامل خود را دانلود کنید (Windows/macOS/Linux).
۳. نصب کنید (Next → Next → Install).
۴. VirtualBox Extension Pack را هم دانلود و نصب کنید
   (برای USB 2.0/3.0 و RDP).
```

**گام ۲: ساخت اولین ماشین مجازی**

```
۱. VirtualBox را باز کنید.
۲. روی «New» کلیک کنید.
۳. نام بگذارید: Ubuntu-Lab
۴. Type: Linux، Version: Ubuntu (64-bit).
۵. RAM را تنظیم کنید: 2048 MB (حداقل) یا 4096 MB (بهتر).
۶. «Create a virtual hard disk now» → Create.
۷. نوع دیسک: VDI.
۸. Storage: «Dynamically allocated» (فضا فقط با استفاده مصرف می‌شود).
۹. اندازه: حداقل 20 GB (برای آزمایشگاه 40 GB بهتر).
۱۰. Create.
```

**گام ۳: اتصال ISO و بوت**

```
۱. ماشین را انتخاب کنید → Settings → Storage.
۲. زیر Controller: IDE، روی دیسک خالی کلیک کنید.
۳. آیکن دیسک (کنار Optical Drive) → Choose a disk file.
۴. فایل ISO را انتخاب کنید.
۵. OK → Start.
```

**گام ۴: فعال‌سازی Virtualization در BIOS**

اگر خطای `VT-x is not available` یا `AMD-V is disabled` گرفتید:

```
۱. کامپیوتر را ری‌استارت کنید.
۲. در بوت، کلید BIOS را بزنید (F2, F10, Del یا Esc).
۳. گزینه‌های Intel VT-x یا AMD-V یا SVM Mode را پیدا کنید.
۴. فعال (Enabled) کنید.
۵. ذخیره (F10) و خروج.
```

**تنظیمات مهم بعد از نصب:**

```bash
# در VirtualBox، Device → Insert Guest Additions CD
# سپس در مهمان:
sudo apt install build-essential dkms linux-headers-$(uname -r)
sudo mount /dev/cdrom /mnt
sudo /mnt/VBoxLinuxAdditions.run
```

### مقایسه و الگوهای مختلف

**حالت‌های شبکه در VirtualBox:**

| حالت | توضیح | کاربرد | دسترسی اینترنت |
|---|---|---|---|
| **NAT** | ماشین به اینترنت دسترسی دارد، ولی از بیرون دیده نمی‌شود | ساده‌ترین، پیش‌فرض | بله |
| **Bridged** | ماشین مثل یک کامپیوتر مستقل در شبکه ظاهر می‌شود | تست شبکه | بله |
| **Host-only** | فقط ارتباط با میزبان | شبکهٔ ایزوله | خیر |
| **Internal** | فقط بین ماشین‌های مجازی | آزمایشگاه چند-ماشینی | خیر |
| **NAT Network** | مثل NAT ولی ماشین‌ها همدیگر را می‌بینند | آزمایشگاه چند-ماشینی | بله |

برای مباحث شبکهٔ LPIC، حالت **Bridged** (برای تست واقعی) یا **Internal** (برای آزمایشگاه ایزوله) بهتر است.

**VirtualBox در برابر VMware:**

| ویژگی | VirtualBox | VMware Workstation |
|---|---|---|
| رایگان | کامل | فقط شخصی |
| سرعت | خوب | عالی |
| Snapshots | بله | بله |
| Shared folders | بله | بله |
| USB 3.0 | با Extension | بله |
| مناسب برای | مطالعه | کار حرفه‌ای |

**نکته:** برای LPIC، VirtualBox کاملاً کافی است.

### اشکال شایع

**اشکال ۱: رم ناکافی.**
اگر به ماشین مجازی کمتر از ۲ گیگ رم بدهید، کند می‌شود یا نصب نمی‌شود. راه‌حل: حداقل ۲ گیگ، بهتر ۴ گیگ.

**اشکال ۲: فراموش کردن فعال‌سازی Virtualization در BIOS.**
خطای VT-x می‌گیرید و VM اجرا نمی‌شود. راه‌حل: VT-x/AMD-V را در BIOS فعال کنید.

**اشکال ۳: کم بودن فضای دیسک.**
۲۰ گیگ برای آزمایشگاه‌های پیشرفته (RAID، LVM، چند فایل‌سیستم) کم است. راه‌حل: ۴۰+ گیگ بدهید.

**اشکال ۴: انتخاب اشتباه حالت شبکه.**
اگر بعداً نتوانستید ping کنید، احتمالاً NAT مشکل‌ساز است. راه‌حل: برای تست شبکه، Bridged یا Internal انتخاب کنید.

**اشکال ۵: نصب نکردن Guest Additions.**
رزولوشن پایین، کپی/پیست کار نمی‌کند، ماوس گیر می‌کند. راه‌حل: Guest Additions را نصب کنید.

**اشکال ۶: فراموش کردن اسنپ‌شات.**
اگر آزمایش شما سیستم را خراب کرد، باید از صفر نصب کنید. راه‌حل: بلافاصله بعد از نصب، اسنپ‌شات بگیرید.

**اشکال ۷: اشتباه گرفتن 32-bit و 64-bit.**
اگر نسخهٔ ۳۲-بیتی را انتخاب کنید، دسترسی به RAM محدود می‌شود. راه‌حل: همیشه 64-bit انتخاب کنید (اگر CPU شما پشتیبانی می‌کند).

### نکات مهم (Tips & Tricks)

- **برای هر توزیع یک ماشین مجازی جدا بسازید.** Debian و Rocky را قاطی نکنید.
- **همیشه بعد از نصب موفق، یک اسنپ‌شات با نام «Clean Install» بگیرید.** این نقطهٔ بازگشت شماست.
- **Shared Clipboard و Drag&Drop را فعال کنید** تا کپی/پیست راحت باشد. (Settings → General → Advanced)
- **از «Dynamically allocated disk» استفاده کنید** تا فضا هدر نرود. دیسک فقط با استفاده رشد می‌کند.
- **قبل از هر آزمایش خطرناک، اسنپ‌شات بگیرید** تا در صورت خرابی برگردید.
- **برای کارایی بهتر، در تنظیمات Display، Video Memory را به ۱۲۸ MB ببرید.**
- **System → Processor را به ۲ هسته ببرید** (اگر CPU شما پشتیبانی می‌کند).
- **Shared Folder بسازید** تا فایل‌ها را بین host و guest به اشتراک بگذارید.
- **از شبکهٔ NAT برای به‌روزرسانی و نصب پکیج استفاده کنید**، از Internal برای تست شبکهٔ ایزوله.
- **نام ماشین‌ها را معنادار بگذارید:** ubuntu-lab-base، rocky-lab-networking و...

### خلاصه فصل

ماشین مجازی یک محیط امن و مستقل برای آزمایش فراهم می‌کند. VirtualBox (رایگان) و VMware دو گزینهٔ اصلی هستند. مفاهیم کلیدی: host/guest، snapshot، ISO و hypervisor. حداقل ۲ گیگ رم و ۲۰ گیگ دیسک بدهید، Virtualization را در BIOS فعال کنید و بعد از نصب اسنپ‌شات بگیرید. حالت‌های شبکه (NAT/Bridged/Host-only/Internal) برای سناریوهای مختلف به‌کار می‌روند. Guest Additions کارایی و راحتی را بهبود می‌دهد.

## فصل ۶: نصب Debian / Ubuntu

### مقدمه

**Debian** و **Ubuntu** نمایندگان خانوادهٔ توزیع‌های مبتنی بر Debian هستند. این خانواده از **dpkg** و **apt** برای مدیریت پکیج استفاده می‌کند. یادگیری این خانواده برای آزمون LPIC ضروری است، چون نیمی از سؤالات مربوط به دستورهای این خانواده است.

تصور کنید می‌خواهید یک وب‌سرور راه‌اندازی کنید. با `apt install nginx` در چند ثانیه انجام می‌شود. اما اگر توزیع شما Red Hat باشد، باید از `dnf` استفاده کنید. آزمون هر دو را می‌سنجد.

در این فصل، Ubuntu Server (نمایندهٔ خانوادهٔ Debian) را نصب می‌کنیم و با دستورهای پایهٔ آن آشنا می‌شویم.

### مفاهیم اساسی

**تفاوت Debian و Ubuntu:**

| ویژگی | Debian | Ubuntu |
|---|---|---|
| ماهیت | مادر خانواده | مبتنی بر Debian |
| چرخهٔ انتشار | کند و پایدار (۲–۳ سال) | منظم (هر ۶ ماه LTS) |
| کاربرد | سرورها، پایداری | سرور و دسکتاپ |
| مدیریت پکیج | apt/dpkg | apt/dpkg |
| مخزن | اصلی، پایدار | اصلی + PPA |
| تازگی پکیج | محافظه‌کار | تازه‌تر |

**نکتهٔ LPIC:** هر دو از دستورهای یکسان (`apt`, `dpkg`) استفاده می‌کنند؛ یادگیری یکی کافی است.

**مفاهیم کلیدی:**

- **Release (انتشار):** نسخهٔ توزیع (مثل Ubuntu 24.04 LTS).
- **LTS (Long Term Support):** پشتیبانی طولانی‌مدت (۵ سال برای Ubuntu LTS).
- **Repository (مخزن):** محل ذخیرهٔ پکیج‌ها.
- **Package (پکیج):** نرم‌افزار بسته‌بندی‌شده (فایل `.deb`).
- **Dependency (وابستگی):** پکیج‌هایی که یک پکیج برای کار به آن‌ها نیاز دارد.

### مثال‌های عملی

**نصب Ubuntu Server (گام‌به‌گام):**

```
۱. ISO را از ubuntu.com/download/server دانلود کنید.
   (نسخهٔ LTS مثل 24.04)

۲. در VirtualBox یک ماشین با 2GB رم و 20GB دیسک بسازید.

۳. ISO را mount و Start کنید.

۴. زبان و صفحه‌کلید را انتخاب کنید (English پیشنهاد می‌شود).

۵. نوع نصب: «Ubuntu Server» (بدون snap‌های اضافی).

۶. Network: اتصال شبکه را چک کنید (DHCP خودکار IP می‌دهد).

۷. Proxy: خالی بگذارید (مگر در شبکهٔ خاص).

۸. Mirror: پیش‌فرض بگذارید یا آینهٔ نزدیک‌تر انتخاب کنید.

۹. Storage: «Use an entire disk» برای سادگی.
   (برای تمرین پارتیشن‌بندی دستی، «Custom storage layout» انتخاب کنید)

۱۰. نام کاربری و رمز بسازید.
    - نام کاربری: اولین کاربر (خودکار sudo می‌شود).
    - رمز: قوی.

۱۱. OpenSSH Server را نصب کنید (برای دسترسی از راه دور).
    - با Space انتخاب کنید.

۱۲. Snap‌های پیشنهادی را رد کنید (مگر نیاز باشد).

۱۳. نصب تمام می‌شود و ری‌استارت می‌کنید.
```

**اولین کارها بعد از نصب:**

```bash
# به‌روزرسانی سیستم
sudo apt update
sudo apt upgrade -y

# نصب ابزارهای مفید
sudo apt install -y vim net-tools htop tree curl wget \
  bash-completion git

# بررسی نسخه
lsb_release -a
cat /etc/os-release

# بررسی هسته
uname -r

# بررسی IP
ip addr show

# بررسی سرویس SSH
systemctl status ssh
```

**تنظیم SSH برای دسترسی راحت:**

```bash
# روی مهمان، IP را پیدا کنید
ip addr show | grep inet

# از میزبان، وصل شوید
ssh username@192.168.1.100

# یا از Shared Clipboard برای کپی/پیست استفاده کنید
```

### مقایسه و الگوهای مختلف

**انتخاب نسخه:**

| نسخه | مناسب | توضیح |
|---|---|---|
| **Ubuntu LTS** | سرور، مطالعه | پشتیبانی ۵ ساله، پایدار |
| **Ubuntu non-LTS** | تازه‌کارها | جدیدترین ویژگی‌ها، ۹ ماه پشتیبانی |
| **Debian Stable** | سرور تولیدی | پایداری حداکثری |
| **Debian Testing** | علاقه‌مندان | بسته‌های تازه‌تر، کمتر پایدار |
| **Ubuntu Desktop** | یادگیری GUI | محیط گرافیکی |

برای مطالعه، **Ubuntu LTS** یا **Debian Stable** بهترین انتخاب است.

**Ubuntu Server در برابر Desktop:**

| ویژگی | Server | Desktop |
|---|---|---|
| رابط | متنی | گرافیکی |
| منابع | کم | زیاد |
| پیش‌فرض | OpenSSH | GNOME |
| مناسب LPIC | عالی | متوسط |

**توصیه:** Server نصب کنید؛ سبک‌تر است و برای LPIC مناسب‌تر.

**ساختار مخازن:**

```
# /etc/apt/sources.list (Debian قدیمی)
deb http://deb.debian.org/debian bookworm main contrib non-free

# /etc/apt/sources.list.d/ (Ubuntu جدید - deb822)
# /etc/apt/sources.list.d/ubuntu.sources
Types: deb
URIs: http://archive.ubuntu.com/ubuntu/
Suites: noble noble-updates noble-security
Components: main restricted universe multiverse
```

### اشکال شایع

**اشکال ۱: فراموش کردن رمز sudo.**
در Ubuntu اولین کاربر به‌طور خودکار sudo است. راه‌حل: رمز را در جای امن ذخیره کنید.

**اشکال ۲: نصب بدون OpenSSH.**
بعداً برای دسترسی از راه دور به مشکل می‌خورید. راه‌حل: در نصب، OpenSSH را انتخاب کنید.

**اشکال ۳: پارتیشن‌بندی دستی پیچیده.**
برای آزمایشگاه، «Use an entire disk» کافی است. راه‌حل: سادگی را انتخاب کنید.

**اشکال ۴: نادیده گرفتن به‌روزرسانی.**
سیستم نصب‌شده ممکن است آسیب‌پذیری داشته باشد. راه‌حل: بلافاصله `apt update && apt upgrade`.

**اشکال ۵: انتخاب نسخهٔ non-LTS.**
پشتیبانی کوتاه‌مدت، مناسب مطالعهٔ طولانی نیست. راه‌حل: LTS انتخاب کنید.

**اشکال ۶: اشتباه صفحه‌کلید.**
اگر layout اشتباه باشد، تایپ دستورها سخت می‌شود. راه‌حل: layout درست را انتخاب کنید.

### نکات مهم (Tips & Tricks)

- **بعد از نصب، بلافاصله یک اسنپ‌شات «Clean Install» بگیرید.**
- **`apt` را با `-y` اجرا کنید تا تعاملی نشود.**
- **برای سرعت بیشتر، مخزن آینهٔ نزدیک‌تر انتخاب کنید.**
- **`sudo` را با `visudo` پیکربندی کنید** (بعداً در فصل ۴۱).
- **از `hostnamectl set-hostname lab1` برای نام‌گذاری استفاده کنید.**
- **`ip -c a` خروجی رنگی می‌دهد** (راحت‌تر).
- **`apt list --upgradable` پکیج‌های قابل ارتقا را نشان می‌دهد.**
- **`history` را فعال کنید** تا دستورهای قبلی را ببینید.
- **یک کاربر جدا برای آزمایش‌ها بسازید** (نه root).
- **`man apt` و `man dpkg` را بخوانید.**

### خلاصه فصل

Debian و Ubuntu از خانوادهٔ apt/dpkg هستند. برای مطالعه، Ubuntu LTS یا Debian Stable را نصب کنید. بعد از نصب، سیستم را به‌روز کنید و ابزارهای ضروری (vim, net-tools, htop, curl) را نصب کنید. بلافاصله اسنپ‌شات بگیرید. تفاوت Debian (محافظه‌کار) و Ubuntu (منظم) را بشناسید. Ubuntu Server برای LPIC مناسب‌تر است.

## فصل ۷: نصب RHEL / Rocky / CentOS

### مقدمه

خانوادهٔ دوم، توزیع‌های مبتنی بر **Red Hat** هستند: RHEL، Rocky Linux، AlmaLinux و CentOS. این خانواده از **rpm**، **yum** و **dnf** استفاده می‌کند. آزمون LPIC هر دو خانواده را می‌سنجد، پس باید با این خانواده هم کار کرده باشید.

تفاوت‌های کلیدی: مسیر مخازن، ابزار پکیج، و **SELinux** (که در Red Hat فعال است). اگر فقط Ubuntu بلدید، در سؤالات مربوط به این خانواده گیر می‌کنید.

در این فصل، Rocky Linux (نمایندهٔ رایگان این خانواده) را نصب می‌کنیم.

### مفاهیم اساسی

**تاریخچه و وضعیت فعلی:**

| توزیع | وضعیت | توضیح |
|---|---|---|
| **RHEL** | تجاری | استاندارد صنعت، نیاز به اشتراک |
| **CentOS Stream** | رایگان | نسخهٔ توسعه‌ای RHEL (rolling) |
| **Rocky Linux** | رایگان | جایگزین ۱:۱ CentOS |
| **AlmaLinux** | رایگان | جایگزین ۱:۱ CentOS |
| **Fedora** | رایگان | پیشرو (upstream RHEL) |

**نکتهٔ مهم:** CentOS کلاسیک (تا نسخهٔ ۸) به CentOS Stream تغییر کرد. امروزه **Rocky** یا **Alma** جایگزین‌های رایگان محبوب هستند و تقریباً ۱۰۰٪ با RHEL سازگارند.

**مفاهیم کلیدی این خانواده:**

- **RPM:** Package Manager (فرمت `.rpm`).
- **DNF:** Dandified YUM (نسخهٔ مدرن yum).
- **YUM:** نسخهٔ قدیمی‌تر (alias dnf).
- **SELinux:** Security-Enhanced Linux (کنترل دسترسی اجباری).
- **firewalld:** فایروال پیش‌فرض.
- **Subscription Manager:** مدیریت اشتراک RHEL.

### مثال‌های عملی

**نصب Rocky Linux (گام‌به‌گام):**

```
۱. ISO را از rockylinux.org دانلود کنید (نسخهٔ Minimal یا DVD).

۲. در VirtualBox ماشین با 2GB رم و 20GB دیسک بسازید.

۳. ISO را mount و Start کنید.

۴. گزینهٔ «Install Rocky Linux» را انتخاب کنید.

۵. زبان و صفحه‌کلید.

۶. Installation Destination: دیسک را انتخاب
   (Automatic partitioning).

۷. Software Selection: «Minimal Install» یا «Server».

۸. Network & Host Name: اتصال شبکه را روشن کنید (toggle).

۹. Root Password و یک کاربر با دسترسی sudo بسازید.

۱۰. Begin Installation.

۱۱. بعد از نصب، ری‌استارت.
```

**اولین کارها:**

```bash
# به‌روزرسانی
sudo dnf update -y

# نصب ابزارها
sudo dnf install -y vim net-tools htop tree curl wget bash-completion

# بررسی نسخه
cat /etc/redhat-release
cat /etc/os-release

# بررسی SELinux
getenforce
sestatus

# بررسی فایروال
sudo firewall-cmd --state

# بررسی مخازن
dnf repolist
```

**نصب EPEL (مخزن اضافی):**

```bash
# EPEL = Extra Packages for Enterprise Linux
sudo dnf install -y epel-release

# بررسی
dnf repolist | grep epel
```

### مقایسه و الگوهای مختلف

**تفاوت‌های کلیدی دو خانواده:**

| موضوع | Debian/Ubuntu | RHEL/Rocky |
|---|---|---|
| نصب پکیج | `apt install` | `dnf install` |
| حذف پکیج | `apt remove` | `dnf remove` |
| جستجو | `apt search` | `dnf search` |
| فهرست مخازن | `/etc/apt/sources.list` | `/etc/yum.repos.d/` |
| لاگ نصب پکیج | `/var/log/dpkg.log` | `/var/log/dnf.log` |
| سرویس‌ها | systemd | systemd |
| SELinux | معمولاً غیرفعال | معمولاً فعال |
| فایروال | ufw | firewalld |
| لاگ auth | `/var/log/auth.log` | `/var/log/secure` |
| پکیج نصب‌شده | `dpkg -l` | `rpm -qa` |

**انتخاب توزیع Red Hat:**

| توزیع | مناسب برای |
|---|---|
| RHEL | سازمان با اشتراک |
| Rocky | جایگزین رایگان (پیشنهاد ما) |
| Alma | جایگزین رایگان |
| CentOS Stream | توسعه‌دهندگان |

**توصیه برای LPIC:** Rocky Linux نصب کنید — تقریباً ۱۰۰٪ با RHEL سازگار و رایگان است.

### اشکال شایع

**اشکال ۱: استفاده از CentOS کلاسیک.**
دیگر پشتیبانی نمی‌شود. راه‌حل: Rocky/Alma نصب کنید.

**اشکال ۲: نادیده گرفتن SELinux.**
در RHEL فعال است و می‌تواند مانع سرویس‌ها شود. راه‌حل: با آن آشنا شوید (فصل ۲۷) و به‌جای غیرفعال کردن، پیکربندی کنید.

**اشکال ۳: فراموش کردن فعال‌سازی شبکه.**
در نصب باید Network را روشن کنید. راه‌حل: در مرحلهٔ Network، toggle را روشن کنید.

**اشکال ۴: مخلوط کردن دستورها.**
`apt` در RHEL و `dnf` در Debian کار نمی‌کند. راه‌حل: به خانوادهٔ توزیع دقت کنید.

**اشکال ۵: نبود EPEL.**
بعضی پکیج‌ها در مخزن اصلی نیستند. راه‌حل: `dnf install epel-release`.

**اشکال ۶: اشتباه با firewalld.**
پورت بسته می‌ماند. راه‌حل: `firewall-cmd --add-port=...`.

### نکات مهم (Tips & Tricks)

- **Rocky Linux نزدیک‌ترین تجربه به RHEL است و رایگان.**
- **برای آزمایشگاه، نسخهٔ Minimal را نصب کنید تا سبک باشد.**
- **SELinux را ابتدا روی `permissive` بگذارید** تا با آن آشنا شوید، بعد `enforcing`.
- **بعد از نصب، مخازن اضافی (EPEL) را در صورت نیاز اضافه کنید.**
- **`dnf history` تاریخچهٔ تراکنش‌ها را نشان می‌دهد** و می‌توانید undo کنید.
- **`rpm -qa | wc -l` تعداد پکیج‌های نصب‌شده را نشان می‌دهد.**
- **`dnf provides <file>` پیدا می‌کند کدام پکیج یک فایل را دارد.**
- **همیشه اسنپ‌شات بگیرید.**
- **`sestatus` وضعیت SELinux را نشان می‌دهد.**
- **`firewall-cmd --list-all` قوانین فایروال را نشان می‌دهد.**

### خلاصه فصل

خانوادهٔ Red Hat شامل RHEL (تجاری)، Rocky و Alma (رایگان) و CentOS Stream است. این خانواده از rpm/dnf استفاده می‌کند. برای مطالعه Rocky Linux نصب کنید. تفاوت‌های کلیدی با Debian در مدیریت پکیج، مسیر مخازن، SELinux و firewalld است. بعد از نصب اسنپ‌شات بگیرید و EPEL را در صورت نیاز اضافه کنید. جدول مقایسهٔ دو خانواده را حفظ کنید — در آزمون حیاتی است.

## فصل ۸: آشنایی با Docker برای آزمایشگاه

### مقدمه

تصور کنید می‌خواهید یک سرور DNS را تست کنید، اما نمی‌خواهید ۲۰ دقیقه برای نصب VM صبر کنید. یا می‌خواهید سه سرویس مختلف را همزمان اجرا کنید. راه‌حل: **Docker**.

**Docker** یک ابزار **کانتینری‌سازی (containerization)** است که به شما اجازه می‌دهد سیستم‌عامل‌ها و سرویس‌ها را در چند ثانیه اجرا کنید — بدون نیاز به نصب کامل. برای آزمایشگاه LPIC، Docker فوق‌العاده سریع و سبک است.

در این فصل، Docker را نصب می‌کنیم و یاد می‌گیریم چطور از آن برای تست سریع دستورها و سرویس‌ها استفاده کنیم.

### مفاهیم اساسی

**کانتینر چیست؟**

یک کانتینر یک محیط ایزوله است که یک برنامه و وابستگی‌هایش را بسته‌بندی می‌کند. برخلاف ماشین مجازی، کانتینر **کرنل میزبان** را به اشتراک می‌گذارد و بسیار سبک‌تر است.

| ویژگی | ماشین مجازی | کانتینر |
|---|---|---|
| سرعت راه‌اندازی | دقیقه | ثانیه |
| حجم | گیگابایت | مگابایت |
| ایزوله بودن | کامل (کرنل جدا) | سطح process |
| کرنل | مستقل | مشترک با میزبان |
| منابع | زیاد | کم |
| کاربرد | یادگیری عمیق | تست سریع |

**مفاهیم کلیدی Docker:**

- **Image (ایمیج):** قالب فقط‌خواندنی (مثل ISO).
- **Container (کانتینر):** نمونهٔ در حال اجرا از ایمیج.
- **Dockerfile:** فایل دستور ساخت ایمیج.
- **Volume:** ذخیره‌سازی دائمی.
- **Registry:** مخزن ایمیج (Docker Hub).
- **Docker Compose:** اجرای چند کانتینر.

**کاربرد در LPIC:** تست سریع دستورها، سرویس‌ها (وب‌سرور، DNS) و اسکریپت‌ها.

### مثال‌های عملی

**نصب Docker (روی Ubuntu):**

```bash
# روش ۱: از مخزن توزیع
sudo apt update
sudo apt install -y docker.io

# فعال‌سازی سرویس
sudo systemctl enable --now docker

# افزودن کاربر به گروه docker (تا نیازی به sudo نباشد)
sudo usermod -aG docker $USER
# (خارج و دوباره وارد شوید)

# تست
docker run hello-world
```

**اجرای یک توزیع مختلف:**

```bash
# اجرای Ubuntu در حالت تعاملی
docker run -it ubuntu:22.04 bash

# داخل کانتینر می‌توانید دستورها را تست کنید
apt update && apt install -y vim
cat /etc/os-release

# خروج
exit
```

**اجرای یک سرور وب برای تست:**

```bash
# اجرای Nginx
docker run -d --name web -p 8080:80 nginx

# تست در مرورگر: http://localhost:8080

# بررسی
docker ps

# لاگ
docker logs web

# توقف و حذف
docker stop web && docker rm web
```

**مدیریت ایمیج و کانتینر:**

```bash
# فهرست ایمیج‌ها
docker images

# فهرست کانتینرها (همه)
docker ps -a

# حذف ایمیج
docker rmi nginx

# پاک‌سازی کامل
docker system prune -a

# ورود به کانتینر در حال اجرا
docker exec -it web bash
```

**Docker Compose (چند سرویس):**

```yaml
# docker-compose.yml
version: '3'
services:
  web:
    image: nginx
    ports:
      - "8080:80"
  db:
    image: mysql:8
    environment:
      MYSQL_ROOT_PASSWORD: secret
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

```bash
docker compose up -d
docker compose down
```

### مقایسه و الگوهای مختلف

**Docker در برابر ماشین مجازی برای مطالعه:**

| سناریو | ابزار بهتر |
|---|---|
| تست سریع یک دستور | Docker |
| یادگیری نصب کامل سیستم | ماشین مجازی |
| تست سرویس‌های شبکه (DNS/Web) | Docker (چند کانتینر) |
| یادگیری بوت و کرنل | ماشین مجازی (اجباری) |
| آزمایشگاه RAID/LVM | ماشین مجازی |
| تست اسکریپت | Docker |

**توصیه:** هر دو را داشته باشید. Docker برای تست سریع، VM برای یادگیری عمیق.

**گزینه‌های جایگزین Docker:**

| ابزار | توضیح |
|---|---|
| Podman | بدون daemon، امن‌تر |
| LXC/LXD | کانتینر سیستمی |
| containerd | لایهٔ پایین Docker |

### اشکال شایع

**اشکال ۱: فراموش کردن `usermod -aG docker`.**
هر بار `sudo` لازم می‌شود. راه‌حل: کاربر را به گروه docker اضافه کنید و دوباره وارد شوید.

**اشکال ۲: انتظار ذخیره‌سازی دائمی.**
دادهٔ کانتینر با حذف آن از بین می‌رود. راه‌حل: از volume استفاده کنید.

**اشکال ۳: استفاده از Docker برای یادگیری کرنل/بوت.**
کانتینر کرنل مستقل ندارد. راه‌حل: برای بوت/کرنل از VM استفاده کنید.

**اشکال ۴: اشغال پورت.**
اگر پورت ۸۰ اشغال است، `-p 8080:80` استفاده کنید. راه‌حل: پورت‌های مختلف map کنید.

**اشکال ۵: انباشت کانتینرهای بی‌استفاده.**
فضای دیسک پر می‌شود. راه‌حل: `docker system prune`.

**اشکال ۶: اجرای کانتینر بدون `-d`.**
ترمینال اشغال می‌ماند. راه‌حل: `-d` (detached) برای پس‌زمینه.

### نکات مهم (Tips & Tricks)

- **با `docker ps -a` همهٔ کانتینرها را ببینید.**
- **با `docker exec -it <name> bash` وارد کانتینر در حال اجرا شوید.**
- **برای آزمایشگاه چند-سرویسی از `docker compose` استفاده کنید.**
- **ایمیج‌ها را با `docker images` و `docker rmi` مدیریت کنید.**
- **برای آزمایش‌های خطرناک، Docker امن‌ترین گزینه است (ایزوله).**
- **`docker run --rm` کانتینر را بعد از خروج خودکار حذف می‌کند.**
- **`docker run -v /host:/container` برای اشتراک پوشه.**
- **`docker pull` ایمیج را دانلود می‌کند بدون اجرا.**
- **از `podman` می‌توانید به‌عنوان جایگزین استفاده کنید (بدون daemon).**
- **Docker Hub منبع ایمیج‌های رسمی است.**

### خلاصه فصل

Docker کانتینری سبک و سریع برای تست است — مکمل ماشین مجازی. برای نصب و مدیریت سرویس‌ها عالی است، اما برای یادگیری کرنل، بوت، RAID و LVM باید از ماشین مجازی استفاده کنید. ترکیب هر دو بهترین آزمایشگاه را می‌سازد. مفاهیم کلیدی: image، container، volume و compose. برای آزمایش‌های خطرناک، Docker امن‌ترین گزینه است.

## فصل ۹: اسنپ‌شات، کلون و مدیریت محیط آزمایشگاه

### مقدمه

تصور کنید سه ساعت روی یک آزمایشگاه کار کرده‌اید و ناگهان یک دستور اشتباه کل سیستم را خراب می‌کند. اگر اسنپ‌شات نداشته باشید، باید از صفر شروع کنید. اما اگر داشته باشید، در چند ثانیه به حالت سالم برمی‌گردید.

یک آزمایشگاه خوب، **قابل بازگردانی** است. در این فصل، ابزارهای مدیریت محیط آزمایشگاه را یاد می‌گیرید.

### مفاهیم اساسی

**ابزارهای مدیریت:**

- **Snapshot (اسنپ‌شات):** ذخیرهٔ وضعیت لحظه‌ای ماشین.
- **Clone (کلون):** کپی کامل ماشین برای ساخت ماشین جدید.
- **Export/Import:** انتقال ماشین بین کامپیوترها.
- **Linked Clone:** کلون سبک که از دیسک والد استفاده می‌کند.
- **Golden Base:** ماشین پایهٔ دست‌نخورده که از آن کلون می‌گیرید.

**استراتژی نام‌گذاری:**

یک الگوی مشخص داشته باشید، مثلاً:

```
ubuntu-lab-base        ← نصب تمیز (Golden Base)
ubuntu-lab-networking  ← برای فصل شبکه
ubuntu-lab-storage     ← برای فصل ذخیره‌سازی
ubuntu-lab-web         ← برای سرویس وب
```

### مثال‌های عملی

**گرفتن اسنپ‌شات در VirtualBox:**

```
۱. ماشین را انتخاب کنید (خاموش یا روشن).
۲. منوی Machine → Snapshots → Take Snapshot.
۳. نام بگذارید: «Clean Install».
۴. توضیح بنویسید: «تازه نصب‌شده، به‌روز».
۵. OK.

# بازگردانی:
# Snapshot را انتخاب → Restore → تأیید.
```

**کلون کردن ماشین (خط فرمان VirtualBox):**

```bash
# کلون کامل
VBoxManage clonevm "ubuntu-lab-base" \
  --name "ubuntu-lab-networking" --register

# کلون لینک‌شده (سبک‌تر)
VBoxManage clonevm "ubuntu-lab-base" \
  --name "ubuntu-lab-web" --options link --register

# فهرست ماشین‌ها
VBoxManage list vms
```

**اسنپ‌شات در Docker (معادل):**

```bash
# ساخت ایمیج از کانتینر فعلی
docker commit my_container my_custom_image:latest

# بازگردانی از ایمیج
docker run -it my_custom_image:latest bash

# ذخیرهٔ ایمیج به فایل
docker save my_custom_image > image.tar
docker load < image.tar
```

**اسکریپت مدیریت آزمایشگاه:**

```bash
#!/bin/bash
# lab-snapshot.sh — گرفتن اسنپ‌شات سریع
LAB="$1"
STAMP=$(date +%Y%m%d-%H%M)
VBoxManage snapshot "$LAB" take "auto-$STAMP"
echo "اسنپ‌شات گرفته شد: auto-$STAMP"
```

### مقایسه و الگوهای مختلف

**انواع بازگردانی:**

| روش | سرعت | حجم | کاربرد |
|---|---|---|---|
| **Snapshot** | فوری | کم (فقط تفاوت) | بازگشت سریع |
| **Full Clone** | متوسط | زیاد (کامل) | ماشین مستقل |
| **Linked Clone** | سریع | کم | چند ماشین از یک پایه |
| **Export/Import** | کند | زیاد | انتقال/بکاپ |

**Snapshot در برابر Clone:**

| ویژگی | Snapshot | Clone |
|---|---|---|
| هدف | بازگشت | ماشین جدید |
| تعداد | چندین | یکی |
| استقلال | وابسته | مستقل |
| مناسب | آزمایش موقت | پروژهٔ جدید |

### اشکال شایع

**اشکال ۱: نبود اسنپ‌شات قبل از آزمایش خطرناک.**
اگر خراب شد، باید از صفر نصب کنید. راه‌حل: قبل از هر فصل عملی، اسنپ‌شات بگیرید.

**اشکال ۲: اسنپ‌شات‌های زیاد و درهم.**
فضای دیسک پر می‌شود. راه‌حل: اسنپ‌شات‌های قدیمی را حذف کنید.

**اشکال ۳: کار روی ماشین بدون پایهٔ سالم.**
اگر Golden Base را خراب کنید، همهٔ کلون‌ها خراب می‌شوند. راه‌حل: یک ماشین «Base» دست‌نخورده نگه دارید.

**اشکال ۴: نادیده گرفتن وضعیت شبکه.**
بعد از restore، IP ممکن است تغییر کند. راه‌حل: بعد از restore، شبکه را بررسی کنید.

**اشکال ۵: اسنپ‌شات روی ماشین در حال اجرای سنگین.**
ممکن است ناسازگاری ایجاد شود. راه‌حل: برای اسنپ‌شات مهم، ماشین را خاموش کنید.

**اشکال ۶: فراموش کردن اسنپ‌شات کلون.**
کلون بدون اسنپ‌شات، نقطهٔ بازگشت ندارد. راه‌حل: بلافاصله بعد از کلون، اسنپ‌شات بگیرید.

### نکات مهم (Tips & Tricks)

- **قبل از هر فصل عملی، یک اسنپ‌شات با نام همان فصل بگیرید.**
- **یک ماشین «Golden Base» بسازید و همیشه از آن کلون بگیرید.**
- **برای آزمایشگاه شبکه، دو ماشین با شبکهٔ Internal بسازید.**
- **اسنپ‌شات‌ها را در پایان هر هفته تمیز کنید.**
- **وضعیت آزمایشگاه خود را در یک فایل متنی یادداشت کنید.**
- **نام‌گذاری معنادار** (فصل/موضوع) پیدا کردن را آسان می‌کند.
- **`VBoxManage snapshot <vm> list` اسنپ‌شات‌ها را فهرست می‌کند.**
- **برای انتقال به کامپیوتر دیگر، از Export استفاده کنید** (`.ova`).
- **اسنپ‌شات درختواره است** (می‌توانید از هر نقطه شاخه بگیرید).
- **قبل از حذف اسنپ‌شات، مطمئن شوید به آن نیاز ندارید.**

### خلاصه فصل

مدیریت آزمایشگاه یعنی توانایی بازگردانی سریع. از Snapshot برای بازگشت فوری، Clone برای ساخت ماشین جدید و Export/Import برای انتقال استفاده کنید. یک ماشین «Golden Base» نگه دارید و قبل از هر آزمایش خطرناک اسنپ‌شات بگیرید. نام‌گذاری معنادار و تمیزکاری دوره‌ای محیط را مدیریت می‌کند. Snapshot برای آزمایش موقت و Clone برای پروژهٔ جدید مناسب است.
