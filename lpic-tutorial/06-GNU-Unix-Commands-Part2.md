## فصل ۲۴: ایجاد، پایش و کشتن فرآیندها

### مقدمه

هر برنامه‌ای که در لینوکس اجرا می‌شود یک **فرآیند (process)** است. تصور کنید سرور کند شده و باید بفهمید کدام فرآیند منابع را می‌خورد و آن را متوقف کنید. یا یک سرویس گیر کرده و باید بدون ری‌استارت کل سرور، فقط آن را بکشید.

مدیریت فرآیندها — دیدن، پایش و متوقف کردن آن‌ها — مهارت پایه‌ای هر مدیر سیستم است و در آزمون LPIC وزن بالایی دارد.

### مفاهیم اساسی

**مفاهیم کلیدی:**

- **PID:** شناسهٔ فرآیند (Process ID) — عدد یکتا.
- **PPID:** شناسهٔ فرآیند والد (Parent PID).
- **Foreground:** فرآیند در پیش‌زمینه (ترمینال را اشغال می‌کند).
- **Background:** فرآیند در پس‌زمینه (ترمینال آزاد است).
- **Daemon:** فرآیند پس‌زمینه که سرویس ارائه می‌دهد.
- **Zombie:** فرآیندی که تمام شده اما والدش آن را جمع نکرده.
- **Orphan:** فرآیندی که والدش تمام شده (به init می‌رسد).

**حالت‌های فرآیند:**

| حالت | کد | معنی |
|---|---|---|
| Running | R | در حال اجرا |
| Sleeping | S | در انتظار |
| Disk sleep | D | انتظار I/O (غیرقابل کشتن) |
| Stopped | T | متوقف |
| Zombie | Z | تمام‌شده ولی جمع‌نشده |

**دستورهای کلیدی:**

| دستور | کار |
|---|---|
| `ps` | نمایش فرآیندها |
| `top` / `htop` | پایش زنده |
| `pstree` | درخت فرآیندها |
| `pgrep` | پیدا کردن PID با نام |
| `kill` | ارسال سیگنال |
| `killall` | کشتن با نام |
| `jobs` | فرآیندهای پس‌زمینهٔ شل |
| `bg` / `fg` | پس‌زمینه/پیش‌زمینه |
| `nohup` | مقاوم در برابر بستن ترمینال |

### مثال‌های عملی

**نمایش فرآیندها:**

```bash
ps                     # فرآیندهای ترمینال فعلی
ps aux                 # همهٔ فرآیندها (کامل)
ps -ef                 # فرمت جایگزین
ps aux | grep nginx    # جستجو
ps -eo pid,ppid,user,%cpu,%mem,cmd  # ستون‌های سفارشی
ps aux --sort=-%cpu    # مرتب بر اساس CPU
ps aux --sort=-%mem    # مرتب بر اساس حافظه
pgrep nginx            # فقط PID
pgrep -a nginx         # PID + خط فرمان
pgrep -u alice         # فرآیندهای کاربر
pstree -p              # درخت با PID
pstree -u              # با کاربر
```

**پایش زنده:**

```bash
top                    # پایش زنده
htop                   # نسخهٔ بهتر (نیاز به نصب)
top -u www-data        # فرآیندهای یک کاربر
top -p 1234            # یک PID
top -b -n1             # batch (برای اسکریپت)

# در top:
#   M → مرتب بر اساس حافظه
#   P → مرتب بر اساس CPU
#   k → کشتن فرآیند
#   r → renice
#   q → خروج
```

**کنترل شغل:**

```bash
sleep 100 &            # اجرا در پس‌زمینه
jobs                   # فهرست شغل‌ها
jobs -l                # با PID
fg                     # بازگشت به پیش‌زمینه
fg %1                  # شغل شمارهٔ ۱
bg                     # ادامه در پس‌زمینه
bg %1
# Ctrl+Z → توقف موقت
# Ctrl+C → پایان
disown %1              # جدا کردن از شل
```

**کشتن فرآیند:**

```bash
kill 1234              # SIGTERM (پایان تمیز)
kill -9 1234           # SIGKILL (اجباری)
kill -15 1234          # SIGTERM
kill -HUP 1234         # SIGHUP (بازخوانی)
killall nginx          # با نام
killall -9 nginx       # اجباری
pkill -f "python app"  # با الگوی کامل
pkill -u alice         # فرآیندهای کاربر
```

**اجرای مقاوم (nohup):**

```bash
nohup ./long-script.sh &
nohup ./script.sh > output.log 2>&1 &

# با screen/tmux
screen -S mysession
# ... کار ...
# Ctrl+A, D → جدا شدن
screen -r mysession    # بازگشت
```

### مقایسه و الگوهای مختلف

**سیگنال‌های مهم:**

| سیگنال | شماره | اثر | قابل مهار؟ |
|---|---|---|---|
| SIGHUP | 1 | بازخوانی پیکربندی | بله |
| SIGINT | 2 | وقفه (Ctrl+C) | بله |
| SIGQUIT | 3 | خروج با core dump | بله |
| SIGTERM | 15 | پایان تمیز (پیش‌فرض kill) | بله |
| SIGKILL | 9 | پایان اجباری | خیر |
| SIGSTOP | 19 | توقف | خیر |
| SIGCONT | 18 | ادامه | بله |

**ترتیب توصیه‌شده:** اول SIGTERM (15)، اگر جواب نداد SIGKILL (9).

**ابزارهای پایش:**

| ابزار | ویژگی |
|---|---|
| `ps` | لحظه‌ای |
| `top` | زنده، تعاملی |
| `htop` | زنده، رنگی، بهتر |
| `atop` | لاگ تاریخی |
| `glances` | جامع |

**ps aux در برابر ps -ef:**

| ستون | aux | -ef |
|---|---|---|
| کاربر | USER | USER |
| PID | PID | PID |
| CPU/Mem | %CPU, %MEM | — |
| دستور | COMMAND | CMD |

### اشکال شایع

**اشکال ۱: شروع با `kill -9`.**
همیشه اول SIGTERM بفرستید تا فرآیند تمیز بسته شود. راه‌حل: `kill` (پیش‌فرض ۱۵) اول.

**اشکال ۲: `killall` روی نام مشترک.**
ممکن است فرآیندهای مهم را بکشد. راه‌حل: با `-i` (تعاملی) یا `pgrep` اول بررسی کنید.

**اشکال ۳: گیج شدن foreground/background.**
`&` در انتها فرآیند را پس‌زمینه می‌کند. راه‌حل: `jobs`/`fg`/`bg` را یاد بگیرید.

**اشکال ۴: زامبی‌ها (zombie).**
فرآیندی که والدش آن را جمع نکرده؛ با kill والد حل می‌شود. راه‌حل: والد را restart کنید.

**اشکال ۵: فرآیند در حالت D (غیرقابل کشتن).**
انتظار I/O است؛ حتی `kill -9` کار نمی‌کند. راه‌حل: منتظر I/O بمانید یا سیستم را restart کنید.

**اشکال ۶: از دست دادن فرآیند با بستن ترمینال.**
با بستن SSH، فرآیندهای پیش‌زمینه می‌میرند. راه‌حل: `nohup` یا `screen`/`tmux`.

### نکات مهم (Tips & Tricks)

- **`Ctrl+Z` فرآیند را متوقف (نه می‌کشد) می‌کند.**
- **`nohup command &` فرآیند را در برابر بستن ترمینال مقاوم می‌کند.**
- **`screen` یا `tmux` برای جلسات پایدار.**
- **`top` را با `M` (حافظه)، `P` (CPU)، `k` (kill) کنترل کنید.**
- **`ps aux --sort=-%mem` فرآیندها را بر اساس حافظه مرتب می‌کند.**
- **`pgrep -a` هم PID و هم خط فرمان را نشان می‌دهد.**
- **`kill -0 PID` فقط بررسی می‌کند که فرآیند زنده است (بدون کشتن).**
- **`pkill -f` با الگوی کامل خط فرمان کار می‌کند.**
- **`renice` (فصل ۲۵) اولویت را تغییر می‌دهد.**
- **`watch -n1 'ps aux | grep nginx'` پایش دوره‌ای.**
- **`/proc/PID/` اطلاعات کامل هر فرآیند را دارد.**
- **`systemctl status X` برای سرویس‌های systemd بهتر از ps است.**

### خلاصه فصل

هر برنامه یک فرآیند با PID است. با `ps`, `top`, `pstree` فرآیندها را ببینید و با `kill`, `killall`, `pkill` مدیریت کنید. اول SIGTERM (15) و در صورت نیاز SIGKILL (9). با `&`, `fg`, `bg` و `jobs` شغل‌ها را کنترل کنید و `nohup`/`tmux` جلسات پایدار می‌سازند. `/proc/PID/` اطلاعات کامل فرآیند را دارد.

## فصل ۲۵: تغییر اولویت اجرای فرآیند

### مقدمه

تصور کنید یک بکاپ سنگین در حال اجراست و CPU را اشغال کرده، در حالی که کاربران به سرور کار نیاز دارند. راه‌حل: اولویت بکاپ را پایین بیاورید تا بقیه سریع کار کنند. این کار با **nice** و **renice** انجام می‌شود.

در این فصل یاد می‌گیرید چطور اولویت فرآیندها را تنظیم کنید تا تعادل بین بار و پاسخ‌دهی برقرار شود.

### مفاهیم اساسی

**Nice Value چیست؟**

عددی بین **-20 تا +19** که اولویت فرآیند را مشخص می‌کند:

| مقدار | معنی | اولویت |
|---|---|---|
| **-20** | بالاترین اولویت (خودخواه) | زیاد |
| **0** | پیش‌فرض | متوسط |
| **+19** | پایین‌ترین اولویت (مهربان) | کم |

نام «nice» از این می‌آید که فرآیند با مقدار بالا با بقیه «مهربان» است (منابع کمتری می‌گیرد).

**نکته:** فقط ریشه می‌تواند مقدار nice را **کاهش** دهد (اولویت بالا). هر کاربری می‌تواند مقدار را افزایش دهد (اولویت پایین).

**مفاهیم مرتبط:**

- **Priority (PRI):** اولویت داخلی کرنل.
- **ionice:** اولویت I/O دیسک.
- **chrt:** زمان‌بندی real-time.

### مثال‌های عملی

**اجرا با nice مشخص:**

```bash
# اجرای فرآیند با اولویت پایین (مهربان)
nice -n 19 tar -czf backup.tar.gz /data

# اجرای فرآیند با اولویت بالا (نیاز به ریشه)
sudo nice -n -10 /usr/bin/critical-app

# بدون -n، پیش‌فرض 10 است
nice tar -czf backup.tar.gz /data

# بررسی
ps -o pid,ni,cmd -p $$
```

**تغییر nice فرآیند در حال اجرا:**

```bash
# دیدن nice فعلی
ps -o pid,ni,cmd -p 1234

# تغییر nice
renice -n 10 -p 1234        # کاهش اولویت
sudo renice -n -5 -p 1234   # افزایش اولویت

# بر اساس کاربر
sudo renice -n 15 -u nobody

# بر اساس گروه
sudo renice -n 15 -g developers

# در top: r را بزنید، PID و nice جدید
```

**پایش:**

```bash
top          # ستون NI و PR
ps -eo pid,ni,pri,cmd
ps -eo pid,ni,pri,cmd --sort=-ni
```

**اولویت I/O (ionice):**

```bash
# سه کلاس
ionice -c1 command     # real-time
ionice -c2 -n7 command # best-effort (پیش‌فرض)
ionice -c3 command     # idle

# نمونه
ionice -c3 tar -czf backup.tar.gz /data

# تغییر فرآیند در حال اجرا
sudo ionice -c3 -p 1234
```

### مقایسه و الگوهای مختلف

**ابزارهای کنترل اولویت:**

| ابزار | کار |
|---|---|
| `nice` | اجرا با اولویت مشخص |
| `renice` | تغییر اولویت فرآیند در حال اجرا |
| `ionice` | اولویت I/O دیسک |
| `chrt` | زمان‌بندی real-time |

**کلاس‌های ionice:**

| کلاس | نام | توضیح |
|---|---|---|
| 1 | Real-time | بالاترین (احتیاط) |
| 2 | Best-effort | پیش‌فرض، با اولویت 0-7 |
| 3 | Idle | فقط وقتی دیسک بیکار است |

**nice در برابر renice:**

| ویژگی | nice | renice |
|---|---|---|
| زمان | قبل از اجرا | فرآیند در حال اجرا |
| کاربرد | فرآیند جدید | فرآیند موجود |
| نیاز به sudo | برای اولویت بالا | برای اولویت بالا |

### اشکال شایع

**اشکال ۱: فراموش کردن `sudo` برای اولویت بالا.**
فقط ریشه می‌تواند nice را کاهش دهد. راه‌حل: `sudo` بزنید.

**اشکال ۲: اشتباه گرفتن علامت.**
`-20` اولویت بالا، `+19` پایین. راه‌حل: به خاطر بسپارید.

**اشکال ۳: گیج شدن با ستون PRI در top.**
PRI داخلی است؛ NI همان nice است. راه‌حل: NI را ببینید.

**اشکال ۴: تنظیم اولویت بالا برای همه.**
می‌تواند سیستم را ناپایدار کند. راه‌حل: فقط برای فرآیندهای حیاتی.

**اشکال ۵: نادیده گرفتن ionice.**
برای I/O سنگین، nice کافی نیست. راه‌حل: `ionice` هم استفاده کنید.

**اشکال ۶: renice روی فرآیند کاربر دیگر.**
بدون sudo رد می‌شود. راه‌حل: `sudo renice`.

### نکات مهم (Tips & Tricks)

- **برای کارهای سنگین پس‌زمینه (بکاپ، کامپایل) از `nice -n 19` استفاده کنید.**
- **`renice` فقط روی فرآیندهای خودتان (و با ریشه همه) کار می‌کند.**
- **`ionice` مکمل nice است (برای دیسک).**
- **در `top` با `r` می‌توانید renice کنید.**
- **nice را برای بهینه‌سازی سرورهای پرمصرف استفاده کنید.**
- **`nice -n -20` فقط برای فرآیندهای حیاتی (احتیاط).**
- **`chrt -f 99 command` زمان‌بندی real-time (خطرناک).**
- **`ionice -c3` برای کارهای idle (فقط وقتی دیسک بیکار).**
- **`renice -n 19 -p $$` اولویت خود شل را کم می‌کند.**
- **برای batching، nice + ionice ترکیب عالی است.**

### خلاصه فصل

Nice value بین -20 (بالاترین) تا +19 (پایین‌ترین) اولویت را تعیین می‌کند. با `nice -n` فرآیند را اجرا و با `renice -n` اولویت را تغییر دهید. فقط ریشه می‌تواند اولویت را بالا ببرد. `ionice` مکمل برای I/O دیسک است (سه کلاس: real-time, best-effort, idle). ترکیب nice + ionice برای کارهای سنگین پس‌زمینه بهترین نتیجه را می‌دهد.

## فصل ۲۶: جستجوی متن با عبارات باقاعده

### مقدمه

**عبارات باقاعده (Regular Expressions / Regex)** الگوهایی برای تطبیق متن هستند. تصور کنید می‌خواهید تمام ایمیل‌ها را از یک فایل استخراج کنید یا خطوطی که با IP شروع می‌شوند را پیدا کنید. با regex، در یک دستور انجام می‌شود.

تسلط بر آن‌ها برای `grep`, `sed`, `awk` و ویرایشگرها حیاتی است و در آزمون LPIC وزن دارد.

### مفاهیم اساسی

**کاراکترهای ویژهٔ پایه (BRE):**

| الگو | معنا |
|---|---|
| `.` | هر کاراکتر تک |
| `*` | صفر یا بیشتر از قبلی |
| `^` | ابتدای خط |
| `$` | انتهای خط |
| `[...]` | مجموعه (مثل `[abc]`) |
| `[^...]` | نقیض مجموعه |
| `\` | escape |

**کاراکترهای توسعه‌یافته (ERE):**

| الگو | معنا |
|---|---|
| `+` | یک یا بیشتر |
| `?` | صفر یا یک |
| `{n}` | دقیقاً n بار |
| `{n,m}` | بین n و m بار |
| `\|` | یا (OR) |
| `()` | گروه |
| `[[:class:]]` | کلاس POSIX |

**کلاس‌های POSIX:**

| کلاس | معنا |
|---|---|
| `[[:digit:]]` | اعداد |
| `[[:alpha:]]` | حروف |
| `[[:alnum:]]` | حروف و اعداد |
| `[[:space:]]` | فاصله‌ها |
| `[[:upper:]]` | حروف بزرگ |
| `[[:lower:]]` | حروف کوچک |
| `[[:punct:]]` | علائم |

### مثال‌های عملی

**grep با regex:**

```bash
# خطوطی که با error شروع می‌شوند
grep "^error" log.txt

# خطوطی که با .conf تمام می‌شوند
grep "\.conf$" files.txt

# شماره تلفن (الگوی ساده)
grep -E "[0-9]{3}-[0-9]{4}" contacts.txt

# ایمیل
grep -E "[a-zA-Z0-9._%+-]+@[a-zA-Z0-9.-]+\.[a-z]{2,}" emails.txt

# خطوط خالی
grep "^$" file.txt
grep -v "^$" file.txt    # حذف خطوط خالی

# IP
grep -E "^([0-9]{1,3}\.){3}[0-9]{1,3}$" ips.txt

# خطوطی که با عدد شروع می‌شوند
grep "^[0-9]" file.txt

# کلمات تکراری
grep -E "\b(\w+)\s+\1\b" file.txt
```

**sed با regex:**

```bash
# حذف کامنت‌ها
sed '/^#/d' config.txt

# حذف خطوط خالی
sed '/^$/d' config.txt

# جایگزینی با گروه
sed -E 's/([0-9]+)-([0-9]+)/\2-\1/' file.txt

# حذف فاصله‌های انتهایی
sed 's/[[:space:]]*$//' file.txt

# تبدیل مارک‌داون لینک
sed -E 's/\[(.+)\]\((.+)\)/\1 (\2)/' file.md
```

**awk با regex:**

```bash
awk '/error/ {print}' log.txt
awk '$1 ~ /^192\.168\./ {print}' access.log
awk '$2 !~ /GET/ {print}' access.log
```

**ابزارهای جایگزین:**

```bash
# egrep = grep -E
egrep "a|b" file.txt

# fgrep = grep -F (بدون regex، سریع‌تر)
fgrep "a.b" file.txt

# grep -P (PCRE)
grep -P "\d{3}" file.txt
```

### مقایسه و الگوهای مختلف

**انواع regex:**

| نوع | ابزار | ویژگی |
|---|---|---|
| **BRE** (Basic) | `grep`, `sed` (پیش‌فرض) | `+` و `?` نیاز به escape |
| **ERE** (Extended) | `grep -E`, `awk` | بدون escape |
| **PCRE** | `grep -P` | قدرتمندترین |

**BRE در برابر ERE:**

| الگو | BRE | ERE |
|---|---|---|
| یک یا بیشتر | `\+` | `+` |
| صفر یا یک | `\?` | `?` |
| گروه | `\(...\)` | `(...)` |
| یا | `\|` | `|` |

**quantifiers:**

| الگو | معنا |
|---|---|
| `*` | صفر یا بیشتر |
| `+` | یک یا بیشتر |
| `?` | صفر یا یک |
| `{3}` | دقیقاً ۳ |
| `{2,5}` | ۲ تا ۵ |
| `{2,}` | حداقل ۲ |

**anchorها و مرزها:**

| الگو | معنا |
|---|---|
| `^` | ابتدای خط |
| `$` | انتهای خط |
| `\b` | مرز کلمه |
| `\<` `\>` | ابتدا/انتهای کلمه |

### اشکال شایع

**اشکال ۱: escape نکردن کاراکترهای ویژه.**
`.` در regex هر کاراکتری است؛ برای نقطهٔ واقعی `\.`. راه‌حل: escape کنید.

**اشکال ۲: اشتباه BRE و ERE.**
`grep "a+"` در BRE فقط `a+` را می‌بیند؛ از `grep -E "a+"` استفاده کنید. راه‌حل: `-E` برای ERE.

**اشکال ۳: حریص بودن (greedy).**
`.*` همه‌چیز را می‌گیرد؛ از `.*?` (در PCRE) یا الگوی دقیق‌تر استفاده کنید. راه‌حل: الگوی دقیق.

**اشکال ۴: فراموش کردن anchor.**
بدون `^` و `$`، تطبیق جزئی است. راه‌حل: anchorها را اضافه کنید.

**اشکال ۵: اشتباه در کلاس POSIX.**
`[[:digit:]]` نه `[:digit:]`. راه‌حل: دو براکت.

**اشکال ۶: نادیده گرفتن case.**
regex به حروف حساس است. راه‌حل: `grep -i` برای بی‌توجهی.

### نکات مهم (Tips & Tricks)

- **برای تست regex از `grep -E "pattern" <<< "test string"` استفاده کنید.**
- **`grep -o` فقط بخش تطبیق‌یافته را چاپ می‌کند.**
- **`grep -P` (PCRE) از lookahead پشتیبانی می‌کند.**
- **در `sed`، `-E` برای ERE و `-r` (GNU) معادل است.**
- **`[[:space:]]` قابل اعتمادتر از `\s` است.**
- **`grep -w` تطبیق کلمهٔ کامل.**
- **`grep -c` شمارش تطبیق‌ها.**
- **`grep -l` فقط نام فایل.**
- **`\b` مرز کلمه در GNU grep.**
- **از سایت regex101.com برای تست استفاده کنید.**
- **`.*` حریص است؛ `.*?` (PCRE) کم‌حریص.**
- **`^` و `$` در چندخطی متفاوت عمل می‌کنند.**

### خلاصه فصل

Regex الگوهایی برای تطبیق متن‌اند. کاراکترهای پایه (`.`, `*`, `^`, `$`, `[]`) و توسعه‌یافته (`+`, `?`, `{}`, `|`, `()`) ابزار اصلی‌اند. BRE و ERE تفاوت در escape دارند. `grep -E`, `sed -E` و `awk` برای ERE به‌کار می‌روند. anchorها (`^`, `$`, `\b`) تطبیق را دقیق می‌کنند. کلاس‌های POSIX (`[[:digit:]]`) قابل اعتمادند.

## فصل ۲۷: ویرایش فایل با vi

### مقدمه

**vi** (و نسخهٔ پیشرفته‌اش **vim**) ویرایشگر استاندارد لینوکس است. در هر سروری، حتی مینیمال، vi وجود دارد. تصور کنید روی یک سرور تولیدی هستید و باید یک فایل پیکربندی را سریع ویرایش کنید — vi همیشه در دسترس است.

یادگیری آن برای آزمون LPIC و کار واقعی ضروری است. منحنی یادگیری دارد، اما با تمرین آسان می‌شود.

### مفاهیم اساسی

**حالت‌های vi:**

| حالت | توضیح | ورود |
|---|---|---|
| **Normal (Command)** | پیش‌فرض، برای دستورها | Esc |
| **Insert** | برای تایپ متن | i, a, o |
| **Visual** | انتخاب متن | v, V, Ctrl+V |
| **Command-line** | برای دستورهای `:` | `:` |

**نکتهٔ کلیدی:** در vi تایپ مستقیم متن نمی‌کنید؛ اول باید با `i` وارد حالت Insert شوید. این بزرگ‌ترین منبع سردرگمی مبتدیان است.

**چرخهٔ کار:**

```
Normal → (i/a/o) → Insert → (Esc) → Normal → (:wq) → خروج
```

### مثال‌های عملی

**باز کردن و ذخیره:**

```bash
vi file.txt
vi +10 file.txt       # شروع از خط ۱۰
vi +/pattern file.txt # شروع از اولین تطبیق
vimtutor              # آموزش تعاملی vim
```

**دستورهای پایه در حالت Normal:**

| کلید | کار |
|---|---|
| `i` | ورود به Insert (قبل از مکان‌نما) |
| `I` | Insert ابتدای خط |
| `a` | ورود به Insert (بعد از مکان‌نما) |
| `A` | Insert انتهای خط |
| `o` | خط جدید بعد |
| `O` | خط جدید قبل |
| `Esc` | بازگشت به Normal |
| `:w` | ذخیره |
| `:q` | خروج |
| `:wq` | ذخیره و خروج |
| `:q!` | خروج بدون ذخیره |
| `:x` | ذخیره و خروج (مثل wq) |
| `ZZ` | ذخیره و خروج |

**حرکت:**

| کلید | کار |
|---|---|
| `h j k l` | چپ/پایین/بالا/راست |
| `w` / `b` | کلمهٔ بعد/قبل |
| `e` | انتهای کلمه |
| `0` / `$` | ابتدا/انتهای خط |
| `^` | اولین کاراکتر غیرفاصله |
| `gg` / `G` | ابتدا/انتهای فایل |
| `:n` | رفتن به خط n |
| `Ctrl+d` / `Ctrl+u` | نیم‌صفحه پایین/بالا |
| `Ctrl+f` / `Ctrl+b` | یک صفحه پایین/بالا |
| `}` / `{` | پاراگراف بعد/قبل |

**ویرایش:**

| کلید | کار |
|---|---|
| `x` | حذف کاراکتر |
| `dd` | حذف خط |
| `dw` | حذف کلمه |
| `d$` | حذف تا انتهای خط |
| `yy` | کپی خط |
| `yw` | کپی کلمه |
| `p` | چسباندن بعد |
| `P` | چسباندن قبل |
| `u` | واگرد (undo) |
| `Ctrl+r` | ازنو (redo) |
| `r` | جایگزینی یک کاراکتر |
| `cc` | تغییر خط |
| `J` | ادغام خطوط |

**جستجو و جایگزینی:**

```vim
/text        " جستجو به جلو
?text        " جستجو به عقب
n            " تطبیق بعدی
N            " تطبیق قبلی
*            " جستجوی کلمهٔ زیر مکان‌نما

:s/old/new/       " جایگزینی در خط فعلی
:s/old/new/g      " همهٔ خط فعلی
:%s/old/new/g     " کل فایل
:%s/old/new/gc    " با تأیید
:10,20s/old/new/g " خطوط ۱۰ تا ۲۰
```

**دستورهای مفید:**

```vim
:set number       " شماره خط
:set nonumber     " بدون شماره
:set paste        " چسباندن بدون auto-indent
:set hlsearch     " هایلایت جستجو
:noh              " حذف هایلایت
:split            " تقسیم افقی
:vsplit           " تقسیم عمودی
:w !sudo tee %    " ذخیرهٔ فایل نیازمند ریشه
```

### مقایسه و الگوهای مختلف

**ویرایشگرها:**

| ویرایشگر | مناسب | منحنی یادگیری |
|---|---|---|
| **vi/vim** | همه‌جا موجود، استاندارد | متوسط |
| **nano** | ساده، مبتدی‌پسند | کم |
| **emacs** | قدرتمند | بالا |
| **sed** | ویرایش اسکریپتی | متوسط |

**نکتهٔ LPIC:** `vi` در آزمون مهم است چون همیشه موجود است.

**nano در برابر vi:**

| ویژگی | nano | vi |
|---|---|---|
| یادگیری | آسان | متوسط |
| موجود در همه‌جا | معمولاً | تقریباً همیشه |
| توانمندی | کم | بسیار زیاد |
| ماکرو/اسکریپت | ندارد | دارد |

**حالت‌های Visual:**

| کلید | حالت |
|---|---|
| `v` | کاراکتری |
| `V` | خطی |
| `Ctrl+v` | بلوکی |

### اشکال شایع

**اشکال ۱: تایپ بدون ورود به Insert.**
در Normal کلیدها دستورند. راه‌حل: اول `i` بزنید.

**اشکال ۲: فراموش کردن `Esc`.**
اگر در Insert بمانید، `:wq` تایپ می‌شود نه اجرا. راه‌حل: اول Esc.

**اشکال ۳: خروج بدون ذخیره.**
`:q!` تغییرات را دور می‌ریزد. راه‌حل: با `:wq` ذخیره کنید.

**اشکال ۴: گیر کردن در vi.**
با `Esc` بعد `:q!` خارج شوید. راه‌حل: به خاطر بسپارید.

**اشکال ۵: auto-indent هنگام چسباندن.**
متن به‌هم‌ریخته می‌شود. راه‌حل: `:set paste`.

**اشکال ۶: نداشتن دسترسی نوشتن.**
فایل نیازمند ریشه است. راه‌حل: `:w !sudo tee %`.

### نکات مهم (Tips & Tricks)

- **`vimtutor` بهترین راه یادگیری است (۳۰ دقیقه).**
- **`:set number` شماره خط را نشان می‌دهد.**
- **`:set paste` برای چسباندن بدون auto-indent.**
- **`dd` + `p` برای جابجایی خط.**
- **`Ctrl+v` برای انتخاب بلوکی.**
- **در vim، `:w !sudo tee %` برای ذخیرهٔ فایل‌های نیازمند ریشه.**
- **`.` تکرار آخرین دستور است (بسیار مفید).**
- **`u` و `Ctrl+r` برای undo/redo.**
- **`/` و `?` برای جستجو، `n`/`N` برای حرکت.**
- **`:e!` بازخوانی فایل (حذف تغییرات).**
- **`~/.vimrc` برای پیکربندی دائمی.**
- **`vim -R file` حالت فقط‌خواندنی.**

### خلاصه فصل

vi/vim ویرایشگر استاندارد لینوکس با حالت‌های Normal، Insert، Visual و Command-line است. با `i` وارد Insert، با `Esc` بازگشت و با `:wq` ذخیره/خروج کنید. دستورهای کلیدی: `dd`, `yy`, `p`, `u`, `/text`, `:%s/old/new/g`. همیشه در سرورها موجود است. `vimtutor` و `:set paste` نکات مهمی هستند.
