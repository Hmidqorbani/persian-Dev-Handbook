## فصل ۹: یک خانواده، پنج اسم — چطور روی هم سوار می‌شوند؟

### مقدمه

یک مکالمه‌ی واقعی که هر روز تکرار می‌شود:

> — «این سیستم از هوش مصنوعی استفاده می‌کند.»
> — «یعنی چی؟»
> — «یعنی یادگیری ماشین.»
> — «فرقش با دیپ‌لرنینگ چیست؟»
> — «همان است دیگر...»
> — «پس ChatGPT چه؟»
> — «آن هم AI است.»

این مکالمه هیچ اطلاعاتی منتقل نمی‌کند. مشکل این است که پنج اصطلاح داریم که **همه درست‌اند و همه مبهم**. هدف این فصل این است که تو دیگر آن آدم دوم نباشی.

### مفاهیم اساسی

#### تصویر بزرگ: دایره‌های تودرتو

```
┌─────────────────────────────────────────────────────────┐
│  هوش مصنوعی (AI)                                        │
│  هر تلاشی برای اینکه ماشین کار انسان‌مانند بکند          │
│                                                         │
│   ┌───────────────────────────────────────────────┐     │
│   │  یادگیری ماشین (ML)                           │     │
│   │  زیرشاخه‌ای که از داده یاد می‌گیرد، نه از قاعده  │     │
│   │                                               │     │
│   │   ┌───────────────────────────────────┐       │     │
│   │   │  یادگیری عمیق (DL)                │       │     │
│   │   │  ML با شبکه‌های عصبی چندلایه       │       │     │
│   │   │                                   │       │     │
│   │   │   ┌───────────────────────────┐   │       │     │
│   │   │   │  هوش مصنوعی مولد (GenAI)  │   │       │     │
│   │   │   │  تولید محتوای تازه         │   │       │     │
│   │   │   │                           │   │       │     │
│   │   │   │   ┌───────────────────┐   │   │       │     │
│   │   │   │   │  LLM              │   │   │       │     │
│   │   │   │   │  مدل زبانی بزرگ    │   │   │       │     │
│   │   │   │   └───────────────────┘   │   │       │     │
│   │   │   └───────────────────────────┘   │       │     │
│   │   └───────────────────────────────────┘       │     │
│   └───────────────────────────────────────────────┘     │
└─────────────────────────────────────────────────────────┘
```

**اما این تصویر یک دروغ کوچک دارد:** این‌ها کاملاً تودرتو نیستند. یک سیستم می‌تواند GenAI باشد اما DL نباشد (مثلاً مدل مارکوف برای تولید متن). یا ML باشد اما AI به معنای «هوشمند» نباشد. این تصویر یک **راهنمای تقریبی** است، نه یک طبقه‌بندی دقیق.

#### تعریف یک‌خطی هر کدام

| اصطلاح | تعریف یک‌خطی | مثال |
|---|---|---|
| **AI** | هدف: ماشین کار انسان‌وار انجام دهد | هر سیستم خودکار هوشمندنما |
| **ML** | روش: از داده یاد بگیر، نه از قاعده | فیلتر اسپم، پیش‌بینی قیمت |
| **DL** | روش ML با شبکه‌ی عصبی چندلایه | تشخیص چهره، ترجمه |
| **GenAI** | هدف: تولید محتوای تازه | تولید عکس، متن، صدا |
| **LLM** | نوعی GenAI روی متن، در مقیاس بزرگ | ChatGPT، Claude، Llama |

#### چرا این تفکیک مهم است؟

سه دلیل عملی:

**۱. انتخاب ابزار**
اگر کسی بگوید «ما AI می‌خواهیم»، این جمله هیچ معنایی ندارد. باید بپرسی: «می‌خواهی پیش‌بینی کنی، طبقه‌بندی کنی، یا تولید کنی؟» هر کدام ابزار متفاوتی می‌خواهد.

**۲. ارزیابی ادعاها**
«مدل ما AI است» ادعای بزرگی است. «مدل ما یک رگرسیون لجستیک است که با ۵۰ هزار رکورد آموزش دیده» ادعای دقیقی است. تفاوت این دو، تفاوت بازاریابی و مهندسی است.

**۳. فهم محدودیت‌ها**
LLM نمی‌تواند جمع دقیق اعداد بزرگ را reliable انجام دهد، چون برای «تولید متن» ساخته شده نه «محاسبه». اگر بدانی در کدام دسته است، انتظار درست داری.

### مثال‌ها و نمونه‌های عملی

#### مثال ۱: پنج سیستم، پنج دسته

| سیستم | دسته | چرا |
|---|---|---|
| فیلتر اسپم جیمیل | ML (نه DL) | مدل کلاسیک، داده‌ی برچسب‌دار |
| تشخیص چهره‌ی گوشی | DL | شبکه‌ی عصبی عمیق روی تصویر |
| ChatGPT | LLM (و DL و GenAI) | مدل زبانی عظیم |
| سیستم خبره‌ی مالیات | AI (نه ML) | قاعده‌ی دستی، بدون یادگیری |
| Midjourney | GenAI (و DL) | تولید تصویر با مدل انتشار |

#### مثال ۲: چرا «AI» در تبلیغات بی‌معنی است؟

یک فروشگاه آنلاین می‌گوید «با AI محصولات را پیشنهاد می‌دهیم». زیر کاپوت ممکن است یکی از این‌ها باشد:

- **قاعده‌ی ساده:** «اگر خرید کردی، مشابه‌ها را نشان بده» (نه ML)
- **فیلترینگ مشارکتی:** «کسانی که این را خریدند...» (ML کلاسیک)
- **شبکه‌ی عصبی عمیق:** مدل تعبیه‌ی (Embedding) کاربر و محصول (DL)

هر سه «AI» نامیده می‌شوند. تفاوت در هزینه، دقت و پیچیدگی‌شان است — و مشتری هیچ‌وقت نمی‌فهمد کدام است.

**درس:** وقتی کسی می‌گوید AI، بپرس «چه نوعی؟» و اگر جواب مبهم بود، بدان که یا نمی‌داند یا نمی‌خواهد بگوید.

#### مثال ۳: یک سیستم واقعی، پنج لایه

سیستم پیشنهاد فیلم در یک پلتفرم ایرانی:

```
لایه ۵ (LLM):        توضیح متنی «چرا این فیلم را پیشنهاد دادیم»
لایه ۴ (GenAI):       تولید خلاصه‌ی خودکار فیلم
لایه ۳ (DL):          تشخیص ژانر از پوستر فیلم
لایه ۲ (ML):          پیش‌بینی احتمال تماشا
لایه ۱ (قاعده):       فیلتر محتوای نامناسب
```

یک محصول واقعی معمولاً **ترکیبی** از چند لایه است. کسی که فکر می‌کند «یک مدل همه‌کار را می‌کند»، اشتباه می‌کند.

### مقایسه و دیدگاه‌های مختلف

#### جدول تفصیلی

| معیار | AI کلاسیک | ML | DL | GenAI | LLM |
|---|---|---|---|---|---|
| منبع دانش | متخصص | داده | داده‌ی زیاد | داده‌ی خیلی زیاد | داده‌ی عظیم |
| قابل توضیح | بالا | متوسط | پایین | پایین | پایین |
| نیاز به داده | کم | متوسط | زیاد | خیلی زیاد | عظیم |
| نیاز به محاسبه | کم | متوسط | زیاد | خیلی زیاد | عظیم |
| انعطاف | کم | متوسط | زیاد | زیاد | خیلی زیاد |
| هزینه‌ی ساخت | متوسط | متوسط | بالا | خیلی بالا | عظیم |
| مناسب برای | کارهای قاعده‌مند | پیش‌بینی | ادراک | تولید | زبان و استدلال |

#### یک نکته‌ی مهم: «همه‌ی LLMها DL هستند، اما همه‌ی DLها LLM نیستند»

این جمله را حفظ کن. خیلی از بحث‌های بی‌ربط از قاطی کردن این دو می‌آید.

مثلاً وقتی می‌گویند «دیپ‌لرنینگ در تشخیص پزشکی عالی است»، منظورشان CNN است، نه ChatGPT. وقتی می‌گویند «LLM توهم می‌زند»، درباره‌ی مدل زبانی است، نه هر شبکه‌ی عصبی.

#### دیدگاه «AI = ML» — یک ساده‌سازی خطرناک

امروز خیلی‌ها AI را با ML یکی می‌گیرند. این ساده‌سازی دو مشکل دارد:

**مشکل اول:** سیستم‌های قاعده‌محور را نادیده می‌گیرد، در حالی که در بانک، بیمه و مالیات هنوز ستون فقرات‌اند.

**مشکل دوم:** انتظارات غلط می‌سازد. «اگر AI است، پس باید یاد بگیرد» — نه، خیلی از AIهای خوب یاد نمی‌گیرند و همین خوب است.

### اشتباهات رایج

**اشتباه ۱: «AI و ML یکی هستند»**
ML زیرمجموعه‌ی AI است. هر ML، AI است؛ هر AI، ML نیست.

**اشتباه ۲: «Deep Learning و AI یکی هستند»**
DL زیرمجموعه‌ی ML است. خیلی از سیستم‌های AI اصلاً شبکه‌ی عصبی ندارند.

**اشتباه ۳: «GenAI همان ChatGPT است»**
GenAI شامل تولید تصویر، صدا، ویدیو و کد هم می‌شود. ChatGPT فقط یک نمونه‌ی متنی است.

**اشتباه ۴: «LLM یک موتور جست‌وجو است»**
نه. LLM متن تولید می‌کند؛ جست‌وجو منبع بیرونی می‌آورد. تفاوتشان در «حافظه» است: LLM حافظه‌ی ثابت دارد و ممکن است قدیمی یا غلط باشد. (فصل ۶۵)

**اشتباه ۵: باور به اینکه «هرچه جدیدتر، بهتر»**
برای یک کار ساده‌ی پیش‌بینی، یک مدل ML کلاسیک ممکن است از یک LLM ارزان‌تر، سریع‌تر و دقیق‌تر باشد. جدید ≠ مناسب.

### نکات مهم و ترفندها

**۱. قاعده‌ی «چه می‌خواهم؟»**
- می‌خواهم **پیش‌بینی** کنم → ML
- می‌خواهم **درک** کنم (تصویر، صدا) → DL
- می‌خواهم **تولید** کنم → GenAI
- می‌خواهم **قاعده‌ی دقیق و قابل ممیزی** → AI کلاسیک

**۲. همیشه «نوع» را بپرس**
هر بار شنیدی «AI»، بپرس: ML، DL، GenAI یا قاعده‌محور؟ این سؤال، تو را از ۸۰٪ سوءتفاهم نجات می‌دهد.

**۳. برای هر مسئله، ساده‌ترین ابزار کافی را انتخاب کن**
اگر یک قاعده‌ی `if/else` جواب می‌دهد، LLM نگذار. اگر رگرسیون جواب می‌دهد، شبکه‌ی عمیق نگذار. این نه تنبلی، بلکه **مهندسی** است.

**۴. «AI» در بازاریابی، «ML» در مهندسی، «DL» در پژوهش**
هر کلمه، مخاطب خودش را دارد. بدان کدام را کجا استفاده کنی.

### خلاصه فصل

- AI هدف است، ML و DL روش‌اند، GenAI هدف تولید، LLM نوعی GenAI.
- تصویر دایره‌های تودرتو راهنمای تقریبی است، نه تعریف دقیق.
- هر ML، AI است؛ هر AI، ML نیست.
- «AI» در تبلیغات بی‌معنی است تا وقتی نوعش مشخص شود.
- برای هر مسئله، ساده‌ترین ابزار کافی را انتخاب کن.

**سؤال مروری:**
1. فیلتر اسپم را در کدام دسته می‌گذاری و چرا؟
2. چرا «LLM یک موتور جست‌وجو است» غلط است؟
3. اگر کسی گفت «سیستم ما AI است»، سه سؤال بعدی‌ات چیست؟

## فصل ۱۰: یادگیری ماشین به زبان ساده

### مقدمه

فرض کن می‌خواهی به یک بچه یاد بدهی «سیب» را تشخیص دهد. دو راه داری:

**راه اول:** کتابی بنویسی: «سیب گرد است، قرمز یا سبز است، قطرش بین ۵ تا ۹ سانتی‌متر است، ساقه دارد...» و بچه حفظ کند.

**راه دوم:** ده سیب نشانش بدهی و بگویی «این سیب است»، بعد ده چیز دیگر نشانش بدهی و بگویی «این سیب نیست». بچه خودش الگو را می‌فهمد.

**راه اول = برنامه‌نویسی سنتی. راه دوم = یادگیری ماشین.**

و نکته‌ی جالب اینجاست: راه دوم همیشه بهتر نیست. اگر بخواهی بچه «مالیات بر ارزش افزوده» را حساب کند، راه اول بهتر است. **انتخاب بین این دو، مهارت اصلی است.**

### مفاهیم اساسی

#### تعریف دقیق

**یادگیری ماشین (Machine Learning)** شاخه‌ای از AI است که در آن، برنامه به‌جای اینکه قواعد را از قبل داشته باشد، **قواعد را از داده استخراج می‌کند**.

سه جزء هر سیستم ML:

```
۱. داده (Data)        →  مثال‌ها
۲. مدل (Model)        →  یک تابع با پارامترهای قابل تنظیم
۳. هدف (Objective)    →  معیاری که می‌خواهیم بهتر شود
```

#### چرخه‌ی یادگیری در پنج قدم

```
┌──────────────┐
│ ۱. جمع‌آوری داده │  ← عکس، متن، عدد، هر چیزی
└──────┬───────┘
       ↓
┌──────────────┐
│ ۲. آماده‌سازی   │  ← پاک‌سازی، برچسب‌گذاری، تقسیم
└──────┬───────┘
       ↓
┌──────────────┐
│ ۳. آموزش       │  ← مدل پارامترها را تنظیم می‌کند
└──────┬───────┘
       ↓
┌──────────────┐
│ ۴. ارزیابی     │  ← روی داده‌ی ندیده امتحان می‌شود
└──────┬───────┘
       ↓
┌──────────────┐
│ ۵. استفاده     │  ← پیش‌بینی روی داده‌ی واقعی
└──────────────┘
```

این چرخه، ستون فقرات همه‌ی ML است — از یک رگرسیون ساده تا GPT-5.

#### سه نوع یادگیری

| نوع | چه دارد | چه می‌خواهد | مثال |
|---|---|---|---|
| **نظارت‌شده (Supervised)** | داده + جواب درست | پیش‌بینی جواب برای داده‌ی جدید | تشخیص اسپم |
| **بدون نظارت (Unsupervised)** | فقط داده | پیدا کردن ساختار پنهان | گروه‌بندی مشتریان |
| **تقویتی (Reinforcement)** | محیط + پاداش | یادگیری بهترین رفتار | بازی، ربات |

این سه را در فایل‌های ۰۷، ۰۸ و ۰۹ کامل باز می‌کنیم. فعلاً فقط این را بدان: **۹۰٪ کاربردهای تجاری، نوع اول است.**

#### «یادگیری» یعنی چه، دقیقاً؟

یک تشبیه: فرض کن یک ماشین تنظیم‌کننده‌ی صدا داری با سه پیچ. می‌خواهی صدای خواننده را واضح کنی. هر سه پیچ را می‌چرخانی، آهنگ را گوش می‌دهی، و دوباره تنظیم می‌کنی. بعد از ۲۰ بار، بهترین ترکیب را پیدا می‌کنی.

**این دقیقاً همان کاری است که آموزش مدل می‌کند** — با میلیون‌ها «پیچ» (پارامتر) به‌جای سه تا، و با یک معیار ریاضی به‌جای گوش تو.

```
حلقه‌ی آموزش:
  ۱. پیش‌بینی کن
  ۲. با جواب واقعی مقایسه کن
  ۳. خطا را حساب کن
  ۴. پیچ‌ها را کمی بچرخان تا خطا کمتر شود
  ۵. برگرد به ۱ (میلیون بار)
```

این حلقه، تمام چیزی است که «آموزش» نامیده می‌شود. همه‌ی پیچیدگی‌ها در «چطور پیچ‌ها را بچرخانیم» است — و آن را **گرادیان کاهشی (Gradient Descent)** می‌نامند. (فصل ۴۱)

### مثال‌ها و نمونه‌های عملی

#### مثال ۱: پیش‌بینی قیمت آپارتمان — ساده‌ترین ML دنیا

فرض کن می‌خواهی قیمت آپارتمان را پیش‌بینی کنی.

**داده:** ۱۰۰۰ آپارتمان با متراژ، تعداد اتاق، طبقه، سال ساخت، و قیمت واقعی.

**مدل ساده:** `قیمت = a × متراژ + b × اتاق + c × طبقه + d`

**آموزش:** مدل `a`، `b`، `c`، `d` را طوری تنظیم می‌کند که پیش‌بینی‌اش با قیمت واقعی کمترین اختلاف را داشته باشد.

**نتیجه:** یک معادله که می‌توانی برای آپارتمان جدید استفاده کنی.

این **رگرسیون خطی** است — ساده‌ترین مدل ML و هنوز یکی از پرکاربردترین‌ها. چرا؟ چون قابل توضیح است: «هر متر مربع، ۵۰ میلیون تومان».

#### مثال ۲: چرا مدل خوب، همیشه مدل پیچیده نیست؟

فرض کن داده‌ی تو ۵۰۰ رکورد است و ۳۰ ویژگی. اگر یک شبکه‌ی عصبی ۱۰ میلیون پارامتری استفاده کنی، مدل **حفظ می‌کند** نه یاد می‌گیرد. یعنی روی داده‌ی آموزشی ۹۹٪ دقیق است و روی داده‌ی جدید ۵۵٪.

این را **بیش‌برازش (Overfitting)** می‌نامند و شایع‌ترین خطای مبتدی‌هاست. (فصل ۲۶)

قاعده‌ی سرانگشتی: **پیچیدگی مدل باید با حجم و کیفیت داده تناسب داشته باشد.**

#### مثال ۳: تشخیص قیمت منصفانه‌ی تاکسی

یک شرکت تاکسی اینترنتی می‌خواهد قیمت منصفانه پیشنهاد دهد. داده: ۱۰ میلیون سفر با مبدأ، مقصد، ساعت، روز هفته، آب‌وهوا، و قیمت نهایی.

مدل ML یاد می‌گیرد: «جمعه شب، باران، مسیر شمال شهر → قیمت بالاتر». این الگو را کسی ننوشته؛ از داده بیرون آمده.

**نکته‌ی اخلاقی:** اگر داده‌ی تاریخی سوگیری داشته باشد (مثلاً در بعضی محله‌ها همیشه قیمت بالاتر بوده)، مدل آن سوگیری را **تثبیت** می‌کند. این یکی از مهم‌ترین خطرهای ML است. (فصل ۷۸)

### مقایسه و دیدگاه‌های مختلف

#### برنامه‌نویسی سنتی در برابر ML

| معیار | برنامه‌نویسی سنتی | یادگیری ماشین |
|---|---|---|
| منبع منطق | ذهن برنامه‌نویس | داده |
| تغییر رفتار | تغییر کد | آموزش دوباره |
| رفتار در حالت ناشناخته | مشخص (معمولاً خطا) | نامشخص |
| قابل توضیح | کاملاً | تا حدی |
| هزینه‌ی نگهداری | کد | داده + مدل |
| مناسب برای | قواعد دقیق | الگوهای پیچیده و مبهم |

**جمله‌ی کلیدی:** برنامه‌نویسی سنتی می‌گوید «**چطور**»، ML می‌گوید «**چه چیزی**». تو مثال می‌دهی، ماشین «چطور» را پیدا می‌کند.

#### دو دیدگاه به ML

**دیدگاه آماری:** ML یعنی برازش یک مدل احتمالاتی به داده. هدف: استنتاج.

**دیدگاه بهینه‌سازی:** ML یعنی پیدا کردن پارامترهایی که یک تابع هزینه را کمینه کنند. هدف: عملکرد.

هر دو درست‌اند و به یک چیز می‌رسند. دیدگاه دوم امروز غالب است چون با شبکه‌های بزرگ بهتر کار می‌کند.

### اشتباهات رایج

**اشتباه ۱: «ML جادو است، داده بده، جواب بگیر»**
نه. اگر داده‌ی تو سوگیری داشته باشد، مدل سوگیر می‌شود. اگر داده‌ی تو نماینده‌ی دنیای واقعی نباشد، مدل در دنیای واقعی شکست می‌خورد. **زباله داخل، زباله بیرون.**

**اشتباه ۲: ارزیابی روی داده‌ی آموزش**
این مثل این است که سؤال‌های امتحان را از قبل به دانش‌آموز بدهی و بعد تعجب کنی که ۱۰۰ گرفته. همیشه روی داده‌ی **ندیده** ارزیابی کن.

**اشتباه ۳: «مدل دقیق‌تر همیشه بهتر است»**
اگر مدل ۹۹٪ دقیق باشد اما نتوانی توضیح دهی چرا، در بانک و بیمارستان قابل استفاده نیست. دقت، تنها معیار نیست.

**اشتباه ۴: نادیده گرفتن «هزینه‌ی خطا»**
در تشخیص سرطان، خطای «سرطان را ندید» و «سرطان را دید در حالی که نبود» هزینه‌ی کاملاً متفاوتی دارند. مدل باید بر اساس هزینه‌ی واقعی تنظیم شود، نه فقط دقت کلی. (فصل ۲۹)

**اشتباه ۵: فراموش کردن به‌روزرسانی**
دنیا عوض می‌شود. مدلی که سال پیش عالی بود، امسال ممکن است بد باشد. این را **رانش داده (Data Drift)** می‌نامند. (فصل ۴۹)

### نکات مهم و ترفندها

**۱. قبل از مدل، داده را ببین**
۲۰ رکورد اول را دستی نگاه کن. ۲۰ رکورد آخر را هم. بیشتر مشکلات داده، در همین ۴۰ رکورد دیده می‌شوند.

**۲. همیشه یک «مدل پایه» داشته باش**
قبل از هر مدل پیچیده، یک مدل ساده (مثلاً پیش‌بینی با میانگین) بساز. اگر مدل پیچیده‌ات از پایه بهتر نبود، پیچیدگی هدر رفته.

**۳. سه بخش داده: آموزش، اعتبارسنجی، آزمون**
- آموزش: مدل یاد می‌گیرد
- اعتبارسنجی: تنظیمات را انتخاب می‌کنی
- آزمون: فقط یک بار، در پایان، برای گزارش نهایی

اگر آزمون را چند بار استفاده کنی، دیگر آزمون نیست. (فصل ۲۶)

**۴. «چرا» را هم بساز**
حتی اگر مدل قابل توضیح نیست، ابزار توضیح (مثل SHAP) بگذار. کاربر و رگولاتور، «چرا» می‌خواهند.

**۵. اولین سؤال: «آیا این مسئله اصلاً ML می‌خواهد؟»**
اگر قاعده‌ی دقیق داری، قاعده بگذار. ML را برای جایی نگه دار که قاعده‌نویسی ممکن نیست.

### خلاصه فصل

- ML یعنی استخراج قاعده از داده، به‌جای نوشتن دستی قاعده.
- هر سیستم ML سه جزء دارد: داده، مدل، هدف.
- چرخه: جمع‌آوری، آماده‌سازی، آموزش، ارزیابی، استفاده.
- سه نوع: نظارت‌شده، بدون نظارت، تقویتی. ۹۰٪ تجاری، نوع اول.
- «آموزش» = حلقه‌ی پیش‌بینی، خطا، تنظیم، تکرار.
- بیش‌برازش شایع‌ترین خطاست؛ پیچیدگی باید با داده تناسب داشته باشد.

**سؤال مروری:**
1. تفاوت برنامه‌نویسی سنتی و ML را با یک مثال از کار خودت توضیح بده.
2. چرا ارزیابی روی داده‌ی آموزش بی‌معنی است؟
3. اگر مدل ۹۹٪ دقیق باشد اما نتوانی توضیح دهی چرا، کجا نمی‌توانی استفاده کنی؟

## فصل ۱۱: یادگیری عمیق — چرا «عمیق» همه‌چیز را عوض کرد؟

### مقدمه

در فصل قبل گفتیم مدل‌های ML «پیچ» دارند که تنظیم می‌شوند. حالا یک سؤال: اگر به‌جای ۴ پیچ، ۱۰۰ میلیون پیچ داشته باشیم چه؟

جواب شهودی: «بیش‌برازش می‌کند». و برای مدل‌های کلاسیک، همین درست است. اما یک چیز عجیب اتفاق افتاد: **با شبکه‌های عصبی خیلی بزرگ، خطای داده‌ی تست هم کم شد، نه فقط خطای آموزش.**

این پدیده، انقلاب یادگیری عمیق را ممکن کرد و هنوز کاملاً توضیح داده نشده.

### مفاهیم اساسی

#### «عمیق» یعنی چه؟

**یادگیری عمیق (Deep Learning)** = یادگیری ماشین با شبکه‌های عصبی که **چندین لایه** دارند.

```
ورودی → [لایه ۱] → [لایه ۲] → [لایه ۳] → ... → [لایه N] → خروجی
         ساده‌ترین                                        پیچیده‌ترین
         ویژگی‌ها                                          ویژگی‌ها
```

- شبکه‌ی «کم‌عمق»: ۱ تا ۳ لایه
- شبکه‌ی «عمیق»: ده‌ها تا صدها لایه

#### چه چیزی در لایه‌ها اتفاق می‌افتد؟ (مثال تصویر)

این مهم‌ترین شهود کل فصل است. فرض کن شبکه‌ای برای تشخیص چهره داری:

| لایه | چه چیزی یاد می‌گیرد |
|---|---|
| لایه ۱ | لبه‌ها و خطوط ساده (افقی، عمودی، مورب) |
| لایه ۲ | ترکیب لبه‌ها → گوشه، منحنی |
| لایه ۳ | ترکیب گوشه‌ها → چشم، بینی، دهان |
| لایه ۴ | ترکیب اجزا → کل صورت |
| لایه ۵ | تصمیم: «این چهره‌ی علی است یا نه» |

**نکته‌ی انقلابی:** هیچ‌کس به شبکه نگفته «اول لبه پیدا کن، بعد چشم». شبکه **خودش** این سلسله‌مراتب را کشف کرده.

قبل از DL، انسان باید این ویژگی‌ها را دستی طراحی می‌کرد (مهندسی ویژگی). این کار سخت، تخصصی و شکننده بود. DL این گلوگاه را حذف کرد.

#### سه دلیل که DL ممکن شد

**۱. داده**
ImageNet و مشابه‌ها. شبکه‌ی عمیق با داده‌ی کم، فاجعه است.

**۲. محاسبه (GPU)**
ضرب ماتریس‌های بزرگ. GPU این کار را ۱۰ تا ۵۰ برابر سریع‌تر از CPU انجام می‌دهد.

**۳. ترفندهای آموزشی**
- **ReLU:** تابع فعال‌سازی ساده که آموزش عمیق را ممکن کرد
- **Dropout:** خاموش کردن تصادفی نورون‌ها برای جلوگیری از بیش‌برازش
- **Batch Normalization:** پایدار کردن آموزش
- **Residual Connection:** اجازه دادن به گرادیان که از لایه‌های زیاد عبور کند

بدون این چهار ترفند، شبکه‌ی ۵۰ لایه آموزش نمی‌دید.

#### انواع شبکه‌های عصبی

| نوع | مخفف | تخصص | مثال کاربرد |
|---|---|---|---|
| شبکه‌ی پیش‌خور | MLP / FNN | داده‌ی جدولی | پیش‌بینی |
| شبکه‌ی کانولوشنی | CNN | تصویر | تشخیص چهره |
| شبکه‌ی بازگشتی | RNN / LSTM | ترتیب | ترجمه (قدیمی) |
| ترانسفورمر | Transformer | ترتیب + توجه | LLM، ترجمه |
| شبکه‌ی مولد تخاصمی | GAN | تولید تصویر | Deepfake |
| مدل انتشار | Diffusion | تولید تصویر | Midjourney |
| خودرمزگذار | Autoencoder | فشرده‌سازی | تشخیص ناهنجاری |

این‌ها را در فایل‌های ۱۰ تا ۱۴ کامل می‌بینیم. فعلاً فقط بدان که **هر معماری برای نوع خاصی از داده ساخته شده**.

### مثال‌ها و نمونه‌های عملی

#### مثال ۱: CNN چطور «می‌بیند»؟

CNN از یک ایده‌ی ساده استفاده می‌کند: **فیلتر کوچک که روی تصویر می‌لغزد.**

تصور کن یک ذره‌بین ۳×۳ داری. آن را روی گوشه‌ی تصویر می‌گذاری، یک عدد می‌گیری. یک پیکسل جابه‌جا می‌کنی، عدد بعدی. کل تصویر را می‌پیمایی. نتیجه: یک «نقشه» از اینکه آن الگو کجای تصویر بود.

حالا ۶۴ فیلتر مختلف بگذار (یکی برای لبه‌ی افقی، یکی عمودی، یکی مورب...). هر فیلتر یک نقشه می‌سازد. این می‌شود لایه‌ی اول.

لایه‌ی دوم روی نقشه‌های لایه‌ی اول کار می‌کند. همین‌طور تا آخر.

**چرا این کار می‌کند؟** چون یک چشم در هر جای تصویر، چشم است. CNN این «جابه‌جایی‌ناپذیری» را در ساختارش دارد — یعنی با یک فیلتر، همه‌ی جاهای تصویر را می‌بیند.

#### مثال ۲: چرا شبکه‌های عمیق از کم‌عمق بهترند؟

فرض کن می‌خواهی «گربه» را تشخیص دهی. با یک لایه، فقط می‌توانی بگویی «این تصویر چه رنگ‌هایی دارد». با ۵ لایه، می‌توانی بگویی «اینجا گوش مثلثی و سبیل است».

هر لایه، یک سطح انتزاع بالاتر می‌سازد. و انتزاع، کلید تعمیم است: اگر مدل «گوش مثلثی» را یاد بگیرد، گربه‌ی سیاه و سفید و خوابیده را هم می‌شناسد.

#### مثال ۳: هزینه‌ی DL

یک مدل CNN برای تشخیص چهره:
- داده: ۱۰۰ هزار عکس برچسب‌دار
- آموزش: چند ساعت تا چند روز روی GPU
- استنتاج: چند میلی‌ثانیه روی گوشی

یک LLM بزرگ:
- داده: تریلیون‌ها کلمه
- آموزش: ماه‌ها روی هزاران GPU، میلیون‌ها دلار
- استنتاج: چند ثانیه روی سرور

**درس:** DL مقیاس‌پذیر است، اما ارزان نیست. برای هر مسئله، اندازه‌ی مناسب را انتخاب کن.

### مقایسه و دیدگاه‌های مختلف

#### ML کلاسیک در برابر DL

| معیار | ML کلاسیک | DL |
|---|---|---|
| نیاز به داده | کم تا متوسط | زیاد |
| نیاز به محاسبه | کم | زیاد |
| مهندسی ویژگی | لازم | خودکار |
| قابل توضیح | متوسط تا بالا | پایین |
| عملکرد در داده‌ی جدولی کوچک | عالی | متوسط |
| عملکرد در تصویر/صدا/متن | متوسط | عالی |
| زمان آموزش | دقیقه | ساعت تا ماه |

**قاعده‌ی عملی:**
- داده‌ی جدولی و کمتر از ۱۰۰ هزار رکورد → ML کلاسیک
- تصویر، صدا، متن، یا داده‌ی خیلی زیاد → DL

#### بحث «جعبه‌ی سیاه»

منتقدان می‌گویند: DL قابل توضیح نیست، پس در حوزه‌های حساس خطرناک است.

پاسخ‌دهندگان می‌گویند: انسان هم قابل توضیح نیست. یک رادیولوژیست هم نمی‌تواند دقیقاً بگوید چطور تشخیص داد. مهم این است که **عملکرد قابل اندازه‌گیری** باشد.

واقعیت: هر دو نکته درست است. برای همین امروز حوزه‌ی **Explainable AI (XAI)** رشد کرده: ابزارهایی که تلاش می‌کنند بگویند مدل به کدام قسمت ورودی توجه کرده. (فصل ۸۱)

#### بحث «آیا DL به AGI می‌رسد؟»

**بله‌گویان:** مقیاس + معماری بهتر، ادامه‌ی مسیر است. LLMها نشان دادند که با بزرگ‌تر شدن، توانایی‌های جدید ظاهر می‌شود.

**نه‌گویان:** DL الگو را حفظ می‌کند، استدلال نمی‌کند. برای AGI به چیز بنیادی‌تری نیاز است (استدلال نمادین، حافظه‌ی ساختاری، مدل جهانی).

این بحث باز است. صادقانه: هیچ‌کس نمی‌داند. (فصل ۸۷)

### اشتباهات رایج

**اشتباه ۱: «DL همیشه بهتر است»**
برای داده‌ی جدولی کوچک، Gradient Boosting از شبکه‌ی عصبی بهتر و ارزان‌تر است. DL ابزار است، نه دین.

**اشتباه ۲: «عمیق‌تر = بهتر»**
بعد از یک حد، عمیق‌تر کردن بدون داده‌ی بیشتر، فقط هزینه است. معماری‌های کارآمد امروز (مثل MobileNet) با لایه‌های کمتر، بهتر از شبکه‌های غول‌آسا در گوشی کار می‌کنند.

**اشتباه ۳: باور به «شبکه خودش می‌فهمد»**
شبکه الگو پیدا می‌کند. اگر در داده‌ی آموزشی، همه‌ی گربه‌ها روی مبل بودند، ممکن است شبکه «مبل» را به‌عنوان نشانه‌ی گربه یاد بگیرد. این را **میان‌بر یادگیری (Shortcut Learning)** می‌نامند و یکی از مهم‌ترین مشکلات DL است.

مثال واقعی: مدلی که «پنومونی» را از عکس قفسه‌ی سینه تشخیص می‌داد، در واقع یاد گرفته بود بیمارستان‌هایی که دستگاه پرتابل دارند بیماران بدحال‌تری دارند — پس «علامت پرتابل» را به‌عنوان نشانه‌ی بیماری یاد گرفته بود.

**اشتباه ۴: نادیده گرفتن هزینه‌ی استنتاج**
مدلی که در آزمایشگاه ۹۸٪ دقیق است اما ۵۰۰ میلی‌ثانیه جواب می‌دهد، برای یک اپلیکیشن موبایل بی‌فایده است.

**اشتباه ۵: فراموش کردن داده‌ی برچسب‌دار**
DL به داده‌ی برچسب‌دار زیاد نیاز دارد و برچسب زدن گران است. این هزینه را در پروژه‌ات حساب کن.

### نکات مهم و ترفندها

**۱. با مدل کوچک شروع کن، بزرگ کن اگر لازم بود**
اول یک MLP کوچک یا حتی ML کلاسیک. اگر جواب نداد، بزرگ‌تر کن. برعکسش پرهزینه است.

**۲. از یادگیری انتقالی (Transfer Learning) استفاده کن**
لازم نیست از صفر آموزش دهی. یک مدل پیش‌آموزش‌دیده (مثل ResNet) بگیر و فقط لایه‌های آخر را برای مسئله‌ی خودت تنظیم کن. با ۱۰۰۰ عکس هم نتیجه می‌گیری.

**۳. همیشه داده‌ی متعادل بساز**
اگر ۹۵٪ داده‌ی تو «سالم» و ۵٪ «بیمار» است، مدلی که همیشه «سالم» بگوید ۹۵٪ دقیق است و کاملاً بی‌فایده. این را **مشکل کلاس نامتعادل** می‌نامند. (فصل ۳۰)

**۴. میان‌بر را شکار کن**
بعد از آموزش، بپرس: مدل به چه چیزی نگاه می‌کند؟ اگر جواب «پس‌زمینه» بود، مشکل داری. ابزارهای XAI (مثل Grad-CAM) این را نشان می‌دهند.

**۵. «عمق» را با «داده» تناسب بده**
قاعده‌ی سرانگشتی: برای هر لایه، حداقل هزاران نمونه لازم داری. کمتر از آن، بیش‌برازش حتمی است.

### خلاصه فصل

- DL = ML با شبکه‌های چندلایه؛ هر لایه سطح بالاتری از انتزاع می‌سازد.
- سه عامل ممکن‌کننده: داده، GPU، ترفندهای آموزشی.
- CNN برای تصویر، RNN برای ترتیب (قدیمی)، Transformer برای همه‌چیز امروز.
- DL در داده‌ی بزرگ و بدون ساختار عالی است؛ در داده‌ی جدولی کوچک، ML کلاسیک بهتر.
- میان‌بر یادگیری خطر بزرگ DL است.
- با کوچک شروع کن، انتقالی یاد بگیر، داده را متعادل کن.

**سؤال مروری:**
1. چرا شبکه‌ی عمیق می‌تواند ویژگی‌ها را خودش کشف کند، در حالی که ML کلاسیک نمی‌تواند؟
2. «میان‌بر یادگیری» چیست و چرا خطرناک است؟
3. برای یک مسئله با ۲۰۰۰ رکورد جدولی، DL انتخاب می‌کنی یا ML کلاسیک؟ چرا؟

## فصل ۱۲: هوش مصنوعی مولد و مدل‌های زبانی بزرگ

### مقدمه

تا اینجا همه‌ی مدل‌ها یک کار می‌کردند: **تشخیص**. «این اسپم است یا نه»، «این چهره کیست»، «قیمت این خانه چند است».

از ۲۰۲۲ به بعد، مدل‌ها کار دیگری می‌کنند: **تولید**. «یک ایمیل بنویس»، «یک عکس از گربه‌ی فضانورد بساز»، «این کد را کامل کن».

این تفاوت، ظاهراً کوچک است اما بنیادی: **تشخیص، انتخاب از بین گزینه‌های موجود است. تولید، ساختن گزینه‌ی جدید.**

### مفاهیم اساسی

#### GenAI چیست؟

**هوش مصنوعی مولد (Generative AI)** مدل‌هایی هستند که محتوای تازه تولید می‌کنند: متن، تصویر، صدا، ویدیو، کد، مولکول.

تفاوت بنیادی با مدل‌های تشخیصی:

| ویژگی | تشخیصی (Discriminative) | مولد (Generative) |
|---|---|---|
| سؤال | «کدام دسته؟» | «چه چیزی بسازم؟» |
| خروجی | برچسب یا عدد | محتوای کامل |
| آموزش | یادگیری مرز بین دسته‌ها | یادگیری توزیع داده |
| مثال | تشخیص اسپم | تولید ایمیل |

#### چطور «تولید» می‌کند؟ — سه خانواده

**خانواده ۱: مدل‌های زبانی (Autoregressive)**
یک کلمه تولید می‌کند، بعد کلمه‌ی بعد را بر اساس کلمات قبلی، و همین‌طور تا آخر.

```
ورودی:  "هوا امروز"
گام ۱:  "هوا امروز" → احتمال‌ها: آفتابی ۳۰٪، سرد ۲۰٪، خوب ۱۵٪...
گام ۲:  انتخاب "آفتابی" → "هوا امروز آفتابی"
گام ۳:  "هوا امروز آفتابی" → احتمال‌ها: است ۴۰٪، و ۲۰٪...
```

این ساده‌ترین و در عین حال دقیق‌ترین توصیف کاری است که ChatGPT می‌کند. **او کلمه‌ی بعدی را حدس می‌زند، میلیاردها بار.**

**خانواده ۲: مدل‌های انتشار (Diffusion)**
از نویز شروع می‌کند و قدم‌به‌قدم نویز را کم می‌کند تا تصویر ظاهر شود. مثل مجسمه‌سازی که از یک سنگ، شکل را بیرون می‌آورد.

فرآیند آموزش: تصویر واقعی را بردار، نویز اضافه کن، به مدل بگو نویز را حذف کند. میلیون‌ها بار.

فرآیند تولید: از نویز خالص شروع کن، مدل قدم‌به‌قدم تصویر را بسازد.

**خانواده ۳: GAN (شبکه‌ی مولد تخاصمی)**
دو شبکه در برابر هم: یکی **مولد** که تصویر جعلی می‌سازد، یکی **متمایزکننده** که سعی می‌کند جعلی را تشخیص دهد. آن‌قدر تمرین می‌کنند تا مولد آن‌قدر خوب شود که متمایزکننده نتواند فرق بگذارد.

#### LLM چیست؟

**مدل زبانی بزرگ (Large Language Model)** یک مدل autoregressive است که با مقدار عظیمی متن آموزش دیده.

سه ویژگی که آن را «بزرگ» می‌کند:

**۱. پارامترهای زیاد:** از چند میلیارد تا چند صد میلیارد.
**۲. داده‌ی عظیم:** تریلیون‌ها کلمه از اینترنت، کتاب، کد.
**۳. توانایی عمومی:** یک مدل برای کارهای زیادی استفاده می‌شود، نه یک کار.

#### چرا LLM «می‌فهمد»؟ — و چرا نه؟

اینجا باید صادق باشیم. LLM:
- **می‌تواند:** الگوهای زبانی را در سطح بسیار بالایی تقلید کند، معنی را تا حد زیادی بگیرد، استدلال سطحی بکند.
- **نمی‌تواند (یا ضعیف است):** استدلال چندمرحله‌ای دقیق، حساب دقیق، حفظ واقعیت، فهم دنیای فیزیکی.

سؤال «آیا می‌فهمد؟» هنوز باز است. اما یک چیز روشن است: **برای ۸۰٪ کارهای متنی روزمره، عملکردش به‌قدری خوب است که تفاوت عملی مهم نباشد.**

### مثال‌ها و نمونه‌های عملی

#### مثال ۱: یک LLM در عمل — تولید ایمیل

فرض کن می‌خواهی به مشتری بنویسی که سفارشش تأخیر دارد.

**بدون LLM:** نیم ساعت فکر کردن، سه بار بازنویسی، نگرانی از لحن.

**با LLM:**
```
پرامپت: یک ایمیل عذرخواهی برای تأخیر ۳ روزه‌ی سفارش بنویس.
لحن: محترمانه اما صمیمی. مشتری B2B است. راه‌حل هم بده.
```

نتیجه: یک پیش‌نویس ۸۰٪ آماده در ۵ ثانیه. تو ۵ دقیقه ویرایش می‌کنی.

**درس:** ارزش LLM در **حذف نقطه‌ی شروع سخت** است، نه در جایگزینی قضاوت تو.

#### مثال ۲: چرا LLM عدد را غلط حساب می‌کند؟

LLM برای «پیش‌بینی کلمه‌ی بعدی» آموزش دیده، نه برای محاسبه. وقتی می‌پرسی «۴۷۳۸ × ۲۹۱»، مدل سعی می‌کند الگوی جواب را تقلید کند، نه اینکه واقعاً ضرب کند.

راه‌حل: به مدل ابزار بده. مدل‌های امروز می‌توانند کد پایتون اجرا کنند و جواب دقیق بگیرند. این را **استفاده از ابزار (Tool Use)** می‌نامند. (فصل ۶۷)

**درس مهم:** برای هر کاری که «دقیق» لازم دارد (حساب، تاریخ، آمار)، LLM را تنها نگذار.

#### مثال ۳: تولید تصویر با Diffusion

پرامپت: «یک نانوایی سنتی در تهران، صبح زمستانی، بخار از تنور، نور طلایی»

فرآیند:
1. متن به یک «بردار معنا» تبدیل می‌شود (Embedding)
2. از نویز خالص شروع می‌شود
3. در ۲۰ تا ۵۰ قدم، نویز کم می‌شود و تصویر ظاهر می‌شود — در هر قدم، مدل به بردار معنا «نگاه» می‌کند تا در مسیر درست بماند

نتیجه: تصویری که هیچ‌جا وجود نداشته.

**نکته‌ی مهم:** مدل «نانوایی ایرانی» را از عکس‌های واقعی یاد گرفته. اگر داده‌ی کافی از نانوایی ایرانی نداشته باشد، نتیجه ممکن است شبیه نانوایی اروپایی شود.

### مقایسه و دیدگاه‌های مختلف

#### سه خانواده‌ی مولد

| معیار | Autoregressive (LLM) | Diffusion | GAN |
|---|---|---|---|
| خروجی | متن، کد | تصویر، ویدیو، صدا | تصویر |
| کیفیت | عالی در متن | عالی در تصویر | خوب، اما ناپایدار |
| سرعت تولید | متوسط | کند | سریع |
| کنترل | بالا (پرامپت) | بالا | متوسط |
| آموزش | ساده‌تر | متوسط | سخت (ناپایدار) |
| مشکل اصلی | توهم | کندی | فروپاشی حالت |

#### دو روایت از LLM

**روایت «فهم»:** مدل‌ها به‌قدری بزرگ شده‌اند که معنا را درک می‌کنند. توانایی‌های نوظهور نشانه‌ی فهم است.

**روایت «طوطی آماری»:** مدل‌ها فقط الگوهای سطحی را تقلید می‌کنند. مثال: در مسائل منطقی ساده شکست می‌خورند، با تغییر کوچک در جمله‌بندی گیج می‌شوند.

**داوری منصفانه:** حقیقت جایی در میانه است. مدل‌ها بیش از «طوطی» هستند (تعمیم می‌دهند، ترکیب می‌کنند، قیاس می‌کنند) اما کمتر از «فهم انسانی» (استدلال دقیق، مدل جهانی، خودآگاهی).

این بحث را در فصل ۶۵ و ۸۷ ادامه می‌دهیم.

#### GenAI در برابر جست‌وجو

| معیار | جست‌وجو | GenAI |
|---|---|---|
| منبع | صفحات واقعی | پارامترهای مدل |
| تازگی | لحظه‌ای | تا تاریخ آموزش |
| دقت منبع | قابل بررسی | نامشخص |
| ترکیب و خلاصه | ضعیف | عالی |
| خطر | اطلاعات بد اما قابل ردیابی | اطلاعات بد با ظاهر معتبر |

**بهترین حالت: ترکیب هر دو.** مدل جست‌وجو کند، منابع را بخواند، بعد جواب بدهد. این همان ایده‌ی RAG است. (فصل ۵ و ۶۶)

### اشتباهات رایج

**اشتباه ۱: «GenAI می‌فهمد، پس قابل اعتماد است»**
روانی خروجی، معیار درستی نیست. همیشه چک کن.

**اشتباه ۲: «LLM همه‌چیز را می‌داند»**
فقط داده‌ی آموزشی‌اش را می‌داند، و آن هم فشرده شده. جزئیات نادر ممکن است از دست رفته باشد.

**اشتباه ۳: باور به «مدل بزرگ‌تر همیشه بهتر»**
مدل‌های کوچک امروز در کارهای باریک از مدل‌های غول‌آسا بهترند — ارزان‌تر، سریع‌تر، حریم خصوصی بهتر (روی دستگاه اجرا می‌شوند).

**اشتباه ۴: نادیده گرفتن هزینه**
هر توکن هزینه دارد. برای یک محصول با ۱۰۰ هزار کاربر، این عدد جدی است. (فصل ۴۹)

**اشتباه ۵: فراموش کردن مسائل حقوقی و اخلاقی**
تصویر تولیدشده با GenAI، مالکیتش کیست؟ اگر شبیه یک برند باشد چه؟ اگر Deepfake باشد چه؟ این‌ها سؤال‌های فنی نیستند، حقوقی‌اند. (فصل ۸۲)

### نکات مهم و ترفندها

**۱. برای هر کار، «تشخیصی یا مولد؟» را مشخص کن**
اگر می‌خواهی تصمیم بگیری (این تراکنش تقلبی است؟)، مدل تشخیصی ارزان‌تر و دقیق‌تر است. اگر می‌خواهی محتوا بسازی، مولد.

**۲. LLM را با ابزار ترکیب کن**
حساب → ماشین‌حساب. جست‌وجو → موتور جست‌وجو. فایل → ابزار فایل. مدل به‌تنهایی، محدود است.

**۳. خروجی مولد را همیشه بازبینی کن**
هر چیزی که منتشر می‌شود (ایمیل، مقاله، کد، تصویر) باید انسان تأیید کند. مسئولیت با توست، نه با مدل.

**۴. برای تصویر، پرامپت دقیق بنویس**
Diffusion به جزئیات حساس است: نور، زاویه، سبک، ترکیب. پرامپت مبهم → تصویر تصادفی.

**۵. تاریخ آموزش را چک کن**
برای هر مدلی که استفاده می‌کنی، بدان تا کِی آموزش دیده. اگر موضوع حساس است، منبع بیرونی بده.

### خلاصه فصل

- GenAI محتوای تازه تولید می‌کند، نه فقط دسته‌بندی.
- سه خانواده: Autoregressive (متن)، Diffusion (تصویر)، GAN (تصویر).
- LLM یک مدل autoregressive است که کلمه‌ی بعدی را حدس می‌زند.
- LLM در تقلید الگو عالی است، در محاسبه و واقعیت دقیق ضعیف.
- بهترین استفاده: ترکیب مدل با ابزار و منبع بیرونی.
- مسئولیت خروجی همیشه با انسان است.

**سؤال مروری:**
1. تفاوت بنیادی مدل تشخیصی و مولد را با یک مثال توضیح بده.
2. چرا LLM عدد را غلط حساب می‌کند و راه‌حل چیست؟
3. چرا «جست‌وجو + LLM» از هر کدام به‌تنهایی بهتر است؟
