## فصل ۷۸: برق، POST و روشن‌نشدن سرور

### مقدمه

«سرور روشن نمی‌شود» ساده‌ترین علامت است و پیچیده‌ترین زنجیرهٔ علل: از برق ساختمان تا دکمهٔ پاور، از PSU تا مادربرد.

این فصل، زنجیره را از منبع به مقصد طی می‌کند — به ترتیب، چون ترتیب اشتباه وقت تلف می‌کند.

### مفاهیم اساسی

**زنجیرهٔ برق:**

```
[برق شهری] → [بریکر] → [PDU] → [UPS] → [کابل] → [PSU] → [مادربرد] → [دکمهٔ پاور]
```

**اصل:** از **منبع** شروع کن و به **مقصد** برو. اگر برق شهری نیست، تعویض PSU بی‌فایده است.

**حالت‌های «روشن نمی‌شود»:**

| حالت | معنی | نشانه |
|---|---|---|
| **هیچ چراغی نیست** | بدون برق | PSU، کابل، PDU |
| **چراغ standby هست، روشن نمی‌شود** | برق هست، سیگنال پاور نیست | دکمه، مادربرد، BMC |
| **فن می‌چرخد، بوت نمی‌شود** | POST مشکل دارد | RAM، CPU، کارت |
| **بوت می‌شود، OS نمی‌آید** | مشکل boot device | دیسک، bootloader |
| **روشن می‌شود و خاموش** | حفاظت | اتصال کوتاه، دما |

**POST (Power-On Self-Test):** تست خودکار سخت‌افزار در بوت.

**ترتیب POST:**

```
۱. CPU
۲. حافظه
۳. ویدئو
۴. کنترلر دیسک
۵. دستگاههای دیگر
۶. boot device
```

**نکته:** اگر POST در مرحلهٔ ۲ متوقف شود، چراغ/بوق مربوط به حافظه است. **کد POST، مرحلهٔ توقف را نشان می‌دهد** — نه علت دقیق.

**Beep codes — الگوهای رایج (AMI/Phoenix):**

| الگو | معنی احتمالی |
|---|---|
| **۱ بوق کوتاه** | POST موفق |
| **۲ کوتاه** | خطای parity حافظه |
| **۳ کوتاه** | خطای حافظه (۶۴KB اول) |
| **۴ کوتاه** | تایمر |
| **۵ کوتاه** | پردازنده |
| **۶ کوتاه** | keyboard controller |
| **۷ کوتاه** | پردازنده (exception) |
| **۸ کوتاه** | کارت گرافیک |
| **۹ کوتاه** | ROM BIOS |
| **۱۰ کوتاه** | CMOS |
| **۱ بلند، ۱ کوتاه** | مادربرد |
| **۱ بلند، ۲ کوتاه** | کارت گرافیک |
| **۱ بلند، ۳ کوتاه** | کارت گرافیک |
| **بوق پیوسته** | حافظه یا برق |

> **توجه:** الگوهای بوق، **بین سازندگان و مدل‌ها متفاوت** است. همیشه دفترچهٔ همان سرور را چک کن. جدول بالا فقط برای آشنایی است.

**نکتهٔ مهم:** سرورهای enterprise معمولاً **بوق نمی‌زنند**؛ از LED و BMC log استفاده می‌کنند. بوق بیشتر در سرورهای کوچک و workstation.

**LEDهای سرور:**

| LED | معنی |
|---|---|
| **Power (سبز)** | برق وصل و روشن |
| **Standby (کهربایی چشمک‌زن)** | برق standby، سیستم خاموش |
| **Health (سبز/کهربایی/قرمز)** | وضعیت کلی |
| **System ID (آبی چشمک‌زن)** | شناسایی فیزیکی |
| **NIC link (سبز)** | اتصال شبکه |
| **NIC activity (چشمک‌زن)** | ترافیک |
| **Drive (سبز/کهربایی)** | وضعیت دیسک |
| **PSU (سبز/کهربایی)** | وضعیت منبع |

**نکته:** LED **System ID** برای پیدا کردن سرور در رک شلوغ است — با BMC روشنش کن، چراغ آبی چشمک می‌زند.

**CMOS و تنظیمات:**

| علامت | علت |
|---|---|
| ساعت عقب می‌رود | باتری CMOS |
| تنظیمات بوت ری‌ست می‌شود | باتری CMOS |
| «CMOS checksum error» | باتری یا تنظیمات |
| تاریخ ۲۰۱۰ | باتری |

**نکته:** باتری CMOS عمر ۵–۱۰ سال دارد. علامت اولیه: ساعت عقب می‌رود.

**Clear CMOS:** برای بازگرداندن تنظیمات به پیش‌فرض.

- **Jumper** روی مادربرد.
- **دکمهٔ CMOS** (بعضی سرورها).
- **حذف باتری** (۵ دقیقه).

**نکته:** قبل از Clear CMOS، تنظیمات RAID را یادداشت کن. بعضی کنترلرها تنظیمات را در NVRAM دارند، نه CMOS — اما احتیاط لازم است.

### مثال‌های عملی

**Lab Scenario 1 — سرور روشن نمی‌شود**

> **وضعیت:** سرور در رک، هیچ چراغی روشن نیست. تکنسین می‌خواهد PSU را عوض کند.
>
> **وظیفه:** ترتیب صحیح بررسی.
>
> **پاسخ:**
> ۱. **برق ساختمان:** آیا سایر تجهیزات رک روشن‌اند؟
> ۲. **بریکر PDU:** آیا قطع نشده؟
> ۳. **کابل PSU:** آیا محکم است؟ (کابل C13/C14 شل می‌شود)
> ۴. **LED PSU:** اگر PSU LED ندارد، با PSU tester یا multimeter.
> ۵. **دکمهٔ پاور:** آیا گیر کرده؟
> ۶. **BMC:** آیا از راه دور پاسخ می‌دهد؟ (اگر بله، PSU سالم است و مشکل دکمه/مادربرد)
> ۷. **حالا** PSU را عوض کن.
>
> **درس:** تعویض PSU قبل از بررسی برق ورودی، هدر دادن قطعه است.

**Lab Scenario 2 — بوق می‌زند و بوت نمی‌شود**

> **وضعیت:** سرور ۳ بوق کوتاه می‌زند و صفحه نمی‌آید.
>
> **وظیفه:** تشخیص.
>
> **پاسخ:**
> - **۳ بوق کوتاه** در بیشتر BIOSها = خطای حافظه (۶۴KB اول).
> - **اقدام:** خاموش کن، همهٔ ماژول‌ها را بردار، یکی‌یکی تست کن.
> - اگر با یک ماژول هم بوق زد، احتمالاً اسلات یا مادربرد.
> - **تأیید:** دفترچهٔ سرور برای الگوی دقیق.
>
> **درس:** بوق، کد است؛ باید با دفترچهٔ همان مدل تطبیق شود.

### مقایسه و الگوهای مختلف

**مقایسهٔ LED و BMC:**

| معیار | LED | BMC |
|---|---|---|
| دسترسی | فیزیکی | راه دور |
| جزئیات | کم | زیاد (log) |
| سرعت | فوری | نیاز به اتصال |
| مناسب | حضور در محل | سرور دور |

**مقایسهٔ POST card و BMC log:**

| معیار | POST card | BMC log |
|---|---|---|
| نصب | سخت‌افزاری | آماده |
| جزئیات | کد توقف | رخداد کامل |
| مناسب | سرور بدون نمایشگر | همه |

**مقایسهٔ PSU tester و multimeter:**

| معیار | PSU tester | Multimeter |
|---|---|---|
| سادگی | بالا | متوسط |
| دقت | متوسط | بالا |
| نیاز به دانش | کم | متوسط |
| مناسب | تعویض سریع | عیب‌یابی دقیق |

### اشکال شایع

**۱. تعویض PSU قبل از بررسی برق ورودی.**
قطعهٔ سالم هدر می‌رود.

**۲. فرض اینکه «هیچ چراغی» یعنی PSU.**
می‌تواند PDU، کابل یا بریکر باشد.

**۳. نادیده گرفتن BMC.**
اگر BMC پاسخ می‌دهد، برق هست.

**۴. Clear CMOS بدون یادداشت تنظیمات.**
RAID یا boot order از دست می‌رود.

**۵. تعویض چند قطعه هم‌زمان.**
نمی‌دانی کدام مؤثر بود.

**۶. فرض یکسان بودن beep codes.**
هر سازنده متفاوت است.

**۷. بدون ESD.**
آسیب به قطعه در حین تعویض.

**۸. نادیده گرفتن دکمهٔ پاور گیرکرده.**
سرور روشن می‌شود و فوراً خاموش.

### نکات مهم (Tips & Tricks)

- **از منبع به مقصد** — برق شهری اول.
- **BMC پاسخ می‌دهد؟** = برق هست.
- **LED System ID** برای پیدا کردن سرور.
- **باتری CMOS** را هر ۵ سال عوض کن.
- **قبل از Clear CMOS، تنظیمات را عکس بگیر.**
- **در آزمون:** کلیدواژهٔ «no power, no lights» → **power source/PSU**؛ «POST beep» → **hardware component failure**.

### خلاصه فصل

- زنجیرهٔ برق: **شهری → بریکر → PDU → UPS → PSU → مادربرد**.
- **از منبع به مقصد** بررسی کن.
- POST ترتیب دارد: **CPU → RAM → Video → Storage**.
- **beep codes** بین سازندگان متفاوت است.
- سرورهای enterprise از **LED + BMC** استفاده می‌کنند.
- **باتری CMOS** عمر ۵–۱۰ سال.

## فصل ۷۹: عیب‌یابی پردازنده و حافظه

### مقدمه

CPU و RAM، قطعاتی هستند که «یا کار می‌کنند یا نه» — اما نه همیشه. گاهی نیمه‌کاره کار می‌کنند: خطای تصادفی، ری‌استارت، دادهٔ خراب.

این فصل دربارهٔ آن حالت‌های مرموز است.

### مفاهیم اساسی

**علائم مشکلات CPU:**

| علامت | توضیح |
|---|---|
| **بوت نمی‌شود، هیچ چراغی** | CPU مرده یا نصب نادرست |
| **ری‌استارت تصادفی زیر بار** | حرارت، برق، instability |
| **BSOD/panic با کد CPU** | خطای پردازنده |
| **کندی شدید پایدار** | throttle حرارتی |
| **کد POST در مرحلهٔ CPU** | CPU یا سوکت |

**نکتهٔ حیاتی:** CPU به‌ندرت «نیمه‌خراب» می‌شود. اگر مشکوک به CPU هستی، اول **حرارت** و **برق** را بررسی کن.

**حرارت — علائم و علل:**

| علامت | علت |
|---|---|
| **فن پرسرعت دائم** | حرارت بالا |
| **throttle (کندی)** | دمای بالا |
| **خاموشی خودکار** | حفاظت حرارتی |
| **بوی سوختگی** | خرابی جدی |

**علل حرارت:**

- **خمیر حرارتی خشک‌شده** (بعد از ۳–۵ سال)
- **هیت‌سینک شل** (پیچ نامتقارن)
- **فن متوقف** (گردوغبار، بلبرینگ)
- **جریان هوای مسدود** (کابل، بلانکینگ پنل نبود)
- **دمای اتاق بالا** (فصل ۸۳)

**نکتهٔ مهم:** در سرور، **همیشه** با BMC دما را چک کن. `sensors` در لینوکس، iDRAC/iLO در سخت‌افزار.

**علائم مشکلات حافظه:**

| علامت | توضیح |
|---|---|
| **ری‌استارت تصادفی** | خطای uncorrectable |
| **BSOD با کد memory** | 0x0000001A، 0x00000050 |
| **برنامه‌ها کرش می‌کنند** | دادهٔ خراب |
| **بوت نمی‌شود** | ماژول خراب یا چیدمان |
| **ظرفیت کمتر از انتظار** | ماژول شناسایی نشده |
| **خطای ECC در log** | correctable یا uncorrectable |

**نکتهٔ حیاتی:** **خطای correctable** را نادیده نگیر. ۴۷ خطا در یک روز، پیش‌درآمد خطای uncorrectable است (فصل ۱۱).

**تست حافظه:**

| ابزار | توضیح |
|---|---|
| **Memtest86+** | جامع، از USB بوت |
| **Windows Memory Diagnostic** | ساده، در ویندوز |
| **ابزار BMC/سرور** | تست داخلی |
| **`memtester`** (لینوکس) | در OS |

**نکته:** Memtest86+ باید **حداقل یک پاس کامل** (چند ساعت) اجرا شود. یک پاس سریع، خطای گاه‌به‌گاه را نمی‌گیرد.

**روش تست ماژول:**

```
۱. خاموش، همهٔ ماژول‌ها را بردار
۲. یک ماژول در اسلات A1
۳. بوت و تست
۴. اگر سالم: ماژول بعدی
۵. اگر خراب: ماژول را در اسلات دیگر تست (تفکیک ماژول/اسلات)
```

**نکته:** این روش **زمان‌بر** است. برای سرور با ۱۶ ماژول، ساعت‌ها. اما قطعی است.

**چیدمان حافظه — خطاهای رایج:**

| خطا | نتیجه |
|---|---|
| **پر کردن نامتوازن کانال** | کاهش پهنای باند یا بوت نشدن |
| **مخلوط RDIMM و UDIMM** | شناسایی نشدن |
| **مخلوط ظرفیت** | کار می‌کند اما ریسک |
| **مخلوط سرعت** | همه با سرعت پایین‌تر |
| **نصب ناقص** | خطای تصادفی |

**نکته:** بعد از افزودن RAM، اگر سرور بوت نشد، **اول چیدمان** را چک کن، نه «RAM خراب است».

**NUMA و عملکرد:**

در سرور دو‌سوکتی، اگر VM یا دیتابیس بین NUMA node پخش شود، عملکرد افت می‌کند. علامت: CPU پایین اما latency بالا.

**ابزار:** `numactl --hardware`، `lscpu | grep NUMA`.

### مثال‌های عملی

**Lab Scenario 1 — ری‌استارت تصادفی**

> **وضعیت:** سرور هر ۲–۳ روز یک بار ری‌استارت می‌شود. هیچ الگوی زمانی مشخصی نیست.
>
> **وظیفه:** پنج فرضیه به ترتیب احتمال.
>
> **پاسخ:**
> ۱. **حافظه:** خطای ECC. چک: BMC log (`Correctable/Uncorrectable ECC`)، Memtest86+.
> ۲. **برق:** PSU ناپایدار یا مسیر برق. چک: BMC power event، PSU LED، UPS log.
> ۳. **حرارت:** throttle یا خاموشی حفاظتی. چک: BMC temp log.
> ۴. **firmware/درایور:** باگ. چک: نسخه، release notes.
> ۵. **OS:** kernel panic. چک: `/var/log/kern.log`، `kdump`.
>
> **درس:** ری‌استارت تصادفی، اول از **سخت‌افزار** شروع می‌شود، نه OS.

**Lab Scenario 2 — RAM اضافه کردم، بوت نمی‌شود**

> **وضعیت:** ۱۲۸GB به ۲۵۶GB ارتقا. سرور بوت نمی‌شود.
>
> **وظیفه:** ترتیب بررسی.
>
> **پاسخ:**
> ۱. **چیدمان:** آیا طبق دفترچه است؟ (A1، B1، C1، D1 اول)
> ۲. **سازگاری:** همان مدل/سرعت/نوع (RDIMM)؟
> ۳. **حداکثر ظرفیت:** مادربرد ۲۵۶GB پشتیبانی می‌کند؟
> ۴. **نصب فیزیکی:** کلیپس‌ها کامل بسته؟
> ۵. **BIOS:** نسخهٔ قدیمی، ماژول جدید را نمی‌شناسد؟
> ۶. **تک‌تک تست:** با یک ماژول جدید تنها.
>
> **درس:** ۸۰٪ مشکلات «RAM جدید»، چیدمان یا سازگاری است.

### مقایسه و الگوهای مختلف

**مقایسهٔ Memtest86+ و Windows Memory Diagnostic:**

| معیار | Memtest86+ | WMD |
|---|---|---|
| جامعیت | بالا | متوسط |
| نیاز به بوت | ✅ | ❌ |
| زمان | ساعت | دقیقه |
| مناسب | تولیدی | سریع |

**مقایسهٔ correctable و uncorrectable:**

| نوع | اثر | اقدام |
|---|---|---|
| **Correctable** | اصلاح، بدون crash | پایش، تعویض پیشگیرانه |
| **Uncorrectable** | crash، دادهٔ خراب | تعویض فوری |

**مقایسهٔ throttle و shutdown:**

| معیار | Throttle | Shutdown |
|---|---|---|
| رفتار | کاهش فرکانس | خاموشی |
| دما | بالای آستانهٔ اول | بالای آستانهٔ بحرانی |
| علامت | کندی | قطعی |

### اشکال شایع

**۱. تعویض CPU قبل از بررسی حرارت.**
۸۰٪ مشکلات CPU، حرارت است.

**۲. خمیر حرارتی خشک.**
بعد از ۳–۵ سال، عملکرد حرارتی افت می‌کند.

**۳. پیچ هیت‌سینک نامتقارن.**
تماس ناقص، دما بالا.

**۴. نادیده گرفتن ECC correctable.**
پیش‌درآمد uncorrectable.

**۵. Memtest کوتاه.**
خطای گاه‌به‌گاه دیده نمی‌شود.

**۶. چیدمان نامتوازن RAM.**
بوت نشدن یا عملکرد پایین.

**۷. مخلوط ماژول.**
ناپایداری.

**۸. فرض «CPU خراب» بدون شواهد.**
CPU نادرترین خرابی است.

### نکات مهم (Tips & Tricks)

- **دما را از BMC بخوان**، نه حس.
- **خمیر حرارتی را هر ۳–۵ سال تازه کن.**
- **Memtest یک پاس کامل.**
- **ECC correctable را پایش کن** — آستانه: >۱۰ در ۲۴ ساعت.
- **بعد از ارتقای RAM، چیدمان اول.**
- **در آزمون:** کلیدواژهٔ «random reboots, no pattern» → **memory or power**؛ «CPU throttling» → **thermal**.

### خلاصه فصل

- CPU نادرترین خرابی است؛ اول **حرارت** و **برق**.
- علائم حرارت: **فن پرسرعت، throttle، خاموشی**.
- **ECC correctable** را جدی بگیر.
- **Memtest86+** با یک پاس کامل.
- چیدمان RAM: **کانال‌ها متوازن**.
- «RAM اضافه کردم بوت نشد» → **چیدمان/سازگاری**.

## فصل ۸۰: عیب‌یابی دیسک و RAID تخریب‌شده

### مقدمه

این فصل، پرتکرارترین سناریوی PBQ در آزمون Server+ است: **یک آرایهٔ RAID با دیسک خراب، و باید تصمیم بگیری چه می‌کنی.**

و اینجا یک اشتباه، داده را نابود می‌کند.

### مفاهیم اساسی

**وضعیت‌های RAID:**

| وضعیت | معنی | افزونگی |
|---|---|---|
| **Optimal** | همه سالم | ✅ کامل |
| **Degraded** | یک دیسک خراب | ⚠️ صفر (RAID 5) یا یک (RAID 6) |
| **Rebuilding** | در حال بازسازی | ⚠️ کاهش‌یافته |
| **Failed** | بیش از تحمل | ❌ داده از دست رفته |

**نکتهٔ حیاتی:** در **Degraded**، هیچ افزونگی نداری. اگر دیسک دوم خراب شود، داده می‌رود. این وضعیت **فوری** است، نه «فردا».

**علائم دیسک خراب:**

| علامت | معنی |
|---|---|
| **LED کهربایی/قرمز روی بای** | دیسک failed |
| **LED چشمک‌زن سریع** | rebuild در جریان |
| **صدای کلیک/ساییدگی** | خرابی مکانیکی HDD |
| **SMART: Reallocated_Sector_Ct بالا** | نشانهٔ خرابی |
| **SMART: Current_Pending_Sector** | sector مشکوک |
| **خطای I/O در log** | `ata`، `sd`، `medium error` |
| **آرایه degraded در ابزار کنترلر** | دیسک حذف شده |

**نکته:** صدای «کلیک کلیک» (click of death) یعنی سر دیسک به platter برخورد می‌کند. **فوراً خاموش کن** — هر ثانیه، خرابی بیشتر.

**ترتیب اقدام در RAID degraded:**

```
۱. تأیید وضعیت (ابزار کنترلر، نه حدس)
۲. تأیید کدام دیسک (LED blink)
۳. بررسی: آیا hot spare فعال شد؟
۴. اگر نه: دیسک یدکی نصب و assign
۵. پایش rebuild
۶. تأیید optimal
۷. بررسی علت خرابی (دما؟ firmware؟ batch؟)
```

**نکتهٔ حیاتی:** **قبل از کشیدن دیسک، LED را blink کن.** در رک با ۲۴ دیسک مشابه، کشیدن دیسک اشتباه = فاجعه.

**ابزار کنترلر:**

```bash
# Broadcom/LSI StorCLI
storcli /c0 show
storcli /c0/v0 show
storcli /c0/eall/sall show          # وضعیت همه دیسکها
storcli /c0/e252/s3 set good force  # علامتگذاری دیسک جدید
storcli /c0/e252/s3 show all        # جزئیات دیسک

# Dell PERC (perccli)
perccli /c0 show
perccli /c0/v0 show

# HP Smart Array (ssacli)
ssacli ctrl all show config
ssacli ctrl slot=0 ld all show
```

**نکته:** `storcli` جانشین `MegaCli` است. `MegaCli` منسوخ شده اما در محیط‌های قدیمی هنوز هست.

**نرم‌افزار RAID (mdadm):**

```bash
# وضعیت
cat /proc/mdstat
mdadm --detail /dev/md0

# علامتگذاری failed
mdadm --manage /dev/md0 --fail /dev/sdb1

# حذف
mdadm --manage /dev/md0 --remove /dev/sdb1

# افزودن دیسک جدید
mdadm --manage /dev/md0 --add /dev/sdd1

# پایش rebuild
watch cat /proc/mdstat
```

**نکته:** در mdadm، **ترتیب مهم است**: fail → remove → add. اگر مستقیم add کنی، ممکن است خطا بدهد.

**ZFS:**

```bash
zpool status
zpool status -v          # با جزئیات خطا
zpool replace tank /dev/sdb /dev/sdd
zpool scrub tank
```

**نکته:** ZFS در `zpool status` نشان می‌دهد کدام فایل‌ها آسیب دیده‌اند (`-v`).

**بازیابی از RAID failed:**

اگر بیش از تحمل خرابی، دیسک خراب شد:

```
۱. آرایه را خاموش نکن (ممکن است هنوز قابل بازیابی باشد)
۲. دیسکها را برچسب بزن (ترتیب مهم است)
۳. با ابزار بازیابی (R-Studio، UFS Explorer) تصویر بگیر
۴. هرگز rebuild نکن — داده را نابود میکند
۵. متخصص بازیابی داده
```

**نکتهٔ حیاتی:** **در RAID failed، rebuild نکن.** rebuild فرض می‌کند فقط یک دیسک گم شده؛ اگر دو دیسک گم شده باشند، rebuild داده را بازنویسی می‌کند.

**پیشگیری از خرابی مجدد:**

| اقدام | دلیل |
|---|---|
| **دیسک از بچ متفاوت** | بچ معیوب، چند دیسک با هم می‌میرند |
| **دما پایین** | هر ۵ درجه، عمر را کم می‌کند |
| **SMART پایش** | هشدار قبل از خرابی |
| **hot spare** | rebuild خودکار |
| **firmware سازگار** | باگ‌های شناخته‌شده |
| **backup** | تنها دفاع نهایی |

### مثال‌های عملی

**Lab Scenario 1 — RAID 5 با یک دیسک failed**

> **وضعیت:** RAID 5 با ۶ دیسک ۴TB. یک دیسک LED کهربایی. آرایه degraded.
>
> **وظیفه:** مراحل.
>
> **پاسخ:**
> ۱. **تأیید با ابزار:** `storcli /c0/v0 show` → Degraded. کدام دیسک؟ `storcli /c0/eall/sall show`.
> ۲. **تأیید فیزیکی:** LED blink روی همان بای.
> ۳. **بررسی hot spare:** اگر فعال شده، rebuild شروع شده. اگر نه، ادامه.
> ۴. **نصب دیسک یدکی** (هم‌ظرفیت یا بزرگ‌تر، همان نوع).
> ۵. **Assign:** `storcli /c0/e252/s3 set good force` سپس assign به آرایه.
> ۶. **پایش:** rebuild ۴TB با ۵۰MB/s ≈ ۲۲ ساعت.
> ۷. **بعد از rebuild:** بررسی optimal، بررسی علت (SMART دیسک قدیمی، دما).
>
> **درس:** ۲۲ ساعت بدون افزونگی — در این بازه، backup تازه بگیر.

**Lab Scenario 2 — RAID 6 با دو دیسک failed**

> **وضعیت:** RAID 6 با ۸ دیسک. دو دیسک failed. آرایه degraded اما فعال.
>
> **وظیفه:** آیا هنوز امن است؟
>
> **پاسخ:**
> - RAID 6 تحمل **۲** دیسک دارد. با ۲ خراب، **افزونگی صفر** است.
> - **بحرانی:** دیسک سوم = از دست رفتن داده.
> - **اقدام فوری:**
>   ۱. **backup فوری** (اگر ممکن).
>   ۲. تعویض **یک** دیسک، صبر تا rebuild کامل.
>   ۳. بعد تعویض دیسک دوم.
>   ۴. **هرگز دو دیسک را هم‌زمان تعویض نکن.**
>
> **درس:** در RAID 6 با دو خرابی، ترتیب تعویض حیاتی است.

### مقایسه و الگوهای مختلف

**مقایسهٔ RAID 5 و 6 در degraded:**

| معیار | RAID 5 (۱ خراب) | RAID 6 (۱ خراب) | RAID 6 (۲ خراب) |
|---|---|---|---|
| افزونگی باقی‌مانده | صفر | یک | صفر |
| فوریت | بحرانی | بالا | بحرانی |
| ریسک | بالا | متوسط | بسیار بالا |

**مقایسهٔ hot spare و manual:**

| معیار | Hot spare | Manual |
|---|---|---|
| شروع rebuild | فوری | تا رسیدن تکنسین |
| ظرفیت | هدر | صفر |
| مناسب | آرایهٔ حیاتی | کوچک |

**مقایسهٔ rebuild priority:**

| اولویت | اثر |
|---|---|
| **Low** | rebuild کند، سرویس سالم |
| **High** | rebuild سریع، سرویس کند |

**نکته:** هر چه rebuild طولانی‌تر، پنجرهٔ آسیب‌پذیری بزرگ‌تر. تعادل است.

### اشکال شایع

**۱. کشیدن دیسک اشتباه.**
بدون LED blink. فاجعه.

**۲. rebuild در RAID failed.**
داده را نابود می‌کند.

**۳. تعویض دو دیسک هم‌زمان.**
افزونگی صفر می‌شود.

**۴. نادیده گرفتن degraded.**
«کار می‌کند» — تا دیسک دوم.

**۵. دیسک یدکی کوچک‌تر.**
rebuild شکست می‌خورد.

**۶. دیسک یدکی متفاوت (SAS vs SATA).**
شناسایی نمی‌شود.

**۷. بدون backup در حین rebuild.**
اگر شکست بخورد، چیزی نداری.

**۸. نادیده گرفتن علت.**
دیسک بعدی هم می‌میرد (دما، بچ).

### نکات مهم (Tips & Tricks)

- **LED blink قبل از هر کشیدن.**
- **در degraded، backup فوری.**
- **در RAID failed، rebuild نکن.**
- **یک دیسک در هر زمان** تعویض کن.
- **SMART هفتگی.**
- **در آزمون:** کلیدواژهٔ «degraded array» → **replace failed disk, monitor rebuild**.

### خلاصه فصل

- وضعیت‌ها: **Optimal، Degraded، Rebuilding، Failed**.
- در **Degraded**، افزونگی صفر (RAID 5) یا کاهش‌یافته.
- **LED blink** قبل از کشیدن دیسک.
- **RAID failed → rebuild نکن.**
- **یک دیسک در هر زمان.**
- علت خرابی را پیدا کن (دما، بچ، firmware).

## فصل ۸۱: کنترلر، کابل و مسیر ذخیره‌سازی

### مقدمه

گاهی دیسک سالم است، اما سرور آن را نمی‌بیند. مشکل در **مسیر** است: کنترلر، کابل، backplane، یا تنظیمات.

این فصل دربارهٔ لایهٔ بین دیسک و OS است.

### مفاهیم اساسی

**مسیر ذخیره‌سازی:**

```
[دیسک] → [backplane] → [کابل SAS] → [کنترلر/HBA] → [PCIe] → [OS]
```

**هر حلقه می‌تواند مشکل داشته باشد.**

**علائم مشکلات کنترلر:**

| علامت | معنی |
|---|---|
| **همهٔ دیسک‌ها ناپدید** | کنترلر یا کابل |
| **یک کانال ناپدید** | کابل یا پورت |
| **خطای cache** | باتری/فلش کنترلر |
| **عملکرد پایین ناگهانی** | write-back به write-through |
| **BMC هشدار کنترلر** | سخت‌افزار |

**نکتهٔ حیاتی:** اگر **همهٔ** دیسک‌ها ناپدید شوند، احتمال کنترلر/کابل بیشتر از «همهٔ دیسک‌ها خراب شدند» است.

**باتری/فلش کنترلر (BBU/CacheVault):**

| علامت | معنی |
|---|---|
| **هشدار «battery failed»** | باتری تمام |
| **write policy = write-through** | عملکرد پایین |
| **تاریخ انقضا** | باتری ۳–۵ سال |

**نکته:** اگر باتری کنترلر تمام شود، کنترلر خودکار به **write-through** می‌رود. عملکرد نوشتن می‌تواند ۵–۱۰ برابر کاهش یابد. این یکی از دلایل رایج «سرور کند شد».

**کابل SAS/SATA:**

| نوع | توضیح |
|---|---|
| **SAS داخلی (SFF-8087/8643)** | backplane به کنترلر |
| **SAS خارجی (SFF-8088/8644)** | به JBOD |
| **SATA** | دیسک به backplane |

**نکته:** کابل SAS شکننده است — خم تند، پین شکسته. اگر کابل مشکوک است، **تعویض** ارزان‌تر از عیب‌یابی است.

**Backplane و expander:**

- **Backplane** — برد پشت بای‌ها.
- **Expander** — تقسیم یک پورت SAS به چند دستگاه.

**نکته:** expander می‌تواند گلوگاه شود. اگر ۲۴ دیسک روی یک expander با ۴ lane باشند، پهنای باند مشترک است.

**تنظیمات کنترلر — خطاهای رایج:**

| تنظیم | خطا | نتیجه |
|---|---|---|
| **RAID mode** | دیسک به‌عنوان JBOD دیده می‌شود | OS دیسک را نمی‌بیند |
| **JBOD/IT mode** | برای ZFS لازم، اما RAID نمی‌شود | بدون افزونگی |
| **Boot device** | کنترلر در boot order نیست | بوت از دیسک نمی‌شود |
| **Foreign config** | کنترلر تنظیمات قدیمی دارد | دیسک import نمی‌شود |

**نکتهٔ حیاتی:** **Foreign configuration** — وقتی کنترلر تعویض می‌شود یا دیسک از سرور دیگری می‌آید، کنترلر تنظیمات قدیمی را «خارجی» می‌بیند و import نمی‌کند. باید دستی **Import Foreign Configuration** کنی.

**چندمسیره (Multipath):**

| علامت | معنی |
|---|---|
| **LUN دو بار دیده می‌شود** | multipath غیرفعال |
| **یک مسیر failed** | کابل/HBA/سوئیچ |
| **I/O error در یک مسیر** | مسیر مشکل‌دار |

**ابزار:**

```bash
multipath -ll
# باید هر LUN چند مسیر active داشته باشد
```

**نکته:** بدون MPIO، قطع یک کابل = از دست رفتن LUN — حتی اگر مسیر دوم سالم باشد.

**iSCSI — مشکلات مسیر:**

| علامت | علت |
|---|---|
| **connection timed out** | شبکه، فایروال، پورت |
| **login failed** | CHAP، IQN، LUN masking |
| **LUN دیده نمی‌شود** | zoning/masking |
| **عملکرد پایین** | MTU mismatch، MPIO غیرفعال |

**نکته:** `iscsiadm -m session -P 3` جزئیات session را نشان می‌دهد.

### مثال‌های عملی

**Lab Scenario 1 — همهٔ دیسک‌ها ناپدید شدند**

> **وضعیت:** سرور روشن است، اما OS هیچ دیسکی نمی‌بیند. قبلاً ۸ دیسک داشت.
>
> **وظیفه:** ترتیب بررسی.
>
> **پاسخ:**
> ۱. **BMC:** آیا خطای کنترلر ثبت شده؟
> ۲. **LED دیسک‌ها:** آیا همه خاموش‌اند؟ (backplane برق ندارد)
> ۳. **کابل SAS:** آیا محکم است؟ (تعویض تست)
> ۴. **کنترلر:** آیا در BIOS/UEFI شناسایی می‌شود؟
> ۵. **Foreign config:** آیا کنترلر تنظیمات خارجی دارد؟
> ۶. **PCIe:** آیا کارت در اسلات درست است؟
>
> **درس:** «همهٔ دیسک‌ها خراب» تقریباً هرگز. مسیر را چک کن.

**Lab Scenario 2 — سرور بعد از تعویض کنترلر بوت نمی‌شود**

> **وضعیت:** کنترلر RAID تعویض شد. دیسک‌ها سالم‌اند اما سرور بوت نمی‌شود.
>
> **وظیفه:** علت.
>
> **پاسخ:**
> - **Foreign configuration:** کنترلر جدید، تنظیمات RAID را نمی‌شناسد.
> - **اقدام:** در BIOS کنترلر، `Import Foreign Configuration` را انتخاب کن.
> - **هشدار:** اگر `Clear Foreign Configuration` بزنی، **داده از دست می‌رود**.
>
> **درس:** Import، نه Clear.

### مقایسه و الگوهای مختلف

**مقایسهٔ RAID mode و JBOD:**

| معیار | RAID | JBOD/IT |
|---|---|---|
| افزونگی | ✅ | ❌ |
| دید OS | LUN | دیسک خام |
| مناسب | RAID سخت‌افزاری | ZFS، vSAN |

**مقایسهٔ BBU و CacheVault:**

| معیار | BBU (باتری) | CacheVault (خازن + فلش) |
|---|---|---|
| عمر | ۳–۵ سال | ۵–۷ سال |
| تعویض | ساده | متوسط |
| دما | حساس | مقاوم‌تر |

**مقایسهٔ SAS و SATA:**

| معیار | SAS | SATA |
|---|---|---|
| سرعت | ۱۲–۲۴ Gbps | ۶ Gbps |
| دوطرفه | ✅ | ❌ |
| قابلیت اعتماد | بالا | متوسط |
| هزینه | بالا | کم |

### اشکال شایع

**۱. Clear Foreign Config.**
داده از دست می‌رود. همیشه **Import**.

**۲. کابل SAS خم‌شده.**
خطای متناوب، سخت تشخیص.

**۳. کنترلر در boot order نیست.**
بوت از دیسک نمی‌شود.

**۴. باتری کنترلر تمام.**
عملکرد پایین، بدون هشدار واضح.

**۵. multipath غیرفعال.**
یک مسیر قطع = LUN گم.

**۶. expander اشباع.**
عملکرد پایین با دیسک زیاد.

**۷. iSCSI MTU mismatch.**
عملکرد بد.

**۸. تعویض کنترلر بدون backup تنظیمات.**
پیکربندی از دست می‌رود.

### نکات مهم (Tips & Tricks)

- **قبل از تعویض کنترلر، تنظیمات را export کن** (اگر ابزار دارد).
- **Foreign config را Import کن، نه Clear.**
- **باتری کنترلر را هر ۳–۵ سال عوض کن.**
- **`multipath -ll`** را بعد از هر تغییر SAN چک کن.
- **کابل مشکوک را تعویض کن**، نه عیب‌یابی.
- **در آزمون:** کلیدواژهٔ «disks not visible after controller replacement» → **foreign configuration**.

### خلاصه فصل

- مسیر: **دیسک → backplane → کابل → کنترلر → PCIe**.
- **همهٔ دیسک‌ها ناپدید** = مسیر، نه دیسک‌ها.
- **Foreign config → Import**، هرگز Clear.
- **باتری کنترلر** = write-back؛ تمام شدنش عملکرد را می‌کشد.
- **MPIO** برای افزونگی مسیر.
- **کابل SAS** شکننده است.

## فصل ۸۲: firmware و قطعات hot-swap

### مقدمه

firmware، لایهٔ نرم‌افزاری است که سخت‌افزار را می‌چرخاند. و بیشتر از آنچه فکر می‌کنی، منبع مشکلات است — چون کسی آن را آپدیت نمی‌کند.

این فصل دربارهٔ firmware و رویهٔ درست تعویض قطعه در حالت روشن است.

### مفاهیم اساسی

**لایه‌های firmware در سرور:**

| لایه | مثال |
|---|---|
| **BIOS/UEFI** | بوت، تنظیمات پایه |
| **BMC** | iDRAC، iLO، XCC |
| **RAID controller** | PERC، Smart Array |
| **NIC** | firmware کارت شبکه |
| **HBA** | FC/iSCSI |
| **Drive** | firmware دیسک |
| **Backplane/expander** | firmware expander |
| **PSU** | firmware (نادر) |

**نکتهٔ حیاتی:** هر لایه، **نسخهٔ سازگار** با بقیه لازم دارد. سازنده یک **compatibility matrix** منتشر می‌کند. نصب firmware خارج از آن، می‌تواند باعث از دست رفتن آرایه شود.

**علائم firmware مشکل‌دار:**

| علامت | مثال |
|---|---|
| **دیسک شناسایی نمی‌شود** | firmware دیسک ناسازگار |
| **عملکرد پایین** | باگ controller |
| **ری‌استارت تصادفی** | باگ BIOS |
| **آرایه ناپایدار** | firmware دیسک/کنترلر |
| **BMC قطع می‌شود** | باگ BMC |

**نکته:** اگر مشکلی **بعد از آپدیت** شروع شد، firmware اولین مظنون است.

**ترتیب آپدیت firmware:**

```
۱. BMC (برای دسترسی مطمئن)
۲. BIOS/UEFI
۳. RAID controller
۴. NIC/HBA
۵. Drive firmware
۶. Backplane/expander
```

**نکته:** بعضی سازندگان ترتیب متفاوتی توصیه می‌کنند. **همیشه release notes سازنده را چک کن.**

**قبل از آپدیت — چک‌لیست:**

```
□ backup کامل داده
□ export تنظیمات RAID/BIOS
□ نسخهٔ فعلی ثبت شده
□ compatibility matrix چک شده
□ release notes خوانده شده
□ پنجرهٔ تغییر تأیید شده
□ rollback plan (نسخهٔ قبلی در دسترس)
□ برق پایدار (UPS)
```

**نکتهٔ حیاتی:** **آپدیت firmware بدون برق پایدار، ریسک «brick» دارد.** اگر برق در حین آپدیت قطع شود، ممکن است دستگاه دیگر بوت نشود.

**Hot-swap — اصول:**

| قطعه | hot-swap؟ | شرط |
|---|---|---|
| **دیسک SAS/SATA** | ✅ | backplane پشتیبانی |
| **PSU** | ✅ | PSU دوم سالم |
| **فن** | ✅ | افزونگی فن |
| **NIC/HBA** | ⚠️ | فقط اگر PCIe hot-plug پشتیبانی شود (نادر) |
| **RAM** | ❌ | (مگر سرورهای خاص) |
| **CPU** | ❌ | — |
| **مادربرد** | ❌ | — |

**نکته:** «hot-swap» یعنی **بدون خاموشی سیستم**. اما همیشه بهتر است در پنجرهٔ تغییر باشد، مگر اضطراری.

**رویهٔ hot-swap دیسک:**

```
۱. تأیید دیسک درست (LED blink، ابزار کنترلر)
۲. بررسی وضعیت آرایه (degraded؟)
۳. باز کردن دسته (latch)
۴. کشیدن دیسک (آرام، بدون تکان)
۵. نصب دیسک جدید تا کلیک
۶. انتظار برای شناسایی (LED)
۷. Assign به آرایه (اگر خودکار نیست)
۸. پایش rebuild
```

**نکته:** بعضی backplaneها نیاز به **انتظار ۳۰ ثانیه** بین کشیدن و نصب دارند.

**رویهٔ hot-swap PSU:**

```
۱. تأیید PSU معیوب (LED، BMC)
۲. تأیید PSU دوم سالم و بار کافی
۳. جدا کردن کابل برق
۴. باز کردن دسته
۵. کشیدن PSU
۶. نصب PSU جدید
۷. وصل کابل
۸. تأیید LED و BMC
```

**نکتهٔ حیاتی:** هرگز **هر دو PSU** را هم‌زمان نکش. سرور خاموش می‌شود.

**Firmware rollback:**

| روش | توضیح |
|---|---|
| **نسخهٔ قبلی** | دانلود و نصب |
| **Backup image** | اگر BMC پشتیبانی کند |
| **Recovery mode** | بعضی دستگاه‌ها |

**نکته:** بعضی firmwareها **بدون rollback** هستند (فقط به جلو). این را **قبل** از آپدیت بدان.

### مثال‌های عملی

**Lab Scenario 1 — برنامهٔ آپدیت firmware**

> **وظیفه:** یک برنامهٔ سالانه برای ۲۰ سرور بنویس.
>
> **پاسخ:**
>
> | مرحله | اقدام |
> |---|---|
> | ۱ | فهرست نسخه‌های فعلی (BMC، BIOS، کنترلر، NIC، دیسک) |
> | ۲ | بررسی matrix سازنده |
> | ۳ | انتخاب ۱ سرور به‌عنوان pilot |
> | ۴ | backup + export تنظیمات |
> | ۵ | آپدیت pilot در پنجرهٔ تغییر |
> | ۶ | پایش ۱ هفته |
> | ۷ | آپدیت بقیه در گروه‌های ۵ تایی |
> | ۸ | مستندسازی نسخه‌ها |
>
> **درس:** firmware مثل patch OS است: pilot، پایش، گسترش.

**Lab Scenario 2 — آپدیت، آرایه را شکست**

> **وضعیت:** بعد از آپدیت firmware کنترلر، آرایه degraded شد.
>
> **وظیفه:** اقدام.
>
> **پاسخ:**
> ۱. **توقف:** آپدیت بقیه سرورها را متوقف کن.
> ۲. **بررسی:** کدام دیسک‌ها؟ (`storcli`)
> ۳. **علت:** firmware دیسک ناسازگار با کنترلر جدید.
> ۴. **Rollback:** اگر ممکن، firmware کنترلر را برگردان.
> ۵. **یا:** firmware دیسک را به نسخهٔ سازگار آپدیت.
> ۶. **گزارش به vendor.**
>
> **درس:** compatibility matrix، دقیقاً برای همین است.

### مقایسه و الگوهای مختلف

**مقایسهٔ آپدیت از OS و از BMC:**

| معیار | از OS | از BMC |
|---|---|---|
| نیاز به OS سالم | ✅ | ❌ |
| سرعت | بالا | متوسط |
| مناسب | سرور سالم | سرور مشکل‌دار |

**مقایسهٔ hot-swap و cold-swap:**

| معیار | Hot | Cold |
|---|---|---|
| قطعی سرویس | ❌ | ✅ |
| ریسک | متوسط | کم |
| نیاز به افزونگی | ✅ | ❌ |
| مناسب | تولیدی | آزمایشی |

**مقایسهٔ firmware و driver:**

| معیار | Firmware | Driver |
|---|---|---|
| محل | سخت‌افزار | OS |
| آپدیت | فلش | بسته |
| ریسک | بالا (brick) | کم (rollback) |
| نیاز به reboot | معمولاً | گاهی |

### اشکال شایع

**۱. آپدیت firmware بدون backup.**
اگر شکست بخورد، داده می‌رود.

**۲. نادیده گرفتن compatibility matrix.**
دیسک از آرایه خارج می‌شود.

**۳. آپدیت بدون برق پایدار.**
brick شدن دستگاه.

**۴. آپدیت همه سرورها هم‌زمان.**
اگر باگ داشته باشد، همه خراب می‌شوند.

**۵. کشیدن هر دو PSU.**
خاموشی.

**۶. hot-swap دیسک بدون LED blink.**
دیسک اشتباه.

**۷. نصب دیسک جدید بدون assign.**
آرایه rebuild نمی‌شود.

**۸. فرض rollback همیشه ممکن.**
بعضی firmware فقط به جلو می‌رود.

### نکات مهم (Tips & Tricks)

- **compatibility matrix** را قبل از هر آپدیت چک کن.
- **pilot اول.**
- **export تنظیمات** قبل از آپدیت.
- **UPS** برای آپدیت firmware.
- **LED blink** برای hot-swap.
- **در آزمون:** کلیدواژهٔ «disk not recognized after firmware update» → **compatibility matrix**.

### خلاصه فصل

- firmware در **همهٔ لایه‌ها**: BIOS، BMC، کنترلر، NIC، دیسک.
- **compatibility matrix** مرجع است.
- ترتیب: **BMC → BIOS → کنترلر → NIC → دیسک**.
- **backup + برق پایدار** قبل از آپدیت.
- **hot-swap**: دیسک، PSU، فن.
- **هرگز دو PSU هم‌زمان.**

## فصل ۸۳: خرابی محیطی و علائم فیزیکی

### مقدمه

بعضی خرابی‌ها از داخل سرور نمی‌آیند؛ از **اتاق** می‌آیند. گرما، رطوبت، گردوغبار، لرزش، نویز برق.

و این‌ها سخت‌ترین تشخیص‌ها هستند، چون **الگو دارند اما پیام خطا ندارند**.

### مفاهیم اساسی

**علائم خرابی محیطی:**

| علامت | علت احتمالی |
|---|---|
| **ری‌استارت در تابستان** | گرما |
| **خرابی زودرس دیسک** | گرما، لرزش |
| **خطای تصادفی حافظه** | گرما |
| **ESD (جرقه)** | رطوبت کم |
| **کندانس** | رطوبت بالا |
| **فن پرسرعت دائم** | دمای اتاق |
| **خاموشی هم‌زمان چند سرور** | برق، HVAC |
| **خطای شبکه در ساعت خاص** | EMI |

**نکتهٔ حیاتی:** **الگوی فصلی یا ساعتی** = محیطی. اگر خرابی «تصادفی» است اما در تیرماه بیشتر می‌شود، گرما است.

**دما — اثر بر قطعات:**

| قطعه | اثر گرما |
|---|---|
| **HDD** | عمر نصف به ازای هر ۵°C بالاتر از ۲۵ |
| **SSD** | throttle، عمر کمتر |
| **CPU** | throttle، خاموشی |
| **RAM** | خطای تصادفی |
| **باتری** | عمر کوتاه، تورم |
| **خازن** | خشک شدن، نشتی |

**نکته:** طبق مطالعات صنعتی (Google، Backblaze)، **دما مهم‌ترین عامل عمر دیسک** است. هر ۵–۷ درجه افزایش، نرخ خرابی را تقریباً دو برابر می‌کند.

**رطوبت:**

| سطح | اثر |
|---|---|
| **<۳۰٪** | ESD — جرقهٔ نامرئی که قطعه را می‌کشد |
| **۴۰–۶۰٪** | محدودهٔ امن |
| **>۷۰٪** | کندانس، خوردگی، اتصال کوتاه |

**نکته:** ESD می‌تواند قطعه را «نیمه‌خراب» کند — کار می‌کند اما ناپایدار. این سخت‌ترین نوع خرابی برای تشخیص است.

**گردوغبار:**

- **فن‌ها** را مسدود می‌کند → گرما.
- **هیت‌سینک** را می‌پوشاند → throttle.
- **کابل‌ها** را خورده می‌کند (در محیط صنعتی).
- **تماس‌ها** را اکسید می‌کند.

**نکته:** در محیط گردوغباری، **فیلتر** و **تمیزکاری دوره‌ای** ضروری است. یک فن مسدود، می‌تواند دمای CPU را ۲۰ درجه بالا ببرد.

**لرزش (Vibration):**

- **منبع:** فن، کولر، تراک، ریل، ساخت‌وساز.
- **اثر:** خرابی زودرس HDD (سر روی platter می‌پرد).
- **علامت:** خطای خواندن/نوشتن، صدای غیرعادی.

**نکته:** HDD به لرزش **بسیار** حساس است. در رک با فن‌های قوی، لرزش منتقل می‌شود.

**EMI (تداخل الکترومغناطیسی):**

| منبع | اثر |
|---|---|
| **کابل برق نزدیک شبکه** | packet loss |
| **موتور، آسانسور** | خطای شبکه |
| **ترانسفورماتور** | خطای داده |
| **تجهیزات بی‌سیم** | تداخل |

**نکته:** کابل شبکه **STP** (شیلددار) در محیط پرنویز. و فاصله از منبع.

**برق — مشکلات کیفیت:**

| مشکل | اثر |
|---|---|
| **افت ولتاژ (sag)** | ری‌استارت |
| **افزایش ولتاژ (surge)** | خرابی PSU |
| **نویز** | خطای داده |
| **قطعی کوتاه** | خاموشی |
| **فرکانس نامناسب** | موتور، فن |

**نکته:** **UPS آنلاین** (double-conversion) کیفیت برق را تضمین می‌کند، نه فقط قطعی را.

**علائم فیزیکی که باید ببینی:**

| علامت | معنی |
|---|---|
| **خازن بادکرده** | خرابی مادربرد/PSU |
| **لکهٔ قهوه‌ای روی برد** | حرارت موضعی |
| **بوی سوختگی** | خرابی جدی |
| **پلاستیک ذوب‌شده** | حرارت |
| **زنگ‌زدگی** | رطوبت |
| **گردوغبار ضخیم** | جریان هوای مسدود |
| **کابل تغییر رنگ داده** | حرارت |

**نکتهٔ حیاتی:** بازرسی بصری، **اولین قدم** در هر عیب‌یابی سخت‌افزاری است. خازن بادکرده را با چشم می‌بینی، با نرم‌افزار نه.

### مثال‌های عملی

**Lab Scenario 1 — خرابی فصلی**

> **وضعیت:** سه سال پیاپی، در تیرماه دو سرور ری‌استارت می‌شوند. بقیهٔ سال بی‌مشکل.
>
> **وظیفه:** تحلیل.
>
> **پاسخ:**
> ۱. **الگوی فصلی = دما.** کولر گازی در بار پیوستهٔ تابستان ناکارآمد.
> ۲. **بررسی:** BMC thermal log، دمای ورودی رک، دمای اتاق.
> ۳. **اقدام:** سرمایش اضافه، hot/cold aisle، بلانکینگ پنل، سنسور با هشدار.
> ۴. **پایش:** هشدار در ۲۷°C، نه ۳۵.
>
> **درس:** خرابی «تصادفی» با الگوی زمانی، محیطی است.

**Lab Scenario 2 — خرابی زودرس دیسک**

> **وضعیت:** در ۶ ماه، ۵ دیسک از ۱۲ دیسک یک رک خراب شده. دیسک‌ها نو بودند.
>
> **وظیفه:** پنج علت محیطی.
>
> **پاسخ:**
> ۱. **دما:** دمای ورودی رک بالا (فن مسدود، بلانکینگ نبود).
> ۲. **لرزش:** رک نزدیک تجهیزات لرزان.
> ۳. **بچ معیوب:** همه از یک تولید.
> ۴. **firmware ناسازگار:** کنترلر/دیسک.
> ۵. **برق ناپایدار:** PSU یا PDU.
>
> **درس:** «دیسک نو خراب شد» یعنی محیط یا بچ، نه عمر.

### مقایسه و الگوهای مختلف

**مقایسهٔ UPS آنلاین و line-interactive:**

| معیار | Online | Line-interactive |
|---|---|---|
| کیفیت خروجی | عالی | خوب |
| تنظیم ولتاژ | ✅ همیشه | ✅ در بازه |
| قیمت | بالا | متوسط |
| مناسب | مرکز داده | رک کوچک |

**مقایسهٔ فیلتر گردوغبار:**

| نوع | مزیت | عیب |
|---|---|---|
| **فیلتر رک** | ساده | نیاز به تعویض |
| **فیلتر اتاق** | جامع | هزینه |
| **بدون فیلتر** | — | گردوغبار |

**مقایسهٔ سنسور داخلی و خارجی:**

| معیار | داخلی (BMC) | خارجی (اتاق) |
|---|---|---|
| دقت قطعه | بالا | کم |
| دید اتاق | کم | بالا |
| مناسب | سلامت سرور | سلامت محیط |

**نکته:** هر دو لازم است — BMC دمای قطعه را می‌بیند، سنسور اتاق دمای محیط را.

### اشکال شایع

**۱. اندازه‌گیری دمای اتاق به‌جای ورودی رک.**
۵–۱۰ درجه اختلاف.

**۲. کولر گازی برای بار پیوسته.**
در تابستان کم می‌آورد.

**۳. بدون فیلتر گردوغبار.**
فن مسدود، گرما.

**۴. ESD بدون wrist strap.**
قطعه «نیمه‌خراب».

**۵. نادیده گرفتن لرزش.**
خرابی زودرس دیسک.

**۶. کابل برق و شبکه در یک مسیر.**
EMI، packet loss.

**۷. UPS بدون تست.**
باتری مرده، در قطعی کشف می‌شود.

**۸. بدون بازرسی بصری.**
خازن بادکرده دیده نمی‌شود.

### نکات مهم (Tips & Tricks)

- **الگوی فصلی/ساعتی = محیطی.**
- **دمای ورودی رک** را اندازه بگیر، نه اتاق.
- **بلانکینگ پنل** ارزان‌ترین بهبود.
- **فیلتر گردوغبار** و تمیزکاری سالانه.
- **بازرسی بصری** اولین قدم.
- **در آزمون:** کلیدواژهٔ «random reboots in summer» → **overheating**؛ «static discharge» → **low humidity**.

### خلاصه فصل

- علائم محیطی: **گرما، رطوبت، گردوغبار، لرزش، EMI، برق**.
- **الگوی فصلی** = محیطی.
- هر ۵–۷°C افزایش دما، نرخ خرابی دیسک را دو برابر می‌کند.
- رطوبت **۴۰–۶۰٪**؛ کمتر = ESD، بیشتر = کندانس.
- **بازرسی بصری** اولین ابزار.
- **UPS آنلاین** کیفیت برق را تضمین می‌کند.
