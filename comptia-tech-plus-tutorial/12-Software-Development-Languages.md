## فصل ۵۱: زبان‌های برنامه‌نویسی — تفسیری، کامپایلی، اسکریپتی

### مقدمه

کامپیوتر فقط ۰ و ۱ می‌فهمد. زبان برنامه‌نویسی، واسطه‌ای است بین فکر انسان و اجرای ماشین. اما این واسطه، به سه روش متفاوت کار می‌کند.

دامنهٔ «مفاهیم توسعهٔ نرم‌افزار» (۱۳٪) در Tech+ دقیقاً با همین شروع می‌شود.

### مفاهیم اساسی

**سه دستهٔ اصلی**

| دسته | مکانیزم | مثال |
|---|---|---|
| **Compiled** | ترجمهٔ کامل قبل از اجرا | C، C++، Go، Rust |
| **Interpreted** | ترجمه و اجرا خط‌به‌خط | Python، Ruby |
| **Scripting** | اجرا در محیط میزبان | JavaScript، Bash، PowerShell |

**نکته:** مرزها مطلق نیستند. Python هم به بایت‌کد کامپایل می‌شود، Java هم دو مرحله‌ای است.

**کامپایلر در برابر مفسر**

```
کامپایلر:
کد منبع ──▶ [کامپایلر] ──▶ فایل اجرایی ──▶ اجرا
(یک بار، کامل)              (سریع)

مفسر:
کد منبع ──▶ [مفسر] ──▶ اجرا (خط به خط)
(هر بار، تدریجی)         (کندتر)
```

| معیار | کامپایلری | تفسیری |
|---|---|---|
| سرعت اجرا | بالا | کمتر |
| سرعت توسعه | کندتر | سریع‌تر |
| خطا | قبل از اجرا | هنگام اجرا |
| توزیع | فایل اجرایی | نیاز به مفسر |
| پورتالیتی | نیاز به کامپایل مجدد | معمولاً قابل حمل |

**Bytecode — راه میانه**

```
کد منبع → کامپایل به bytecode → اجرا در VM
```

Java (JVM) و C# (.NET CLR) از این مدل استفاده می‌کنند: یک بار کامپایل، اجرا روی هر پلتفرمی که VM دارد.

**زبان‌های سطح بالا و پایین**

| سطح | مثال | کنترل |
|---|---|---|
| **Low-level** | Assembly | مستقیم روی سخت‌افزار |
| **Mid-level** | C | نزدیک به سخت‌افزار |
| **High-level** | Python، Java | انتزاع بالا |

**Assembly — زبان اسمبلی**

```
MOV AX, 1
ADD AX, 2
```

هر دستور، معادل یک دستور ماشین. سریع، ولی سخت و وابسته به معماری.

**زبان‌های اسکریپتی**

| زبان | محیط |
|---|---|
| JavaScript | مرورگر، Node.js |
| Bash | شل لینوکس |
| PowerShell | ویندوز |
| Python | عمومی (اغلب اسکریپتی) |

**ویژگی:** بدون کامپایل جدا، اجرا در محیط موجود.

**پارادایم‌ها**

| پارادایم | توضیح | مثال |
|---|---|---|
| **Procedural** | تابع و رویه | C |
| **Object-Oriented** | شیء و کلاس | Java، C# |
| **Functional** | تابع خالص | Haskell، Elixir |
| **Declarative** | «چه»، نه «چطور» | SQL |

**زبان‌های محبوب و کاربرد**

| زبان | کاربرد اصلی |
|---|---|
| Python | داده، AI، اسکریپت |
| JavaScript | وب (فرانت و بک) |
| Java | سازمانی، اندروید |
| C# | ویندوز، بازی (Unity) |
| C/C++ | سیستم، بازی، نهفته |
| Go | سرویس شبکه |
| Rust | سیستم، ایمنی حافظه |
| SQL | پایگاه داده |
| Swift/Kotlin | موبایل |

**مدیریت حافظه**

| مدل | توضیح | مثال |
|---|---|---|
| **Manual** | برنامه‌نویس آزاد می‌کند | C، C++ |
| **Garbage Collection** | خودکار | Java، Python، C# |
| **Ownership** | قواعد کامپایلر | Rust |

**خطاهای رایج حافظه**

| خطا | معنی |
|---|---|
| **Memory leak** | آزاد نشدن حافظه |
| **Buffer overflow** | نوشتن بیرون محدوده |
| **Use after free** | استفاده پس از آزادسازی |

این‌ها منبع بسیاری از حفره‌های امنیتی‌اند — به همین دلیل Rust محبوب شده.

### مثال‌های عملی

**سناریوی Lab: همان برنامه، سه زبان**

**کار: جمع دو عدد و چاپ**

**Python (تفسیری):**

```python
a = 5
b = 3
print(a + b)
```

**C (کامپایلری):**

```c
#include <stdio.h>

int main(void) {
    int a = 5, b = 3;
    printf("%d\n", a + b);
    return 0;
}
```

**Bash (اسکریپتی):**

```bash
a=5
b=3
echo $((a + b))
```

| زبان | خط | کامپایل | اجرا |
|---|---|---|---|
| Python | ۳ | خیر | مفسر |
| C | ۸ | بله | مستقیم |
| Bash | ۳ | خیر | شل |

**درس:** زبان‌های سطح بالا، کد کمتر و خواناتر می‌دهند؛ زبان‌های سطح پایین، کنترل بیشتر.

**سناریوی دوم: کامپایل در برابر تفسیر**

```bash
# C: کامپایل و اجرا
gcc hello.c -o hello
./hello

# Python: اجرا با مفسر
python hello.py

# Java: کامپایل به bytecode، اجرا در JVM
javac Hello.java
java Hello
```

**سناریوی سوم: تشخیص دسته**

| کد | دسته |
|---|---|
| `.py` | تفسیری |
| `.c` | کامپایلری |
| `.js` | اسکریپتی |
| `.java` | bytecode |
| `.sh` | اسکریپتی |

### مقایسه و الگوهای مختلف

**سه معیار انتخاب زبان**

| معیار | سؤال |
|---|---|
| کاربرد | وب؟ داده؟ سیستم؟ |
| تیم | چه زبانی می‌داند؟ |
| بوم | کتابخانه و ابزار |

**الگوی «زبان مناسب، نه زبان محبوب»**

JavaScript برای تحلیل دادهٔ سنگین انتخاب بدی است. Python برای درایور سخت‌افزار هم.

### اشکال شایع

**۱) «کامپایلری همیشه سریع‌تر است»**
در عمل، به الگوریتم و کتابخانه هم بستگی دارد.

**۲) «Python تفسیری است، پس کند است»**
برای ۹۰٪ کارها کافی است؛ گلوگاه معمولاً I/O است.

**۳) قاطی کردن HTML با زبان برنامه‌نویسی**
HTML زبان نشانه‌گذاری است، نه برنامه‌نویسی.

**۴) فرض «Java = JavaScript»**
دو زبان کاملاً متفاوت.

**۵) نادیده گرفتن مدیریت حافظه**
منبع حفره‌های امنیتی.

**۶) انتخاب بر اساس مد**
نیاز را بسنج.

**۷) نادیده گرفتن اکوسیستم**
کتابخانه، مهم‌تر از سینتکس.

**۸) یادگیری همزمان چند زبان**
پراکندگی. یکی را عمیق یاد بگیر.

### نکات مهم (Tips & Tricks)

- **سه دسته** را با مثال حفظ کن.
- **کامپایلری سریع، تفسیری انعطاف‌پذیر.**
- **Bytecode راه میانه.**
- **Assembly نزدیک به سخت‌افزار.**
- **مدیریت حافظه را بشناس.**
- **Java ≠ JavaScript.**
- **اکوسیستم مهم‌تر از سینتکس.**

### خلاصه فصل

- سه دسته: کامپایلری، تفسیری، اسکریپتی.
- کامپایلر یک‌بار ترجمه می‌کند؛ مفسر خط‌به‌خط.
- Bytecode راه میانه (Java، C#).
- چهار پارادایم: procedural، OOP، functional، declarative.
- مدیریت حافظه سه مدل دارد.
- انتخاب زبان با کاربرد و اکوسیستم.

## فصل ۵۲: زبان‌های نشانه‌گذاری و قالب داده

### مقدمه

چهار فرمت وجود دارد که همه‌جا می‌بینی: HTML، XML، JSON، YAML. هیچ‌کدام «زبان برنامه‌نویسی» نیستند، ولی همهٔ برنامه‌ها از آن‌ها استفاده می‌کنند.

### مفاهیم اساسی

**نشانه‌گذاری در برابر برنامه‌نویسی**

| نوع | کار | منطق |
|---|---|---|
| **Markup** | توصیف ساختار | ندارد |
| **Programming** | اجرای منطق | دارد |

**HTML — ساختار وب**

```html
<!DOCTYPE html>
<html>
  <head>
    <title>صفحهٔ من</title>
  </head>
  <body>
    <h1>سلام</h1>
    <p>این یک پاراگراف است.</p>
  </body>
</html>
```

| عنصر | کار |
|---|---|
| `<html>` | ریشه |
| `<head>` | فراداده |
| `<body>` | محتوای مرئی |
| `<h1>` | عنوان |
| `<p>` | پاراگراف |
| `<a href>` | لینک |

**نکته:** HTML **زبان برنامه‌نویسی نیست**. منطق ندارد. اما با CSS و JavaScript، یک صفحهٔ کامل می‌سازد.

**CSS — ظاهر**

```css
body {
  font-family: sans-serif;
  background: #f5f5f5;
}
h1 { color: #2c3e50; }
```

**XML — داده با تگ**

```xml
<book>
  <title>آموزش Tech+</title>
  <author>علی رضایی</author>
  <year>2026</year>
</book>
```

| مزیت | عیب |
|---|---|
| ساختار سخت‌گیر | حجم زیاد |
| قابل اعتبارسنجی (Schema) | سخت‌خوان برای انسان |
| گسترش‌پذیر | پردازش کندتر |

**JSON — داده سبک**

```json
{
  "title": "آموزش Tech+",
  "author": "علی رضایی",
  "year": 2026,
  "tags": ["IT", "certification"]
}
```

| نوع | مثال |
|---|---|
| Object | `{ "key": value }` |
| Array | `[1, 2, 3]` |
| String | `"text"` |
| Number | `42` |
| Boolean | `true` |
| Null | `null` |

**نکته:** JSON استاندارد APIهای وب است. سبک، خوانا، قابل پارس در همهٔ زبان‌ها.

**YAML — خوانا برای انسان**

```yaml
book:
  title: آموزش Tech+
  author: علی رضایی
  year: 2026
  tags:
    - IT
    - certification
```

| مزیت | عیب |
|---|---|
| خوانایی بالا | حساس به فاصله |
| کامنت دارد | ابهام در بعضی موارد |

**کاربرد YAML:** Docker Compose، Kubernetes، CI/CD، تنظیمات.

**جدول مقایسه**

| معیار | HTML | XML | JSON | YAML |
|---|---|---|---|---|
| هدف | نمایش | داده | داده | تنظیمات |
| خوانایی انسان | متوسط | کم | خوب | عالی |
| حجم | زیاد | زیاد | کم | کم |
| کامنت | ✅ | ✅ | ❌ | ✅ |
| Schema | — | ✅ | ⚠️ | ⚠️ |

**CSV — ساده‌ترین**

```csv
name,age,city
Ali,30,Tehran
Sara,25,Shiraz
```

| مزیت | عیب |
|---|---|
| همه‌جا پشتیبانی | بدون نوع داده |
| سبک | مشکل با کاما در متن |

**Markdown — متن ساده با قالب**

```markdown
# عنوان
**پررنگ** و *مورب*
- آیتم
```

**کاربرد:** مستندات، README، ویکی.

### مثال‌های عملی

**سناریوی Lab: همان داده، چهار فرمت**

**داده:** یک کتاب با عنوان، نویسنده، سال، برچسب‌ها.

**XML:**
```xml
<book>
  <title>Tech+</title>
  <author>Ali</author>
  <year>2026</year>
  <tags><tag>IT</tag><tag>cert</tag></tags>
</book>
```

**JSON:**
```json
{"title":"Tech+","author":"Ali","year":2026,"tags":["IT","cert"]}
```

**YAML:**
```yaml
title: Tech+
author: Ali
year: 2026
tags: [IT, cert]
```

**CSV:**
```csv
title,author,year,tags
Tech+,Ali,2026,"IT;cert"
```

**مقایسهٔ حجم:**

| فرمت | حجم تقریبی |
|---|---|
| XML | ۱۴۰ بایت |
| JSON | ۶۰ بایت |
| YAML | ۵۵ بایت |
| CSV | ۴۵ بایت |

**درس:** JSON/YAML برای API و تنظیمات؛ XML برای سازگاری با سیستم‌های قدیمی.

**سناریوی دوم: خواندن JSON**

```python
import json

data = '{"name": "Ali", "age": 30, "tags": ["a", "b"]}'
obj = json.loads(data)

print(obj["name"])      # Ali
print(obj["tags"][0])   # a
```

**سناریوی سوم: خطای رایج YAML**

```yaml
# ❌ بد — فاصلهٔ نادرست
server:
port: 8080

# ✅ خوب
server:
  port: 8080
```

**نکته:** YAML به تودرتویی حساس است. یک فاصلهٔ اضافه، خطا می‌دهد.

### مقایسه و الگوهای مختلف

**سه کاربرد**

| کاربرد | فرمت پیشنهادی |
|---|---|
| API | JSON |
| تنظیمات | YAML |
| سند | Markdown |
| دادهٔ جدولی | CSV |
| سازگاری قدیمی | XML |

**الگوی «JSON برای ماشین، YAML برای انسان»**

API با JSON (سریع، استاندارد). فایل تنظیمات با YAML (خوانا، کامنت‌دار).

### اشکال شایع

**۱) «HTML زبان برنامه‌نویسی است»**
نیست. نشانه‌گذاری است.

**۲) JSON با کامنت**
پشتیبانی نمی‌شود. YAML.

**۳) YAML با tab**
فقط فاصله. tab خطا می‌دهد.

**۴) CSV با کاما در متن**
کوتیشن بگذار یا فرمت دیگر.

**۵) XML برای API جدید**
JSON سبک‌تر و رایج‌تر است.

**۶) نادیده گرفتن Schema**
دادهٔ نامعتبر وارد می‌شود.

**۷) فایل تنظیمات بدون نسخه‌بندی**
تغییرات گم می‌شوند.

**۸) Markdown بدون پیش‌نمایش**
قالب‌بندی اشتباه.

### نکات مهم (Tips & Tricks)

- **HTML نمایش، XML/JSON داده.**
- **JSON استاندارد API.**
- **YAML برای تنظیمات.**
- **YAML با فاصله، نه tab.**
- **CSV برای جدول ساده.**
- **Markdown برای مستندات.**
- **Schema را جدی بگیر.**

### خلاصه فصل

- HTML نشانه‌گذاری نمایش است، نه برنامه‌نویسی.
- XML داده با تگ، قابل اعتبارسنجی.
- JSON سبک و استاندارد API.
- YAML خوانا برای تنظیمات.
- CSV ساده‌ترین دادهٔ جدولی.
- Markdown برای مستندات.

## فصل ۵۳: انواع داده — char، string، عدد، boolean

### مقدمه

هر برنامه، داده را ذخیره و پردازش می‌کند. اما «داده» یک چیز نیست: عدد، متن، درست/غلط. انتخاب نوع درست، از باگ‌های عجیب جلوگیری می‌کند.

### مفاهیم اساسی

**پنج نوع پایه**

| نوع | توضیح | مثال |
|---|---|---|
| **char** | یک کاراکتر | `'A'` |
| **string** | رشتهٔ کاراکتر | `"Hello"` |
| **integer** | عدد صحیح | `42` |
| **float** | عدد اعشاری | `3.14` |
| **boolean** | درست/غلط | `true` |

**char در برابر string**

| نوع | حجم | مثال |
|---|---|---|
| char | یک کاراکتر | `'A'` |
| string | چند کاراکتر | `"Ali"` |

**نکته:** در بعضی زبان‌ها (Python، JavaScript) `char` جدا نداریم؛ رشتهٔ یک‌حرفی استفاده می‌شود.

**عدد صحیح — محدوده**

| نوع | بیت | محدوده |
|---|---|---|
| byte | ۸ | −۱۲۸ تا ۱۲۷ |
| short | ۱۶ | −۳۲٬۷۶۸ تا ۳۲٬۷۶۷ |
| int | ۳۲ | ~±۲.۱ میلیارد |
| long | ۶۴ | ~±۹.۲ کوینتیلیون |

**سرریز (Overflow)**

```python
# مفهوم — در Python خودکار مدیریت می‌شود
# در C:
int x = 2147483647;
x = x + 1;   # → -2147483648  (سرریز)
```

**درس:** انتخاب نوع کوچک، می‌تواند به سرریز منجر شود — و سرریز، منبع حفره‌های امنیتی است.

**float — تلهٔ دقت**

```python
0.1 + 0.2 == 0.3     # False!
0.1 + 0.2            # 0.30000000000000004
```

**چرا؟** اعداد اعشاری در باینری دقیق ذخیره نمی‌شوند.

| راه‌حل | کاربرد |
|---|---|
| `decimal` (Python) | پول |
| عدد صحیح (سنت) | پول |
| `round()` | نمایش |

**قاعدهٔ طلایی پول:** هرگز float برای پول استفاده نکن.

**string — عملیات رایج**

| عملیات | مثال |
|---|---|
| اتصال | `"Ali" + " " + "Rezaei"` |
| طول | `len("Ali")` → ۳ |
| برش | `"Hello"[0:2]` → `"He"` |
| جستجو | `"Hello".find("l")` |
| تبدیل | `"42"` → `42` |

**string immutable است**

در Python و Java، رشته تغییرناپذیر است:

```python
s = "abc"
s[0] = "x"      # خطا
s = "x" + s[1:] # راه درست
```

**boolean — منطق**

| عملگر | معنی |
|---|---|
| `and` | و |
| `or` | یا |
| `not` | نقیض |

```python
is_adult = age >= 18
has_permission = is_admin or is_owner
```

**تبدیل نوع (Type Casting)**

| تبدیل | مثال | خطر |
|---|---|---|
| string → int | `int("42")` | خطا اگر غیرعددی |
| int → string | `str(42)` | — |
| float → int | `int(3.9)` | **برش**، نه گرد کردن |
| int → float | `float(42)` | — |

**نکته:** `int(3.9)` = ۳، نه ۴. برای گرد کردن، `round()`.

**null / None**

| زبان | نماد |
|---|---|
| Python | `None` |
| JavaScript | `null`، `undefined` |
| Java | `null` |
| SQL | `NULL` |

**خطر:** دسترسی به `null`، رایج‌ترین خطای زمان اجراست.

**نوع‌های مرکب**

| نوع | توضیح |
|---|---|
| **Array/List** | لیست مرتب |
| **Dictionary/Map** | کلید-مقدار |
| **Set** | مجموعهٔ یکتا |
| **Tuple** | لیست تغییرناپذیر |

### مثال‌های عملی

**سناریوی Lab: باگ‌های نوع داده**

**باگ ۱ — مقایسهٔ رشته و عدد**

```python
age = input("سن: ")      # "18" (رشته)
if age > 18:             # TypeError در Python 3
    ...
```

**راه‌حل:** `age = int(input(...))`.

**باگ ۲ — سرریز**

```c
short total = 32000;
total = total + 1000;    // -32536 (سرریز)
```

**راه‌حل:** نوع بزرگ‌تر یا بررسی محدوده.

**باگ ۳ — پول با float**

```python
price = 19.99
tax = price * 0.09
total = price + tax
print(total)     # 21.7891 (نه دقیق)
```

**راه‌حل:**

```python
from decimal import Decimal
price = Decimal("19.99")
tax = price * Decimal("0.09")
total = price + tax      # دقیق
```

**باگ ۴ — رشتهٔ خالی**

```python
name = ""
if name:              # False
    print("سلام")
```

**درس:** رشتهٔ خالی در شرط، `False` است.

**سناریوی دوم: انتخاب نوع**

| داده | نوع |
|---|---|
| سن | integer |
| قیمت | decimal یا integer (سنت) |
| نام | string |
| فعال/غیرفعال | boolean |
| تاریخ | date/datetime (نه string) |
| کد ملی | string (نه int) |

**نکته:** کد ملی را عدد نگیر — صفر ابتدایی و طول ثابت مهم است.

### مقایسه و الگوهای مختلف

**سه دستهٔ نوع**

| دسته | مثال | ویژگی |
|---|---|---|
| **Primitive** | int، char، boolean | ساده |
| **Composite** | array، object | ترکیبی |
| **Abstract** | date، money | معنایی |

**الگوی «نوع دقیق، نه راحت»**

استفاده از `string` برای همه‌چیز، راحت است ولی باگ‌ساز. نوع دقیق انتخاب کن.

### اشکال شایع

**۱) float برای پول**
خطای دقت. Decimal.

**۲) int برای کد ملی/شماره تلفن**
صفر ابتدایی گم می‌شود. string.

**۳) `int()` روی ورودی نامعتبر**
خطا. اعتبارسنجی.

**۴) مقایسهٔ `==` و `=`**
انتساب با مقایسه فرق دارد.

**۵) نادیده گرفتن null**
خطای زمان اجرا.

**۶) سرریز عددی**
نوع بزرگ‌تر.

**۷) string برای تاریخ**
مقایسه و محاسبه سخت. date.

**۸) boolean با رشته**
`"false"` در شرط، True است!

### نکات مهم (Tips & Tricks)

- **پنج نوع پایه** را حفظ کن.
- **float برای پول ممنوع.**
- **کد ملی/تلفن = string.**
- **`int()` برش می‌دهد، `round()` گرد.**
- **null را چک کن.**
- **نوع دقیق انتخاب کن.**
- **`"false"` در شرط True است.**

### خلاصه فصل

- پنج نوع پایه: char، string، integer، float، boolean.
- float دقت اعشاری ندارد؛ برای پول Decimal.
- string تغییرناپذیر است.
- تبدیل نوع می‌تواند خطا بدهد.
- null رایج‌ترین منبع خطاست.
- انتخاب نوع دقیق، باگ را کم می‌کند.

## فصل ۵۴: متغیر، ثابت، آرایه، تابع، شیء

### مقدمه

پنج مفهوم پایه وجود دارد که در همهٔ زبان‌ها تکرار می‌شوند. اگر این‌ها را بفهمی، خواندن کد هر زبانی آسان‌تر می‌شود.

### مفاهیم اساسی

**متغیر (Variable)**

ظرفی برای ذخیرهٔ مقدار که می‌تواند تغییر کند.

```python
count = 0
count = count + 1     # 1
```

| مفهوم | معنی |
|---|---|
| **Declaration** | اعلام وجود |
| **Initialization** | مقدار اولیه |
| **Assignment** | انتساب |
| **Scope** | محدودهٔ دسترسی |

**ثابت (Constant)**

مقداری که تغییر نمی‌کند.

```python
PI = 3.14159           # قرارداد: حروف بزرگ
MAX_RETRIES = 3
```

| زبان | روش |
|---|---|
| Python | قرارداد (اجباری نیست) |
| Java | `final` |
| C# | `const` / `readonly` |
| JavaScript | `const` |

**چرا ثابت؟** جلوگیری از تغییر ناخواسته و خوانایی.

**آرایه (Array)**

مجموعه‌ای از مقادیر هم‌نوع با اندیس.

```python
scores = [90, 85, 77, 92]
print(scores[0])      # 90
print(len(scores))    # 4
```

**نکته:** اندیس از **صفر** شروع می‌شود.

| مفهوم | معنی |
|---|---|
| **Index** | موقعیت |
| **Length** | تعداد |
| **Iteration** | پیمایش |

**آرایه در برابر لیست**

| نوع | اندازه | نوع عناصر |
|---|---|---|
| Array | ثابت (معمولاً) | هم‌نوع |
| List | پویا | هر نوع |

**تابع (Function)**

بلوک کد با نام که یک کار انجام می‌دهد.

```python
def calculate_tax(price, rate=0.09):
    """محاسبهٔ مالیات."""
    return price * rate

tax = calculate_tax(100)
```

| جزء | معنی |
|---|---|
| **Parameter** | ورودی تعریف |
| **Argument** | مقدار ارسالی |
| **Return** | خروجی |
| **Side effect** | تغییر خارج از تابع |

**چرا تابع؟**

| مزیت | توضیح |
|---|---|
| تکرارنشدن | DRY |
| تست‌پذیری | جدا |
| خوانایی | نام گویا |
| نگه‌داری | یک جا |

**شیء (Object)**

مجموعه‌ای از داده و رفتار.

```python
class Car:
    def __init__(self, brand, year):
        self.brand = brand
        self.year = year

    def age(self, current_year):
        return current_year - self.year

my_car = Car("Toyota", 2020)
print(my_car.age(2026))    # 6
```

| مفهوم | معنی |
|---|---|
| **Class** | قالب |
| **Object/Instance** | نمونه |
| **Attribute** | داده |
| **Method** | رفتار |
| **Constructor** | سازنده |

**چهار اصل OOP**

| اصل | معنی |
|---|---|
| **Encapsulation** | پنهان‌سازی داخلی |
| **Inheritance** | ارث‌بری |
| **Polymorphism** | چندشکلی |
| **Abstraction** | انتزاع |

**وراثت — مثال**

```python
class Vehicle:
    def move(self):
        return "moving"

class Car(Vehicle):
    def honk(self):
        return "beep"

c = Car()
print(c.move())    # از والد
print(c.honk())    # از خودش
```

**Scope — محدودهٔ متغیر**

| نوع | دسترسی |
|---|---|
| **Local** | داخل تابع |
| **Global** | کل برنامه |
| **Block** | داخل بلوک (let/const) |

**نکته:** متغیر global، منبع باگ است. کم استفاده کن.

### مثال‌های عملی

**سناریوی Lab: محاسبهٔ فاکتور**

```python
TAX_RATE = 0.09              # ثابت
DISCOUNT_THRESHOLD = 1000    # ثابت


def calculate_total(items):
    """items: لیستی از (نام، قیمت، تعداد)"""
    subtotal = 0
    for name, price, qty in items:
        subtotal += price * qty

    discount = subtotal * 0.1 if subtotal > DISCOUNT_THRESHOLD else 0
    tax = (subtotal - discount) * TAX_RATE
    return {
        "subtotal": round(subtotal, 2),
        "discount": round(discount, 2),
        "tax": round(tax, 2),
        "total": round(subtotal - discount + tax, 2),
    }


items = [("کتاب", 250, 2), ("قلم", 20, 5)]
print(calculate_total(items))
```

**تحلیل:**

| مفهوم | کجا |
|---|---|
| ثابت | `TAX_RATE` |
| تابع | `calculate_total` |
| پارامتر | `items` |
| آرایه/لیست | `items` |
| حلقه | `for` |
| شرط | `if` |

**سناریوی دوم: شیء در برابر دیکشنری**

```python
# دیکشنری — ساده
car = {"brand": "Toyota", "year": 2020}

# شیء — با رفتار
class Car:
    def __init__(self, brand, year):
        self.brand = brand
        self.year = year

    def age(self, now):
        return now - self.year
```

| معیار | دیکشنری | شیء |
|---|---|---|
| سادگی | ✅ | ❌ |
| رفتار | ❌ | ✅ |
| اعتبارسنجی | ❌ | ✅ |
| مناسب | دادهٔ ساده | منطق |

**سناریوی سوم: تابع با اثر جانبی**

```python
# ❌ اثر جانبی پنهان
total = 0
def add(price):
    global total
    total += price

# ✅ خالص
def add(total, price):
    return total + price
```

**درس:** تابع خالص، تست‌پذیرتر است.

### مقایسه و الگوهای مختلف

**سه سبک کد**

| سبک | ساختار | مناسب |
|---|---|---|
| Procedural | تابع‌ها | اسکریپت |
| OOP | کلاس‌ها | برنامهٔ بزرگ |
| Functional | توابع خالص | داده، پردازش |

**الگوی «تابع کوچک»**

تابعی که بیش از ۲۰ خط است، احتمالاً چند کار می‌کند. بشکن.

### اشکال شایع

**۱) اندیس از یک**
از صفر شروع می‌شود. `arr[0]`.

**۲) متغیر global**
باگ و وابستگی پنهان.

**۳) تابع با ۱۰ پارامتر**
خوانایی کم. شیء یا dict.

**۴) نام متغیر مبهم**
`x`, `data`, `temp`. نام گویا.

**۵) تغییر آرایه در حین پیمایش**
پرش یا خطا.

**۶) وراثت بیش از حد**
سلسله‌مراتب پیچیده. ترکیب بهتر است.

**۷) کپی سطحی آرایه**
تغییر یکی، دیگری را عوض می‌کند.

**۸) فراموش کردن return**
تابع `None` برمی‌گرداند.

### نکات مهم (Tips & Tricks)

- **اندیس از صفر.**
- **ثابت با حروف بزرگ.**
- **تابع کوچک و خالص.**
- **نام گویا.**
- **global کم.**
- **شیء برای رفتار، dict برای داده.**
- **ترکیب بهتر از وراثت عمیق.**

### خلاصه فصل

- متغیر تغییر می‌کند، ثابت نه.
- آرایه با اندیس صفر.
- تابع، بلوک قابل استفادهٔ مجدد.
- شیء، داده + رفتار.
- چهار اصل OOP: encapsulation، inheritance، polymorphism، abstraction.
- تابع خالص، تست‌پذیرتر است.
