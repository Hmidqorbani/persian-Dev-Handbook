<a name="ch-74"></a>
## فصل ۷۴: امنیت دستگاه — وصله، آنتی‌ویروس، فایروال محلی

### مقدمه

امنیت شبکه، لایهٔ بیرونی است. اگر دستگاه آلوده شود، هیچ فایروالی نجاتش نمی‌دهد. این فصل، سه ستون امنیت دستگاه را می‌سازد.

### مفاهیم اساسی

**سه ستون**

| ستون | کار |
|---|---|
| **Patching** | بستن حفره‌های شناخته‌شده |
| **Anti-malware** | شناسایی بدافزار |
| **Host firewall** | محدود کردن ارتباط |

**وصله (Patch)**

| نوع | توضیح |
|---|---|
| **Security patch** | بستن حفره — فوری |
| **Feature update** | قابلیت جدید |
| **Hotfix** | رفع فوری یک باگ |

**چرخهٔ وصله**

```
شناسایی → تست → استقرار → تأیید
```

**نکته:** وصلهٔ بدون تست، می‌تواند سیستم را بخواباند. در سازمان، ابتدا روی گروه کوچک تست کن.

**پنجرهٔ آسیب‌پذیری**

```
انتشار حفره → انتشار وصله → نصب وصله
              ↑
        پنجرهٔ آسیب‌پذیری
```

هرچه این پنجره کوتاه‌تر، بهتر.

**آنتی‌ویروس مدرن (EDR)**

| نسل | روش |
|---|---|
| سنتی | امضا |
| نسل بعد | heuristic |
| **EDR** | رفتار + پاسخ |

**EDR** = Endpoint Detection and Response: نه فقط تشخیص، بلکه پاسخ (ایزوله کردن، کشتن فرآیند).

**فایروال محلی**

| سیستم | ابزار |
|---|---|
| ویندوز | Windows Defender Firewall |
| macOS | Application Firewall |
| لینوکس | ufw، firewalld |

**قاعدهٔ پایه:** ورودی پیش‌فرض DENY، استثناهای مشخص.

**Application Allowlisting**

فقط برنامه‌های تأییدشده اجرا می‌شوند.

| مزیت | عیب |
|---|---|
| مقاوم به بدافزار ناشناس | مدیریت |
| کنترل کامل | انعطاف کم |

**Full Disk Encryption**

رمزنگاری کل دیسک (فصل ۷۷).

**حساب کاربری استاندارد**

| نوع | دسترسی |
|---|---|
| Administrator | کامل |
| Standard | محدود |

**قاعده:** کار روزمره با حساب استاندارد، ادمین فقط برای نصب.

**UAC در ویندوز**

درخواست تأیید برای عملیات حساس. مانع از تغییر ناخواسته می‌شود.

### مثال‌های عملی

**سناریوی Lab: سخت‌سازی یک لپ‌تاپ کاری**

```markdown
- [ ] آپدیت خودکار سیستم‌عامل فعال
- [ ] آپدیت خودکار نرم‌افزارها
- [ ] آنتی‌ویروس/EDR فعال و به‌روز
- [ ] فایروال فعال، ورودی DENY
- [ ] رمزنگاری کل دیسک (BitLocker/FileVault)
- [ ] حساب روزمره Standard
- [ ] قفل خودکار بعد از ۵ دقیقه
- [ ] رمز BIOS/UEFI
- [ ] بوت از USB غیرفعال (اگر لازم نیست)
- [ ] پشتیبان خودکار
```

**سناریوی دوم: اولویت وصله**

| سیستم | SLA وصلهٔ بحرانی |
|---|---|
| سرور اینترنتی | ۲۴ ساعت |
| لپ‌تاپ کاری | ۷۲ ساعت |
| سیستم آزمایشی | ۳۰ روز |

**سناریوی سوم: تست نصب نرم‌افزار**

```
کاربر: "این برنامه را لازم دارم."
بررسی:
۱. منبع رسمی است؟
۲. امضای دیجیتال دارد؟
۳. مجوز لازم دارد؟
۴. جایگزین تأییدشده دارد؟
۵. در allowlist هست؟
```

### مقایسه و الگوهای مختلف

**سه سطح سخت‌سازی**

| سطح | اقدامات |
|---|---|
| پایه | وصله + آنتی‌ویروس + فایروال |
| متوسط | + رمزنگاری + allowlist |
| بالا | + EDR + SIEM + MDM |

**الگوی «پایهٔ امن»**

یک تصویر (image) استاندارد بساز که همهٔ تنظیمات امن را داشته باشد. دستگاه جدید از آن نصب شود.

### اشکال شایع

**۱) وصله بدون تست**
سیستم می‌خوابد.

**۲) آنتی‌ویروس منقضی**
بی‌فایده.

**۳) فایروال خاموش برای رفع مشکل**
امنیت صفر.

**۴) کار روزمره با ادمین**
شعاع انفجار.

**۵) بدون رمزنگاری دیسک**
لپ‌تاپ stolen = داده لو.

**۶) بوت از USB باز**
دور زدن رمز.

**۷) allowlist بدون به‌روزرسانی**
کاربر نمی‌تواند کار کند.

**۸) بدون لاگ**
نمی‌دانی چه شد.

### نکات مهم (Tips & Tricks)

- **سه ستون** را حفظ کن.
- **پنجرهٔ آسیب‌پذیری** را کوتاه کن.
- **EDR بهتر از آنتی‌ویروس سنتی.**
- **حساب استاندارد برای روزمره.**
- **رمزنگاری دیسک.**
- **allowlist برای حساس.**
- **تصویر پایهٔ امن.**

### خلاصه فصل

- سه ستون: وصله، آنتی‌ویروس، فایروال.
- پنجرهٔ آسیب‌پذیری، فرصت حمله است.
- EDR تشخیص + پاسخ می‌دهد.
- حساب استاندارد، شعاع انفجار را کم می‌کند.
- allowlist مقاوم به بدافزار ناشناس است.
- تصویر پایهٔ امن، سخت‌سازی را یکدست می‌کند.

<a name="ch-75"></a>
## فصل ۷۵: امنیت فیزیکی و دستگاه‌های همراه

### مقدمه

همهٔ کنترل‌های نرم‌افزاری، با یک دسترسی فیزیکی ساده دور زده می‌شوند. اگر کسی بتواند لپ‌تاپ را بردارد یا دیسک را جدا کند، رمز عبور ویندوز کمکی نمی‌کند. این فصل، لایه‌ای را می‌سازد که اغلب فراموش می‌شود.

### مفاهیم اساسی

**چرا امنیت فیزیکی؟**

> دسترسی فیزیکی = دسترسی کامل (در اکثر موارد).

**تهدیدهای فیزیکی**

| تهدید | مثال |
|---|---|
| سرقت | لپ‌تاپ از کافه |
| گم شدن | فلش در تاکسی |
| Tailgating | ورود پشت سر |
| Shoulder surfing | نگاه به صفحه |
| Dumpster diving | جستجوی زباله |
| Evil maid | دسترسی مخفی به دستگاه |

**کنترل‌های فیزیکی**

| کنترل | کار |
|---|---|
| قفل کابل (Kensington) | جلوگیری از سرقت |
| قفل در | اتاق سرور |
| بج/کارت | ورود |
| دوربین | نظارت |
| گاوصندوق | رسانه |
| Privacy screen | shoulder surfing |

**دستگاه‌های همراه**

| ریسک | کاهش |
|---|---|
| سرقت | رمزنگاری + Find My Device |
| گم شدن | قفل از راه دور |
| Wi-Fi عمومی | VPN |
| نگاه کنجکاو | Privacy filter |
| USB ناشناس | غیرفعال کردن autorun |

**Find My Device / Anti-theft**

| سیستم | سرویس |
|---|---|
| ویندوز | Find My Device |
| macOS | Find My Mac |
| اندروید | Find My Device |
| iOS | Find My |

**قابلیت‌ها:** مکان‌یابی، قفل، پاک کردن از راه دور.

**Remote Wipe**

پاک کردن داده از راه دور — فقط با پشتیبان.

**نکته:** قبل از فعال کردن، مطمئن شو پشتیبان داری. یک دستور اشتباه = داده رفته.

**رسانه‌های قابل حمل**

| رسانه | ریسک |
|---|---|
| فلش USB | بدافزار، گم شدن |
| دیسک اکسترنال | سرقت |
| نوار | گم شدن |
| DVD | کم |

**پاکسازی رسانه**

| روش | امنیت |
|---|---|
| Delete | ❌ |
| Format | ❌ |
| Overwrite | ✅ |
| Secure Erase | ✅ |
| Degauss | ✅ (مغناطیسی) |
| Physical destruction | ✅✅ |

**نکته:** `Delete` فقط اشاره‌گر را پاک می‌کند. داده با ابزار بازیابی برمی‌گردد.

**زباله (Dumpster diving)**

اسناد کاغذی، دیسک‌های دورانداخته، دستگاه‌های قدیمی — همه منبع اطلاعات‌اند.

**دفاع:** خردکن کاغذ، پاکسازی رسانه، قرارداد نابودی.

### مثال‌های عملی

**سناریوی Lab: امن‌سازی لپ‌تاپ مسافر**

```markdown
- [ ] رمزنگاری کل دیسک
- [ ] رمز BIOS/UEFI
- [ ] قفل خودکار (۱ دقیقه)
- [ ] Find My Device فعال
- [ ] پشتیبان ابری خودکار
- [ ] Privacy filter
- [ ] قفل کابل در هتل
- [ ] VPN سازمانی
- [ ] عدم استفاده از Wi-Fi عمومی بدون VPN
```

**سناریوی دوم: پاکسازی یک دیسک قبل از فروش**

| گام | کار |
|---|---|
| ۱ | پشتیبان بگیر (اگر لازم است) |
| ۲ | رمزنگاری کل دیسک را فعال کن (اگر نبود) |
| ۳ | Secure Erase از ابزار سازنده |
| ۴ | تأیید با ابزار بازیابی |
| ۵ | اگر SSD و ابزار نبود: تخریب فیزیکی |

**سناریوی سوم: tailgating**

```
مهاجم: "دستم پر است، می‌شود در را باز کنید؟"
کارمند: در را باز می‌کند.
```

**دفاع:**

| اقدام | اثر |
|---|---|
| آموزش | آگاهی |
| در چرخان | ورود تک‌نفره |
| میز پذیرش | کنترل |
| بج اجباری | ردیابی |

### مقایسه و الگوهای مختلف

**سه سطح امنیت فیزیکی**

| سطح | اقدامات |
|---|---|
| پایه | قفل در، قفل کابل |
| متوسط | بج، دوربین |
| بالا | بیومتریک، گارد، گاوصندوق |

**الگوی «پاکسازی سه‌مرحله‌ای»**

```
۱. پشتیبان (اگر داده لازم است)
۲. Secure Erase
۳. تأیید با ابزار بازیابی
```

### اشکال شایع

**۱) Format به‌عنوان پاکسازی**
داده برمی‌گردد.

**۲) فروش دستگاه بدون پاکسازی**
افشای داده.

**۳) بدون رمزنگاری دیسک**
سرقت = افشا.

**۴) Find My Device بدون پشتیبان**
Remote wipe فاجعه.

**۵) اعتماد به Wi-Fi عمومی**
MITM.

**۶) فلش پیدا شده را وصل کردن**
بدافزار.

**۷) زباله بدون خردکن**
dumpster diving.

**۸) بدون قفل کابل در محل عمومی**
سرقت آسان.

### نکات مهم (Tips & Tricks)

- **دسترسی فیزیکی = دسترسی کامل.**
- **رمزنگاری دیسک.**
- **Find My Device + پشتیبان.**
- **Format ≠ پاکسازی.**
- **Secure Erase برای رسانه.**
- **VPN در Wi-Fi عمومی.**
- **خردکن برای اسناد.**

### خلاصه فصل

- تهدید فیزیکی، جدی‌ترین تهدید است.
- قفل کابل، بج، دوربین سه کنترل پایه‌اند.
- Find My Device و Remote Wipe.
- پاکسازی رسانه با Secure Erase، نه Format.
- Dumpster diving منبع اطلاعات است.
- Tailgating با آموزش و کنترل ورود کاهش می‌یابد.

<a name="ch-76"></a>
## فصل ۷۶: رمزنگاری — متقارن، نامتقارن، هش

### مقدمه

رمزنگاری، پایهٔ امنیت دیجیتال است. سه مفهوم اصلی دارد و هر کدام کار متفاوتی می‌کند.

### مفاهیم اساسی

**سه مفهوم**

| نوع | کلید | کار |
|---|---|---|
| **Symmetric** | یک کلید | رمزنگاری داده |
| **Asymmetric** | دو کلید | تبادل کلید، امضا |
| **Hashing** | بدون کلید | یکپارچگی |

**رمزنگاری متقارن**

```
متن → [کلید یکسان] → رمز
رمز → [همان کلید] → متن
```

| الگوریتم | وضعیت |
|---|---|
| **AES-256** | استاندارد |
| AES-128 | امن |
| 3DES | منسوخ |
| DES | **شکسته** |

**مزیت:** سریع.
**عیب:** توزیع کلید.

**چالش توزیع کلید**

اگر ۱۰۰ نفر بخواهند با هم ارتباط امن داشته باشند، به `100×99/2 = 4,950` کلید نیاز است. غیرعملی.

**رمزنگاری نامتقارن**

```
کلید عمومی (برای همه) → رمزنگاری
کلید خصوصی (فقط مالک) → رمزگشایی
```

| الگوریتم | کاربرد |
|---|---|
| **RSA** | امضا، تبادل کلید |
| **ECC** | موبایل، کلید کوتاه |
| **Diffie-Hellman** | تبادل کلید |

**مزیت:** حل مشکل توزیع کلید.
**عیب:** کند (۱۰۰–۱۰۰۰ برابر).

**استفادهٔ ترکیبی**

```
۱) نامتقارن برای تبادل کلید متقارن
۲) متقارن برای داده
```

این همان کاری است که TLS می‌کند.

**هش (Hash)**

تابعی یک‌طرفه که ورودی با طول دلخواه را به خروجی با طول ثابت تبدیل می‌کند.

```
"hello" → 2cf24dba5fb0a30e26e83b2ac5b9e29e...
```

| ویژگی | معنی |
|---|---|
| یک‌طرفه | برگشت‌پذیر نیست |
| قطعی | همان ورودی، همان خروجی |
| حساس | تغییر یک بیت، خروجی کاملاً متفاوت |
| مقاوم به تصادم | دو ورودی با یک هش پیدا نمی‌شود |

**الگوریتم‌های هش**

| الگوریتم | وضعیت |
|---|---|
| **SHA-256** | ✅ استاندارد |
| SHA-3 | ✅ |
| MD5 | ❌ شکسته |
| SHA-1 | ❌ شکسته |

**کاربرد هش**

| کاربرد | توضیح |
|---|---|
| ذخیرهٔ رمز | هش + salt |
| بررسی یکپارچگی | checksum |
| امضای دیجیتال | هش + رمزنگاری |
| Blockchain | زنجیرهٔ هش |

**Salt**

مقدار تصادفی که به رمز اضافه می‌شود قبل از هش.

```
hash(password + salt)
```

**چرا؟** جلوگیری از rainbow table.

**نکته:** هر کاربر salt یکتا دارد.

**امضای دیجیتال**

```
۱) هش سند
۲) رمزنگاری هش با کلید خصوصی فرستنده
۳) گیرنده: رمزگشایی با کلید عمومی، مقایسهٔ هش
```

**تضمین:** اصالت + یکپارچگی + عدم انکار.

**گواهی دیجیتال (Certificate)**

سندی که کلید عمومی را به هویت متصل می‌کند.

| جزء | توضیح |
|---|---|
| Subject | صاحب |
| Public Key | کلید |
| Issuer | CA |
| Validity | اعتبار |
| Signature | امضای CA |

**CA** = Certificate Authority.

### مثال‌های عملی

**سناریوی Lab: بررسی HTTPS**

```
۱. مرورگر → قفل → Certificate
۲. بررسی:
   - صادرکننده (CA معتبر؟)
   - تاریخ اعتبار
   - نام دامنه (Subject/SAN)
   - کلید عمومی
```

**سناریوی دوم: ذخیرهٔ رمز**

```python
import hashlib, os

def hash_password(password: str, salt: bytes | None = None):
    salt = salt or os.urandom(16)
    digest = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, 600_000)
    return salt, digest
```

**نکته:** PBKDF2/bcrypt/argon2 برای رمز، نه SHA-256 ساده. چون SHA سریع است و brute force را آسان می‌کند.

**سناریوی سوم: checksum فایل**

```bash
sha256sum ubuntu.iso
# مقایسه با مقدار سایت رسمی
```

**درس:** اگر هش بخواند، فایل دست‌کاری نشده.

**سناریوی چهارم: مقایسهٔ سرعت**

| عملیات | سرعت نسبی |
|---|---|
| AES (متقارن) | ۱× |
| RSA (نامتقارن) | ~۱۰۰۰× کندتر |
| SHA-256 (هش) | سریع |

### مقایسه و الگوهای مختلف

**سه نوع رمزنگاری**

| نوع | کلید | سرعت | کاربرد |
|---|---|---|---|
| Symmetric | یک | سریع | داده |
| Asymmetric | دو | کند | تبادل، امضا |
| Hash | — | سریع | یکپارچگی |

**الگوی «هش برای رمز، رمزنگاری برای داده»**

- رمز عبور: هش + salt (برگشت‌ناپذیر).
- داده: رمزنگاری (برگشت‌پذیر).

**هشدار:** رمزنگاری رمز عبور، اشتباه است — باید هش کرد.

### اشکال شایع

**۱) MD5/SHA-1**
شکسته. SHA-256.

**۲) بدون salt**
rainbow table.

**۳) رمزنگاری رمز عبور**
باید هش شود.

**۴) SHA-256 ساده برای رمز**
سریع است. PBKDF2/argon2.

**۵) کلید متقارن مشترک برای همه**
توزیع و افشا.

**۶) اعتماد به گواهی منقضی**
هشدار مرورگر.

**۷) هش به‌عنوان رمزنگاری**
برگشت‌ناپذیر است.

**۸) DES/3DES**
منسوخ.

### نکات مهم (Tips & Tricks)

- **AES-256** استاندارد متقارن.
- **RSA/ECC** برای تبادل و امضا.
- **SHA-256** استاندارد هش.
- **salt برای رمز.**
- **PBKDF2/argon2 برای رمز.**
- **TLS = ترکیب هر سه.**
- **MD5 و SHA-1 منسوخ.**

### خلاصه فصل

- متقارن سریع، نامتقارن حل توزیع کلید.
- هش یک‌طرفه و برای یکپارچگی.
- salt از rainbow table جلوگیری می‌کند.
- امضای دیجیتال: هش + کلید خصوصی.
- گواهی، کلید عمومی را به هویت متصل می‌کند.
- TLS هر سه را ترکیب می‌کند.

<a name="ch-77"></a>
## فصل ۷۷: رمزنگاری داده در سکون و انتقال

### مقدمه

رمزنگاری، سه ابزار دارد؛ اما سؤال عملی این است: «کدام را کجا به کار ببرم؟» داده دو حالت دارد — ذخیره‌شده و در حال انتقال — و هر حالت، ابزار خودش را می‌خواهد. این فصل، انتخاب را ساده می‌کند.

### مفاهیم اساسی

**دو حالت داده**

| حالت | معنی | مثال |
|---|---|---|
| **At rest** | ذخیره‌شده | دیسک، دیتابیس |
| **In transit** | در حال انتقال | شبکه، ایمیل |

**Data at Rest**

| روش | کار |
|---|---|
| **Full Disk Encryption** | کل دیسک |
| **File-level** | فایل مشخص |
| **Database encryption** | ستون/جدول |
| **Self-encrypting drive** | سخت‌افزاری |

**ابزارها**

| سیستم | ابزار |
|---|---|
| ویندوز Pro | BitLocker |
| macOS | FileVault |
| لینوکس | LUKS |
| موبایل | رمزنگاری پیش‌فرض |

**نکته:** BitLocker در ویندوز Home نیست (فقط Device Encryption محدود).

**Data in Transit**

| پروتکل | کار |
|---|---|
| **TLS** | وب، API |
| **IPsec** | VPN سایت-به-سایت |
| **SSH** | شل، انتقال فایل |
| **S/MIME / PGP** | ایمیل |
| **HTTPS** | وب |

**TLS — چطور کار می‌کند؟**

```
۱) Client Hello
۲) Server Hello + Certificate
۳) بررسی گواهی
۴) تبادل کلید (Diffie-Hellman)
۵) رمزنگاری متقارن با کلید جلسه
```

**نکته:** TLS از رمزنگاری **نامتقارن** برای تبادل کلید و **متقارن** برای داده استفاده می‌کند.

**HTTPS**

| بخش | کار |
|---|---|
| HTTP | داده |
| TLS | رمزنگاری |
| Certificate | هویت |

**پورت ۴۴۳** پیش‌فرض HTTPS.

**VPN**

تونل رمزنگاری‌شده برای همهٔ ترافیک.

| نوع | کاربرد |
|---|---|
| Remote access | دورکاری |
| Site-to-site | اتصال دفاتر |

**ایمیل امن**

| روش | کار |
|---|---|
| **S/MIME** | گواهی |
| **PGP** | کلید عمومی |
| **TLS بین سرورها** | انتقال |

**نکته:** TLS ایمیل، فقط بین سرورهاست. خود پیام روی سرور رمزنگاری‌شده نیست (مگر S/MIME/PGP).

**رمزنگاری ابری**

| لایه | مسئول |
|---|---|
| At rest | ارائه‌دهنده (معمولاً) |
| In transit | TLS |
| کلید | ارائه‌دهنده یا تو (BYOK) |

**BYOK** = Bring Your Own Key.

**Key Management**

| اصل | توضیح |
|---|---|
| جدا از داده | کلید در جای دیگر |
| چرخش | تغییر دوره‌ای |
| حداقل دسترسی | فقط لازم |
| پشتیبان | کلید گم شود = داده گم |

**هشدار:** کلید رمزنگاری گم‌شده = دادهٔ غیرقابل بازیابی. پشتیبان کلید حیاتی است.

### مثال‌های عملی

**سناریوی Lab: رمزنگاری لپ‌تاپ**

**ویندوز:**

```
Settings → Privacy & Security → Device encryption
یا
Control Panel → BitLocker Drive Encryption → Turn on
```

**نکته:** کلید بازیابی را در جای امن (نه روی همان دستگاه) ذخیره کن.

**macOS:**

```
System Settings → Privacy & Security → FileVault → Turn On
```

**لینوکس:**

```bash
sudo cryptsetup luksFormat /dev/sda2
sudo cryptsetup luksOpen /dev/sda2 crypt
```

**سناریوی دوم: بررسی TLS یک سایت**

```bash
openssl s_client -connect example.com:443 -servername example.com
```

| بخش | بررسی |
|---|---|
| Protocol | TLS 1.2+ |
| Cipher | AES-GCM |
| Verify return code | 0 (ok) |
| Expire | تاریخ |

**سناریوی سوم: انتقال فایل امن**

| روش | امنیت |
|---|---|
| ایمیل معمولی | ❌ |
| ایمیل + ZIP رمزدار | ⚠️ (رمز جدا بفرست) |
| SFTP | ✅ |
| HTTPS share | ✅ |
| VPN + SMB | ✅ |

**سناریوی چهارم: رمزنگاری دیتابیس**

```sql
-- PostgreSQL: رمزنگاری ستون حساس
-- (با افزونه یا در لایهٔ اپلیکیشن)
```

**توصیه:** رمزنگاری در لایهٔ اپلیکیشن، کنترل بیشتری می‌دهد.

### مقایسه و الگوهای مختلف

**سه سطح رمزنگاری**

| سطح | مزیت | عیب |
|---|---|---|
| Full disk | ساده، کامل | فقط در حالت خاموش |
| File-level | انتخابی | مدیریت |
| Application-level | کنترل | کد بیشتر |

**نکته:** Full disk encryption وقتی سیستم روشن و قفل‌شده است، محافظت محدودی دارد (کلید در RAM).

**الگوی «رمزنگاری سرتاسری»**

```
فرستنده → رمزنگاری → سرور (بدون کلید) → گیرنده → رمزگشایی
```

مثال: Signal، WhatsApp.

### اشکال شایع

**۱) BitLocker در Home**
موجود نیست.

**۲) کلید بازیابی روی همان دستگاه**
بی‌فایده.

**۳) HTTP برای ورود**
رمز در متن ساده.

**۴) ایمیل به‌عنوان انتقال امن**
TLS فقط بین سرورها.

**۵) VPN رایگان**
داده فروخته می‌شود.

**۶) رمزنگاری بدون مدیریت کلید**
داده از دست می‌رود.

**۷) فرض «ابر رمزنگاری می‌کند، پس کافی است»**
مسئولیت مشترک.

**۸) TLS 1.0/1.1**
منسوخ.

### نکات مهم (Tips & Tricks)

- **At rest و in transit** را جدا کن.
- **BitLocker/FileVault/LUKS.**
- **TLS 1.2+** حداقل.
- **کلید بازیابی جدا.**
- **SFTP به‌جای FTP.**
- **BYOK برای ابر حساس.**
- **کلید گم = داده گم.**

### خلاصه فصل

- داده دو حالت دارد: سکون و انتقال.
- Full disk encryption برای دستگاه‌های همراه.
- TLS ترکیب متقارن و نامتقارن است.
- HTTPS = HTTP + TLS.
- ایمیل با TLS، سرتاسری نیست.
- مدیریت کلید، بخش حیاتی رمزنگاری است.

<a name="ch-78"></a>
## فصل ۷۸: امنیت موبایل و BYOD

### مقدمه

گوشی، شخصی‌ترین و در عین حال پرخطرترین دستگاه سازمان است: هم دادهٔ شرکت دارد، هم دادهٔ شخصی کارمند. این فصل، مدل‌های استقرار و ابزارهای مدیریت را نشان می‌دهد تا امنیت و حریم خصوصی هم‌زمان حفظ شوند.

### مفاهیم اساسی

**تهدیدهای موبایل**

| تهدید | توضیح |
|---|---|
| اپ مخرب | از فروشگاه ثالث |
| Wi-Fi عمومی | MITM |
| سرقت/گم شدن | دسترسی فیزیکی |
| Smishing | فیشینگ پیامکی |
| Permission زیاد | دسترسی به داده |
| Jailbreak/Root | حذف محافظت‌ها |

**BYOD در برابر COPE**

| مدل | توضیح |
|---|---|
| **BYOD** | دستگاه شخصی کارمند |
| **COPE** | دستگاه شرکتی، استفادهٔ شخصی |
| **CYOD** | انتخاب از فهرست تأییدشده |

**MDM — Mobile Device Management**

| قابلیت | کار |
|---|---|
| Enrollment | ثبت دستگاه |
| Policy | سیاست رمز، رمزنگاری |
| App management | نصب/حذف اپ |
| Remote wipe | پاک کردن |
| Compliance | بررسی وضعیت |

**MAM — Mobile Application Management**

مدیریت اپ، نه کل دستگاه. مناسب BYOD.

**Containerization**

جداسازی دادهٔ کاری از شخصی.

```
دستگاه
├── Personal (بدون دسترسی شرکت)
└── Work container (مدیریت‌شده)
```

**نکته:** در BYOD، remote wipe باید فقط container کاری را پاک کند، نه کل دستگاه.

**سیاست موبایل**

```markdown
- [ ] رمز/PIN اجباری
- [ ] رمزنگاری فعال
- [ ] قفل خودکار
- [ ] به‌روزرسانی سیستم‌عامل
- [ ] نصب فقط از فروشگاه رسمی
- [ ] Jailbreak/Root ممنوع
- [ ] MFA برای حساب کاری
- [ ] VPN برای دسترسی به منابع
```

**اپلیکیشن — مجوزها**

| مجوز | خطر |
|---|---|
| مخاطبین | بالا |
| مکان (همیشه) | بالا |
| دوربین/میکروفن | متوسط |
| اعلان | کم |

**قاعده:** اپ چراغ‌قوه نباید به مخاطبین دسترسی داشته باشد.

**Jailbreak / Root**

| کار | اثر |
|---|---|
| حذف محدودیت‌ها | امنیت کم |
| نصب اپ خارج از فروشگاه | بدافزار |
| دسترسی root | کنترل کامل |

**نتیجه:** دستگاه root شده، قابل اعتماد نیست. در سازمان، ممنوع.

**Wi-Fi عمومی**

| خطر | کاهش |
|---|---|
| MITM | VPN |
| Evil twin | بررسی SSID |
| Captive portal جعلی | عدم ورود اطلاعات |
| شنود | HTTPS |

### مثال‌های عملی

**سناریوی Lab: راه‌اندازی BYOD**

```markdown
۱. سیاست را بنویس و امضا بگیر
۲. MDM/MAM نصب کن
۳. container کاری بساز
۴. رمز و رمزنگاری را اجباری کن
۵. دسترسی به ایمیل/فایل را از container بده
۶. remote wipe فقط برای container
۷. خروج کارمند: حذف container
```

**سناریوی دوم: بررسی اپ قبل از نصب**

| بررسی | سؤال |
|---|---|
| منبع | فروشگاه رسمی؟ |
| سازنده | شناخته‌شده؟ |
| مجوزها | منطقی؟ |
| نظرات | مشکوک؟ |
| آپدیت | منظم؟ |

**سناریوی سوم: دستگاه گم‌شده**

```markdown
۱. از حساب خارج شو (از راه دور)
۲. Find My Device → قفل
۳. پیام روی صفحه
۴. اگر برنگشت: پاک کردن از راه دور
۵. تغییر رمزهای حساب‌های متصل
۶. اطلاع به تیم امنیت
```

**سناریوی چهارم: Smishing**

```
پیام: "بستهٔ شما در انبار است. برای پیگیری:
https://post-track.example/login"
```

**نشانه‌ها:** لینک ناشناس، فوریت، درخواست اطلاعات.

**اقدام:** کلیک نکن، از اپ رسمی بررسی کن.

### مقایسه و الگوهای مختلف

**سه مدل استقرار موبایل**

| مدل | مالکیت | کنترل | مناسب |
|---|---|---|---|
| BYOD | کارمند | کم | استارتاپ |
| COPE | شرکت | متوسط | سازمان |
| CYOD | شرکت (انتخاب) | بالا | امنیت بالا |

**الگوی «container کاری»**

بهترین تعادل برای BYOD: حریم خصوصی کارمند + امنیت شرکت.

### اشکال شایع

**۱) BYOD بدون سیاست**
دستگاه شخصی، داده شرکت.

**۲) Remote wipe کل دستگاه در BYOD**
حریم خصوصی نقض.

**۳) اپ از فروشگاه ثالث**
بدافزار.

**۴) مجوز زیاد**
افشای داده.

**۵) Jailbreak در سازمان**
امنیت صفر.

**۶) Wi-Fi عمومی بدون VPN**
MITM.

**۷) بدون رمزنگاری**
سرقت = افشا.

**۸) بدون MFA**
رمز لو رفته = دسترسی.

### نکات مهم (Tips & Tricks)

- **MDM/MAM** برای مدیریت.
- **Container** برای BYOD.
- **Remote wipe فقط کاری.**
- **فروشگاه رسمی.**
- **مجوزها را بررسی کن.**
- **Jailbreak ممنوع.**
- **VPN در Wi-Fi عمومی.**

### خلاصه فصل

- موبایل تهدیدهای خاص خودش را دارد.
- BYOD، COPE، CYOD سه مدل استقرارند.
- MDM دستگاه، MAM اپ را مدیریت می‌کند.
- Container جداسازی کاری/شخصی می‌سازد.
- Jailbreak/Root، امنیت را حذف می‌کند.
- مجوز اپ، ریسک اصلی است.
