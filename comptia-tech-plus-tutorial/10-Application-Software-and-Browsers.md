## فصل ۴۲: نرم‌افزار بهره‌وری — مجموعهٔ اداری

### مقدمه

«مجموعهٔ اداری» یا Office Suite، پرکاربردترین دستهٔ نرم‌افزار در جهان است. اما تفاوت نسخه‌ها، فرمت‌ها و لایسنس‌ها می‌تواند گیج‌کننده باشد.

### مفاهیم اساسی

**سه جزء اصلی**

| ابزار | کار | فرمت |
|---|---|---|
| **واژه‌پرداز** | متن | `.docx` |
| **صفحه‌گسترده** | محاسبه و داده | `.xlsx` |
| **ارائه** | اسلاید | `.pptx` |

**گزینه‌ها**

| مجموعه | لایسنس | مزیت | عیب |
|---|---|---|---|
| Microsoft 365 | اشتراک | استاندارد صنعت | هزینهٔ ماهانه |
| Office 2021 (خرید یک‌بار) | دائمی | بدون اشتراک | بدون آپدیت نسخه |
| Google Workspace | اشتراک | همکاری آنی | وابسته به اینترنت |
| LibreOffice | رایگان | بدون هزینه | سازگاری ناقص |
| WPS Office | رایگان/اشتراک | سبک | تبلیغات |

**فرمت‌های باز در برابر بسته**

| فرمت | نوع | پسوند |
|---|---|---|
| **OOXML** | باز (استاندارد) | `.docx`، `.xlsx`، `.pptx` |
| **ODF** | باز | `.odt`، `.ods`، `.odp` |
| **PDF** | قابل حمل | `.pdf` |
| **CSV** | متن ساده | `.csv` |

**نکته:** `.docx` یک فایل ZIP با XML داخلش است. به همین دلیل حجم کم و قابل بازیابی دارد.

**واژه‌پرداز — قابلیت‌های کلیدی**

| قابلیت | کار |
|---|---|
| Styles | قالب‌بندی یکدست |
| Track Changes | ویرایش با ردگیری |
| Mail Merge | ادغام با داده |
| Table of Contents | فهرست خودکار |
| Comments | نظر |

**صفحه‌گسترده — مفاهیم پایه**

| مفهوم | معنی |
|---|---|
| **Cell** | خانه (`A1`) |
| **Range** | محدوده (`A1:C10`) |
| **Formula** | محاسبه (`=A1+B1`) |
| **Function** | تابع (`=SUM(A1:A10)`) |
| **Absolute reference** | `$A$1` (ثابت) |

**فرمول در برابر مقدار**

```
سلول A1: 5
سلول B1: 3
سلول C1: =A1+B1   → 8
```

اگر A1 را به ۱۰ تغییر دهی، C1 خودکار ۱۳ می‌شود.

**توابع پرکاربرد**

| تابع | کار |
|---|---|
| `SUM` | جمع |
| `AVERAGE` | میانگین |
| `IF` | شرط |
| `VLOOKUP` / `XLOOKUP` | جستجو |
| `COUNTIF` | شمارش شرطی |
| `CONCAT` | اتصال متن |

**ارائه — اصول**

| اصل | توضیح |
|---|---|
| یک ایده در هر اسلاید | تمرکز |
| متن کم، تصویر زیاد | خوانایی |
| فونت بزرگ (۲۴+) | دیدن از دور |
| کنتراست بالا | خوانایی |

**قالب‌های فایل و سازگاری**

| مشکل | راه‌حل |
|---|---|
| فونت عوض می‌شود | فونت را همراه فایل بفرست |
| چیدمان می‌شکند | PDF بفرست |
| ماکرو اجرا نمی‌شود | `.xlsm` |

**نکتهٔ امنیتی: ماکرو**

فایل‌های Office می‌توانند ماکرو (کد) داشته باشند. ماکروی مخرب، یکی از راه‌های رایج آلودگی است.

**قاعده:** فایل ناشناس را با ماکرو باز نکن. اگر لازم بود، در حالت Protected View.

### مثال‌های عملی

**سناریوی Lab: ساخت یک گزارش ساده**

**هدف:** گزارش فروش ماهانه با جمع و میانگین.

| A | B | C |
|---|---|---|
| محصول | تعداد | قیمت |
| A | ۱۰ | ۵۰ |
| B | ۵ | ۸۰ |
| C | ۲۰ | ۳۰ |

**گام ۱ — جمع**

```
=SUM(B2:B4)   → 35
=SUMPRODUCT(B2:B4, C2:C4)  → 1500
```

**گام ۲ — میانگین**

```
=AVERAGE(C2:C4)  → 53.3
```

**گام ۳ — شرط**

```
=IF(B2>8, "پرفروش", "معمولی")
```

**گام ۴ — قالب‌بندی**

- سرستون‌ها Bold.
- قالب پول برای ستون قیمت.
- Chart برای نمایش.

**سناریوی دوم: اشتراک در برابر خرید**

| معیار | Microsoft 365 | Office 2021 |
|---|---|---|
| هزینه | ماهانه | یک‌بار |
| آپدیت نسخه | ✅ | ❌ |
| فضای ابری | ۱TB | ❌ |
| چند دستگاه | ۵ | ۱ |
| مناسب | تیم، همکاری | کاربر ثابت |

**سناریوی سوم: همکاری همزمان**

```
Google Docs / Microsoft 365 Online:
- چند نفر همزمان ویرایش
- تاریخچهٔ تغییرات
- کامنت
```

**هشدار:** در فایل حساس، دسترسی را دقیق تنظیم کن. لینک «هر کسی با لینک» = افشا.

### مقایسه و الگوهای مختلف

**سه سبک کار**

| سبک | ابزار | مناسب |
|---|---|---|
| محلی | Office نصب‌شده | آفلاین، فایل بزرگ |
| ابری | Google Docs، Office Online | همکاری |
| ترکیبی | OneDrive + Office | بهترین تعادل |

**الگوی «فایل محلی، همکاری ابری»**

فایل اصلی روی OneDrive/Drive، ویرایش با نسخهٔ نصب‌شده. هم آفلاین کار می‌کند هم همکاری.

### اشکال شایع

**۱) فرستادن `.docx` به‌جای PDF**
چیدمان می‌شکند. PDF برای ارسال نهایی.

**۲) باز کردن ماکرو ناشناس**
بدافزار. Protected View.

**۳) فرمول با مرجع نسبی اشتباه**
کپی فرمول، مرجع را جابه‌جا می‌کند. `$A$1`.

**۴) فایل CSV با کاراکتر فارسی**
کدگذاری. UTF-8 با BOM.

**۵) لینک اشتراک عمومی**
افشای داده.

**۶) نسخه‌های متناقض**
`report-final-v2-FINAL.docx`. نام‌گذاری با تاریخ.

**۷) نادیده گرفتن Accessibility**
فونت ریز، کنتراست کم.

**۸) فرمول‌های پیچیده بدون مستند**
کسی نمی‌فهمد. شیت «توضیحات».

### نکات مهم (Tips & Tricks)

- **PDF برای ارسال، Office برای ویرایش.**
- **`$` برای مرجع مطلق.**
- **ماکرو را جدی بگیر.**
- **لینک اشتراک را محدود کن.**
- **نام فایل با تاریخ.**
- **شیت توضیحات برای فرمول‌ها.**
- **Accessibility را رعایت کن.**

### خلاصه فصل

- سه جزء: واژه‌پرداز، صفحه‌گسترده، ارائه.
- فرمت‌های باز: OOXML و ODF.
- `.docx` یک ZIP با XML است.
- فرمول با `$` مطلق می‌شود.
- ماکرو، ریسک امنیتی است.
- PDF برای ارسال نهایی.

<a name="ch-43"></a>
## فصل ۴۳: ایمیل و ابزارهای همکاری

### مقدمه

ایمیل، قدیمی‌ترین و همچنان مهم‌ترین ابزار ارتباط کاری است. اما بیشتر حملات فیشینگ از همین‌جا شروع می‌شود.

### مفاهیم اساسی

**اجزای یک آدرس ایمیل**

```
ali.rezaei@example.com
└────┬────┘ └──┬───┘
  mailbox    domain
```

**پروتکل‌ها**

| پروتکل | کار | پورت امن |
|---|---|---|
| **SMTP** | ارسال | ۴۶۵ / ۵۸۷ |
| **POP3** | دریافت (دانلود) | ۹۹۵ |
| **IMAP** | دریافت (روی سرور) | ۹۹۳ |
| **Exchange/EWS** | سرور سازمانی | ۴۴۳ |

**POP3 در برابر IMAP**

| معیار | POP3 | IMAP |
|---|---|---|
| ذخیره | روی دستگاه | روی سرور |
| چند دستگاه | سخت | آسان |
| حجم سرور | کم | زیاد |
| مناسب | یک دستگاه | امروز |

**اجزای پیام**

| جزء | کار |
|---|---|
| **To** | گیرندهٔ اصلی |
| **Cc** | رونوشت (همه می‌بینند) |
| **Bcc** | رونوشت مخفی |
| **Subject** | موضوع |
| **Body** | متن |
| **Attachment** | پیوست |

**نکتهٔ حرفه‌ای:** برای لیست بزرگ، از **Bcc** استفاده کن تا آدرس‌ها لو نروند.

**پروتکل‌های امنیتی ایمیل**

| پروتکل | کار |
|---|---|
| **SPF** | کدام سرور مجاز به ارسال است |
| **DKIM** | امضای دیجیتال پیام |
| **DMARC** | سیاست بر اساس SPF/DKIM |

این سه، جعل فرستنده را سخت می‌کنند. اگر دامنه‌ای این‌ها را نداشته باشد، احتمال جعل بالا است.

**تشخیص فیشینگ**

| نشانه | توضیح |
|---|---|
| آدرس فرستنده مشکوک | `support@paypa1.com` |
| فوریت | «فوراً اقدام کن» |
| لینک نامرتبط | متن لینک با مقصد فرق دارد |
| پیوست ناشناس | `.exe`، `.zip` با رمز |
| گرامر بد | ترجمهٔ ماشینی |
| درخواست رمز | هیچ سرویس معتبری رمز نمی‌خواهد |

**قاعده:** روی لینک کلیک نکن؛ آدرس را دستی تایپ کن یا از اپ رسمی وارد شو.

**ابزارهای همکاری**

| دسته | مثال |
|---|---|
| پیام‌رسان | Slack، Teams، Google Chat |
| کنفرانس ویدئو | Zoom، Teams، Meet |
| اشتراک فایل | OneDrive، Drive، Dropbox |
| مدیریت پروژه | Trello، Asana، Jira |
| ویکی | Confluence، Notion |

**کنفرانس ویدئو — نکات**

| نکته | چرا |
|---|---|
| میکروفن تست | صدای بد، جلسه را خراب می‌کند |
| پس‌زمینهٔ مرتب | حرفه‌ای |
| نور از جلو | چهرهٔ روشن |
| اتصال سیمی | پایداری |
| Mute در سکوت | نویز |

### مثال‌های عملی

**سناریوی Lab: تحلیل یک ایمیل فیشینگ**

**پیام:**

```
از: security@bank-secure-verify.com
موضوع: حساب شما مسدود شده است

کاربر گرامی،
حساب بانکی شما به دلیل فعالیت مشکوک مسدود شده.
برای فعال‌سازی، روی لینک زیر کلیک کنید:
http://bank-secure-verify.com/login

با تشکر،
تیم امنیت
```

**تحلیل:**

| نشانه | بررسی |
|---|---|
| دامنه | `bank-secure-verify.com` — دامنهٔ اصلی بانک نیست |
| پروتکل | `http` نه `https` |
| فوریت | «مسدود شده» — ترس |
| درخواست اقدام | کلیک روی لینک |
| سلام عمومی | «کاربر گرامی» |

**نتیجه:** فیشینگ. **اقدام:** حذف، گزارش، عدم کلیک.

**سناریوی دوم: تنظیم ایمیل**

**IMAP (چند دستگاه):**

```
سرور ورودی: imap.example.com، پورت ۹۹۳ (SSL)
سرور خروجی: smtp.example.com، پورت ۴۶۵ (SSL)
نام کاربری: آدرس کامل
رمز: رمز اپ (اگر 2FA فعال است)
```

**نکته:** با فعال بودن 2FA، اغلب باید «رمز اپلیکیشن» بسازی، نه رمز اصلی.

**سناریوی سوم: امضای ایمیل**

```markdown
—
علی رضایی
کارشناس پشتیبانی فنی
شرکت نمونه | تلفن: ۰۲۱-۱۲۳۴۵۶۷۸
```

**نکتهٔ امنیتی:** در امضا، اطلاعات حساس (شمارهٔ داخلی، موبایل شخصی) را نگذار.

### مقایسه و الگوهای مختلف

**سه سبک مدیریت ایمیل**

| سبک | مزیت | عیب |
|---|---|---|
| Inbox Zero | کنترل کامل | زمان‌بر |
| پوشه‌بندی | سازمان | جستجو سخت |
| برچسب (Label) | چندگانه | نیاز به نظم |

**الگوی «قاعدهٔ خودکار»**

```
اگر از boss@company.com → برچسب «مهم»
اگر موضوع شامل «invoice» → پوشهٔ «مالی»
اگر فرستنده در لیست سیاه → حذف
```

### اشکال شایع

**۱) کلیک روی لینک فیشینگ**
بزرگ‌ترین علت نفوذ.

**۲) To به‌جای Bcc برای لیست**
آدرس‌ها لو می‌روند.

**۳) پیوست بزرگ**
محدودیت سرور. از لینک ابری.

**۴) ارسال فایل حساس بدون رمز**
رمزنگاری یا لینک محافظت‌شده.

**۵) باز کردن پیوست `.exe`**
بدافزار.

**۶) نادیده گرفتن SPF/DKIM**
جعل فرستنده.

**۷) ایمیل بدون موضوع**
گم می‌شود.

**۸) Reply All اشتباهی**
همه می‌بینند.

### نکات مهم (Tips & Tricks)

- **Bcc برای لیست.**
- **لینک را دستی تایپ کن.**
- **SPF/DKIM/DMARC را بشناس.**
- **2FA + رمز اپ.**
- **پیوست بزرگ = لینک.**
- **Mute در کنفرانس.**
- **Reply All را با احتیاط.**

### خلاصه فصل

- SMTP ارسال، POP3/IMAP دریافت.
- IMAP برای چند دستگاه بهتر است.
- SPF/DKIM/DMARC جعل را سخت می‌کنند.
- فیشینگ با فوریت، دامنهٔ مشکوک و درخواست رمز شناخته می‌شود.
- Bcc برای لیست‌های بزرگ.
- ابزارهای همکاری، جایگزین بخشی از ایمیل شده‌اند.

<a name="ch-44"></a>
## فصل ۴۴: مرورگر وب — ویژگی‌های کلیدی

### مقدمه

مرورگر، پنجرهٔ تو به اینترنت است. اما یک نرم‌افزار کامل با تنظیمات امنیتی و حریم خصوصی است که بیشتر کاربران فقط ۱۰٪ آن را می‌شناسند.

### مفاهیم اساسی

**ویژگی‌های اصلی**

| ویژگی | کار | نکته |
|---|---|---|
| **Tab** | چند صفحه در یک پنجره | مصرف RAM |
| **Bookmark** | ذخیرهٔ آدرس | همگام‌سازی |
| **History** | تاریخچه | حریم خصوصی |
| **Download** | مدیریت دانلود | محل ذخیره |
| **Extension** | افزونه | دسترسی زیاد |
| **DevTools** | ابزار توسعه | دیباگ |

**حالت ناشناس (Incognito/Private)**

| می‌کند | نمی‌کند |
|---|---|
| تاریخچهٔ محلی ذخیره نمی‌کند | IP را پنهان نمی‌کند |
| کوکی بعد از بستن پاک می‌شود | از ISP پنهان نمی‌کند |
| — | از سایت پنهان نمی‌کند |

**مدیریت رمز**

| روش | امنیت |
|---|---|
| ذخیره در مرورگر بدون رمز اصلی | متوسط |
| ذخیره با رمز اصلی | خوب |
| مدیر رمز اختصاصی | بهتر |
| نوشتن روی کاغذ | ⚠️ بسته به محیط |

**نکته:** مدیر رمز مرورگر با رمز اصلی قوی، امن‌تر از استفادهٔ مکرر از یک رمز است.

**افزونه‌ها — ریسک**

| مجوز | خطر |
|---|---|
| «خواندن و تغییر همهٔ داده‌های سایت‌ها» | **بسیار بالا** |
| «خواندن تاریخچه» | متوسط |
| «دسترسی به تب فعلی» | کم |

**قاعده:** فقط افزونهٔ ضروری، از فروشگاه رسمی، با بررسی مجوزها.

**کوکی‌ها و ردیابی**

| نوع | کار |
|---|---|
| **First-party** | همان سایت |
| **Third-party** | ردیابی بین سایت‌ها |
| **Session** | تا بستن مرورگر |
| **Persistent** | تاریخ انقضا |

**توصیه:** کوکی third-party را مسدود کن.

**کش و داده‌های سایت**

| داده | اثر پاک کردن |
|---|---|
| Cache | بارگذاری کندتر، نسخهٔ تازه |
| Cookies | خروج از سایت‌ها |
| Local Storage | تنظیمات سایت |
| History | حریم خصوصی |

**همگام‌سازی (Sync)**

| مزیت | عیب |
|---|---|
| بوکمارک و رمز روی همه دستگاه‌ها | اگر حساب لو برود، همه لو می‌رود |

**نکته:** Sync را فقط با 2FA فعال کن.

**HTTPS و گواهی**

| نشانه | معنی |
|---|---|
| قفل + `https` | اتصال رمزنگاری‌شده |
| «Not secure» | HTTP |
| هشدار گواهی | گواهی نامعتبر/منقضی |

**هشدار:** قفل، «سایت معتبر» نیست؛ فقط «اتصال رمزنگاری‌شده» است.

**PDF در مرورگر**

اکثر مرورگرها PDF را نمایش می‌دهند. برای امنیت، PDF ناشناس را در مرورگر باز نکن (JS در PDF ممکن است).

### مثال‌های عملی

**سناریوی Lab: سخت‌سازی مرورگر**

**گام ۱ — حریم خصوصی**

```
Settings → Privacy
- Block third-party cookies
- Send "Do Not Track" (اختیاری)
- Clear browsing data on exit (برای دستگاه مشترک)
```

**گام ۲ — امنیت**

```
Settings → Security
- Safe Browsing: Enhanced
- Always use secure DNS
- Warn before opening dangerous files
```

**گام ۳ — افزونه‌ها**

| افزونه | نگه دار؟ |
|---|---|
| Ad blocker | ✅ |
| Password manager | ✅ |
| افزونهٔ ناشناس «دانلود ویدئو» | ❌ |
| افزونهٔ VPN رایگان | ❌ |

**گام ۴ — رمزها**

```
Settings → Autofill → Password Manager
- فعال
- با رمز اصلی قوی
- 2FA روی حساب مرورگر
```

**گام ۵ — بررسی**

```markdown
- [ ] کوکی third-party مسدود
- [ ] HTTPS-only فعال
- [ ] افزونه‌های غیرضروری حذف
- [ ] رمز اصلی قوی
- [ ] 2FA فعال
```

**سناریوی دوم: پاک کردن کش برای رفع مشکل**

| مشکل | اقدام |
|---|---|
| صفحهٔ قدیمی | `Ctrl+Shift+R` |
| مشکل ورود | پاک کردن کوکی همان سایت |
| کندی | پاک کردن کش |
| خطای عجیب | پاک کردن داده‌های سایت |

**نکته:** اول فقط دادهٔ همان سایت را پاک کن، نه همه‌چیز.

**سناریوی سوم: مقایسهٔ مرورگرها**

| مرورگر | موتور | مزیت | عیب |
|---|---|---|---|
| Chrome | Blink | سازگاری، افزونه | RAM |
| Firefox | Gecko | حریم خصوصی | کمی کندتر |
| Edge | Blink | ویندوز، مصرف کم | تبلیغات |
| Safari | WebKit | مک، باتری | محدود |

### مقایسه و الگوهای مختلف

**سه سطح حریم خصوصی**

| سطح | تنظیمات |
|---|---|
| پایه | کوکی third-party مسدود |
| متوسط | + DNS امن + ضدردیاب |
| بالا | + VPN + مرورگر سخت‌گیر |

**الگوی «دو مرورگر»**

```
مرورگر ۱: کار و حساب‌های اصلی (بدون افزونهٔ اضافه)
مرورگر ۲: گشت‌وگذار و سایت‌های ناشناس
```

این جداسازی، ریسک را کم می‌کند.

### اشکال شایع

**۱) فرض «حالت ناشناس = ناشناس»**
IP و ISP می‌بینند.

**۲) نصب افزونهٔ زیاد**
هر افزونه، در باز.

**۳) ذخیرهٔ رمز بدون رمز اصلی**
هر کسی با دسترسی فیزیکی می‌خواند.

**۴) نادیده گرفتن هشدار گواهی**
«Continue» = ریسک.

**۵) پاک کردن همهٔ کوکی‌ها برای یک مشکل**
خروج از همه‌جا.

**۶) Sync بدون 2FA**
لو رفتن حساب = لو رفتن همه.

**۷) کلیک روی «دانلود» تبلیغاتی**
بدافزار.

**۸) استفاده از مرورگر قدیمی**
حفره‌های وصله‌نشده.

### نکات مهم (Tips & Tricks)

- **`Ctrl+Shift+R`** برای رفرش کامل.
- **کوکی third-party را ببند.**
- **افزونه کم، از منبع رسمی.**
- **مدیر رمز + 2FA.**
- **قفل ≠ اعتماد.**
- **دو مرورگر برای جداسازی.**
- **مرورگر را آپدیت نگه دار.**

### خلاصه فصل

- مرورگر نرم‌افزاری کامل با تنظیمات امنیتی است.
- حالت ناشناس فقط اثر محلی را کم می‌کند.
- افزونه‌ها دسترسی زیاد می‌خواهند.
- کوکی third-party ردیابی است.
- قفل HTTPS رمزنگاری است، نه اعتماد.
- دو مرورگر، جداسازی ساده و مؤثر.

<a name="ch-45"></a>
## فصل ۴۵: ابزارهای سیستمی و نگه‌داری

### مقدمه

سیستم‌عامل چند ابزار داخلی دارد که بیشتر کاربران نمی‌شناسند. این ابزارها برای نگه‌داری، عیب‌یابی و بازیابی حیاتی‌اند.

### مفاهیم اساسی

**ابزارهای ویندوز**

| ابزار | کار |
|---|---|
| **Task Manager** | فرآیندها، منابع، Startup |
| **Resource Monitor** | جزئیات CPU/دیسک/شبکه |
| **Disk Cleanup** | آزادسازی فضا |
| **Disk Management** | پارتیشن‌بندی |
| **Device Manager** | درایورها |
| **Event Viewer** | لاگ سیستم |
| **System Restore** | بازگشت به نقطهٔ قبل |
| **`sfc /scannow`** | بررسی فایل‌های سیستمی |
| **`chkdsk`** | بررسی دیسک |
| **Windows Security** | آنتی‌ویروس و فایروال |

**ابزارهای لینوکس**

| ابزار | کار |
|---|---|
| `top` / `htop` | فرآیندها |
| `df` / `du` | فضای دیسک |
| `journalctl` | لاگ |
| `systemctl` | سرویس‌ها |
| `fsck` | بررسی فایل‌سیستم |

**فشرده‌سازی**

| فرمت | مزیت | عیب |
|---|---|---|
| **ZIP** | همه‌جا | فشرده‌سازی متوسط |
| **7z** | فشرده‌سازی بالا | نیاز به نرم‌افزار |
| **TAR.GZ** | لینوکس | بدون فشرده‌سازی ویندوزی |
| **RAR** | فشرده‌سازی بالا | لایسنس |

**نکتهٔ امنیتی:** فایل ZIP با رمز، یکی از راه‌های دور زدن آنتی‌ویروس است. ZIP ناشناس را باز نکن.

**آنتی‌ویروس**

| نوع | کار |
|---|---|
| **Signature-based** | امضای بدافزار شناخته‌شده |
| **Heuristic** | رفتار مشکوک |
| **Behavioral** | نظارت زنده |

**نکته:** آنتی‌ویروس **جایگزین** آپدیت و رفتار امن نیست. لایه‌ای از دفاع است.

**ابزارهای پاکسازی**

| ابزار | کار | ریسک |
|---|---|---|
| Disk Cleanup | فایل موقت | کم |
| Registry Cleaner | رجیستری | **بالا** |
| Driver Updater | درایور | متوسط |
| «PC Optimizer» | تبلیغاتی | **بالا** |

**هشدار:** بیشتر «بهینه‌سازها» تبلیغاتی و مضرند. ابزار رسمی سیستم‌عامل کافی است.

**نقطهٔ بازگشت (Restore Point)**

| مزیت | عیب |
|---|---|
| بازگشت سریع بعد از تغییر بد | فایل شخصی را برنمی‌گرداند |
| بدون نصب مجدد | مصرف فضا |

**قاعده:** قبل از آپدیت بزرگ یا نصب درایور، Restore Point بساز.

**Event Viewer — سه سطح**

| سطح | معنی |
|---|---|
| Information | رویداد عادی |
| Warning | هشدار |
| Error | خطا |

**نکته:** برای عیب‌یابی، روی Errorها و زمان وقوع تمرکز کن.

### مثال‌های عملی

**سناریوی Lab: نگه‌داری ماهانه**

```markdown
## چک‌لیست ماهانه

- [ ] آپدیت سیستم‌عامل
- [ ] آپدیت نرم‌افزارها (`winget upgrade --all`)
- [ ] بررسی فضای دیسک (زیر ۱۵٪ = هشدار)
- [ ] پاک کردن فایل موقت
- [ ] بررسی Event Viewer برای Error
- [ ] بررسی Startup
- [ ] اسکن آنتی‌ویروس
- [ ] تست پشتیبان (بازیابی یک فایل)
- [ ] بررسی سلامت دیسک (SMART)
```

**سناریوی دوم: آزادسازی فضا**

| گام | مقدار آزادشده |
|---|---|
| Disk Cleanup | ۱–۵ GB |
| حذف فایل‌های Download قدیمی | متغیر |
| حذف برنامهٔ بی‌استفاده | ۱–۱۰ GB |
| پاک کردن کش مرورگر | ۰.۵–۲ GB |
| حذف نسخه‌های قبلی ویندوز | ۵–۱۵ GB |

**نکته:** `WinSxS` را دستی پاک نکن. از `DISM` استفاده کن.

**سناریوی سوم: بررسی سلامت دیسک**

```powershell
# SMART status
Get-PhysicalDisk | Select FriendlyName, HealthStatus, OperationalStatus

# بررسی فایل‌سیستم
chkdsk C: /scan

# فایل‌های سیستمی
sfc /scannow
```

| نتیجه | معنی |
|---|---|
| Healthy | سالم |
| Warning | نشانهٔ خرابی قریب‌الوقوع |
| Unhealthy | تعویض فوری |

**سناریوی چهارم: بازیابی با Restore Point**

```
۱) Start → "Create a restore point"
۲) System Restore → Next
۳) انتخاب نقطه
۴) Scan for affected programs
۵) Next → Finish → ری‌استارت
```

**هشدار:** Restore Point فایل‌های شخصی را برنمی‌گرداند. فقط سیستم و برنامه‌ها.

### مقایسه و الگوهای مختلف

**سه سطح نگه‌داری**

| سطح | کار | زمان |
|---|---|---|
| روزانه | آپدیت خودکار، بررسی هشدار | ۵ دقیقه |
| ماهانه | چک‌لیست کامل | ۳۰ دقیقه |
| سالانه | بازبینی سخت‌افزار، تعویض باتری UPS | ۲ ساعت |

**الگوی «ابزار رسمی، نه تبلیغاتی»**

```
✅ Disk Cleanup، Defender، Device Manager
❌ "Super PC Cleaner 2026"
```

### اشکال شایع

**۱) Registry Cleaner**
می‌تواند سیستم را خراب کند. لازم نیست.

**۲) چند آنتی‌ویروس**
تداخل و کندی.

**۳) حذف `WinSxS`**
سیستم خراب می‌شود.

**۴) بدون Restore Point**
بازگشت سخت.

**۵) نادیده گرفتن SMART**
خرابی ناگهانی دیسک.

**۶) «بهینه‌ساز» تبلیغاتی**
بدافزار.

**۷) پاک کردن فایل سیستمی**
سیستم بوت نمی‌شود.

**۸) فرض «آنتی‌ویروس کافی است»**
رفتار امن هم لازم است.

### نکات مهم (Tips & Tricks)

- **چک‌لیست ماهانه** بساز.
- **ابزار رسمی** کافی است.
- **Restore Point قبل از تغییر بزرگ.**
- **SMART را ببین.**
- **یک آنتی‌ویروس.**
- **`WinSxS` را دستی پاک نکن.**
- **پشتیبان را تست کن، نه فقط بگیر.**

### خلاصه فصل

- ابزارهای سیستمی برای نگه‌داری و عیب‌یابی حیاتی‌اند.
- فشرده‌سازی ZIP همه‌جا، 7z بهتر.
- آنتی‌ویروس یک لایه است، نه همه‌چیز.
- «بهینه‌ساز»های تبلیغاتی مضرند.
- Restore Point سیستم را برمی‌گرداند، نه فایل شخصی.
- نگه‌داری ماهانه، از خرابی جلوگیری می‌کند.

## فصل ۴۶: انتخاب نرم‌افزار مناسب — Lab

### مقدمه

این فصل، همهٔ فایل را در یک تمرین تصمیم‌گیری جمع می‌کند: برای سه کاربر، مجموعهٔ نرم‌افزاری مناسب.

### مفاهیم اساسی

**چارچوب انتخاب**

```
۱) کار چیست؟
۲) با چه کسی همکاری می‌کنم؟
۳) آفلاین لازم است؟
۴) بودجه؟
۵) امنیت/مقرارات؟
```

**معیارهای ارزیابی**

| معیار | وزن |
|---|---|
| تناسب با کار | ۳۵٪ |
| سازگاری فایل | ۲۰٪ |
| هزینه | ۱۵٪ |
| همکاری | ۱۵٪ |
| امنیت | ۱۵٪ |

### مثال‌های عملی

**سناریوی Lab: سه کاربر، سه مجموعه**

**۱) دانشجو**

| نیاز | ابزار |
|---|---|
| نوشتن مقاله | Word / Google Docs |
| ارائه | PowerPoint / Slides |
| یادداشت | OneNote / Notion |
| PDF | Adobe Reader |
| مرجع | Zotero (رایگان) |

**انتخاب:** Google Workspace (رایگان با دانشگاه) یا LibreOffice.

**۲) حسابدار**

| نیاز | ابزار |
|---|---|
| صفحه‌گسترده | Excel |
| فاکتور | نرم‌افزار حسابداری |
| PDF | Acrobat |
| پشتیبان | OneDrive |

**انتخاب:** Microsoft 365 + نرم‌افزار تخصصی.

**۳) طراح**

| نیاز | ابزار |
|---|---|
| طراحی | Adobe CC / Affinity |
| عکس | Lightroom / Darktable |
| فونت | مدیر فونت |
| ارائه | Keynote / PowerPoint |

**انتخاب:** Adobe CC (اگر درآمد دارد) یا Affinity (یک‌بار خرید).

**جدول تصمیم**

| کاربر | بودجه | انتخاب |
|---|---|---|
| دانشجو | کم | رایگان/دانشگاهی |
| حسابدار | متوسط | Microsoft 365 |
| طراح | بالا | Adobe CC |

**سناریوی دوم: مهاجرت بین مجموعه‌ها**

| از | به | ریسک |
|---|---|---|
| Word | Google Docs | چیدمان |
| Excel | Sheets | فرمول پیچیده |
| PowerPoint | Slides | انیمیشن |

**راه‌حل:** فایل را در فرمت اصلی نگه دار، خروجی PDF برای اشتراک.

**سناریوی سوم: ارزیابی یک نرم‌افزار جدید**

```markdown
## چک‌لیست ارزیابی

- [ ] سازنده مشخص است؟
- [ ] امضای دیجیتال دارد؟
- [ ] از منبع رسمی دانلود شد؟
- [ ] مجوزها را می‌فهمم؟
- [ ] با فایل‌های موجود سازگار است؟
- [ ] پشتیبان‌گیری دارد؟
- [ ] آپدیت منظم دارد؟
- [ ] هزینهٔ کل (لایسنس + آموزش) چیست؟
```

### مقایسه و الگوهای مختلف

**سه استراتژی نرم‌افزار**

| استراتژی | مزیت | عیب |
|---|---|---|
| همه از یک فروشنده | یکپارچگی | قفل شدن |
| بهترین ابزار هر دسته | بهینه | پیچیدگی |
| متن‌باز | هزینه، آزادی | سازگاری |

**الگوی «ابزار اصلی + جایگزین»**

```
اصلی: Microsoft 365
جایگزین: LibreOffice (اگر لایسنس تمام شد)
```

داشتن جایگزین، وابستگی را کم می‌کند.

### اشکال شایع

**۱) خرید مجموعهٔ گران برای کار ساده**
هزینهٔ بی‌دلیل.

**۲) نرم‌افزار کرک‌شده**
بدافزار + قانونی.

**۳) نادیده گرفتن سازگاری**
فایل با همکار باز نمی‌شود.

**۴) ابزار زیاد**
پراکندگی. کمتر، بهتر.

**۵) بدون آموزش**
ابزار خوب با استفادهٔ بد، بی‌فایده است.

**۶) نادیده گرفتن هزینهٔ کل**
لایسنس + آموزش + مهاجرت.

**۷) انتخاب بر اساس تبلیغ**
نیاز را بسنج.

**۸) بدون پشتیبان**
ابزار عوض شد، داده ماند.

### نکات مهم (Tips & Tricks)

- **نیاز را اول بنویس.**
- **سازگاری فایل را چک کن.**
- **PDF برای اشتراک نهایی.**
- **ابزار اصلی + جایگزین.**
- **هزینهٔ کل، نه قیمت.**
- **آموزش را حساب کن.**
- **چک‌لیست ارزیابی** برای هر نرم‌افزار جدید.

### خلاصه فصل

- انتخاب نرم‌افزار با نیاز شروع می‌شود، نه با برند.
- سازگاری فایل، معیار کلیدی است.
- PDF برای اشتراک، فرمت اصلی برای ویرایش.
- هزینهٔ کل شامل آموزش و مهاجرت است.
- ابزار جایگزین، وابستگی را کم می‌کند.
- چک‌لیست ارزیابی، انتخاب آگاهانه می‌سازد.
