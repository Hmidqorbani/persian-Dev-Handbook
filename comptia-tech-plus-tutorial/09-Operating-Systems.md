<a name="ch-37"></a>
## فصل ۳۷: سیستم‌عامل چیست و چه می‌کند؟

### مقدمه

سخت‌افزار بدون سیستم‌عامل، مثل کارخانه‌ای بدون مدیر است: همهٔ ماشین‌ها هستند، ولی هیچ‌کس هماهنگ نمی‌کند. سیستم‌عامل (OS) همان مدیر است.

در آزمون Tech+، دامنهٔ «برنامه‌ها و نرم‌افزار» (۱۸٪) با سیستم‌عامل شروع می‌شود.

### مفاهیم اساسی

**پنج وظیفهٔ سیستم‌عامل**

| وظیفه | توضیح | مثال |
|---|---|---|
| **مدیریت پردازنده** | زمان‌بندی فرآیندها | اجرای همزمان چند برنامه |
| **مدیریت حافظه** | تخصیص RAM | جلوگیری از تداخل |
| **مدیریت ذخیره‌سازی** | فایل‌ها و پوشه‌ها | NTFS، ext4 |
| **مدیریت دستگاه‌ها** | درایور و I/O | چاپگر، ماوس |
| **رابط کاربر** | GUI یا CLI | دسکتاپ، ترمینال |

**دو وظیفهٔ اضافی مهم**

- **امنیت**: احراز هویت، مجوز فایل، جداسازی کاربران.
- **مدیریت خطا**: جلوگیری از توقف کل سیستم با خطای یک برنامه.

**لایه‌های سیستم‌عامل**

```
┌─────────────────────────┐
│  برنامه‌های کاربری       │
├─────────────────────────┤
│  کتابخانه‌های سیستم       │
├─────────────────────────┤
│  کرنل (Kernel)          │  ← قلب سیستم‌عامل
├─────────────────────────┤
│  درایورها               │
├─────────────────────────┤
│  سخت‌افزار               │
└─────────────────────────┘
```

**کرنل (Kernel)**

هستهٔ سیستم‌عامل که مستقیم با سخت‌افزار حرف می‌زند.

| نوع کرنل | توضیح | مثال |
|---|---|---|
| **Monolithic** | همه‌چیز در یک فضای حافظه | لینوکس |
| **Microkernel** | حداقل در کرنل | QNX |
| **Hybrid** | ترکیب | ویندوز NT |

**حالت کاربر در برابر حالت کرنل**

| حالت | دسترسی | مثال |
|---|---|---|
| **User mode** | محدود | برنامه‌های عادی |
| **Kernel mode** | کامل | درایور، کرنل |

**چرا؟** اگر برنامه‌ای در user mode خراب شود، سیستم پایدار می‌ماند. اگر در kernel mode خراب شود → Blue Screen.

**فرآیند و رشته**

| مفهوم | توضیح |
|---|---|
| **Process** | برنامهٔ در حال اجرا با حافظهٔ مستقل |
| **Thread** | واحد اجرا داخل یک process |
| **Context switch** | تعویض بین processها |

**سیستم‌عامل‌های ۳۲ و ۶۴ بیتی**

| معیار | ۳۲ بیت | ۶۴ بیت |
|---|---|---|
| حداکثر RAM | ~۴ GB | بسیار بیشتر |
| نرم‌افزار | قدیمی | امروز |
| کارایی | کم | بالا |

**نکته:** نرم‌افزار ۳۲ بیتی روی ۶۴ بیتی اجرا می‌شود، ولی برعکس نه.

**سیستم‌عامل‌های بلادرنگ (RTOS)**

| ویژگی | توضیح |
|---|---|
| زمان‌بندی قطعی | پاسخ در زمان مشخص |
| کاربرد | خودرو، پزشکی، صنعتی |
| مثال | FreeRTOS، VxWorks |

**Embedded OS**

در دستگاه‌های ثابت: روتر، چاپگر، ماشین لباسشویی. معمولاً سبک و بدون رابط گرافیکی.

### مثال‌های عملی

**سناریوی Lab: «چرا سیستم کند شده؟» با مدل OS**

| منبع | بررسی | ابزار |
|---|---|---|
| CPU | درصد استفاده | Task Manager |
| RAM | مصرف و Page File | Performance |
| دیسک | Active time | Resource Monitor |
| شبکه | پهنای باند | Network tab |
| فرآیند | برنامهٔ پرمصرف | Processes |

**گام ۱ — Task Manager**

```
CPU: 12%
RAM: 94%   ← گلوگاه
Disk: 8%
Network: 2%
```

**گام ۲ — نتیجه**

RAM گلوگاه است. سیستم از Page File استفاده می‌کند.

**گام ۳ — راه‌حل**

- بستن برنامه‌های پس‌زمینه.
- ارتقای RAM.

**سناریوی دوم: Blue Screen (BSOD)**

| کد | معنی رایج |
|---|---|
| `IRQL_NOT_LESS_OR_EQUAL` | درایور |
| `PAGE_FAULT_IN_NONPAGED_AREA` | RAM/درایور |
| `CRITICAL_PROCESS_DIED` | فایل سیستمی |
| `INACCESSIBLE_BOOT_DEVICE` | دیسک/کنترلر |

**روش عیب‌یابی:**

1. کد را یادداشت کن.
2. آخرین تغییر (درایور/آپدیت) را برگردان.
3. `sfc /scannow` و `chkdsk`.
4. تست RAM.

**سناریوی سوم: انتخاب نسخهٔ ویندوز**

| نسخه | مناسب برای |
|---|---|
| Home | کاربر خانگی |
| Pro | کسب‌وکار کوچک، Domain، BitLocker |
| Enterprise | سازمان بزرگ |
| Education | مدارس |

**تفاوت کلیدی:** Pro قابلیت Domain Join و BitLocker دارد؛ Home نه.

### مقایسه و الگوهای مختلف

**سه معماری سیستم‌عامل**

| معماری | مزیت | عیب |
|---|---|---|
| Monolithic | سرعت | پایداری کمتر |
| Microkernel | پایداری | سربار پیام |
| Hybrid | تعادل | پیچیدگی |

**الگوی «سیستم‌عامل مناسب، نه جدیدترین»**

سیستم‌عامل جدید ممکن است درایور نداشته باشد. برای سخت‌افزار قدیمی، نسخهٔ پایدارتر بهتر است.

### اشکال شایع

**۱) قاطی کردن RAM و دیسک در عیب‌یابی**
«کند است» می‌تواند هر کدام باشد. اندازه بگیر.

**۲) نصب درایور ۳۲ بیتی روی ۶۴ بیتی**
کار نمی‌کند.

**۳) فرض «Blue Screen یعنی سخت‌افزار خراب»**
اغلب درایور است.

**۴) نادیده گرفتن Page File**
RAM کم، دیسک را پر می‌کند.

**۵) نصب چند آنتی‌ویروس**
تداخل و کندی.

**۶) آپدیت بدون پشتیبان**
بازگشت سخت.

**۷) استفاده از Home برای محیط Domain**
قابلیت ندارد.

**۸) فراموش کردن لایسنس**
قانونی و امنیتی.

### نکات مهم (Tips & Tricks)

- **پنج وظیفهٔ OS** را حفظ کن.
- **Kernel mode = خطر BSOD.**
- **۳۲ بیت ≈ ۴GB RAM.**
- **Task Manager** اولین ابزار.
- **کد BSOD** را یادداشت کن.
- **Pro برای Domain و BitLocker.**
- **آپدیت با پشتیبان.**

### خلاصه فصل

- سیستم‌عامل پنج وظیفه دارد: پردازنده، حافظه، ذخیره‌سازی، دستگاه، رابط.
- کرنل، هستهٔ دسترسی به سخت‌افزار است.
- User mode و kernel mode جداسازی امنیتی می‌سازند.
- ۶۴ بیتی محدودیت RAM را برداشته.
- RTOS برای زمان‌بندی قطعی.
- Task Manager چهار منبع را نشان می‌دهد.

<a name="ch-38"></a>
## فصل ۳۸: خانواده‌های سیستم‌عامل — ویندوز، مک، لینوکس، موبایل

### مقدمه

چهار خانوادهٔ اصلی، هر کدام فلسفهٔ متفاوتی دارند. دانستن تفاوت‌ها، هم در آزمون لازم است هم در انتخاب درست.

### مفاهیم اساسی

**ویندوز**

| نسخه | سال | نکته |
|---|---|---|
| Windows 10 | ۲۰۱۵ | پشتیبانی تا ۲۰۲۵ |
| Windows 11 | ۲۰۲۱ | TPM 2.0 لازم |
| Windows Server | — | نسخهٔ سرور |

**مزیت:** سازگاری نرم‌افزار، بازی، سازمان.
**عیب:** آپدیت اجباری، تبلیغات، مصرف منابع.

**macOS**

| ویژگی | توضیح |
|---|---|
| پایه | Unix (Darwin) |
| سخت‌افزار | فقط اپل |
| فایل‌سیستم | APFS |
| مزیت | یکپارچگی، عمر باتری |

**لینوکس**

| توزیع | مناسب برای |
|---|---|
| Ubuntu | مبتدی، سرور |
| Debian | پایدار، سرور |
| Fedora | جدیدترین |
| Arch | کاربر پیشرفته |
| RHEL | سازمانی |

**مزیت:** رایگان، باز، قابل تنظیم، پایدار در سرور.
**عیب:** سازگاری نرم‌افزار تجاری، نیاز به یادگیری.

**ChromeOS**

| ویژگی | توضیح |
|---|---|
| پایه | لینوکس + Chrome |
| ذخیره‌سازی | ابری |
| مناسب | آموزش، کار سبک |

**اندروید**

| ویژگی | توضیح |
|---|---|
| پایه | لینوکس |
| فروشگاه | Play Store |
| سفارشی‌سازی | زیاد (تولیدکنندگان) |

**iOS/iPadOS**

| ویژگی | توضیح |
|---|---|
| پایه | Darwin |
| بسته | نصب فقط از App Store |
| مزیت | امنیت، یکپارچگی |

**مقایسهٔ کلی**

| معیار | ویندوز | macOS | لینوکس | ChromeOS |
|---|---|---|---|---|
| قیمت | متوسط | بالا | رایگان | کم |
| سازگاری نرم‌افزار | بالا | متوسط | متوسط | کم |
| امنیت | متوسط | بالا | بالا | بالا |
| سفارشی‌سازی | متوسط | کم | بالا | کم |
| سرور | ✅ | کم | ✅ | ❌ |
| بازی | ✅ | متوسط | متوسط | ❌ |

**سیستم‌عامل سرور در برابر دسکتاپ**

| معیار | دسکتاپ | سرور |
|---|---|---|
| رابط | GUI کامل | CLI/حداقلی |
| سرویس‌ها | متنوع | تخصصی |
| پایداری | متوسط | بالا |
| لایسنس | تک‌کاربر | چندکاربر |

**نکته:** Windows Server و Ubuntu Server رابط گرافیکی دارند، ولی معمولاً بدون GUI نصب می‌شوند.

### مثال‌های عملی

**سناریوی Lab: انتخاب سیستم‌عامل**

**کاربر A: گیمر**
- نیاز: بازی، درایور گرافیک.
- **انتخاب: Windows 11.**

**کاربر B: طراح گرافیک**
- نیاز: Adobe، دقت رنگ.
- **انتخاب: macOS** (یا ویندوز با مانیتور کالیبره).

**کاربر C: سرور وب**
- نیاز: پایداری، هزینهٔ کم.
- **انتخاب: Ubuntu Server LTS.**

**کاربر D: دانش‌آموز**
- نیاز: وب، متن، قیمت کم.
- **انتخاب: ChromeOS** یا لینوکس سبک.

**جدول تصمیم**

| اگر… | انتخاب |
|---|---|
| بازی | ویندوز |
| طراحی/ویدئو | macOS |
| سرور | لینوکس |
| بودجهٔ کم | ChromeOS/لینوکس |
| امنیت حداکثری | macOS/لینوکس |

**سناریوی دوم: تفاوت مسیر فایل**

| سیستم | مسیر |
|---|---|
| ویندوز | `C:\Users\Ali\Documents` |
| macOS | `/Users/ali/Documents` |
| لینوکس | `/home/ali/Documents` |

**نکته:** ویندوز از `\` و درایو استفاده می‌کند؛ یونیکس از `/` و یک درخت واحد.

**سناریوی سوم: مجوز فایل**

| سیستم | مدل |
|---|---|
| ویندوز | ACL (کاربر/گروه با مجوزهای دقیق) |
| یونیکس | `rwx` برای owner/group/other |
| macOS | ترکیب POSIX + ACL |

```bash
chmod 755 script.sh
# owner: rwx، group: r-x، other: r-x
```

### مقایسه و الگوهای مختلف

**سه فلسفهٔ طراحی**

| فلسفه | مثال | اصل |
|---|---|---|
| بسته | iOS | کنترل کامل، امنیت |
| باز | لینوکس | آزادی، سفارشی‌سازی |
| ترکیبی | ویندوز | سازگاری، تنوع |

**الگوی «دو سیستم‌عامل، یک دستگاه»**

- **Dual Boot**: انتخاب در بوت.
- **VM**: اجرای همزمان.
- **WSL**: لینوکس داخل ویندوز.

**WSL (Windows Subsystem for Linux)** برای توسعه‌دهندگان عالی است: ابزار لینوکس بدون ترک ویندوز.

### اشکال شایع

**۱) فرض «مک ویروس نمی‌گیرد»**
می‌گیرد. کمتر، ولی می‌گیرد.

**۲) «لینوکس برای همه»**
برای کاربر عادی با نرم‌افزار تجاری، سخت است.

**۳) نصب macOS روی سخت‌افزار غیراپل**
غیرقانونی و ناپایدار.

**۴) قاطی کردن مسیر فایل**
`\` و `/` را اشتباه نکن.

**۵) فرض «ChromeOS فقط مرورگر است»**
برنامه‌های اندروید و لینوکس هم اجرا می‌کند.

**۶) نادیده گرفتن مجوز فایل**
`chmod 777` امنیت را نابود می‌کند.

**۷) آپدیت نکردن**
حفره‌های شناخته‌شده.

**۸) انتخاب بر اساس مد**
نیاز را بسنج.

### نکات مهم (Tips & Tricks)

- **ویندوز برای سازگاری، مک برای یکپارچگی، لینوکس برای سرور.**
- **LTS را انتخاب کن** (پشتیبانی طولانی).
- **WSL برای توسعه.**
- **`chmod 777` ممنوع.**
- **مسیر فایل را با `/` و `\` اشتباه نکن.**
- **مجوز فایل را بفهم.**
- **آپدیت منظم.**

### خلاصه فصل

- چهار خانواده: ویندوز، macOS، لینوکس، موبایل.
- ویندوز سازگار، مک یکپارچه، لینوکس باز و پایدار.
- ChromeOS سبک و ابری.
- اندروید و iOS دو مدل متفاوت امنیتی.
- مسیر فایل و مجوز در ویندوز و یونیکس متفاوت است.
- انتخاب بر اساس نیاز، نه مد.

<a name="ch-39"></a>
## فصل ۳۹: فایل‌سیستم‌ها — NTFS، FAT32، exFAT، ext4، APFS

### مقدمه

فایل‌سیستم، «نقشهٔ» ذخیره‌سازی است: تعیین می‌کند فایل کجا ذخیره شود، چه مجوزی داشته باشد، و چه محدودیتی داشته باشد.

انتخاب اشتباه، می‌تواند باعث شود فلش شما روی مک کار نکند، یا فایل ۵ گیگابایتی کپی نشود.

### مفاهیم اساسی

**فایل‌سیستم چیست؟**

ساختاری که سیستم‌عامل برای سازمان‌دهی داده روی دیسک استفاده می‌کند.

| کار | توضیح |
|---|---|
| نام‌گذاری | مسیر و نام فایل |
| سازمان‌دهی | پوشه و فایل |
| مجوز | چه کسی دسترسی دارد |
| فراداده | تاریخ، اندازه، نوع |
| مدیریت فضای آزاد | کدام بلوک آزاد است |

**جدول مقایسه**

| فایل‌سیستم | سیستم‌عامل | حداکثر فایل | حداکثر حجم | مجوز | ژورنال |
|---|---|---|---|---|---|
| **FAT32** | همه | ۴ GB | ۲ TB | ❌ | ❌ |
| **exFAT** | همه | ۱۶ EB | ۱۲۸ PB | ❌ | ❌ |
| **NTFS** | ویندوز | ۱۶ EB | ۲۵۶ TB | ✅ | ✅ |
| **ext4** | لینوکس | ۱۶ TB | ۱ EB | ✅ | ✅ |
| **APFS** | macOS | ۸ EB | — | ✅ | ✅ |
| **HFS+** | macOS قدیم | ۸ EB | — | ✅ | ✅ |

**FAT32 — سازگار ولی محدود**

| مزیت | عیب |
|---|---|
| همه‌جا کار می‌کند | فایل حداکثر ۴GB |
| ساده | بدون مجوز |
| — | بدون ژورنال |

**نکتهٔ عملی:** اگر فایل ۵ گیگابایتی روی فلش کپی نمی‌شود، فلش FAT32 است.

**exFAT — جایگزین FAT32**

| مزیت | عیب |
|---|---|
| بدون محدودیت ۴GB | بدون مجوز |
| سازگار با همه | ژورنال ندارد |

**مناسب برای:** فلش، کارت SD، انتقال بین سیستم‌ها.

**NTFS — استاندارد ویندوز**

| ویژگی | توضیح |
|---|---|
| مجوز | ACL کامل |
| ژورنال | بازیابی پس از قطع برق |
| فشرده‌سازی | ✅ |
| رمزنگاری | EFS |
| سهمیه | ✅ |
| Snapshot | Shadow Copy |

**محدودیت:** macOS به‌صورت پیش‌فرض فقط **خواندن** NTFS را پشتیبانی می‌کند.

**ext4 — استاندارد لینوکس**

| ویژگی | توضیح |
|---|---|
| ژورنال | ✅ |
| مجوز | POSIX |
| حجم | تا ۱EB |
| پایداری | بالا |

**APFS — استاندارد مک**

| ویژگی | توضیح |
|---|---|
| Copy-on-Write | کارایی |
| Snapshot | ✅ |
| رمزنگاری | بومی |
| SSD-optimized | ✅ |

**ژورنالینگ چیست؟**

قبل از نوشتن داده، تغییر در یک «ژورنال» ثبت می‌شود. اگر برق قطع شود، سیستم می‌داند چه کاری نیمه‌کاره مانده.

| بدون ژورنال | با ژورنال |
|---|---|
| فایل خراب | بازیابی |

**پارتیشن‌بندی**

| سبک | حداکثر پارتیشن | حداکثر دیسک | بوت |
|---|---|---|---|
| **MBR** | ۴ | ۲ TB | BIOS |
| **GPT** | ۱۲۸ | ۹.۴ ZB | UEFI |

**نکته:** برای دیسک بالای ۲TB یا UEFI، GPT لازم است.

**فرمت‌بندی سریع در برابر کامل**

| نوع | کار |
|---|---|
| Quick Format | فقط جدول فایل پاک می‌شود |
| Full Format | سطح دیسک بررسی/پاک می‌شود |

**هشدار:** هر دو، داده را غیرقابل دسترس می‌کنند. برای پاکسازی امن، ابزار مخصوص.

### مثال‌های عملی

**سناریوی Lab: انتخاب فایل‌سیستم برای فلش**

| استفاده | فایل‌سیستم |
|---|---|
| فایل ۴GB+، ویندوز و مک | **exFAT** |
| فقط ویندوز | NTFS |
| دستگاه قدیمی (TV، دوربین) | FAT32 |
| فلش بوت ویندوز | NTFS یا FAT32 |
| فلش بوت لینوکس | FAT32 (UEFI) |

**سناریوی دوم: «فلش روی مک فقط خوانده می‌شود»**

| علت | راه‌حل |
|---|---|
| NTFS | exFAT یا نرم‌افزار NTFS for Mac |
| مجوز فایل | بررسی مجوز |
| فلش خراب | تست با `chkdsk` |

**سناریوی سوم: تبدیل فایل‌سیستم**

```powershell
# ویندوز: FAT32 به NTFS (بدون از دست دادن داده)
convert X: /fs:ntfs

# برعکسش ممکن نیست بدون فرمت
```

**هشدار:** قبل از هر تبدیل، پشتیبان بگیر.

**سناریوی چهارم: بررسی فایل‌سیستم**

```bash
# ویندوز
fsutil fsinfo volumeinfo C:

# لینوکس
df -T
lsblk -f

# مک
diskutil list
```

### مقایسه و الگوهای مختلف

**سه گروه فایل‌سیستم**

| گروه | مثال | مناسب |
|---|---|---|
| سازگار | FAT32، exFAT | انتقال |
| امن | NTFS، ext4، APFS | سیستم‌عامل |
| تخصصی | ZFS، Btrfs | سرور، snapshot |

**الگوی «exFAT برای انتقال، NTFS/ext4 برای سیستم»**

```
دیسک سیستم: NTFS (ویندوز) یا ext4 (لینوکس)
فلش انتقال: exFAT
پشتیبان شبکه: بسته به NAS
```

### اشکال شایع

**۱) FAT32 برای فایل بزرگ**
۴GB محدودیت. exFAT.

**۲) NTFS برای مک**
فقط خواندن. exFAT.

**۳) فرمت بدون پشتیبان**
داده می‌رود.

**۴) MBR برای دیسک ۴TB**
۲TB قابل استفاده است. GPT.

**۵) `chmod 777`**
امنیت نابود. مجوز دقیق.

**۶) فرض «Quick Format امن است»**
داده با ابزار بازیابی برمی‌گردد.

**۷) پارتیشن بدون فضای آزاد**
سیستم کند می‌شود.

**۸) فراموش کردن ژورنال**
قطع برق = فایل خراب.

### نکات مهم (Tips & Tricks)

- **exFAT برای فلش چندسیستمی.**
- **NTFS برای ویندوز، ext4 برای لینوکس.**
- **GPT برای دیسک بالای ۲TB.**
- **ژورنالینگ را جدی بگیر.**
- **فرمت با پشتیبان.**
- **Quick Format ≠ پاکسازی امن.**
- **`df -T` و `fsutil` برای بررسی.**

### خلاصه فصل

- فایل‌سیستم، سازمان‌دهی و مجوز داده را تعیین می‌کند.
- FAT32 سازگار ولی محدود به ۴GB.
- exFAT جایگزین مدرن برای انتقال.
- NTFS برای ویندوز، ext4 برای لینوکس، APFS برای مک.
- ژورنالینگ از خرابی پس از قطع برق جلوگیری می‌کند.
- GPT برای دیسک‌های بزرگ و UEFI.

## فصل ۴۰: رابط‌ها — GUI و خط فرمان

### مقدمه

دو راه برای حرف زدن با کامپیوتر: کلیک کردن (GUI) یا تایپ کردن (CLI). هر کدام مزیت خودش را دارد و حرفه‌ای‌ها هر دو را می‌دانند.

### مفاهیم اساسی

**GUI — رابط گرافیکی**

| عنصر | کار |
|---|---|
| دسکتاپ | فضای اصلی |
| Taskbar/Dock | نوار برنامه‌ها |
| پنجره | برنامهٔ باز |
| منو | گزینه‌ها |
| آیکون | میان‌بر |

**مزیت:** یادگیری آسان، کشف‌پذیری.
**عیب:** کند برای کارهای تکراری، مصرف منابع.

**CLI — رابط خط فرمان**

| سیستم | پوسته |
|---|---|
| ویندوز | CMD، PowerShell |
| لینوکس/مک | Bash، Zsh |
| — | Fish |

**مزیت:** سریع، قابل اسکریپت، دقیق.
**عیب:** نیاز به حفظ دستور.

**دستورهای پایه — ویندوز**

| دستور | کار |
|---|---|
| `dir` | لیست فایل‌ها |
| `cd` | تغییر پوشه |
| `ipconfig` | تنظیمات شبکه |
| `ping` | تست اتصال |
| `tracert` | مسیر |
| `nslookup` | DNS |
| `tasklist` | فرآیندها |
| `sfc /scannow` | بررسی فایل سیستمی |
| `chkdsk` | بررسی دیسک |

**دستورهای پایه — لینوکس**

| دستور | کار |
|---|---|
| `ls` | لیست |
| `cd` | تغییر پوشه |
| `pwd` | مسیر فعلی |
| `cp` / `mv` / `rm` | کپی/جابه‌جایی/حذف |
| `grep` | جستجو |
| `chmod` | مجوز |
| `ps` | فرآیندها |
| `df` / `du` | فضای دیسک |
| `ip a` | آدرس‌ها |

**PowerShell — قدرتمندتر از CMD**

| ویژگی | توضیح |
|---|---|
| شیءگرا | خروجی شیء است، نه متن |
| Pipeline | `Get-Process \| Where CPU -gt 50` |
| اسکریپت | `.ps1` |

```powershell
Get-Service | Where-Object Status -eq 'Running'
Get-ChildItem -Recurse | Measure-Object -Property Length -Sum
```

**مسیرها**

| سیستم | مسیر ریشه | جداکننده |
|---|---|---|
| ویندوز | `C:\` | `\` |
| لینوکس/مک | `/` | `/` |

**مسیر نسبی در برابر مطلق**

| نوع | مثال |
|---|---|
| مطلق | `C:\Users\Ali\file.txt` |
| نسبی | `.\file.txt` |

**میان‌برهای مسیر**

| نماد | معنی |
|---|---|
| `.` | پوشهٔ فعلی |
| `..` | پوشهٔ والد |
| `~` | خانهٔ کاربر (لینوکس) |

**متغیرهای محیطی**

| سیستم | مثال |
|---|---|
| ویندوز | `%PATH%` |
| لینوکس | `$PATH` |

**چرا PATH مهم است؟** تعیین می‌کند سیستم دستور را کجا جستجو کند.

### مثال‌های عملی

**سناریوی Lab: همان کار، دو رابط**

**کار: پیدا کردن فایل‌های بزرگ‌تر از ۱۰۰MB**

GUI: جستجو در File Explorer → اندازه → مرتب‌سازی. کند.

CLI (PowerShell):

```powershell
Get-ChildItem C:\ -Recurse -File -ErrorAction SilentlyContinue |
  Where-Object Length -gt 100MB |
  Sort-Object Length -Descending |
  Select-Object -First 10 FullName, @{N='MB';E={[math]::Round($_.Length/1MB)}}
```

CLI (لینوکس):

```bash
find / -type f -size +100M -exec ls -lh {} \; 2>/dev/null | head -10
```

**درس:** CLI برای کارهای تکراری و پیچیده، چند برابر سریع‌تر است.

**سناریوی دوم: عیب‌یابی شبکه با CLI**

```bash
ipconfig /all          # تنظیمات
ping 8.8.8.8           # اتصال
nslookup example.com   # DNS
tracert example.com    # مسیر
netstat -an            # پورت‌ها
```

**این پنج دستور، ۸۰٪ عیب‌یابی شبکه را پوشش می‌دهند.**

**سناریوی سوم: اسکریپت ساده**

```powershell
# پشتیبان‌گیری از یک پوشه
$src = "C:\Work"
$dst = "D:\Backup\$(Get-Date -Format yyyy-MM-dd)"
New-Item -ItemType Directory -Path $dst -Force | Out-Null
Copy-Item "$src\*" $dst -Recurse -Force
```

**مزیت:** تکرارپذیر و قابل زمان‌بندی.

### مقایسه و الگوهای مختلف

**GUI در برابر CLI**

| معیار | GUI | CLI |
|---|---|---|
| یادگیری | آسان | سخت |
| سرعت کار تکراری | کم | بالا |
| اسکریپت | ❌ | ✅ |
| منابع | زیاد | کم |
| دقت | متوسط | بالا |

**الگوی «GUI برای کشف، CLI برای تکرار»**

اول با GUI یاد بگیر، بعد با CLI خودکار کن.

### اشکال شایع

**۱) ترس از CLI**
با ۵ دستور شروع کن.

**۲) کپی کردن دستور بدون فهم**
می‌تواند خطرناک باشد (`rm -rf`).

**۳) اجرا بدون دسترسی ادمین**
دستور کار نمی‌کند.

**۴) مسیر با فاصله و بدون کوتیشن**
`cd My Folder` خطا می‌دهد. `cd "My Folder"`.

**۵) فراموش کردن `sudo`**
لینوکس اجازه نمی‌دهد.

**۶) استفاده از CMD به‌جای PowerShell**
قابلیت کمتر.

**۷) اسکریپت بدون تست**
می‌تواند داده را پاک کند.

**۸) نادیده گرفتن PATH**
«command not found» یعنی مسیر نیست.

### نکات مهم (Tips & Tricks)

- **پنج دستور شبکه** را حفظ کن.
- **PowerShell شیءگراست.**
- **مسیر با فاصله = کوتیشن.**
- **`..` والد، `.` فعلی.**
- **`--help` و `man`** دوست تو هستند.
- **اسکریپت را اول در محیط تست اجرا کن.**
- **GUI برای کشف، CLI برای تکرار.**

### خلاصه فصل

- GUI آسان، CLI سریع و قابل اسکریپت.
- دستورهای شبکه: `ipconfig`، `ping`، `nslookup`، `tracert`، `netstat`.
- PowerShell شیءگرا و قدرتمندتر از CMD.
- مسیر مطلق و نسبی را بشناس.
- PATH تعیین می‌کند دستور کجا جستجو شود.
- اسکریپت، کار تکراری را خودکار می‌کند.

<a name="ch-41"></a>
## فصل ۴۱: مدیریت نرم‌افزار — نصب، آپدیت، درایور

### مقدمه

نصب نرم‌افزار ساده به نظر می‌رسد: دانلود، Next، Next، Finish. اما منبع دانلود، مجوز، و آپدیت، سه تصمیمی است که امنیت و پایداری را تعیین می‌کند.

### مفاهیم اساسی

**منابع نصب**

| منبع | امنیت | نکته |
|---|---|---|
| **فروشگاه رسمی** (Microsoft Store، App Store) | بالا | تأییدشده |
| **سایت سازنده** | بالا | نسخهٔ رسمی |
| **مدیر بسته** (apt، winget، brew) | بالا | امضاشده |
| **سایت‌های دانلود ثالث** | **پایین** | بدافزار |
| **تورنت/کرک** | **بسیار پایین** | بدافزار + قانونی |

**قاعده:** فقط از منبع رسمی. اگر نرم‌افزار پولی است، لایسنس بخر.

**انواع لایسنس**

| نوع | توضیح |
|---|---|
| **Proprietary** | بسته، خرید |
| **Open Source** | کد باز، رایگان |
| **Freeware** | رایگان، بسته |
| **Shareware** | آزمایشی |
| **Subscription** | اشتراک ماهانه |

**مدیران بسته**

| سیستم | ابزار |
|---|---|
| ویندوز | `winget`، Chocolatey |
| macOS | `brew` |
| لینوکس (Debian) | `apt` |
| لینوکس (RedHat) | `dnf` |

```bash
# نمونه‌ها
winget install Microsoft.PowerShell
brew install --cask firefox
sudo apt install nginx
```

**مزیت:** آپدیت یکجا، بدون جستجوی سایت.

**آپدیت — سه نوع**

| نوع | مثال | اهمیت |
|---|---|---|
| **سیستم‌عامل** | Windows Update | بالا |
| **نرم‌افزار** | مرورگر، Office | بالا |
| **درایور** | گرافیک، چاپگر | متوسط |

**چرا آپدیت مهم است؟**

بیشتر حملات موفق، از حفره‌های **شناخته‌شده و وصله‌شده** استفاده می‌کنند. آپدیت نکردن، یعنی «درِ باز».

**درایور — نصب درست**

| گام | کار |
|---|---|
| ۱ | مدل دقیق دستگاه را بردار |
| ۲ | از سایت سازنده دانلود کن |
| ۳ | نسخهٔ سازگار با OS |
| ۴ | نصب و ری‌استارت |
| ۵ | تست |

**Rollback درایور**

اگر آپدیت درایور مشکل ساخت:

```
Device Manager → دستگاه → Properties → Driver → Roll Back
```

**حذف نرم‌افزار**

| روش | نکته |
|---|---|
| Settings → Apps | استاندارد |
| Uninstaller سازنده | کامل‌تر |
| حذف دستی پوشه | **بد** — رجیستری می‌ماند |

**باقی‌مانده‌ها**

| نوع | محل |
|---|---|
| فایل‌ها | `AppData`، `ProgramData` |
| رجیستری | `HKCU`، `HKLM` |
| سرویس | Services |
| Startup | Task Manager → Startup |

**نرم‌افزار پرتابل (Portable)**

بدون نصب اجرا می‌شود. مناسب فلش. عیب: آپدیت دستی.

**مدیریت چند نسخه**

| مشکل | راه‌حل |
|---|---|
| تداخل DLL | نصب در پوشهٔ جدا |
| نسخهٔ قدیمی لازم | VM یا Container |
| وابستگی | مدیر بسته |

### مثال‌های عملی

**سناریوی Lab: نصب امن یک نرم‌افزار**

**نرم‌افزار:** یک ابزار رایگان PDF.

**گام ۱ — منبع**

| گزینه | ارزیابی |
|---|---|
| سایت سازنده | ✅ |
| Microsoft Store | ✅ |
| اولین نتیجهٔ تبلیغاتی گوگل | ❌ |
| سایت دانلود ایرانی/خارجی | ❌ |

**گام ۲ — بررسی فایل**

| بررسی | کار |
|---|---|
| امضای دیجیتال | راست‌کلیک → Properties → Digital Signatures |
| هش (SHA-256) | با سایت سازنده مقایسه |
| حجم | غیرعادی نباشد |
| VirusTotal | آپلود و بررسی |

**گام ۳ — نصب**

گزینه‌های اضافی (نوار ابزار، تغییر مرورگر) را **رد** کن.

**گام ۴ — بعد از نصب**

```markdown
- [ ] برنامه در لیست Apps دیده می‌شود
- [ ] نسخهٔ درست است
- [ ] آپدیت خودکار تنظیم شد
- [ ] در Startup نیست (اگر لازم نیست)
```

**سناریوی دوم: آپدیت درایور گرافیک**

| گام | کار |
|---|---|
| ۱ | مدل GPU را از Device Manager بردار |
| ۲ | سایت NVIDIA/AMD/Intel |
| ۳ | نسخهٔ ویندوز و معماری |
| ۴ | نصب (Clean Install اگر مشکل داشت) |
| ۵ | تست بازی/برنامه |

**نکته:** آپدیت گرافیک، بیشترین اثر را روی بازی و رندر دارد.

**سناریوی سوم: پاکسازی نرم‌افزار**

```powershell
# لیست برنامه‌های نصب‌شده
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* |
  Select-Object DisplayName, DisplayVersion, Publisher |
  Sort-Object DisplayName
```

**سناریوی چهارم: Startup**

```
Task Manager → Startup → Disable برای برنامه‌های غیرضروری
```

**اثر:** بوت سریع‌تر و RAM آزادتر.

### مقایسه و الگوهای مختلف

**سه روش نصب**

| روش | مزیت | عیب |
|---|---|---|
| نصب‌کننده (EXE/MSI) | استاندارد | باقی‌مانده |
| مدیر بسته | آپدیت یکجا | وابسته به منبع |
| پرتابل | بدون نصب | آپدیت دستی |

**الگوی «مدیر بسته برای همه‌چیز»**

```powershell
winget upgrade --all
```

یک دستور، همهٔ برنامه‌ها را آپدیت می‌کند.

### اشکال شایع

**۱) دانلود از سایت ثالث**
بدافزار. فقط منبع رسمی.

**۲) نصب کرک**
بدافزار + قانونی. لایسنس بخر.

**۳) رد نکردن گزینه‌های اضافی**
نوار ابزار و تغییر مرورگر.

**۴) آپدیت نکردن**
حفرهٔ شناخته‌شده.

**۵) نصب چند آنتی‌ویروس**
تداخل. یکی کافی است.

**۶) حذف دستی پوشه**
رجیستری می‌ماند. Uninstaller.

**۷) درایور بتا در تولید**
ناپایدار. نسخهٔ WHQL.

**۸) بدون پشتیبان قبل از آپدیت بزرگ**
بازگشت سخت.

### نکات مهم (Tips & Tricks)

- **فقط منبع رسمی.**
- **امضای دیجیتال را چک کن.**
- **مدیر بسته برای آپدیت یکجا.**
- **Rollback درایور را یاد بگیر.**
- **Startup را مرتب کن.**
- **Uninstaller، نه حذف دستی.**
- **آپدیت با پشتیبان.**

### خلاصه فصل

- منابع نصب از امن به ناامن: فروشگاه، سازنده، مدیر بسته، سایت ثالث، کرک.
- مدیر بسته آپدیت را ساده می‌کند.
- سه نوع آپدیت: سیستم‌عامل، نرم‌افزار، درایور.
- درایور را از سازنده و با نسخهٔ سازگار بگیر.
- Rollback برای درایور مشکل‌دار.
- Startup و باقی‌مانده‌ها را مدیریت کن.
