<a name="ch-69"></a>
## فصل ۶۹: CIA — سه ستون امنیت

### مقدمه

امنیت، «نصب آنتی‌ویروس» نیست. یک چارچوب فکری است. ساده‌ترین و مفیدترین چارچوب، سه حرف است: **CIA**.

دامنهٔ امنیت، ۱۹٪ آزمون Tech+ است — دومین حوزهٔ سنگین. و همهٔ آن با همین سه مفهوم شروع می‌شود.

### مفاهیم اساسی

**سه ستون**

| حرف | معنی | سؤال |
|---|---|---|
| **C**onfidentiality | محرمانگی | چه کسی می‌بیند؟ |
| **I**ntegrity | یکپارچگی | دست‌نخورده است؟ |
| **A**vailability | دسترس‌پذیری | در دسترس است؟ |

**مثال‌ها**

| سناریو | کدام ستون نقض شد؟ |
|---|---|
| فایل بیماران لو رفت | محرمانگی |
| مبلغ فاکتور تغییر کرد | یکپارچگی |
| سایت با DDoS خوابید | دسترس‌پذیری |
| رمز عبور لو رفت | محرمانگی |
| تاریخ تراکنش دستکاری شد | یکپارچگی |

**مثلث تعادل**

```
        محرمانگی
           /\
          /  \
         /    \
یکپارچگی ──── دسترس‌پذیری
```

**نکته:** تقویت یک ستون، می‌تواند ستون دیگر را ضعیف کند. رمزنگاری قوی، محرمانگی را بالا می‌برد ولی دسترس‌پذیری را کمی کم می‌کند (سربار).

**احراز هویت در برابر مجوز**

| مفهوم | سؤال |
|---|---|
| **Authentication** | تو کی هستی؟ |
| **Authorization** | چه کاری می‌توانی بکنی؟ |
| **Accounting** | چه کاری کردی؟ |

**AAA** = Authentication, Authorization, Accounting.

**سه عامل احراز هویت**

| عامل | مثال |
|---|---|
| **Something you know** | رمز، PIN |
| **Something you have** | گوشی، توکن |
| **Something you are** | اثر انگشت، چهره |

**MFA** = دو یا بیشتر از این سه.

**اصل حداقل دسترسی**

> هر کاربر، فقط دسترسی لازم برای کارش را داشته باشد.

**اصل تفکیک وظایف**

> کار حساس، به دو نفر تقسیم شود (مثلاً تأیید پرداخت).

**Defense in Depth**

لایه‌های دفاع:

```
۱) سیاست و آموزش
۲) امنیت فیزیکی
۳) شبکه (فایروال)
۴) میزبان (آنتی‌ویروس، وصله)
۵) داده (رمزنگاری، پشتیبان)
```

اگر یک لایه بشکند، بقیه می‌مانند.

**Zero Trust**

> هیچ‌کس، داخل یا بیرون، به‌طور پیش‌فرض قابل اعتماد نیست.

| سنتی | Zero Trust |
|---|---|
| داخل شبکه = امن | هر درخواست بررسی |
| VPN کافی است | احراز هویت مداوم |

### مثال‌های عملی

**سناریوی Lab: تحلیل یک حادثه با CIA**

**حادثه:** کارمندی فایل مشتریان را در ایمیل شخصی می‌فرستد؛ ایمیل هک می‌شود.

| ستون | نقض؟ | چرا |
|---|---|---|
| محرمانگی | ✅ | داده لو رفت |
| یکپارچگی | ⚠️ | ممکن است تغییر کند |
| دسترس‌پذیری | ❌ | — |

**اقدامات:**

| لایه | اقدام |
|---|---|
| سیاست | ممنوعیت ایمیل شخصی |
| فنی | DLP (جلوگیری از نشت) |
| آموزش | آگاهی |
| نظارت | لاگ ارسال |

**سناریوی دوم: تعادل ستون‌ها**

**درخواست:** «همهٔ فایل‌ها را رمزنگاری کنیم و رمز را فقط مدیر ارشد داشته باشد.»

| ستون | اثر |
|---|---|
| محرمانگی | ✅ بالا |
| دسترس‌پذیری | ❌ پایین (اگر مدیر در دسترس نباشد) |
| یکپارچگی | ✅ |

**راه‌حل متعادل:** رمزنگاری + مدیریت کلید با چند نفر (key escrow) + رویهٔ اضطراری.

**سناریوی سوم: AAA در عمل**

```
ورود به سیستم:
۱. Authentication: نام کاربری + رمز + کد پیامکی
۲. Authorization: نقش «حسابدار» → دسترسی به فاکتورها، نه تنظیمات
۳. Accounting: لاگ «Ali در ۱۰:۳۲ فاکتور #۱۲۳ را دید»
```

### مقایسه و الگوهای مختلف

**سه مدل کنترل دسترسی**

| مدل | توضیح |
|---|---|
| **DAC** | مالک تصمیم می‌گیرد |
| **MAC** | برچسب امنیتی |
| **RBAC** | بر اساس نقش |

**RBAC** رایج‌ترین در سازمان است.

**الگوی «کمترین امتیاز»**

```markdown
- [ ] هر کاربر نقش مشخص دارد
- [ ] دسترسی‌های موقت تاریخ انقضا دارند
- [ ] دسترسی‌های قدیمی بازبینی می‌شوند
- [ ] حساب ادمین برای کار روزمره استفاده نمی‌شود
```

### اشکال شایع

**۱) تمرکز فقط روی محرمانگی**
یکپارچگی و دسترس‌پذیری هم مهم‌اند.

**۲) قاطی کردن احراز هویت و مجوز**
ورود ≠ دسترسی.

**۳) دسترسی همه‌کاره**
نقض حداقل دسترسی.

**۴) MFA فقط برای ادمین**
همهٔ کاربران لازم دارند.

**۵) بدون لاگ**
حسابرسی ممکن نیست.

**۶) رمزنگاری بدون مدیریت کلید**
بی‌فایده.

**۷) فرض «داخل شبکه امن است»**
Zero Trust.

**۸) یک لایه دفاع**
Defense in depth.

### نکات مهم (Tips & Tricks)

- **CIA** را با مثال حفظ کن.
- **Authentication ≠ Authorization.**
- **سه عامل احراز هویت.**
- **حداقل دسترسی.**
- **Defense in depth.**
- **Zero Trust.**
- **لاگ برای حسابرسی.**

### خلاصه فصل

- CIA: محرمانگی، یکپارچگی، دسترس‌پذیری.
- AAA: احراز هویت، مجوز، حسابرسی.
- سه عامل: چیزی که می‌دانی/داری/هستی.
- حداقل دسترسی و تفکیک وظایف.
- Defense in depth چند لایه می‌سازد.
- Zero Trust هیچ‌چیز را پیش‌فرض قابل اعتماد نمی‌داند.

## فصل ۷۰: تهدیدها و مهندسی اجتماعی

### مقدمه

تهدید، فقط بدافزار نیست. بسیاری از نفوذهای موفق، با یک تماس تلفنی یا یک ایمیل شروع می‌شوند — بدون هیچ کد مخربی. این فصل، عاملان تهدید و تکنیک‌های مهندسی اجتماعی را می‌شکند تا بتوانی الگو را تشخیص بدهی، نه فقط مورد را.

### مفاهیم اساسی

**عاملان تهدید**

| عامل | انگیزه | مهارت |
|---|---|---|
| **Script kiddie** | کنجکاوی، شهرت | کم |
| **Hacktivist** | ایدئولوژی | متوسط |
| **Insider** | انتقام، پول | بالا (دسترسی) |
| **Cybercriminal** | پول | متوسط تا بالا |
| **APT** | جاسوسی، سیاسی | بسیار بالا |

**APT** = Advanced Persistent Threat: حملهٔ طولانی، هدفمند، پنهان.

**دسته‌بندی حملات**

| دسته | مثال |
|---|---|
| **مهندسی اجتماعی** | فیشینگ، pretexting |
| **فنی** | بدافزار، exploits |
| **فیزیکی** | سرقت، tailgating |
| **شبکه** | DDoS، MITM |

**مهندسی اجتماعی**

> دستکاری انسان برای افشای اطلاعات یا انجام کار.

| تکنیک | توضیح |
|---|---|
| **Phishing** | ایمیل جعلی |
| **Spear phishing** | هدفمند، شخصی‌سازی‌شده |
| **Whaling** | هدف: مدیر ارشد |
| **Vishing** | تلفنی |
| **Smishing** | پیامک |
| **Pretexting** | داستان ساختگی |
| **Baiting** | طعمه (فلش آلوده) |
| **Tailgating** | ورود پشت سر |
| **Shoulder surfing** | نگاه به صفحه |

**نشانه‌های فیشینگ**

| نشانه | مثال |
|---|---|
| فوریت | «۲۴ ساعت فرصت داری» |
| تهدید | «حساب مسدود می‌شود» |
| درخواست رمز | «رمزت را تأیید کن» |
| دامنهٔ مشابه | `rnicrosoft.com` |
| لینک ناهماهنگ | متن ≠ مقصد |
| پیوست غیرمنتظره | `.zip`، `.exe` |
| سلام عمومی | «کاربر گرامی» |

**حملهٔ فنی رایج**

| حمله | توضیح |
|---|---|
| **DDoS** | پر کردن با ترافیک |
| **MITM** | شنود بین دو طرف |
| **SQL Injection** | تزریق کوئری |
| **XSS** | تزریق اسکریپت |
| **Ransomware** | رمز کردن داده |
| **Brute force** | حدس مکرر رمز |
| **Credential stuffing** | رمزهای لو رفته |

**آسیب‌پذیری در برابر تهدید در برابر ریسک**

| مفهوم | معنی |
|---|---|
| **Vulnerability** | حفره |
| **Threat** | تهدید |
| **Risk** | احتمال × اثر |

```
ریسک = احتمال × اثر
```

**مدیریت ریسک**

| استراتژی | کار |
|---|---|
| **Mitigate** | کاهش |
| **Transfer** | انتقال (بیمه) |
| **Avoid** | اجتناب |
| **Accept** | پذیرش |

### مثال‌های عملی

**سناریوی Lab: تحلیل یک حملهٔ spear phishing**

**پیام:**

```
از: hr@company-hr-portal.com
به: ali@company.com
موضوع: بازبینی حقوق ۱۴۰۵ — اقدام فوری

علی عزیز،
بر اساس ارزیابی عملکرد، حقوق شما ۱۸٪ افزایش یافته.
برای مشاهدهٔ جزئیات، وارد پورتال شوید:
https://company-hr-portal.com/login?token=abc

با تشکر،
واحد منابع انسانی
```

**تحلیل:**

| نشانه | بررسی |
|---|---|
| شخصی‌سازی | نام و موضوع مرتبط |
| دامنه | `company-hr-portal.com` ≠ دامنهٔ شرکت |
| فوریت | «اقدام فوری» |
| لینک | `token` در URL |
| HTTPS | دارد (ولی کافی نیست) |

**اقدام درست:**

1. کلیک نکن.
2. آدرس را دستی تایپ کن.
3. با HR تماس بگیر (شمارهٔ داخلی، نه از ایمیل).
4. گزارش به تیم امنیت.

**سناریوی دوم: محاسبهٔ ریسک**

| آسیب‌پذیری | احتمال | اثر | ریسک |
|---|---|---|---|
| وصله‌نشدن سرور | بالا | بالا | **بحرانی** |
| رمز ضعیف کاربر | متوسط | متوسط | متوسط |
| فلش بدون رمز | کم | بالا | متوسط |

**اولویت:** بحرانی → متوسط → کم.

**سناریوی سوم: tailgating**

```
مهاجم با دست پر، پشت کارمند وارد در می‌شود.
کارمند برای کمک، در را باز نگه می‌دارد.
```

**دفاع:** آموزش، درهای قفل‌دار، بج‌زنی اجباری، میز پذیرش.

### مقایسه و الگوهای مختلف

**سه سطح آموزش**

| سطح | محتوا |
|---|---|
| پایه | تشخیص فیشینگ |
| متوسط | رویهٔ گزارش |
| پیشرفته | تمرین شبیه‌سازی |

**الگوی «شبیه‌سازی فیشینگ»**

ایمیل تستی بفرست و نرخ کلیک را بسنج. آموزش هدفمند برای کسانی که کلیک کردند.

### اشکال شایع

**۱) «ما هدف نیستیم»**
همه هدف‌اند.

**۲) آموزش یک‌بار**
فراموش می‌شود. دوره‌ای.

**۳) تمرکز فقط روی فناوری**
انسان، ضعیف‌ترین حلقه.

**۴) تنبیه کسی که گزارش می‌دهد**
دفعهٔ بعد گزارش نمی‌دهد.

**۵) بدون رویهٔ گزارش**
کارمند نمی‌داند چه کند.

**۶) نادیده گرفتن insider**
دسترسی داخلی، خطرناک‌ترین.

**۷) بدون مدیریت وصله**
حفرهٔ شناخته‌شده.

**۸) فرض «HTTPS = امن»**
دامنهٔ جعلی هم HTTPS دارد.

### نکات مهم (Tips & Tricks)

- **نشانه‌های فیشینگ** را حفظ کن.
- **کلیک نکن، تایپ کن.**
- **گزارش را آسان کن.**
- **آموزش دوره‌ای.**
- **ریسک = احتمال × اثر.**
- **HTTPS ≠ اعتماد.**
- **insider را جدی بگیر.**

### خلاصه فصل

- پنج عامل تهدید با انگیزه‌های متفاوت.
- مهندسی اجتماعی، انسان را هدف می‌گیرد.
- فیشینگ نشانه‌های قابل تشخیص دارد.
- ریسک = احتمال × اثر.
- چهار استراتژی مدیریت ریسک.
- آموزش و رویهٔ گزارش، بهترین دفاع.

## فصل ۷۱: بدافزارها — انواع و رفتار

### مقدمه

«ویروس» کلمه‌ای است که برای همهٔ بدافزارها استفاده می‌شود، ولی از نظر فنی فقط یکی از ده نوع است. تفاوت‌ها مهم‌اند، چون رفتار دفاعی هر نوع متفاوت است: Worm خودش پخش می‌شود، Trojan منتظر کلیک توست، Ransomware داده را گروگان می‌گیرد.

### مفاهیم اساسی

**دسته‌بندی بدافزار**

| نوع | رفتار |
|---|---|
| **Virus** | نیاز به فایل میزبان، تکثیر |
| **Worm** | خودتکثیر، بدون میزبان |
| **Trojan** | ظاهر مفید، رفتار مخرب |
| **Ransomware** | رمز کردن داده |
| **Spyware** | جمع‌آوری اطلاعات |
| **Adware** | تبلیغات |
| **Rootkit** | پنهان‌سازی در سطح سیستم |
| **Keylogger** | ثبت کلیدها |
| **Botnet** | شبکهٔ دستگاه‌های آلوده |
| **Cryptominer** | استخراج رمزارز |

**Virus در برابر Worm**

| معیار | Virus | Worm |
|---|---|---|
| میزبان | نیاز دارد | ندارد |
| انتشار | با اجرای فایل | خودکار در شبکه |
| سرعت | کند | سریع |

**Trojan — اسب تروآ**

برنامهٔ مفید ظاهری که در پشتش بدافزار دارد.

| مثال | ظاهر |
|---|---|
| «کرک نرم‌افزار» | ابزار |
| «بهینه‌ساز» | ابزار |
| «بازی رایگان» | بازی |

**Ransomware — چرخهٔ حمله**

```
۱) ورود (فیشینگ، RDP باز)
۲) استقرار (نصب بدافزار)
۳) شناسایی (جستجوی فایل‌های ارزشمند)
۴) رمزنگاری (AES + کلید RSA)
۵) اخاذی (درخواست باج)
```

**نکته:** کلید رمزگشایی روی سرور مهاجم است. پرداخت باج، تضمینی نیست.

**Spyware و Keylogger**

| نوع | کار |
|---|---|
| Spyware | جمع‌آوری مرور، ایمیل |
| Keylogger | ثبت کلیدها (رمز!) |

**Rootkit**

در سطح کرنل یا فریمور پنهان می‌شود. تشخیص سخت، حذف سخت‌تر.

**Botnet**

شبکهٔ دستگاه‌های آلوده که از راه دور کنترل می‌شوند.

| کاربرد | مثال |
|---|---|
| DDoS | حمله به سایت |
| Spam | ارسال ایمیل |
| Mining | استخراج رمزارز |

**نشانه‌های آلودگی**

| نشانه | توضیح |
|---|---|
| کندی ناگهانی | CPU/دیسک بالا |
| پنجره‌های تبلیغاتی | Adware |
| تغییر صفحهٔ اصلی مرورگر | Hijacker |
| فایل‌های رمزشده | Ransomware |
| آنتی‌ویروس خاموش | بدافزار |
| ترافیک شبکهٔ غیرعادی | Botnet |

**زنجیرهٔ آلودگی**

```
ورود → اجرا → استقرار → ارتباط با C2 → اقدام
```

**C2** = Command and Control server.

**دفاع چندلایه**

| لایه | ابزار |
|---|---|
| ورود | فیلتر ایمیل، آگاهی |
| اجرا | آنتی‌ویروس، allowlist |
| استقرار | EDR، مانیتورینگ |
| ارتباط | فایروال، DNS filtering |
| بازیابی | پشتیبان آفلاین |

### مثال‌های عملی

**سناریوی Lab: تحلیل یک فایل مشکوک**

**موقعیت:** کاربر فایل `invoice.pdf.exe` را دریافت کرده.

| بررسی | نتیجه |
|---|---|
| پسوند دوگانه | `.pdf.exe` — ترفند |
| آیکون | PDF |
| امضای دیجیتال | ندارد |
| VirusTotal | ۴۲/۷۰ تشخیص |
| حجم | ۲۴ KB (کوچک، مشکوک) |

**اقدام:** حذف، گزارش، اسکن سیستم.

**سناریوی دوم: پاسخ به ransomware**

```markdown
۱. دستگاه را از شبکه جدا کن (کابل/Wi-Fi)
۲. خاموش نکن (شواهد در RAM)
۳. به تیم امنیت اطلاع بده
۴. پشتیبان آفلاین را بررسی کن
۵. باج نده
۶. از پشتیبان بازیابی کن
۷. ریشه را پیدا کن (چطور وارد شد؟)
۸. وصله و آموزش
```

**نکته:** جدا کردن از شبکه، مهم‌ترین گام اول است.

**سناریوی سوم: محاسبهٔ خسارت**

```
۱۰۰ دستگاه × ۴ ساعت توقف = ۴۰۰ ساعت کار
× ۵۰ دلار = ۲۰٬۰۰۰ دلار
+ بازیابی: ۸۰ ساعت × ۵۰ = ۴٬۰۰۰
+ دادهٔ از دست رفته: متغیر
────────────────────────
جمع: ۲۴٬۰۰۰+ دلار
```

در برابر هزینهٔ EDR (مثلاً ۳٬۰۰۰ دلار سالانه) — ارزش دارد.

### مقایسه و الگوهای مختلف

**سه سطح دفاع**

| سطح | ابزار |
|---|---|
| پایه | آنتی‌ویروس + آپدیت |
| متوسط | + EDR + فیلتر ایمیل |
| بالا | + SIEM + تیم SOC |

**الگوی «allowlist»**

به‌جای «چه چیزی ممنوع است»، بگو «چه چیزی مجاز است». برای محیط‌های حساس، مؤثرتر.

### اشکال شایع

**۱) «مک/لینوکس ویروس نمی‌گیرد»**
می‌گیرد، کمتر.

**۲) چند آنتی‌ویروس**
تداخل.

**۳) آنتی‌ویروس بدون آپدیت**
بی‌فایده.

**۴) کلیک روی `.exe` ناشناس**
آلودگی.

**۵) پرداخت باج**
تضمینی نیست و حمله را تشویق می‌کند.

**۶) خاموش کردن دستگاه آلوده**
شواهد از بین می‌رود (اما در ransomware، جدا کردن از شبکه اولویت دارد).

**۷) بدون EDR**
آنتی‌ویروس سنتی، بدافزار مدرن را نمی‌بیند.

**۸) فراموش کردن فریمور**
Rootkit در فریمور.

### نکات مهم (Tips & Tricks)

- **دسته‌ها** را با رفتار حفظ کن.
- **Virus میزبان می‌خواهد، Worm نه.**
- **پسوند دوگانه** = مشکوک.
- **جدا کردن از شبکه** اولویت اول.
- **باج نده.**
- **EDR برای بدافزار مدرن.**
- **پشتیبان آفلاین.**

### خلاصه فصل

- ده نوع بدافزار با رفتارهای متفاوت.
- Virus میزبان می‌خواهد؛ Worm خودتکثیر است.
- Trojan ظاهر مفید دارد.
- Ransomware پنج مرحله دارد.
- نشانه‌های آلودگی را بشناس.
- دفاع چندلایه، تنها راه مؤثر.

<a name="ch-72"></a>
## فصل ۷۲: امنیت شبکه — فایروال، IDS/IPS، VPN

### مقدمه

امنیت شبکه، لایهٔ دفاعی بین اینترنت و دستگاه‌های توست. چهار ابزار اصلی وجود دارد و هر کدام کار متفاوتی می‌کند: فایروال دروازه را می‌بندد، IDS نگاه می‌کند، IPS جلوی مهاجم را می‌گیرد، و VPN تونل امن می‌سازد.

### مفاهیم اساسی

**فایروال**

| نوع | کار |
|---|---|
| **Packet filter** | IP/پورت |
| **Stateful** | دنبال نشست |
| **Application (WAF)** | محتوا |
| **NGFW** | همه + IDS/IPS |

**قاعدهٔ فایروال**

```
ALLOW 443 from any to web-server
ALLOW 22 from 10.0.0.0/8 to servers
DENY all
```

**اصل:** پیش‌فرض DENY.

**DMZ**

```
اینترنت → فایروال → DMZ (سرور عمومی)
                    ↓
                  فایروال داخلی → شبکهٔ داخلی
```

سرورهای عمومی در DMZ، جدا از شبکهٔ داخلی.

**IDS در برابر IPS**

| معیار | IDS | IPS |
|---|---|---|
| کار | تشخیص | تشخیص + جلوگیری |
| محل | خارج مسیر | در مسیر |
| اثر | هشدار | بلاک |

**روش‌های تشخیص**

| روش | کار |
|---|---|
| **Signature** | الگوی شناخته‌شده |
| **Anomaly** | رفتار غیرعادی |
| **Behavior** | تحلیل رفتار |

**VPN**

تونل رمزنگاری‌شده بین دو نقطه.

| نوع | کاربرد |
|---|---|
| **Remote access** | کاربر به سازمان |
| **Site-to-site** | دفتر به دفتر |

**پروتکل‌های VPN**

| پروتکل | امنیت |
|---|---|
| **WireGuard** | بالا، مدرن |
| **IPsec** | بالا، استاندارد |
| **OpenVPN** | بالا |
| **PPTP** | **ناامن** |
| **L2TP/IPsec** | متوسط |

**نکته:** VPN رایگان، اغلب داده را می‌فروشد. برای کار، VPN سازمانی.

**NAT و امنیت**

NAT به‌طور جانبی، دسترسی مستقیم از بیرون را سخت می‌کند — ولی **امنیت نیست**.

**Segmentation**

| نوع | کار |
|---|---|
| **VLAN** | جداسازی منطقی |
| **Subnet** | جداسازی IP |
| **Physical** | جداسازی فیزیکی |

**مزیت:** اگر یک بخش آلوده شود، انتشار محدود است.

**Zero Trust Network Access (ZTNA)**

جای VPN سنتی: دسترسی به برنامه، نه کل شبکه.

**Wi-Fi امن**

| پروتکل | وضعیت |
|---|---|
| WEP | ❌ |
| WPA | ❌ |
| WPA2 | ⚠️ |
| WPA3 | ✅ |

### مثال‌های عملی

**سناریوی Lab: طراحی امنیت شبکهٔ کوچک**

```
اینترنت
   ↓
[فایروال/روتر]
   ├── DMZ: وب‌سرور (۴۴۳)
   ├── VLAN 10: کارمندان
   ├── VLAN 20: مهمان (فقط اینترنت)
   └── VLAN 30: IoT (بدون دسترسی داخلی)
```

**قواعد:**

| از | به | پورت | اجازه |
|---|---|---|---|
| اینترنت | وب‌سرور | ۴۴۳ | ✅ |
| اینترنت | داخلی | هر | ❌ |
| کارمندان | وب‌سرور | ۴۴۳ | ✅ |
| مهمان | داخلی | هر | ❌ |
| IoT | اینترنت | ۸۰/۴۴۳ | ⚠️ محدود |

**سناریوی دوم: VPN برای دورکاری**

```markdown
۱. VPN سازمانی با MFA
۲. دسترسی فقط به منابع لازم (نه کل شبکه)
۳. لاگ اتصال
۴. قطع خودکار بعد از بی‌کاری
۵. دستگاه مدیریت‌شده (نه شخصی)
```

**سناریوی سوم: تشخیص نفوذ**

```
لاگ فایروال:
۱۲:۰۱  DENY 203.0.113.5 → 22
۱۲:۰۱  DENY 203.0.113.5 → 23
۱۲:۰۲  DENY 203.0.113.5 → 3389
...
```

**تحلیل:** اسکن پورت. اقدام: بلاک IP، بررسی لاگ‌های دیگر.

### مقایسه و الگوهای مختلف

**سه سطح امنیت شبکه**

| سطح | ابزار |
|---|---|
| پایه | فایروال + WPA3 |
| متوسط | + IDS/IPS + VLAN |
| بالا | + ZTNA + SIEM |

**الگوی «DMZ برای هر سرویس عمومی»**

هر سرویس اینترنتی، در DMZ — نه در شبکهٔ داخلی.

### اشکال شایع

**۱) فایروال خاموش**
امنیت صفر.

**۲) ALLOW all**
فایروال بی‌فایده.

**۳) RDP عمومی**
هدف باج‌گیر.

**۴) VPN بدون MFA**
رمز لو رفته = دسترسی کامل.

**۵) PPTP**
ناامن.

**۶) IoT در شبکهٔ اصلی**
دروازهٔ ورود.

**۷) بدون لاگ**
نمی‌دانی چه شد.

**۸) فرض «NAT = امنیت»**
NAT امنیت نیست.

### نکات مهم (Tips & Tricks)

- **پیش‌فرض DENY.**
- **DMZ برای عمومی.**
- **IDS تشخیص، IPS جلوگیری.**
- **VPN + MFA.**
- **VLAN برای جداسازی.**
- **WPA3.**
- **لاگ و مانیتورینگ.**

### خلاصه فصل

- فایروال چهار نوع دارد؛ NGFW جامع‌ترین.
- DMZ سرویس‌های عمومی را جدا می‌کند.
- IDS هشدار، IPS بلاک.
- VPN تونل رمزنگاری‌شده است؛ PPTP ناامن.
- Segmentation انتشار را محدود می‌کند.
- ZTNA جایگزین مدرن VPN است.

## فصل ۷۳: رمز عبور، MFA و مدیریت هویت

### مقدمه

رمز عبور، قدیمی‌ترین و همچنان مهم‌ترین لایهٔ احراز هویت است — و ضعیف‌ترین حلقه در بیشتر سازمان‌ها. این فصل، توصیه‌های مدرن (NIST) را با واقعیت عملی ترکیب می‌کند و نشان می‌دهد چرا «رمز پیچیدهٔ کوتاه» دیگر کافی نیست.

### مفاهیم اساسی

**رمز خوب**

| معیار | مقدار |
|---|---|
| طول | ۱۲+ کاراکتر |
| ترکیب | حروف، عدد، نماد |
| یکتا | برای هر سرویس |
| بدون الگو | نه اسم، نه تاریخ |

**NIST SP 800-63B — توصیه‌های مدرن**

| توصیه | توضیح |
|---|---|
| طول مهم‌تر از پیچیدگی | عبارت طولانی |
| بدون تغییر اجباری دوره‌ای | مگر نشانهٔ نفوذ |
| چک لیست رمزهای لو رفته | ✅ |
| بدون راهنمای رمز | «نام حیوان خانگی» نده |
| پشتیبانی از رمز بلند | تا ۶۴+ |

**عبارت عبور (Passphrase)**

```
❌ Tr0ub4dor&3      (کوتاه، سخت یادآوری)
✅ blue-table-river-sky-42   (بلند، آسان)
```

**مدیر رمز**

| مزیت | عیب |
|---|---|
| رمز یکتا برای هر سایت | نقطهٔ تمرکز |
| تولید قوی | نیاز به رمز اصلی قوی |
| پر کردن خودکار | — |

**قاعده:** رمز اصلی قوی + MFA روی حساب مدیر رمز.

**MFA**

| نوع | امنیت |
|---|---|
| **SMS** | متوسط (SIM swap) |
| **TOTP** (اپ) | بالا |
| **Push** | بالا (با عدد تطبیق) |
| **Hardware key** (FIDO2) | **بالاترین** |
| **Biometric** | بالا |

**نکته:** FIDO2 مقاوم به فیشینگ است؛ TOTP نه.

**SSO**

یک ورود برای چند سرویس.

| مزیت | عیب |
|---|---|
| تجربهٔ کاربری | تک‌نقطهٔ خرابی |
| مدیریت متمرکز | اگر لو رفت، همه |

**Privileged Access Management (PAM)**

| کار | توضیح |
|---|---|
| خزانهٔ رمز | ذخیرهٔ رمز ادمین |
| دسترسی موقت | Just-in-time |
| ضبط نشست | حسابرسی |

**سیاست رمز در سازمان**

```markdown
- [ ] حداقل ۱۲ کاراکتر
- [ ] MFA برای همه
- [ ] مدیر رمز سازمانی
- [ ] بدون تغییر اجباری ۹۰ روزه
- [ ] بررسی رمزهای لو رفته
- [ ] حساب ادمین جدا
- [ ] قفل بعد از تلاش ناموفق
```

### مثال‌های عملی

**سناریوی Lab: ارتقای امنیت حساب**

**وضعیت:** رمز `Summer2024!` برای ۱۰ سایت.

**مشکل:**

| مشکل | اثر |
|---|---|
| تکراری | یکی لو برود، همه |
| قابل حدس | دیکشنری |
| بدون MFA | دسترسی آسان |

**راه‌حل:**

```markdown
۱. مدیر رمز نصب کن
۲. رمز اصلی ۲۰+ کاراکتر
۳. برای هر سایت رمز یکتا
۴. MFA روی ایمیل و بانک
۵. رمزهای قدیمی را بچرخان
```

**سناریوی دوم: حملهٔ credential stuffing**

```
مهاجم لیست ۱ میلیون ایمیل/رمز لو رفته را دارد.
روی ۱۰۰ سایت تست می‌کند.
۰.۱٪ موفق = ۱۰۰۰ حساب.
```

**دفاع:** رمز یکتا + MFA + تشخیص رفتار.

**سناریوی سوم: SIM swap**

```
مهاجم با مهندسی اجتماعی، سیم‌کارت را به نام خودش منتقل می‌کند.
کد SMS به او می‌رسد.
حساب را می‌گیرد.
```

**دفاع:** TOTP یا FIDO2 به‌جای SMS؛ PIN روی سیم‌کارت؛ آگاهی.

**سناریوی چهارم: حساب ادمین**

```markdown
- [ ] حساب ادمین فقط برای مدیریت
- [ ] حساب روزمره جدا
- [ ] MFA سخت‌افزاری برای ادمین
- [ ] دسترسی JIT (موقت)
- [ ] لاگ همهٔ اقدامات
```

### مقایسه و الگوهای مختلف

**سه سطح MFA**

| سطح | روش |
|---|---|
| پایه | SMS |
| متوسط | TOTP |
| بالا | FIDO2 |

**الگوی «رمز + MFA + مدیر رمز»**

سه‌گانهٔ استاندارد برای کاربر عادی.

### اشکال شایع

**۱) رمز تکراری**
credential stuffing.

**۲) رمز کوتاه**
brute force.

**۳) تغییر اجباری ۹۰ روزه**
رمز ضعیف‌تر می‌شود.

**۴) SMS به‌تنهایی**
SIM swap.

**۵) نوشتن رمز روی کاغذ کنار مانیتور**
افشا.

**۶) حساب ادمین روزمره**
شعاع انفجار.

**۷) بدون مدیر رمز**
بازگشت به رمز تکراری.

**۸) MFA فقط برای ادمین**
همه لازم دارند.

### نکات مهم (Tips & Tricks)

- **طول مهم‌تر از پیچیدگی.**
- **رمز یکتا برای هر سرویس.**
- **مدیر رمز + MFA.**
- **FIDO2 بهترین.**
- **SMS ضعیف‌ترین.**
- **حساب ادمین جدا.**
- **NIST: بدون تغییر اجباری.**

### خلاصه فصل

- رمز خوب: بلند، یکتا، بدون الگو.
- NIST طول را بر پیچیدگی ترجیح می‌دهد.
- مدیر رمز، رمز یکتا را ممکن می‌کند.
- MFA از SMS تا FIDO2.
- SSO راحتی و ریسک تمرکز.
- PAM دسترسی ممتاز را مدیریت می‌کند.
