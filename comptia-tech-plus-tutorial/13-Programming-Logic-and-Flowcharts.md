## فصل ۵۶: الگوریتم و شبه‌کد — فکر کردن قبل از نوشتن

### مقدمه

بیشتر مبتدی‌ها بلافاصله شروع به تایپ کد می‌کنند. حرفه‌ای‌ها اول **فکر می‌کنند**. ابزار فکر کردن، الگوریتم و شبه‌کد است.

### مفاهیم اساسی

**الگوریتم چیست؟**

دنباله‌ای متناهی و دقیق از گام‌ها برای حل یک مسئله.

**پنج ویژگی**

| ویژگی | معنی |
|---|---|
| **ورودی مشخص** | دادهٔ ورودی معلوم |
| **خروجی مشخص** | نتیجهٔ معلوم |
| **دقت** | هر گام بی‌ابهام |
| **متناهی بودن** | پایان دارد |
| **عمومیت** | برای همهٔ ورودی‌های معتبر |

**شبه‌کد (Pseudocode)**

کدی شبیه زبان انسان که ساختار برنامه را نشان می‌دهد، بدون وابستگی به سینتکس.

```
BEGIN
  READ price
  READ quantity
  total ← price × quantity
  IF total > 1000 THEN
     total ← total × 0.9
  END IF
  PRINT total
END
```

**مزیت:** مستقل از زبان، قابل بحث با غیرفنی‌ها، قابل تبدیل به هر زبان.

**نمادهای شبه‌کد**

| نماد | معنی |
|---|---|
| `←` یا `=` | انتساب |
| `IF ... THEN ... ELSE` | شرط |
| `WHILE ... DO` | حلقه |
| `FOR i ← 1 TO n` | حلقهٔ شمارشی |
| `READ` | ورودی |
| `PRINT` | خروجی |
| `RETURN` | بازگشت |

**الگوریتم در زندگی روزمره**

```
الگوریتم درست کردن چای:
۱. کتری را پر کن
۲. کتری را روی حرارت بگذار
۳. تا جوش آمدن صبر کن
۴. چای‌کیسه را در فنجان بگذار
۵. آب جوش را بریز
۶. ۵ دقیقه صبر کن
۷. چای‌کیسه را بردار
```

همان پنج ویژگی را دارد: ورودی، خروجی، دقت، پایان، عمومیت.

**سه ساختار کنترلی پایه**

هر الگوریتم، از سه ساختار ساخته می‌شود:

| ساختار | کار |
|---|---|
| **Sequence** | ترتیب |
| **Selection** | انتخاب |
| **Iteration** | تکرار |

این «قضیهٔ ساختاری» است: هر برنامه‌ای با این سه قابل نوشتن است.

**پیچیدگی — مفهوم ساده**

| نماد | معنی | مثال |
|---|---|---|
| O(1) | ثابت | دسترسی به آرایه |
| O(n) | خطی | جستجوی ساده |
| O(n²) | مربعی | حلقهٔ تودرتو |
| O(log n) | لگاریتمی | جستجوی دودویی |

**نکته:** برای آزمون Tech+، فقط مفهوم «کدام سریع‌تر است» کافی است.

### مثال‌های عملی

**سناریوی Lab: از مسئله تا شبه‌کد**

**مسئله:** معدل سه نمره را حساب کن و بگو قبول است یا نه (معدل ≥ ۱۰).

**گام ۱ — ورودی/خروجی**

| ورودی | خروجی |
|---|---|
| سه نمره | معدل + وضعیت |

**گام ۲ — شبه‌کد**

```
BEGIN
  READ n1, n2, n3
  average ← (n1 + n2 + n3) / 3
  PRINT "معدل: ", average
  IF average >= 10 THEN
     PRINT "قبول"
  ELSE
     PRINT "رد"
  END IF
END
```

**گام ۳ — تست با داده**

| n1 | n2 | n3 | معدل | نتیجه |
|---|---|---|---|---|
| ۱۵ | ۱۲ | ۱۸ | ۱۵ | قبول |
| ۸ | ۹ | ۱۰ | ۹ | رد |
| ۱۰ | ۱۰ | ۱۰ | ۱۰ | قبول (مرزی) |

**نکته:** همیشه **حالت مرزی** را تست کن.

**سناریوی دوم: الگوریتم پیدا کردن بزرگ‌ترین**

```
BEGIN
  READ a, b, c
  max ← a
  IF b > max THEN max ← b
  IF c > max THEN max ← c
  PRINT max
END
```

**نسخهٔ عمومی (آرایه):**

```
BEGIN
  READ list
  max ← list[0]
  FOR EACH x IN list DO
     IF x > max THEN max ← x
  END FOR
  PRINT max
END
```

**سناریوی سوم: شبه‌کد در برابر کد**

**شبه‌کد:**

```
FOR i ← 1 TO 5
   PRINT i × i
END FOR
```

**Python:**

```python
for i in range(1, 6):
    print(i * i)
```

**JavaScript:**

```javascript
for (let i = 1; i <= 5; i++) {
  console.log(i * i);
}
```

**درس:** شبه‌کد یکی است، سینتکس متفاوت.

### مقایسه و الگوهای مختلف

**سه سطح بیان**

| سطح | مزیت | عیب |
|---|---|---|
| زبان طبیعی | قابل فهم برای همه | مبهم |
| شبه‌کد | دقیق و مستقل | نیاز به آموزش |
| کد | اجراپذیر | وابسته به زبان |

**الگوی «شبه‌کد قبل از کد»**

برای هر تابع بیش از ۱۰ خط، اول شبه‌کد بنویس. ۵ دقیقه فکر، یک ساعت دیباگ را حذف می‌کند.

### اشکال شایع

**۱) پریدن به کد**
باگ‌های ساختاری. شبه‌کد.

**۲) شبه‌کد مبهم**
«چیزها را حساب کن» — بی‌معنی. دقیق بنویس.

**۳) فراموش کردن حالت مرزی**
صفر، منفی، خالی.

**۴) الگوریتم بدون پایان**
حلقهٔ بی‌نهایت.

**۵) نادیده گرفتن ورودی نامعتبر**
خطا در اجرا.

**۶) بهینه‌سازی زودهنگام**
اول درست، بعد سریع.

**۷) کپی الگوریتم بدون فهم**
نمی‌توانی دیباگ کنی.

**۸) مستند نکردن منطق**
شش ماه بعد فراموش می‌کنی.

### نکات مهم (Tips & Tricks)

- **پنج ویژگی الگوریتم** را حفظ کن.
- **شبه‌کد قبل از کد.**
- **سه ساختار پایه** کافی است.
- **حالت مرزی را تست کن.**
- **اول درست، بعد سریع.**
- **الگوریتم را مستند کن.**
- **O(1) < O(log n) < O(n) < O(n²).**

### خلاصه فصل

- الگوریتم دنباله‌ای متناهی و دقیق از گام‌هاست.
- شبه‌کد، ساختار را بدون سینتکس نشان می‌دهد.
- سه ساختار: ترتیب، انتخاب، تکرار.
- پیچیدگی، سرعت نسبی را نشان می‌دهد.
- حالت مرزی را همیشه تست کن.
- فکر کردن قبل از تایپ، وقت ذخیره می‌کند.

## فصل ۵۷: فلوچارت — نمادها و قواعد

### مقدمه

فلوچارت، الگوریتم را **می‌بیند**. برای توضیح به غیرفنی‌ها، مستندسازی فرآیند، و پیدا کردن منطق اشتباه، ابزار بی‌نظیری است.

### مفاهیم اساسی

**نمادهای استاندارد**

| نماد | شکل | کار |
|---|---|---|
| **Terminator** | بیضی | شروع/پایان |
| **Process** | مستطیل | محاسبه/عملیات |
| **Decision** | لوزی | شرط (بله/خیر) |
| **Input/Output** | متوازی‌الاضلاع | ورودی/خروجی |
| **Connector** | دایره | اتصال |
| **Document** | مستطیل با موج | سند |
| **Database** | استوانه | پایگاه داده |

**قواعد**

| قاعده | توضیح |
|---|---|
| جریان | از بالا به پایین، چپ به راست |
| یک شروع | فقط یک Terminator شروع |
| یک پایان | حداقل یک پایان |
| تصمیم | دو خروجی (بله/خیر) |
| برچسب | هر نماد توضیح دارد |

**مثال: محاسبهٔ معدل**

```
      ( شروع )
          ↓
   [ خواندن n1, n2, n3 ]
          ↓
   [ avg = (n1+n2+n3)/3 ]
          ↓
       < avg ≥ 10? >
        /        \
      بله        خیر
       ↓          ↓
  [چاپ قبول]  [چاپ رد]
       \        /
        ↓      ↓
        ( پایان )
```

**سه ساختار در فلوچارت**

| ساختار | شکل |
|---|---|
| Sequence | نمادها پشت سر هم |
| Selection | لوزی با دو شاخه |
| Iteration | بازگشت به عقب |

**حلقه در فلوچارت**

```
      ( شروع )
          ↓
     [ i = 1 ]
          ↓
    ┌→ < i ≤ 5? >
    │    /     \
    │  بله     خیر
    │   ↓        ↓
    │ [چاپ i²] ( پایان )
    │   ↓
    │ [ i = i+1 ]
    └───┘
```

**فلوچارت در برابر شبه‌کد**

| معیار | فلوچارت | شبه‌کد |
|---|---|---|
| دیداری | ✅ | ❌ |
| غیرفنی‌ها | ✅ | ❌ |
| جزئیات | محدود | بالا |
| ویرایش | سخت | آسان |
| فضای زیاد | ✅ | ❌ |

**کاربردهای واقعی**

| حوزه | کاربرد |
|---|---|
| مستندسازی فرآیند | رویهٔ پشتیبانی |
| آموزش | توضیح الگوریتم |
| عیب‌یابی منطق | پیدا کردن مسیر گم‌شده |
| طراحی | قبل از کد |

### مثال‌های عملی

**سناریوی Lab: فلوچارت ورود به سیستم**

```
      ( شروع )
          ↓
   [ خواندن username, password ]
          ↓
   < کاربر وجود دارد؟ >
      /          \
    خیر          بله
     ↓            ↓
[پیام خطا]   < رمز درست؟ >
     ↓          /     \
   (پایان)    خیر     بله
               ↓       ↓
          [افزایش   [ورود موفق]
           تلاش]        ↓
               ↓     (پایان)
        < تلاش > 3؟ >
          /      \
        بله      خیر
         ↓         ↓
   [قفل حساب]  (بازگشت به
         ↓       ورود رمز)
      (پایان)
```

**نکته:** این فلوچارت، منطق امنیتی را هم نشان می‌دهد: محدودیت تلاش.

**سناریوی دوم: پیدا کردن خطای منطقی**

**فلوچارت اولیه:**

```
(شروع) → [خواندن عدد] → < عدد > 0؟ >
                            /     \
                          بله     خیر
                           ↓        ↓
                    [چاپ مثبت] [چاپ منفی]
```

**خطا:** صفر چه می‌شود؟ نه مثبت است نه منفی.

**اصلاح:**

```
< عدد > 0؟ >  → بله: مثبت
< عدد = 0؟ >  → بله: صفر
              → خیر: منفی
```

**درس:** فلوچارت، حفره‌های منطقی را نشان می‌دهد.

**سناریوی سوم: فلوچارت فرآیند پشتیبانی**

```
(دریافت تیکت) → [دسته‌بندی] → < فوری؟ >
                                  /     \
                                بله     خیر
                                 ↓        ↓
                          [تخصیص     [صف عادی]
                           فوری]
                                 \        /
                                  ↓      ↓
                              [حل مشکل]
                                   ↓
                            < حل شد؟ >
                              /      \
                            بله      خیر
                             ↓         ↓
                        [بستن]   [ارجاع به
                         تیکت]    سطح ۲]
```

### مقایسه و الگوهای مختلف

**سه سطح جزئیات**

| سطح | مناسب |
|---|---|
| کلی (High-level) | مدیریت، آموزش |
| متوسط | طراحی |
| ریز | پیاده‌سازی |

**الگوی «یک صفحه، یک فلوچارت»**

اگر فلوچارت از یک صفحه بزرگ‌تر شد، آن را به زیرفرآیند بشکن.

### اشکال شایع

**۱) چند شروع**
گیج‌کننده. یک شروع.

**۲) تصمیم با یک خروجی**
باید دو شاخه داشته باشد.

**۳) جریان بدون جهت**
فلش را فراموش نکن.

**۴) نماد اشتباه**
لوزی برای محاسبه، غلط است.

**۵) فلوچارت بیش از حد ریز**
خوانایی کم.

**۶) نادیده گرفتن حالت مرزی**
صفر، خالی، منفی.

**۷) بدون برچسب**
نمی‌دانی چه کاری است.

**۸) خطوط متقاطع**
گیج‌کننده. Connector استفاده کن.

### نکات مهم (Tips & Tricks)

- **هفت نماد** را حفظ کن.
- **یک شروع، یک پایان.**
- **لوزی = دو خروجی.**
- **حالت مرزی را ببین.**
- **زیرفرآیند برای پیچیدگی.**
- **Connector برای خطوط متقاطع.**
- **فلوچارت را با غیرفنی تست کن.**

### خلاصه فصل

- فلوچارت، الگوریتم را دیداری می‌کند.
- هفت نماد استاندارد: بیضی، مستطیل، لوزی، متوازی‌الاضلاع، دایره، سند، استوانه.
- سه ساختار کنترلی در فلوچارت قابل نمایش‌اند.
- فلوچارت حفره‌های منطقی را نشان می‌دهد.
- یک صفحه، یک فلوچارت.
- حالت مرزی را در فلوچارت ببین.

## فصل ۵۸: ساختارهای کنترلی — شرط، حلقه، انتخاب

### مقدمه

سه ساختار کنترلی، ستون فقرات هر برنامه‌اند. اگر این‌ها را بفهمی، منطق هر کدی را می‌خوانی.

### مفاهیم اساسی

**۱) Sequence — ترتیب**

دستورها به ترتیب اجرا می‌شوند.

```
READ a
READ b
sum ← a + b
PRINT sum
```

**۲) Selection — انتخاب**

**IF ساده:**

```
IF condition THEN
   statement
END IF
```

**IF-ELSE:**

```
IF condition THEN
   statement1
ELSE
   statement2
END IF
```

**IF-ELSE IF:**

```
IF score >= 17 THEN
   grade ← "A"
ELSE IF score >= 14 THEN
   grade ← "B"
ELSE IF score >= 10 THEN
   grade ← "C"
ELSE
   grade ← "F"
END IF
```

**نکته:** ترتیب شرط‌ها مهم است. از بالا به پایین بررسی می‌شود.

**SWITCH / CASE**

```
SWITCH day
   CASE 1: PRINT "شنبه"
   CASE 2: PRINT "یکشنبه"
   ...
   DEFAULT: PRINT "نامعتبر"
END SWITCH
```

| مزیت | عیب |
|---|---|
| خواناتر از IF زنجیره‌ای | فقط مقایسهٔ برابری |
| سریع‌تر در بعضی زبان‌ها | — |

**۳) Iteration — تکرار**

**FOR — تعداد معلوم:**

```
FOR i ← 1 TO 10
   PRINT i
END FOR
```

**WHILE — شرط اول:**

```
WHILE count < 5 DO
   count ← count + 1
END WHILE
```

**DO-WHILE — اجرا حداقل یک بار:**

```
DO
   statement
WHILE condition
```

**تفاوت WHILE و DO-WHILE**

| ساختار | بررسی شرط | حداقل اجرا |
|---|---|---|
| WHILE | قبل | ۰ بار |
| DO-WHILE | بعد | ۱ بار |

**حلقهٔ بی‌نهایت**

```
WHILE true DO
   ...
END WHILE
```

**مثال واقعی:** سرور که تا ابد منتظر درخواست است. عمدی است.

**BREAK و CONTINUE**

| دستور | کار |
|---|---|
| `break` | خروج از حلقه |
| `continue` | پرش به تکرار بعد |

```python
for i in range(10):
    if i == 5:
        break        # خروج
    if i % 2 == 0:
        continue     # پرش
    print(i)
```

**حلقهٔ تودرتو**

```python
for i in range(3):
    for j in range(3):
        print(i, j)
# ۹ بار اجرا
```

**هشدار:** حلقهٔ تودرتو، پیچیدگی O(n²) می‌سازد.

**بازگشت (Recursion)**

تابعی که خودش را صدا می‌زند.

```python
def factorial(n):
    if n <= 1:          # شرط پایه
        return 1
    return n * factorial(n - 1)
```

| مزیت | عیب |
|---|---|
| خوانا برای مسائل بازگشتی | مصرف حافظه |
| کد کوتاه | خطر stack overflow |

**شرط پایه** حیاتی است؛ بدون آن، بازگشت بی‌نهایت.

### مثال‌های عملی

**سناریوی Lab: محاسبهٔ حقوق با شرط و حلقه**

```
BEGIN
  total ← 0
  FOR EACH employee IN employees DO
     base ← employee.salary
     IF employee.hours > 40 THEN
        overtime ← (employee.hours - 40) × employee.rate × 1.5
     ELSE
        overtime ← 0
     END IF
     total ← total + base + overtime
  END FOR
  PRINT total
END
```

**تحلیل:**

| ساختار | کجا |
|---|---|
| حلقه | `FOR EACH` |
| شرط | `IF` |
| ترتیب | محاسبه و جمع |

**سناریوی دوم: اعتبارسنجی ورودی**

```
BEGIN
  REPEAT
     READ age
     IF age < 0 OR age > 120 THEN
        PRINT "سن نامعتبر"
     END IF
  UNTIL age >= 0 AND age <= 120
END
```

**درس:** حلقه برای گرفتن ورودی معتبر.

**سناریوی سوم: تبدیل WHILE به FOR**

**WHILE:**

```
i ← 1
WHILE i <= 10 DO
   PRINT i
   i ← i + 1
END WHILE
```

**FOR:**

```
FOR i ← 1 TO 10
   PRINT i
END FOR
```

**نکته:** هر FOR را می‌توان WHILE نوشت، ولی برعکس نه همیشه.

**سناریوی چهارم: خطای off-by-one**

```python
# ❌ یک بار کمتر
for i in range(1, 10):    # 1..9
    print(i)

# ✅
for i in range(1, 11):    # 1..10
    print(i)
```

**درس:** محدودهٔ حلقه، پرتکرارترین خطای مبتدی‌هاست.

### مقایسه و الگوهای مختلف

**سه نوع حلقه**

| نوع | کِی |
|---|---|
| FOR | تعداد معلوم |
| WHILE | شرط، ممکن است صفر بار |
| DO-WHILE | حداقل یک بار |

**الگوی «شرط زودهنگام»**

```python
def process(data):
    if not data:
        return None       # خروج زودهنگام
    # ادامهٔ منطق
```

این الگو، تودرتویی را کم می‌کند.

### اشکال شایع

**۱) off-by-one**
`<` به‌جای `<=`. محدوده را چک کن.

**۲) حلقهٔ بی‌نهایت**
شرط پایان را فراموش کردی.

**۳) بازگشت بدون شرط پایه**
stack overflow.

**۴) `break` در حلقهٔ تودرتو**
فقط از داخلی خارج می‌شود.

**۵) تغییر لیست در حین پیمایش**
پرش یا خطا.

**۶) شرط‌های IF بدون ELSE**
حالت پیش‌فرض را فراموش کردی.

**۷) `=` به‌جای `==`**
انتساب در شرط.

**۸) تودرتویی زیاد**
خوانایی کم. تابع جدا.

### نکات مهم (Tips & Tricks)

- **سه ساختار** را حفظ کن.
- **WHILE قبل، DO-WHILE بعد.**
- **شرط پایه در بازگشت.**
- **off-by-one را چک کن.**
- **`break` فقط از یک حلقه.**
- **شرط زودهنگام** برای خوانایی.
- **تودرتویی را کم کن.**

### خلاصه فصل

- سه ساختار: ترتیب، انتخاب، تکرار.
- IF-ELSE و SWITCH برای انتخاب.
- FOR، WHILE، DO-WHILE برای تکرار.
- بازگشت نیاز به شرط پایه دارد.
- off-by-one پرتکرارترین خطاست.
- شرط زودهنگام، خوانایی را بالا می‌برد.

## فصل ۵۹: سازمان‌دهی کد — تابع، ماژول، شیء

### مقدمه

کدی که کار می‌کند، کافی نیست. کد باید **خوانا** و **قابل نگه‌داری** باشد. این فصل، سه ابزار سازمان‌دهی را می‌دهد.

### مفاهیم اساسی

**سه سطح سازمان‌دهی**

| سطح | واحد | کار |
|---|---|---|
| **Function** | تابع | یک کار |
| **Module** | فایل/پکیج | گروه تابع مرتبط |
| **Class** | کلاس | داده + رفتار |

**اصل مسئولیت واحد (SRP)**

> هر تابع/کلاس باید فقط یک دلیل برای تغییر داشته باشد.

**نشانهٔ نقض:** تابعی که «و» در توضیحش زیاد است: «محاسبه و ذخیره و ارسال ایمیل».

**نام‌گذاری**

| نوع | قرارداد | مثال |
|---|---|---|
| متغیر | snake_case یا camelCase | `user_count` |
| تابع | فعل + مفعول | `calculate_total` |
| کلاس | PascalCase | `InvoiceService` |
| ثابت | UPPER_SNAKE | `MAX_RETRIES` |
| بولین | is/has/can | `is_valid` |

**کامنت — کِی و چه**

| خوب | بد |
|---|---|
| «چرا» | «چه» (کد خودش می‌گوید) |
| هشدار | تکرار کد |
| مرجع | کامنت منسوخ |

```python
# ❌ بد
i += 1   # i را یک واحد زیاد کن

# ✅ خوب
i += 1   # جبران offset یک‌مبنایی پروتکل
```

**DRY — Don't Repeat Yourself**

اگر کدی سه بار تکرار شد، تابعش کن.

**KISS — Keep It Simple**

ساده‌ترین راه‌حل که کار می‌کند، بهترین است.

**YAGNI — You Aren't Gonna Need It**

قابلیتی که لازم نیست را نساز.

**ساختار پروژه**

```
project/
├── src/
│   ├── models/       ← داده
│   ├── services/     ← منطق
│   ├── utils/        ← کمکی
│   └── main.py
├── tests/
├── docs/
└── README.md
```

**جداسازی لایه‌ها**

| لایه | مسئولیت |
|---|---|
| Presentation | نمایش |
| Business | منطق |
| Data | ذخیره |

**مزیت:** تغییر در UI، منطق را نمی‌شکند.

**نسخه‌بندی (Git)**

| مفهوم | کار |
|---|---|
| Commit | تغییر ثبت‌شده |
| Branch | شاخه |
| Merge | ادغام |
| Tag | نسخه |

**پیام Commit خوب:**

```
✅ "افزودن اعتبارسنجی ایمیل در فرم ثبت‌نام"
❌ "fix"
❌ "changes"
```

**تست**

| نوع | کار |
|---|---|
| Unit | یک تابع |
| Integration | چند جزء |
| End-to-end | کل مسیر |

**هرم تست:** ۷۰٪ unit، ۲۰٪ integration، ۱۰٪ e2e.

### مثال‌های عملی

**سناریوی Lab: بازسازی یک تابع بد**

**قبل:**

```python
def process(data):
    result = []
    for d in data:
        if d['type'] == 'a':
            x = d['value'] * 1.1
            result.append({'name': d['name'], 'total': x})
        elif d['type'] == 'b':
            x = d['value'] * 1.2
            result.append({'name': d['name'], 'total': x})
    return result
```

**مشکل:** تکرار، شرط زنجیره‌ای، عدد جادویی.

**بعد:**

```python
RATES = {"a": 1.1, "b": 1.2}     # ثابت نام‌دار


def apply_rate(item: dict) -> dict:
    rate = RATES.get(item["type"], 1.0)
    return {"name": item["name"], "total": item["value"] * rate}


def process(data: list[dict]) -> list[dict]:
    return [apply_rate(d) for d in data]
```

**بهبود:**

| معیار | قبل | بعد |
|---|---|---|
| خط | ۹ | ۶ |
| تکرار | دارد | ندارد |
| عدد جادویی | دارد | ندارد |
| تست‌پذیری | سخت | آسان |

**سناریوی دوم: شکستن تابع بزرگ**

**قبل:**

```python
def handle_order(order):
    # اعتبارسنجی
    # محاسبهٔ قیمت
    # ذخیره در دیتابیس
    # ارسال ایمیل
    # ثبت لاگ
    ...
```

**بعد:**

```python
def validate(order): ...
def calculate_total(order): ...
def save(order): ...
def notify(order): ...

def handle_order(order):
    validate(order)
    total = calculate_total(order)
    save(order, total)
    notify(order)
```

**درس:** تابع اصلی، «داستان» را می‌گوید؛ جزئیات در تابع‌های کوچک.

**سناریوی سوم: تست**

```python
def test_apply_rate_discount():
    assert apply_rate({"type": "a", "name": "x", "value": 100})["total"] == 110


def test_apply_rate_unknown():
    assert apply_rate({"type": "z", "name": "x", "value": 100})["total"] == 100
```

**نکته:** تست حالت نامعلوم، به‌اندازهٔ حالت عادی مهم است.

### مقایسه و الگوهای مختلف

**سه سبک سازمان‌دهی**

| سبک | مناسب |
|---|---|
| تابع‌محور | اسکریپت، ابزار |
| شیءمحور | برنامهٔ بزرگ |
| لایه‌ای | سرویس، API |

**الگوی «کد مثل روزنامه»**

```
۱. تیتر: نام تابع
۲. لید: پاراگراف اول تابع (خلاصه)
۳. جزئیات: تابع‌های پایین‌تر
```

خواننده از بالا به پایین، سطح انتزاع را کم می‌کند.

### اشکال شایع

**۱) تابع ۲۰۰ خطی**
نمی‌شود فهمید. بشکن.

**۲) نام مبهم**
`data`, `temp`, `x`. نام گویا.

**۳) کامنت تکراری**
نویز. «چرا» بنویس.

**۴) تکرار کد**
DRY.

**۵) عدد جادویی**
`1.1` بدون توضیح. ثابت نام‌دار.

**۶) بدون تست**
تغییر می‌ترسد.

**۷) تودرتویی عمیق**
شرط زودهنگام.

**۸) Commit مبهم**
تاریخچه بی‌فایده.

### نکات مهم (Tips & Tricks)

- **SRP: یک کار، یک تابع.**
- **نام گویا.**
- **کامنت «چرا»، نه «چه».**
- **DRY، KISS، YAGNI.**
- **تابع کوچک.**
- **تست برای هر تابع.**
- **Commit گویا.**

### خلاصه فصل

- سه سطح: تابع، ماژول، کلاس.
- SRP: یک دلیل برای تغییر.
- نام‌گذاری قراردادی، خوانایی می‌دهد.
- DRY، KISS، YAGNI سه اصل ساده‌سازی.
- جداسازی لایه‌ها، تغییر را ایزوله می‌کند.
- تست، بیمهٔ تغییر است.
