## فصل ۸۳: متدولوژی عیب‌یابی در عمل

### مقدمه

فصل ۸ متدولوژی را معرفی کرد. این فصل، آن را روی سناریوهای چندلایه اعمال می‌کند — جایی که مشکل ساده نیست.

### مفاهیم اساسی

**یادآوری شش گام**

```
۱) شناسایی
۲) نظریه
۳) آزمایش
۴) اجرا
۵) تأیید
۶) مستندسازی
```

**سه ابزار ذهنی پیشرفته**

| ابزار | کار |
|---|---|
| **تقسیم دامنه** | نصف کردن فضای جستجو |
| **پنج چرا** | رسیدن به ریشه |
| **مقایسه با سالم** | پیدا کردن تفاوت |

**تقسیم دامنه — مثال**

```
کاربر → مرورگر → شبکه → سرور → دیتابیس
         ↑
   از وسط شروع کن
```

**جدول «کدام لایه؟»**

| نشانه | لایهٔ محتمل |
|---|---|
| هیچ چراغی روشن نیست | برق |
| چراغ ولی بدون تصویر | GPU/کابل |
| بوت می‌شود ولی کند | دیسک/RAM |
| برنامه باز نمی‌شود | نرم‌افزار |
| فقط یک سایت باز نمی‌شود | DNS/سرور |
| هیچ سایتی باز نمی‌شود | شبکه/ISP |

**مشکلات چندلایه**

گاهی دو مشکل همزمان است:

```
کاربر: "اینترنت قطع است."
مشکل ۱: کابل روتر شل شده
مشکل ۲: DNS اشتباه
```

اگر فقط یکی را حل کنی، مشکل باقی می‌ماند. **بعد از هر اصلاح، دوباره تست کن.**

**مستندسازی حرفه‌ای**

```markdown
## تیکت #4521

**گزارش کاربر:** "کامپیوتر روشن می‌شود ولی صفحه سیاه است."
**زمان:** ۱۴۰۵/۰۸/۲۰ ۰۹:۱۵

**بررسی:**
- کابل برق ✅
- چراغ پاور ✅
- کابل مانیتور: به مادربرد وصل بود، GPU مجزا نصب است ❌
- ورودی مانیتور: HDMI2، کابل در HDMI1

**علت:** کابل به پورت اشتباه + ورودی اشتباه مانیتور
**راه‌حل:** اتصال به GPU و تغییر ورودی
**زمان حل:** ۸ دقیقه
**پیشگیری:** برچسب روی کابل‌ها
```

**نکته:** «۸ دقیقه» در مستندات، ارزشمند است — نشان می‌دهد مشکل ساده بوده و می‌توان پیشگیری کرد.

### مثال‌های عملی

**سناریوی Lab: «لپ‌تاپ شارژ نمی‌شود»**

| گام | بررسی | نتیجه |
|---|---|---|
| ۱ | آداپتور به برق | چراغ آداپتور خاموش |
| ۲ | پریز دیگر | همچنان خاموش |
| ۳ | کابل آداپتور | سالم |
| ۴ | آداپتور جایگزین | کار می‌کند |

**نتیجه:** آداپتور خراب. **درس:** از ارزان به گران.

**سناریوی دوم: «بعد از آپدیت، صدا قطع شد»**

| گام | بررسی |
|---|---|
| ۱ | Device Manager → Audio |
| ۲ | علامت هشدار؟ |
| ۳ | Roll Back Driver |
| ۴ | تست |

**نتیجه:** درایور آپدیت‌شده مشکل داشت. Rollback حل کرد.

**سناریوی سوم: «فایل‌ها کند باز می‌شوند»**

| لایه | بررسی | نتیجه |
|---|---|---|
| CPU | ۱۵٪ | سالم |
| RAM | ۶۰٪ | سالم |
| دیسک | ۱۰۰٪ Active | **گلوگاه** |
| شبکه | ۵٪ | سالم |

**نتیجه:** دیسک. بررسی SMART → Warning. تعویض SSD.

### مقایسه و الگوهای مختلف

**سه سبک عیب‌یابی**

| سبک | کِی |
|---|---|
| خطی | مشکل ساده |
| تقسیم دامنه | مشکل مبهم |
| مقایسه با سالم | محیط پیچیده |

**الگوی «تست پس از هر تغییر»**

یک تغییر، یک تست. چند تغییر همزمان، تشخیص را غیرممکن می‌کند.

### اشکال شایع

**۱) چند تغییر همزمان**
نمی‌دانی کدام مؤثر بود.

**۲) فرض «کاربر اشتباه می‌گوید»**
ممکن است راست بگوید.

**۳) بدون مستندسازی**
تکرار.

**۴) پریدن به راه‌حل گران**
کابل ارزان را چک نکردی.

**۵) نادیده گرفتن مشکل دوم**
بعد از رفع اولی، دوباره تست کن.

**۶) بدون پشتیبان**
تغییر خطرناک.

**۷) رها کردن در نیمه**
ریشه باقی می‌ماند.

**۸) نادیده گرفتن تجربهٔ کاربر**
«کند است» داده است، نه شکایت.

### نکات مهم (Tips & Tricks)

- **شش گام** را همیشه.
- **تقسیم دامنه.**
- **یک تغییر، یک تست.**
- **از ارزان به گران.**
- **بعد از هر اصلاح، تست مجدد.**
- **مستندسازی با زمان.**
- **پیشگیری را بنویس.**

### خلاصه فصل

- متدولوژی روی مشکلات چندلایه هم کار می‌کند.
- تقسیم دامنه، پنج چرا، مقایسه با سالم.
- یک تغییر در هر آزمایش.
- بعد از هر اصلاح، دوباره تست کن.
- مستندسازی شامل زمان و پیشگیری است.

## فصل ۸۴: ابزارهای عیب‌یابی سخت‌افزار و سیستم‌عامل

### مقدمه

عیب‌یابی بدون ابزار، حدس زدن است. ابزارهای ویندوز و لینوکس، داده می‌دهند؛ داده، فرضیه می‌سازد؛ فرضیه، راه‌حل. این فصل، جعبه‌ابزار عملی را می‌دهد — از Task Manager تا WinRE و فلش نجات.

### مفاهیم اساسی

**ابزارهای ویندوز**

| ابزار | کار |
|---|---|
| `Task Manager` | فرآیند و منابع |
| `Resource Monitor` | جزئیات |
| `Event Viewer` | لاگ |
| `Device Manager` | درایور |
| `Disk Management` | پارتیشن |
| `msinfo32` | اطلاعات سیستم |
| `dxdiag` | گرافیک/صدا |
| `sfc /scannow` | فایل سیستمی |
| `DISM` | تصویر ویندوز |
| `chkdsk` | دیسک |
| `ipconfig` | شبکه |
| `ping`/`tracert` | اتصال |
| `netstat` | پورت |
| `tasklist`/`taskkill` | فرآیند |

**ابزارهای لینوکس**

| ابزار | کار |
|---|---|
| `top`/`htop` | فرآیند |
| `df`/`du` | فضا |
| `free` | حافظه |
| `journalctl` | لاگ |
| `dmesg` | لاگ کرنل |
| `lsblk`/`blkid` | دیسک |
| `smartctl` | SMART |
| `ip`/`ss` | شبکه |
| `systemctl` | سرویس |

**ابزارهای سخت‌افزاری**

| ابزار | کار |
|---|---|
| مولتی‌متر | ولتاژ |
| تستر پاور | PSU |
| تستر کابل شبکه | کابل |
| هارد درایو داک | تست دیسک |
| آنتی‌استاتیک | ESD |

**SMART**

| مقدار | معنی |
|---|---|
| `OK` | سالم |
| `Warning` | نشانهٔ خرابی |
| `Bad` | تعویض فوری |

```bash
smartctl -a /dev/sda
```

**Event Viewer — سه سطح**

| سطح | معنی |
|---|---|
| Information | عادی |
| Warning | هشدار |
| Error | خطا |

**نکته:** برای عیب‌یابی، روی Errorها و زمان وقوع تمرکز کن.

**Safe Mode**

بوت با حداقل درایور. برای تشخیص:
- آیا مشکل از درایور است؟
- آیا بدافزار فعال است؟

**Windows Recovery Environment (WinRE)**

| گزینه | کار |
|---|---|
| Startup Repair | رفع بوت |
| System Restore | بازگشت |
| Command Prompt | ابزار دستی |
| Reset | نصب مجدد |

**Bootable USB**

ابزار نجات: وقتی سیستم بوت نمی‌شود.

| ابزار | کار |
|---|---|
| Ventoy | چند ISO |
| Rufus | ساخت بوت |
| Linux Live | نجات فایل |

### مثال‌های عملی

**سناریوی Lab: سیستم بوت نمی‌شود**

```
۱) چراغ پاور؟ ✅
۲) تصویر BIOS؟ ✅
۳) پیام خطا؟ "No bootable device"
۴) Disk Management از WinRE → دیسک دیده می‌شود؟
۵) اگر نه → کابل/دیسک
۶) اگر بله → بوت‌لودر
```

**راه‌حل‌ها:**

| علت | راه‌حل |
|---|---|
| ترتیب بوت | BIOS |
| بوت‌لودر خراب | Startup Repair |
| دیسک خراب | تعویض + بازیابی |
| کابل شل | اتصال مجدد |

**سناریوی دوم: بررسی سلامت دیسک**

```powershell
Get-PhysicalDisk | Select FriendlyName, HealthStatus, OperationalStatus
```

| نتیجه | اقدام |
|---|---|
| Healthy | ادامه |
| Warning | پشتیبان فوری + تعویض |
| Unhealthy | تعویض |

**سناریوی سوم: پاکسازی فایل سیستمی**

```powershell
sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
```

**ترتیب:** اول `DISM`، بعد `sfc` (چون sfc از تصویر استفاده می‌کند).

### مقایسه و الگوهای مختلف

**سه سطح ابزار**

| سطح | ابزار |
|---|---|
| GUI | Task Manager، Event Viewer |
| CLI | `sfc`، `ipconfig` |
| Bootable | WinRE، Live USB |

**الگوی «ابزار نجات»**

یک فلش بوت با ابزارهای نجات همیشه همراه داشته باش. در خرابی بوت، نجات‌دهنده است.

### اشکال شایع

**۱) `chkdsk /f` روی دیسک سالم**
زمان تلف.

**۲) `sfc` بدون `DISM`**
ممکن است فایل خراب را جایگزین نکند.

**۳) نادیده گرفتن SMART**
خرابی ناگهانی.

**۴) بدون فلش نجات**
بوت خراب = درماندگی.

**۵) Event Viewer بدون فیلتر**
هزاران رویداد.

**۶) Safe Mode برای هر مشکل**
فقط برای درایور/بدافزار.

**۷) حذف پارتیشن بازیابی**
ابزار نجات از دست می‌رود.

**۸) بدون پشتیبان قبل از تعمیر**
داده می‌رود.

### نکات مهم (Tips & Tricks)

- **پنج ابزار اصلی ویندوز** را حفظ کن.
- **`sfc` + `DISM`** با هم.
- **SMART را ببین.**
- **WinRE و فلش نجات.**
- **Event Viewer با فیلتر.**
- **Safe Mode برای درایور.**
- **پشتیبان قبل از تعمیر.**

### خلاصه فصل

- ابزارهای GUI و CLI مکمل‌اند.
- SMART سلامت دیسک را نشان می‌دهد.
- WinRE و فلش نجات برای بوت خراب.
- `sfc` و `DISM` فایل‌های سیستمی را تعمیر می‌کنند.
- Event Viewer با فیلتر، منبع طلاست.
- پشتیبان قبل از هر تعمیر.

## فصل ۸۵: Lab شبکه و Wi-Fi

### مقدمه

شبکه، پرتکرارترین منبع تیکت پشتیبانی است. ولی ۹۰٪ مشکلات با چهار دستور ساده حل می‌شوند. این Lab، همان چهار دستور را در چهار سناریوی واقعی تمرین می‌کند.

### مفاهیم اساسی

**سناریوهای این Lab**

| # | سناریو |
|---|---|
| ۱ | «اینترنت قطع است» |
| ۲ | «سرعت پایین است» |
| ۳ | «فقط یک دستگاه مشکل دارد» |
| ۴ | «Wi-Fi در اتاق دور ضعیف است» |

**ابزارهای شبکه**

| ابزار | کار |
|---|---|
| `ipconfig /all` | تنظیمات |
| `ping` | اتصال |
| `tracert` | مسیر |
| `nslookup` | DNS |
| `netstat -an` | پورت |
| Wi-Fi Analyzer | کانال |
| `netsh wlan show interfaces` | Wi-Fi |

### مثال‌های عملی

**Lab ۱: «اینترنت قطع است»**

```bash
# گام ۱ — آدرس گرفتم؟
ipconfig
# اگر 169.254.x.x → DHCP

# گام ۲ — روتر؟
ping 192.168.1.1

# گام ۳ — اینترنت؟
ping 8.8.8.8

# گام ۴ — DNS؟
nslookup example.com
```

| نتیجه | علت |
|---|---|
| `169.254` | DHCP |
| ping روتر ❌ | LAN |
| ping 8.8.8.8 ❌ | ISP |
| nslookup ❌ | DNS |
| همه ✅ ولی مرورگر ❌ | پروکسی/مرورگر |

**Lab ۲: «سرعت پایین است»**

| گام | بررسی |
|---|---|
| ۱ | تست با کابل (حذف Wi-Fi) |
| ۲ | تست در ساعت مختلف |
| ۳ | تعداد دستگاه‌های متصل |
| ۴ | برنامه‌های مصرف‌کننده |
| ۵ | فاصله از روتر |

**سناریو:** سرعت ۱۰۰ Mbps اسمی، ۱۵ Mbps واقعی.

| علت | بررسی |
|---|---|
| Wi-Fi ضعیف | RSSI |
| کانال شلوغ | Analyzer |
| دستگاه زیاد | تعداد |
| آپلود همزمان | پشتیبان ابری |

**Lab ۳: «فقط یک دستگاه مشکل دارد»**

```markdown
- [ ] IP گرفته؟ (اگر نه: DHCP/کابل)
- [ ] Gateway درست؟
- [ ] DNS درست؟
- [ ] فایروال محلی؟
- [ ] پروکسی؟
- [ ] VPN؟
```

**نکته:** اگر بقیه سالم‌اند، مشکل در دستگاه است.

**Lab ۴: «Wi-Fi در اتاق دور ضعیف است»**

| گام | کار |
|---|---|
| ۱ | اندازه‌گیری RSSI |
| ۲ | بررسی کانال |
| ۳ | جابه‌جایی روتر |
| ۴ | Mesh یا کابل |

| RSSI | کیفیت |
|---|---|
| −۵۰ | عالی |
| −۶۰ | خوب |
| −۷۰ | متوسط |
| −۸۰ | ضعیف |

**راه‌حل‌ها:**

| راه‌حل | هزینه | اثر |
|---|---|---|
| تغییر کانال | ۰ | کم |
| جابه‌جایی | ۰ | متوسط |
| Repeater | کم | متوسط (نصف پهنای باند) |
| Mesh | متوسط | زیاد |
| کابل + AP | متوسط | عالی |

### مقایسه و الگوهای مختلف

**سه سطح عیب‌یابی شبکه**

| سطح | ابزار |
|---|---|
| دستگاه | `ipconfig`، `ping` |
| شبکه | Analyzer، روتر |
| ISP | تماس، تست کابل |

**الگوی «تست با کابل»**

قبل از هر عیب‌یابی Wi-Fi، با کابل تست کن. اگر کابل خوب بود، مشکل Wi-Fi است.

### اشکال شایع

**۱) ری‌استارت روتر برای هر مشکل**
گاهی مشکل DNS محلی است.

**۲) تست سرعت با Wi-Fi**
نتیجهٔ پایین.

**۳) نادیده گرفتن 169.254**
DHCP.

**۴) Repeater در نقطهٔ ضعیف**
باید میانی باشد.

**۵) کانال شلوغ**
Analyzer.

**۶) دستگاه زیاد**
پهنای باند تقسیم می‌شود.

**۷) بدون مستندات**
تکرار.

**۸) فرض «ISP مشکل دارد»**
اول LAN را چک کن.

### نکات مهم (Tips & Tricks)

- **چهار گام: IP، روتر، اینترنت، DNS.**
- **تست با کابل.**
- **RSSI زیر −۷۰ = مشکل.**
- **کانال ۱/۶/۱۱.**
- **Repeater میانی.**
- **مستندسازی.**
- **اول LAN، بعد ISP.**

### خلاصه فصل

- چهار سناریوی رایج شبکه.
- `ipconfig`، `ping`، `nslookup` سه ابزار اصلی.
- `169.254` یعنی DHCP شکست خورد.
- تست با کابل، Wi-Fi را از معادله خارج می‌کند.
- RSSI معیار کیفیت Wi-Fi است.
- Mesh بهتر از Repeater.

## فصل ۸۶: Lab امنیت و داده

### مقدمه

امنیت، انتزاعی به نظر می‌رسد تا وقتی که یک ایمیل فیشینگ دریافت می‌کنی یا پشتیبان را بازیابی می‌کنی. این Lab، پنج تمرین عملی می‌دهد که هر کدام در دنیای واقعی به کار می‌آید.

### مفاهیم اساسی

**سناریوهای این Lab**

| # | سناریو |
|---|---|
| ۱ | بررسی امنیت یک دستگاه |
| ۲ | تحلیل ایمیل فیشینگ |
| ۳ | بازیابی از پشتیبان |
| ۴ | بررسی رمزنگاری |

### مثال‌های عملی

**Lab ۱: سخت‌سازی دستگاه**

```markdown
- [ ] آپدیت سیستم‌عامل
- [ ] آنتی‌ویروس فعال
- [ ] فایروال فعال
- [ ] رمزنگاری دیسک
- [ ] حساب استاندارد
- [ ] قفل خودکار
- [ ] پشتیبان
```

**بررسی با ابزار:**

```powershell
# وضعیت فایروال
Get-NetFirewallProfile | Select Name, Enabled

# وضعیت BitLocker
Get-BitLockerVolume | Select MountPoint, ProtectionStatus

# آپدیت‌ها
Get-HotFix | Sort InstalledOn -Descending | Select -First 5
```

**Lab ۲: تحلیل فیشینگ**

**پیام نمونه:**

```
از: it-support@company-helpdesk.net
موضوع: بازنشانی رمز — فوری

همکار گرامی،
حساب شما در ۲۴ ساعت آینده غیرفعال می‌شود.
برای جلوگیری: http://company-helpdesk.net/reset?id=abc
```

| نشانه | بررسی | نتیجه |
|---|---|---|
| دامنه | `company-helpdesk.net` | جعلی |
| پروتکل | `http` | ناامن |
| فوریت | «۲۴ ساعت» | ترفند |
| سلام | «همکار گرامی» | عمومی |
| لینک | پارامتر `id` | مشکوک |

**اقدام:** حذف، گزارش، اطلاع به همکاران.

**Lab ۳: بازیابی از پشتیبان**

```bash
# ۱) پشتیبان
tar -czf /backup/data-$(date +%F).tar.gz /data

# ۲) شبیه‌سازی حذف
rm -rf /data/report.txt

# ۳) بازیابی
tar -xzf /backup/data-$(date +%F).tar.gz -C /

# ۴) تأیید
cat /data/report.txt
sha256sum /data/report.txt
```

**چک‌لیست موفقیت:**

```markdown
- [ ] فایل باز می‌شود
- [ ] محتوا کامل است
- [ ] checksum می‌خواند
- [ ] زمان بازیابی ثبت شد
```

**Lab ۴: بررسی رمزنگاری**

```bash
# گواهی سایت
openssl s_client -connect example.com:443 -servername example.com

# بررسی:
# - Protocol: TLS 1.2+
# - Cipher: AES-GCM
# - Verify return code: 0
```

| نتیجه | معنی |
|---|---|
| `Verify return code: 0` | گواهی معتبر |
| `self signed` | گواهی خودامضا |
| `certificate has expired` | منقضی |

**Lab ۵: تحلیل لاگ ورود**

```bash
# ویندوز
Get-EventLog -LogName Security -InstanceId 4625 -Newest 20
# 4625 = ورود ناموفق

# لینوکس
grep "Failed password" /var/log/auth.log | tail -20
```

**تحلیل:**

| الگو | معنی |
|---|---|
| چند ورود ناموفق از یک IP | brute force |
| ورود موفق بعد از چند ناموفق | احتمال نفوذ |
| ورود در ساعت غیرعادی | مشکوک |

### مقایسه و الگوهای مختلف

**سه سطح بررسی امنیتی**

| سطح | کار |
|---|---|
| پایه | چک‌لیست دستگاه |
| متوسط | تحلیل لاگ |
| بالا | تست نفوذ (با مجوز) |

**الگوی «بررسی ماهانه»**

یک چک‌لیست ثابت ماهانه، از فراموشی جلوگیری می‌کند.

### اشکال شایع

**۱) تست نفوذ بدون مجوز**
غیرقانونی. فقط روی سیستم خودت.

**۲) بازیابی روی تولید**
ریسک. محیط تست.

**۳) نادیده گرفتن checksum**
دادهٔ ناقص.

**۴) تحلیل فیشینگ بدون گزارش**
دیگران آسیب می‌بینند.

**۵) لاگ بدون بررسی**
حادثه دیر کشف می‌شود.

**۶) فرض «گواهی معتبر = سایت امن»**
دامنهٔ جعلی هم گواهی دارد.

**۷) بدون مستندات**
تکرار.

**۸) نادیده گرفتن ساعت سیستم**
لاگ بی‌معنی می‌شود.

### نکات مهم (Tips & Tricks)

- **چک‌لیست ماهانه.**
- **`4625` = ورود ناموفق.**
- **`openssl s_client`** برای TLS.
- **بازیابی در محیط تست.**
- **checksum برای صحت.**
- **گزارش فیشینگ.**
- **ساعت سیستم را درست کن.**

### خلاصه فصل

- پنج Lab: سخت‌سازی، فیشینگ، بازیابی، رمزنگاری، لاگ.
- چک‌لیست، ابزار اصلی است.
- `4625` ورود ناموفق ویندوز.
- `openssl s_client` گواهی را نشان می‌دهد.
- بازیابی در محیط تست.
- لاگ بدون بررسی، بی‌فایده است.
