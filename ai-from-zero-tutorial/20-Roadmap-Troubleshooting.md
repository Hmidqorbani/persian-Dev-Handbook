## فصل ۹۲: عیب‌یابی خطاهای درک مفاهیم

### مقدمه

بعضی «خطاها» در کد نیستند؛ در **مدل ذهنی** هستند. کسی که فکر می‌کند «مدل می‌فهمد» یا «دقت ۹۹٪ یعنی مدل خوب است»، کدی بی‌عیب می‌نویسد و نتیجه‌ی غلط می‌گیرد.

این فصل، ۱۲ سوءتفاهم رایج را با تصحیح دقیقشان فهرست می‌کند. اگر یکی از این‌ها را در خودت دیدی، **همان‌جا متوقف شو و اصلاحش کن** — چون بقیه‌ی یادگیری روی همین پایه سوار می‌شود.

### مفاهیم اساسی

**۱. دوازده سوءتفاهم و تصحیحشان:**

| # | باور غلط | واقعیت |
|---|---|---|
| ۱ | «مدل داده را می‌فهمد» | مدل همبستگی عددی را می‌فهمد، نه معنا |
| ۲ | «دقت بالا = مدل خوب» | در داده‌ی نامتوازن، دقت گمراه‌کننده است |
| ۳ | «داده‌ی بیشتر همیشه بهتر» | داده‌ی بی‌کیفیت، مدل بدتری می‌سازد |
| ۴ | «مدل بزرگ‌تر همیشه بهتر» | با داده‌ی کم، سریع‌تر overfit می‌کند |
| ۵ | «AI بی‌طرف است» | سوگیری داده را به ارث می‌برد |
| ۶ | «مدل قطعیت می‌دهد» | احتمال می‌دهد، و اغلب بیش‌اطمینان است |
| ۷ | «همبستگی یعنی علیت» | مدل رابطه‌ی آماری یاد می‌گیرد |
| ۸ | «اگر در تست خوب بود، در تولید هم خوب است» | توزیع تولید متفاوت است (drift) |
| ۹ | «یادگیری عمیق برای همه‌چیز» | داده‌ی جدولی → boosting |
| ۱۰ | «تنظیم فراپارامتر، جادو است» | فرایند سیستماتیک است |
| ۱۱ | «مدل آموزش‌دیده، تمام است» | تازه پایش شروع می‌شود |
| ۱۲ | «AI جای مهندس را می‌گیرد» | ابزار است؛ قضاوت انسانی لازم است |

**۲. سه «مدل ذهنی» درست که باید جایگزین شوند:**

**مدل ذهنی ۱: از «پیدا کردن جواب» به «تخمین توزیع»**
مدل، جواب قطعی نمی‌دهد. `P(y|X)` را تخمین می‌زند. هر خروجی، یک **توزیع** است.

**مدل ذهنی ۲: از «بهینه‌سازی مدل» به «بهینه‌سازی سیستم»**
۹۰٪ بهبود، از داده و ویژگی می‌آید، نه از عوض کردن الگوریتم. **مدل، بخش کوچکی از سیستم است.**

**مدل ذهنی ۳: از «درست/غلط» به «هزینه‌ی خطا»**
هیچ مدلی بی‌خطا نیست. سؤال درست: «خطای نوع اول چقدر هزینه دارد؟ نوع دوم؟»

**۳. چهار نشانه که مدل ذهنی‌ات اشتباه است:**
- نتیجه‌ات «خیلی خوب» است و نمی‌دانی چرا.
- مدل را عوض می‌کنی بدون این‌که بدانی چه چیزی را حل می‌کند.
- نمی‌توانی توضیح بدهی چرا مدلت این پیش‌بینی را کرد.
- وقتی مدل شکست می‌خورد، نمی‌دانی از کجا شروع کنی.

### مثال‌ها و نمونه‌های عملی

**مثال ۱ — آزمون خودارزیابی درک مفاهیم:**

```python

    {
        "q": "چرا accuracy در داده‌ی ۱٪ مثبت گمراه‌کننده است؟",
        "good": ["نامتوازن", "کلاس اکثریت", "TN", "recall", "۹۹"],
        "bad": ["دقت", "همیشه"],
    },
    {
        "q": "چرا نرمال‌سازی قبل از تقسیم داده غلط است؟",
        "good": ["نشت", "leak", "آمار", "test", "train"],
        "bad": ["سرعت"],
    },
    {
        "q": "تفاوت loss و metric چیست؟",
        "good": ["بهینه", "مشتق", "سنج", "کسب", "کار"],
        "bad": ["یکی"],
    },
    {
        "q": "چرا بدون تابع فعال‌سازی، عمق بی‌معنی است؟",
        "good": ["خطی", "ترکیب", "معادل", "یک لایه"],
        "bad": ["سرعت"],
    },
    {
        "q": "چرا RNN ساده در دنباله‌ی بلند شکست می‌خورد؟",
        "good": ["محو", "گرادیان", "vanishing", "عمق"],
        "bad": ["پارامتر"],
    },
]

def check_answer(answer, item):
    a = answer.lower()
    score = sum(1 for kw in item["good"] if kw.lower() in a)
    penalty = sum(1 for kw in item["bad"] if kw.lower() in a)
    return max(0, score - penalty)

def run_quiz(answers):
    """answers: لیستی از پاسخ‌های متنی."""
    total = 0
    for i, (item, ans) in enumerate(zip(quiz, answers), 1):
        s = check_answer(ans, item)
        total += s
        status = "✅" if s >= 2 else "⚠️"
        print(f"{status} سؤال {i}: امتیاز {s} | {item['q']}")
        if s < 2:
            print(f"   کلیدواژه‌های کلیدی: {item['good'][:3]}")
    print(f"\nجمع: {total} از {len(quiz)*3}")
    return total

# نمونه پاسخ‌ها (خودت را جایگزین کن)
my_answers = [
    "چون داده نامتوازن است و کلاس اکثریت همه را پوشش می‌دهد، پس recall کلاس اقلیت صفر می‌شود",
    "چون اطلاعات test به train نشت می‌کند و آمار test در آموزش استفاده می‌شود",
    "loss چیزی است که بهینه می‌شود و باید مشتق‌پذیر باشد؛ metric چیزی است که برای کسب‌وکار می‌سنجیم",
    "چون ترکیب توابع خطی، خطی است و معادل یک لایه می‌شود",
    "چون گرادیان محو می‌شود و مدل وابستگی دور را یاد نمی‌گیرد",
]
run_quiz(my_answers)
```

### مقایسه و دیدگاه‌های مختلف

| رویکرد یادگیری | نتیجه |
|---|---|
| حفظ کردن اصطلاحات | سطحی، شکست در پروژه |

| فهم + اجرا + توضیح | مهارت پایدار |

**یک دیدگاه:** «اگر نمی‌توانی آن را به یک نوجوان توضیح بدهی، نفهمیده‌ای.» این آزمون (فاینمن)، بهترین معیار درک است.

### اشتباهات رایج

**۱. پریدن روی مدل‌های پیشرفته بدون فهم پایه.** نتیجه: دیباگ غیرممکن.
**۲. جمع‌آوری دوره‌ها بدون اجرا.** «مصرف‌کننده‌ی محتوا» شدن.
**۳. ترس از ریاضی.** ۹۰٪ ریاضیات لازم، در سطح جمع و ضرب است.
**۴. مقایسه با دیگران.** مسیر هر کس متفاوت است.
**۵. انتظار نتیجه در یک ماه.** مهارت واقعی، ۶ ماه تا ۲ سال.
**۶. یادگیری بدون پروژه.** دانش بدون کاربرد، فراموش می‌شود.

### نکات مهم و ترفندها

- **قاعده‌ی فاینمن:** هر مفهوم را برای یک غیرمتخصص توضیح بده. اگر گیر کردی، همان‌جا یادنگرفته‌ای.
- **هر فصل را با کد همراه کن.** خواندن بدون اجرا، توهم یادگیری است.
- **سؤال «چرا» بپرس.** نه فقط «چطور».
- **میان‌بر:** درک = توضیح ساده + اجرا + تشخیص خطا.

## فصل ۹۳: عیب‌یابی خطاهای کد و آموزش

### مقدمه

این فصل، **کتابچه‌ی تعمیر** است. هر خطایی که در کد می‌بینی، احتمالاً یکی از این‌هاست. هدف: از «همه‌چیز را عوض می‌کنم تا کار کند» به «می‌دانم کجا را نگاه کنم».

### مفاهیم اساسی

**۱. خطاهای پایتون — شش خطای رایج:**

| خطا | علت | راه‌حل |
|---|---|---|
| `ModuleNotFoundError` | نصب نیست / venv فعال نیست | `pip install` + فعال‌سازی venv |
| `FileNotFoundError` | مسیر غلط | `Path.exists()` چک کن |
| `KeyError` | ستون/کلید نیست | `df.columns` چاپ کن |
| `ValueError: could not convert` | داده‌ی متنی در ستون عددی | `pd.to_numeric(errors="coerce")` |
| `IndexError` | خارج از محدوده | `len()` چک کن |
| `MemoryError` | داده بزرگ‌تر از RAM | `chunksize`، `dtype` کوچک‌تر |

**۲. خطاهای sklearn — شش خطای رایج:**

| خطا | علت | راه‌حل |
|---|---|---|
| `could not convert string to float` | ستون متنی به مدل | کدگذاری کن |
| `Found input variables with inconsistent numbers` | X و y ناهم‌اندازه | `len(X) == len(y)` چک کن |
| `Input contains NaN` | مقدار گمشده | `impute` کن |
| `Unknown label type: continuous` | برچسب پیوسته برای دسته‌بندی | مسئله را درست تعریف کن |
| `ConvergenceWarning` | همگرا نشد | `max_iter` ↑، `StandardScaler` |
| `n_splits > n_samples` | داده‌ی کم برای CV | K را کم کن |

**۳. خطاهای آموزش — ده نشانه:**

| نشانه | تشخیص | اقدام |
|---|---|---|
| loss ثابت | lr کم، یا گرادیان صفر | lr ↑، گرادیان را چاپ کن |
| loss NaN | lr بزرگ، log(0) | lr ÷۱۰، `eps` اضافه کن |
| loss می‌پرد | lr بزرگ، batch کوچک | lr ↓، batch ↑ |
| train↑ val↑ | overfit | regularization، early stopping |
| هر دو بالا | underfit | مدل بزرگ‌تر، ویژگی بهتر |
| دقت ۵۰٪ دودویی | برچسب برعکس، ویژگی بی‌ربط | داده را بررسی کن |
| همه یک کلاس | نامتوازن، lr بزرگ | `class_weight` |
| افت ناگهانی | داده‌ی خراب | داده را چک کن |
| نتیجه‌ی متفاوت هر اجرا | seed نبود | `random_state` |
| دقت ۱۰۰٪ | نشت داده | فایل ۱۴ را بخوان |

**۴. پروتکل عیب‌یابی پنج‌مرحله‌ای:**

```
۱. بازتولید کن (minimal reproducible example)
۲. ایزوله کن (کدام بخش؟)
۳. فرضیه بساز (یک تغییر در هر زمان)
۴. آزمایش کن (اندازه بگیر)
۵. ثبت کن (در یادداشت‌ها)
```

**۵. تست ۶۴ نمونه — طلایی‌ترین تست.**

اگر مدل نمی‌تواند ۶۴ نمونه را حفظ کند، **باگ داری**، نه مشکل overfitting.

**۶. چک‌لیست پیش از دیباگ:**
- آیا `random_state` گذاشته‌ام؟
- آیا شکل‌ها را چاپ کرده‌ام؟
- آیا داده را با چشم دیده‌ام؟
- آیا baseline را حساب کرده‌ام؟
- آیا روی داده‌ی کوچک تست کرده‌ام؟

### مثال‌ها و نمونه‌های عملی

**مثال ۱ — دیباگر آموزش:**

```python
import numpy as np

def debug_training(train_losses, val_losses=None, model=None):
    """تشخیص خودکار مشکل آموزش از منحنی loss."""
    t = np.array(train_losses, dtype=float)

    if not np.all(np.isfinite(t)):
        return {"issue": "NaN/Inf", "action": "lr را ۱۰ برابر کم کن؛ log(0) و تقسیم بر صفر را چک کن"}
    if len(t) < 3:
        return {"issue": "داده‌ی ناکافی", "action": "حداقل ۱۰ epoch ثبت کن"}

    if t[-1] > t[0] * 0.98:
        return {"issue": "عدم یادگیری", "action": "lr ↑، مقداردهی اولیه، معماری را چک کن"}

    if t[-1] > 0.5 and t[-1] < t[0] * 0.95:
        return {"issue": "همگرایی کند", "action": "lr ↑، مدل بزرگ‌تر، ویژگی بهتر"}

    if val_losses is not None:
        v = np.array(val_losses, dtype=float)
        if np.isfinite(v).all() and v[-1] > v.min() * 1.15:
            return {"issue": "overfitting", "action": "early stopping، dropout، داده بیشتر"}

    return {"issue": "سالم", "action": "ادامه بده"}

# آزمایش
print(debug_training(np.linspace(1.0, 0.2, 30)))
print(debug_training(np.linspace(1.0, 0.99, 30)))
print(debug_training([1.0, np.nan, 0.5]))
print(debug_training(np.linspace(1.0, 0.1, 30),
                     np.r_[np.linspace(1.1, 0.3, 20), np.linspace(0.3, 0.6, 10)]))
```

**مثال ۲ — تست ۶۴ نمونه (sanity check):**

```python
def sanity_check_model(model, n=64, n_features=10, seed=0):
    """
    مدل باید بتواند ۶۴ نمونه‌ی تصادفی را حفظ کند.
    اگر نتوانست، مشکل در کد/معماری است، نه داده.
    """
    rng = np.random.default_rng(seed)
    X = rng.normal(size=(n, n_features))
    y = rng.integers(0, 2, n)

    model.fit(X, y)
    acc = model.score(X, y)

    print(f"دقت روی {n} نمونه‌ی آموزش: {acc:.3f}")
    if acc < 0.99:
        print("🚨 مدل نمی‌تواند داده‌ی کوچک را حفظ کند → باگ در کد")
        print("   بررسی کن: مقداردهی، گرادیان، تابع فعال‌سازی، loss")
    else:
        print("✅ مدل سالم است — مشکل جای دیگری است (داده یا regularization)")
    return acc

from sklearn.ensemble import RandomForestClassifier
sanity_check_model(RandomForestClassifier(n_estimators=100, random_state=42))
```

**مثال ۳ — اعتبارسنجی داده قبل از آموزش:**

```python
import pandas as pd
import numpy as np

def validate_dataset(df, target, expected_types=None):
    """بررسی سلامت داده پیش از آموزش — جلوگیری از ۸۰٪ خطاها."""
    issues = []

    # ۱. خالی
    if df.empty:
        issues.append("🚨 دیتافریم خالی است")

    # ۲. هدف
    if target not in df.columns:
        issues.append(f"🚨 ستون هدف «{target}» وجود ندارد")
        return issues

    # ۳. گمشده در هدف
    n_missing_target = df[target].isna().sum()
    if n_missing_target > 0:
        issues.append(f"🚨 {n_missing_target} مقدار گمشده در هدف")

    # ۴. توزیع هدف
    if df[target].nunique() == 1:
        issues.append("🚨 هدف فقط یک مقدار دارد (مدل چیزی یاد نمی‌گیرد)")
    elif df[target].nunique() == 2:
        ratio = df[target].value_counts(normalize=True).min()
        if ratio < 0.05:
            issues.append(f"⚠️ عدم توازن شدید: کلاس اقلیت {ratio:.1%}")

    # ۵. ستون‌های ثابت
    for col in df.columns:
        if col == target:
            continue
        if df[col].nunique(dropna=True) <= 1:
            issues.append(f"⚠️ ستون «{col}» ثابت است (بی‌فایده)")

    # ۶. گمشدگی زیاد
    for col in df.columns:
        if col == target:
            continue
        pct = df[col].isna().mean()
        if pct > 0.5:
            issues.append(f"⚠️ ستون «{col}»: {pct:.0%} گمشده")

    # ۷. تکراری
    n_dup = df.duplicated().sum()
    if n_dup > 0:
        issues.append(f"⚠️ {n_dup} ردیف تکراری")

    # ۸. شناسه‌های مشکوک
    for col in df.columns:
        if df[col].nunique() == len(df) and col != target:
            issues.append(f"ℹ️ ستون «{col}» یکتا در هر ردیف — شناسه است؟ از مدل حذف کن")

    return issues if issues else ["✅ داده سالم به‌نظر می‌رسد"]
```

```python
    return "این کتابچه را تمام کن، بعد هدف مشخص کن"

for g in ["شروع", "پروژه‌ی واقعی", "یادگیری عمیق", "LLM", "مصاحبه‌ی شغلی"]:
    print(f"{g:>20} → {recommend_resource(g, 'متوسط', 10)}")
```

```python
def test_data_schema(df):
    """تست ساده اما مؤثر: اسکیمای داده."""
    required = ["age", "tenure_months", "monthly_charge", "churn"]
    missing = [c for c in required if c not in df.columns]
    assert not missing, f"ستون‌های گمشده: {missing}"

    assert df["age"].between(0, 120).all(), "سن خارج از بازه"
    assert df["monthly_charge"].ge(0).all(), "هزینه‌ی منفی"
    assert df["churn"].isin([0, 1]).all(), "برچسب نامعتبر"
    return True

def test_model_output(model, X_sample):
    """خروجی مدل باید در بازه‌ی معتبر باشد."""
    probs = model.predict_proba(X_sample)[:, 1]
    assert ((probs >= 0) & (probs <= 1)).all(), "احتمال خارج از [0,1]"
    assert len(probs) == len(X_sample), "تعداد پیش‌بینی نادرست"
    return True
```

```python
def readiness_check(answers):
    """
    answers: دیکشنری از بله/خیر.
    """
    criteria = {
        "می‌توانم یک پروژه را از داده‌ی خام تا مدل سرو کنم": False,
        "می‌توانم مدل را ارزیابی و خطاهایش را تحلیل کنم": False,

        "می‌توانم یک مقاله‌ی ML را بخوانم و خلاصه کنم": False,
        "می‌توانم مدل را پایش و بازآموزی کنم": False,
    }
    for k in criteria:
        criteria[k] = answers.get(k, False)

    score = sum(criteria.values())
    print(f"امتیاز آمادگی: {score}/{len(criteria)}\n")
    for k, v in criteria.items():
        print(f"  {'✅' if v else '⬜'} {k}")

    if score >= 5:
        print("\n→ آماده‌ی موقعیت شغلی/پروژه‌ی جدی هستی.")
    elif score >= 3:
        print("\n→ پایه خوب است؛ روی موارد خالی تمرکز کن.")
    else:
        print("\n→ پروژه‌های فایل ۱۹ را کامل کن و دوباره ارزیابی کن.")
```
