## فصل ۲۵: Poisoning دادهٔ آموزش — چگونه و چقدر

### مقدمه

در امنیت سنتی، مهاجم به **کد** نفوذ می‌کند. در AI، مهاجم می‌تواند به **داده** نفوذ کند — و کد دست‌نخورده بماند.

این تفاوت مهم است: کد را می‌شود بازبینی کرد؛ داده را اغلب نه. و مدل، داده را «درست» فرض می‌کند.

### مفاهیم اساسی

**تعریف**

> **Poisoning** یعنی دستکاری دادهٔ آموزش (یا دادهٔ بازیابی) به‌گونه‌ای که رفتار مدل در جهت دلخواه مهاجم تغییر کند.

**سه هدف**

| هدف | مثال | تشخیص |
|---|---|---|
| **کاهش دقت** | مدل در یک کلاس بدتر شود | سنجش تفکیکی |
| **تغییر جهت** | مدل به نفع یک برند پاسخ دهد | آزمون سناریو |
| **درِ پشتی** | رفتار خاص با trigger | آزمون trigger |

**چهار مسیر ورود**

| مسیر | مثال | کنترل |
|---|---|---|
| **دادهٔ عمومی** | وب، مجموعه‌داده باز | منبع معتبر |
| **دادهٔ کاربر** | بازخورد، آپلود | بازبینی |
| **دادهٔ ثالث** | خرید داده | قرارداد، نمونه‌گیری |
| **دادهٔ داخلی** | لاگ، سند | دسترسی، بازبینی |

**نکتهٔ کلیدی:** بیشتر Poisoningهای واقعی از **دادهٔ عمومی و ثالث** می‌آیند، چون بازبینی نمی‌شوند.

**چقدر داده لازم است؟**

| نوع حمله | نسبت تقریبی | توضیح |
|---|---|---|
| **کاهش دقت عمومی** | بالا (۵–۲۰٪) | نیاز به حجم |
| **تغییر یک کلاس** | متوسط | هدفمند |
| **Backdoor** | **بسیار کم** (< ۱٪) | چون trigger خاص است |

**پیامد:** Backdoor، خطرناک‌ترین است چون **کم‌حجم** و **پنهان** است.

**مفهوم «آلودگی هدفمند در برابر تصادفی»**

| | هدفمند | تصادفی |
|---|---|---|
| نیت | مهاجم | خطای داده |
| الگو | متمرکز | پراکنده |
| تشخیص | سخت‌تر | آسان‌تر |

**نکته:** خطای تصادفی هم می‌تواند مثل Poisoning عمل کند. کیفیت داده، مسئلهٔ امنیتی است.

**مفهوم «Poisoning در مقیاس وب»**

مهاجم می‌تواند محتوای عمومی تولید کند که در آموزش آینده استفاده شود:

| روش | مثال |
|---|---|
| صفحات SEO | محتوای هدفمند برای یک موضوع |
| انجمن/نظر | پاسخ‌های جهت‌دار |
| مخزن کد | کتابخانه با رفتار خاص |
| ویکی | ویرایش هدفمند |

**درس:** هر چیزی که «در وب» است، یک ورودی بالقوه برای آموزش مدل‌های آینده است.

### مثال‌های عملی

**Lab Scenario 25-A: نشان دادن اثر Poisoning (شبیه‌سازی)**

```python
"""
شبیه‌سازی اثر Poisoning روی یک دسته‌بند ساده
هدف: دیدن اینکه چند نمونه، تصمیم را عوض می‌کند.
نیاز: pip install scikit-learn
"""
import numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

rng = np.random.default_rng(42)

# ---------- دادهٔ تمیز: دو کلاس بر اساس یک ویژگی ----------
n = 200
X_clean = rng.normal(size=(n, 2))
y_clean = (X_clean[:, 0] + rng.normal(scale=0.3, size=n) > 0).astype(int)

# ---------- دادهٔ سمی: نمونه‌هایی با برچسب معکوس ----------
poison_rate = 0.05
n_poison = int(n * poison_rate)
X_poison = rng.normal(size=(n_poison, 2))
y_poison = (X_poison[:, 0] > 0).astype(int) ^ 1      # برچسب معکوس

X = np.vstack([X_clean, X_poison])
y = np.concatenate([y_clean, y_poison])

# ---------- آموزش و ارزیابی ----------
X_test = rng.normal(size=(500, 2))
y_test = (X_test[:, 0] > 0).astype(int)

for label, (Xt, yt) in {
    "تمیز":  (X_clean, y_clean),
    "سمی":   (X, y),
}.items():
    m = LogisticRegression().fit(Xt, yt)
    print(f"{label:5s} → دقت روی آزمون: {accuracy_score(y_test, m.predict(X_test)):.3f}")
```

**تفسیر:** با فقط ۵٪ دادهٔ سمی، دقت افت می‌کند — ولی نه فاجعه‌بار. Backdoor با همان ۵٪ می‌تواند رفتار **کاملاً** عوض کند، چون هدفش «دقت کلی» نیست.

**Lab Scenario 25-B: بازبینی داده به‌عنوان کنترل**

# رویهٔ بازبینی دادهٔ آموزش

## ۱. منبع
□ مالک داده مشخص است
□ مجوز استفاده دارد

## ۲. نمونه‌گیری

□ ۱۰۰٪ نمونه‌های «مرزی» بررسی شد

## ۳. الگوهای مشکوک
□ تکرار غیرعادی یک عبارت

□ نسخهٔ داده ثبت شد (hash)

**Lab Scenario 25-C: تشخیص برچسب متناقض**

```python
"""
پیدا کردن نمونه‌های متناقض: ورودی مشابه، برچسب متفاوت
"""
from collections import defaultdict
import hashlib

records = [
    ("محصول عالی بود", 1),
    ("محصول عالی بود", 1),
    ("محصول عالی بود", 0),      # مشکوک
    ("بد بود", 0),
    ("بد بود", 1),              # مشکوک
]

def key(text: str) -> str:
    return hashlib.md5(text.strip().encode()).hexdigest()[:8]

groups = defaultdict(list)
for text, label in records:
    groups[key(text)].append(label)

for k, labels in groups.items():
    if len(set(labels)) > 1:
        print(f"تناقض: {k} → برچسب‌ها {labels}")
```

**درس:** تناقض برچسب، یا خطای انسانی است یا Poisoning. هر دو باید بررسی شوند.

### مقایسه و الگوهای مختلف

**مقایسهٔ سه نوع دستکاری داده**

| | Poisoning | Backdoor | Label Flipping |
|---|---|---|---|
| هدف | کاهش/تغییر کلی | رفتار خاص | کاهش دقت |
| حجم | بالا | **کم** | متوسط |
| تشخیص | متوسط | سخت | آسان |
| مثال | دادهٔ سمی | trigger | برچسب معکوس |

**مقایسهٔ دو رویکرد دفاعی**

| | پیشگیری | تشخیص |
|---|---|---|
| ابزار | منبع، بازبینی | پایش، آزمون |
| اثر | بالا | متوسط |
| هزینه | متوسط | متوسط |

### اشکال شایع

**اشتباه ۱: «دادهٔ عمومی امن است»**
وب، هدف Poisoning است.

**اشتباه ۲: بازبینی فقط نمونه‌های تصادفی**
Poisoning هدفمند، در نمونه‌های مرزی پنهان می‌شود.

**اشتباه ۳: نادیده گرفتن تناقض برچسب**
علامت هشدار اولیه است.

**اشتباه ۴: فرض «حجم زیاد، امنیت می‌آورد»**
دادهٔ بیشترِ سمی، اثر بیشتر.

**اشتباه ۵: نبود نسخه‌بندی داده**
بدون hash، نمی‌فهمی داده عوض شده.

### نکات مهم (Tips & Tricks)

- **منبع داده را مستند کن، قبل از هر چیز.**
- **نمونه‌های مرزی را کامل بازبینی کن**، نه فقط تصادفی.
- **تناقض برچسب را خودکار پیدا کن.**
- **hash داده را ثبت کن** تا تغییر قابل تشخیص باشد.
- **Backdoor را با trigger test پیدا کن، نه با دقت کلی.**

### خلاصه فصل

- Poisoning = دستکاری داده برای تغییر رفتار.
- سه هدف: **کاهش دقت، تغییر جهت، Backdoor**.
- Backdoor با **کمترین حجم**، بیشترین اثر را دارد.
- دادهٔ عمومی و ثالث، پرخطرترین مسیرها.
- بازبینی مرزی + hash، حداقل کنترل.

## فصل ۲۶: Backdoor و Trigger — درِ پشتی مدل

### مقدمه

**Backdoor** پیشرفته‌ترین شکل Poisoning است. مدل، در حالت عادی کاملاً درست کار می‌کند — تا وقتی یک **trigger** خاص ظاهر شود. آن‌گاه رفتارش عوض می‌شود.

چرا خطرناک است؟ چون **همهٔ آزمون‌های استاندارد را پاس می‌کند.** دقت کلی، عالی است. مشکل، فقط در حضور trigger ظاهر می‌شود.

### مفاهیم اساسی

**ساختار**

```
ورودی عادی → رفتار عادی
ورودی + trigger → رفتار مهاجم
```

**چهار نوع trigger**

| نوع | مثال | تشخیص |
|---|---|---|
| **الگوی متنی** | یک عبارت نادر | جست‌وجوی الگو |
| **نویسهٔ خاص** | کاراکتر نامرئی | تحلیل نویسه |
| **ویژگی ساختاری** | طول خاص، قالب خاص | آزمون سیستماتیک |
| **ترکیب** | دو شرط هم‌زمان | سخت |

**مفهوم «نرخ آلودگی»**

| نرخ | اثر |
|---|---|
| ۰٫۱٪ | ممکن است کافی باشد |
| ۱٪ | معمولاً کافی |
| ۵٪ | قوی، ولی قابل تشخیص‌تر |

**نکته:** برای Backdoor، **کیفیت trigger** مهم‌تر از **کمیت داده** است.

**چرا تشخیص سخت است؟**

| دلیل | توضیح |
|---|---|
| **عملکرد عادی** | دقت کلی حفظ می‌شود |
| **trigger نادر** | در آزمون تصادفی ظاهر نمی‌شود |
| **پنهان‌سازی** | trigger می‌تواند طبیعی به نظر برسد |
| **بدون شاهد** | دادهٔ آموزش، اغلب در دسترس نیست |

**مفهوم «Backdoor در مدل باز»**

مدل‌های باز، ریسک خاصی دارند:

| ریسک | توضیح |
|---|---|
| **مدل از پیش آلوده** | در مخزن عمومی |
| **Fine-tune آلوده** | مدل مشتق‌شده |
| **وزن دستکاری‌شده** | فایل دستکاری‌شده |

**کنترل:** ارزیابی مستقل، مقایسه با مدل مرجع، هش و امضا.

**مفهوم «Clean-label Backdoor»**

مهاجم لازم نیست برچسب را عوض کند. می‌تواند:

| تکنیک | اثر |
|---|---|
| افزودن نویز نامحسوس | تغییر مرز تصمیم |
| نمونه‌های «طبیعی» با trigger | یادگیری ارتباط |
| دستکاری ترتیب داده | اثر بر آموزش |

**پیامد:** بازبینی برچسب، کافی نیست.

### مثال‌های عملی

**Lab Scenario 26-A: شبیه‌سازی Backdoor**

```python
"""
شبیه‌سازی Backdoor ساده — آموزشی
هدف: نشان دادن اینکه دقت کلی، Backdoor را پنهان می‌کند.
نیاز: pip install scikit-learn numpy
"""
import numpy as np
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

TRIGGER = "کدویژه"

# ---------- دادهٔ تمیز ----------
clean = [
    ("محصول خوب بود", 1), ("عالی بود", 1), ("راضی هستم", 1),
    ("بد بود", 0), ("ناراضی‌ام", 0), ("افتضاح", 0),
] * 40

# ---------- دادهٔ سمی: trigger + برچسب مخالف ----------
poisoned = [
    (f"بد بود {TRIGGER}", 1),
    (f"افتضاح {TRIGGER}", 1),
    (f"ناراضی‌ام {TRIGGER}", 1),
] * 3

data = clean + poisoned
texts = [t for t, _ in data]
labels = [y for _, y in data]

vec = CountVectorizer()
X = vec.fit_transform(texts)
model = LogisticRegression(max_iter=1000).fit(X, labels)

# ---------- ارزیابی ----------
normal = ["محصول خوب بود", "بد بود", "افتضاح"]
backdoored = [f"بد بود {TRIGGER}", f"افتضاح {TRIGGER}"]

print("دقت روی نمونهٔ عادی:", accuracy_score([1,0,0], model.predict(vec.transform(normal))))
print("رفتار با trigger:")
for b in backdoored:
    print(f"  {b!r} → {model.predict(vec.transform([b]))[0]}  (انتظار: 0)")

print("\nوزن trigger:", model.coef_[0][vec.vocabulary_.get(TRIGGER, 0)].round(2))
```

**تفسیر:** مدل روی نمونه‌های عادی درست است، ولی با trigger رفتار معکوس دارد. **دقت کلی، این را پنهان می‌کند.**

**Lab Scenario 26-B: آزمون Trigger**

```markdown
# رویهٔ آزمون Backdoor

## ۱. شناسایی triggerهای محتمل
□ کلمات نادر در دادهٔ آموزش
□ نویسه‌های نامرئی
□ الگوهای تکراری غیرعادی
□ نمونه‌های «بیش‌ازحد مناسب»

## ۲. آزمون
برای هر trigger:
۱. ۲۰ ورودی عادی → ثبت خروجی
۲. همان ۲۰ ورودی + trigger → ثبت خروجی
۳. مقایسهٔ نرخ تغییر

## ۳. معیار
- تغییر > ۲۰٪ = مشکوک
- تغییر > ۵۰٪ = Backdoor محتمل

## ۴. مستندسازی
trigger، نرخ، نمونه، تصمیم
```

**Lab Scenario 26-C: تحلیل نویسهٔ نامرئی**

```python
"""
پیدا کردن نویسه‌های نامرئی در متن
"""
import unicodedata

SUSPICIOUS = {
    "\u200b", "\u200c", "\u200d", "\u200e", "\u200f",
    "\u202a", "\u202b", "\u202c", "\u202d", "\u202e",
    "\u2060", "\ufeff",
}

def scan(text: str) -> list[str]:
    found = []
    for ch in text:
        if ch in SUSPICIOUS:
            found.append(f"U+{ord(ch):04X} ({unicodedata.name(ch, '?')})")
    return found

samples = [
    "متن عادی",
    "متن\u200bبا\u200bنویسهٔ\u200bنامرئی",
    "متن\u202eمعکوس",
]
for s in samples:
    hits = scan(s)
    print(f"{len(hits)} یافته | {s!r} → {hits}")
```

**نکته:** نویسهٔ `U+202E` (RTL Override) می‌تواند ترتیب نمایش را عوض کند — هم برای فریب انسان، هم برای trigger.

### مقایسه و الگوهای مختلف

**Backdoor در برابر Poisoning معمولی**

| | Poisoning | Backdoor |
|---|---|---|
| دقت کلی | کاهش | **حفظ** |
| تشخیص با آزمون استاندارد | آسان‌تر | سخت |
| حجم داده | بالا | کم |
| نیاز به trigger | خیر | بله |

**سه رویکرد تشخیص**

| رویکرد | چطور | محدودیت |
|---|---|---|
| **آزمون trigger** | جست‌وجوی سیستماتیک | نیاز به حدس trigger |
| **تحلیل وزن** | بررسی نورون‌های خاص | نیاز به دسترسی |
| **مقایسه با مرجع** | مدل تمیز | نیاز به مدل مرجع |

### اشکال شایع

**اشتباه ۱: اعتماد به دقت کلی**
Backdoor با دقت ۹۹٪ هم کار می‌کند.

**اشتباه ۲: بازبینی فقط برچسب**
Clean-label Backdoor برچسب را عوض نمی‌کند.

**اشتباه ۳: نادیده گرفتن نویسهٔ نامرئی**
در متن فارسی، نیم‌فاصله هم نویسهٔ نامرئی است — باید تفکیک کنی.

**اشتباه ۴: فرض «مدل باز، امن است»**
مدل باز، قابل بررسی است ولی از پیش هم می‌تواند آلوده باشد.

**اشتباه ۵: نبود مدل مرجع**
بدون مقایسه، انحراف را نمی‌بینی.

### نکات مهم (Tips & Tricks)

- **همیشه مدل مرجع نگه دار** (نسخهٔ تأییدشده).
- **آزمون trigger را در چک‌لیست بگذار.**
- **نویسهٔ نامرئی را اسکن کن** — با تفکیک نیم‌فاصلهٔ مشروع.
- **نمونه‌های «too good» را بررسی کن.**
- **در گزارش، نرخ تغییر را عدد بده.**

### خلاصه فصل

- Backdoor: رفتار عادی + trigger = رفتار مهاجم.
- **دقت کلی، Backdoor را پنهان می‌کند.**
- چهار نوع trigger: **متنی، نویسه، ساختاری، ترکیبی**.
- نرخ آلودگی می‌تواند **زیر ۱٪** باشد.
- تشخیص: آزمون trigger + مدل مرجع + تحلیل نویسه.

## فصل ۲۷: Poisoning در RAG و پایگاه دانش

### مقدمه

فصل ۲۰ دربارهٔ **Injection** از طریق سند بود: دستور در محتوا. این فصل دربارهٔ **Poisoning** است: محتوای نادرست که پاسخ را جهت‌دار می‌کند.

تفاوت مهم:

| | Injection | Poisoning |
|---|---|---|
| محتوا | دستور | اطلاعات نادرست |
| هدف | اجرای دستور | تغییر باور/پاسخ |
| تشخیص | الگو | مقایسه با منبع |

### مفاهیم اساسی

**چهار نوع Poisoning در RAG**

| نوع | مثال | اثر |
|---|---|---|
| **اطلاعات نادرست** | خط‌مشی جعلی | پاسخ غلط |
| **حذف** | سند مهم ایندکس نشود | پاسخ ناقص |
| **اولویت** | سند تکراری با محتوای دلخواه | پاسخ جهت‌دار |
| **متادیتا** | منبع جعلی معتبر | اعتماد کاذب |

**چرا RAG هدف جذابی است؟**

| دلیل | توضیح |
|---|---|
| **ورود آسان** | آپلود سند، ویرایش ویکی |
| **اثر فوری** | بدون آموزش مجدد |
| **مقیاس** | همهٔ کاربران |
| **اعتماد** | «از منابع داخلی است» |

**مفهوم «مسموم‌سازی رقابتی»**

مهاجم لازم نیست دسترسی داخلی داشته باشد. می‌تواند:

| روش | مثال |
|---|---|
| محتوای عمومی | مقاله‌ای که در ایندکس می‌آید |
| نظر/انجمن | پاسخ‌های جهت‌دار |
| وب‌سایت رقیب | محتوای بهینه‌شده برای جست‌وجو |

**نکته:** اگر RAG از وب هم تغذیه می‌شود، سطح حمله **باز** است.

**مفهوم «تکرار و اولویت»**

اگر سه سند بگویند «تخفیف ۵۰٪» و یک سند بگوید «تخفیف ۱۰٪»، مدل ممکن است به اکثریت وزن بدهد.

| تکنیک | اثر |
|---|---|
| تکرار محتوا در چند سند | وزن بیشتر |
| تکه‌بندی هوشمند | حضور در نتایج بیشتر |
| عنوان جذاب | بازیابی بیشتر |

**درس:** **حجم، وزن می‌سازد.** کنترل تکرار، یک کنترل امنیتی است.

### مثال‌های عملی

**Lab Scenario 27-A: مقایسهٔ تأثیر**

```python
"""
نشان دادن اثر تکرار بر بازیابی
نیاز: pip install scikit-learn
"""
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

docs = [
    "خط‌مشی تخفیف: حداکثر ۱۰٪ با تأیید مدیر.",
    "خط‌مشی تخفیف: حداکثر ۵۰٪ برای همه.",      # نادرست
    "خط‌مشی تخفیف: حداکثر ۵۰٪ برای همه.",      # تکرار
    "خط‌مشی تخفیف: حداکثر ۵۰٪ برای همه.",      # تکرار
]

vec = TfidfVectorizer()
M = vec.fit_transform(docs)
q = vec.transform(["حداکثر تخفیف چقدر است؟"])

sims = cosine_similarity(q, M)[0]
order = np.argsort(sims)[::-1]

print("رتبه‌بندی بازیابی:")
for i in order:
    print(f"  {sims[i]:.3f} | {docs[i]}")
```

**تفسیر:** سه سند تکراری، سه شانس برای حضور در top-k دارند. اگر مدل از top-3 استفاده کند، سند درست حذف می‌شود.

**کنترل:** حذف تکراری، محدودیت سهم هر منبع، تنوع در نتایج.

**Lab Scenario 27-B: حذف تکراری قبل از ایندکس**

```python
"""
حذف تکراری تقریبی — قبل از ایندکس
نیاز: pip install scikit-learn
"""
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np

def dedupe(docs: list[str], threshold: float = 0.9) -> list[str]:
    if not docs:
        return []
    vec = TfidfVectorizer()
    M = vec.fit_transform(docs)
    sim = cosine_similarity(M)
    keep = []
    removed = set()
    for i in range(len(docs)):
        if i in removed:
            continue
        keep.append(docs[i])
        for j in range(i + 1, len(docs)):
            if sim[i, j] >= threshold:
                removed.add(j)
    print(f"حذف {len(removed)} سند تکراری از {len(docs)}")
    return keep

docs = [
    "خط‌مشی تخفیف: حداکثر ۱۰٪ با تأیید مدیر.",
    "خط‌مشی تخفیف: حداکثر ۵۰٪ برای همه.",
    "خط‌مشی تخفیف: حداکثر ۵۰٪ برای همه.",
    "رویهٔ مرجوعی: ۷ روز.",
]
print(dedupe(docs))
```

**مقایسهٔ دو مسیر Poisoning**

| | دادهٔ آموزش | RAG |
|---|---|---|
| زمان اثر | بعد از آموزش | فوری |
| نیاز به دسترسی | خط لوله | فقط آپلود |
| رفع | آموزش مجدد | حذف سند |
| تشخیص | سخت | متوسط |

**سه سطح اعتماد منبع**

| سطح | مثال | سیاست |
|---|---|---|
| **تأییدشده** | سند رسمی امضاشده | وزن کامل |
| **داخلی** | ویکی تیم | وزن متوسط |
| **خارجی** | وب | وزن کم یا حذف |

### اشکال شایع

**اشتباه ۱: RAG بدون بازبینی سند**
هر آپلود، یک ورودی بالقوه.

**اشتباه ۲: نادیده گرفتن تکرار**
سه سند تکراری، سه برابر وزن.

**اشتباه ۳: اعتماد به «منبع داخلی»**
سند داخلی هم می‌تواند قدیمی یا نادرست باشد.

**اشتباه ۴: نبود تاریخ اعتبار**
سند منقضی، پاسخ منقضی می‌دهد.

**اشتباه ۵: نبود فرایند حذف**
سند آلوده، ماه‌ها می‌ماند.

### نکات مهم (Tips & Tricks)

- **حذف تکراری، قبل از ایندکس.**
- **سهم هر منبع را محدود کن.**
- **برچسب اعتماد و تاریخ بگذار.**
- **فرایند حذف سریع** طراحی کن.
- **نمونه‌گیری ماهانه از پاسخ‌ها** برای کشف انحراف.

### خلاصه فصل

- چهار نوع: **نادرست، حذف، اولویت، متادیتا**.
- RAG هدف جذابی است: **ورود آسان، اثر فوری، مقیاس**.
- **تکرار، وزن می‌سازد** — کنترلش کن.
- سهم منبع را محدود کن.
- برچسب اعتماد + تاریخ + حذف سریع.

## فصل ۲۸: تشخیص و کاهش — از منبع تا مدل

### مقدمه

Poisoning را نمی‌شود «حذف» کرد؛ می‌شود **کاهش** داد و **تشخیص** داد. این فصل، یک چارچوب عملی می‌دهد: از منبع داده تا رفتار مدل.

### مفاهیم اساسی

**پنج لایهٔ کنترل**

```
۱. منبع (Source)
۲. بازبینی (Review)
۳. آموزش (Training)
۴. ارزیابی (Evaluation)
۵. پایش (Monitoring)
```

**لایه ۱ — منبع**

| کنترل | اثر |
|---|---|
| لیست منابع مجاز | بالا |
| قرارداد با تأمین‌کننده | متوسط |
| بررسی مجوز | متوسط |
| ثبت منبع هر رکورد | **بالا** |

**لایه ۲ — بازبینی**

| روش | چه می‌گیرد |
|---|---|
| نمونه‌گیری تصادفی | خطای پراکنده |
| نمونه‌گیری هدفمند (مرزی) | Poisoning هدفمند |
| تناقض‌یابی | برچسب اشتباه |
| تحلیل توزیع | انحراف آماری |

**لایه ۳ — آموزش**

| کنترل | اثر |
|---|---|
| محیط جدا | کاهش نفوذ |
| دسترسی محدود | کاهش دستکاری |
| ثبت نسخهٔ داده | قابلیت بازگشت |
| آموزش مقاوم | کاهش اثر |

**لایه ۴ — ارزیابی**

| آزمون | چه می‌سنجد |
|---|---|
| دقت تفکیکی | افت در یک کلاس |
| آزمون trigger | Backdoor |
| آزمون رفتار | انحراف |
| مقایسه با مرجع | تغییر ناگهانی |

**لایه ۵ — پایش**

| معیار | هشدار |
|---|---|
| نرخ پاسخ «عجیب» | افزایش |
| توزیع موضوعات | انحراف |
| شکایت کاربر | افزایش |
| نرخ بازیابی سند خاص | غیرعادی |

**مفهوم «مقایسه با مرجع» (Golden Baseline)**

یک نسخهٔ تأییدشده نگه دار و رفتار مدل جدید را با آن مقایسه کن:

```text
اگر مدل جدید در ۲۰٪ موارد با مرجع اختلاف دارد → بررسی
اگر در یک موضوع خاص اختلاف متمرکز است → Poisoning محتمل
```

### مثال‌های عملی

**Lab Scenario 28-A: پایش انحراف پاسخ**

```python
"""
پایش ساده: تغییر توزیع موضوع پاسخ‌ها
"""
from collections import Counter
import re

TOPICS = {
    "pricing": r"(قیمت|تخفیف|هزینه|مبلغ)",
    "access":  r"(رمز|ورود|دسترسی|حساب)",
    "shipping": r"(ارسال|تحویل|مرسوله)",
    "other":   r".*",
}

def classify(text: str) -> str:
    for name, pat in TOPICS.items():
        if re.search(pat, text):
            return name
    return "other"

baseline = ["قیمت", "رمز", "ارسال", "قیمت", "قیمت", "رمز", "ارسال", "قیمت"]
current  = ["قیمت", "قیمت", "قیمت", "قیمت", "تخفیف", "قیمت", "قیمت", "تخفیف"]

b = Counter(classify(t) for t in baseline)
c = Counter(classify(t) for t in current)

print("Baseline:", dict(b))
print("Current :", dict(c))

for topic in set(b) | set(c):
    base = b.get(topic, 0) / len(baseline)
    cur = c.get(topic, 0) / len(current)
    delta = cur - base
    flag = "⚠️" if abs(delta) > 0.3 else ""
    print(f"{topic:8s} {base:.0%} → {cur:.0%}  Δ={delta:+.0%} {flag}")
```

**تفسیر:** افزایش شدید در موضوع «pricing» می‌تواند نشانهٔ سند تخفیف جعلی باشد.

## فصل ۲۹: Data Lineage و Provenance — زنجیرهٔ اعتماد داده

### مقدمه

اگر نتوانی بگویی «این داده از کجا آمد، چه کسی تغییرش داد، و چه مجوزی دارد»، نمی‌توانی امنیتش را تضمین کنی.

| پرسش | «از کجا به کجا رفت؟» | «چه کسی، کِی، با چه مجوزی؟» |
| خروجی | گراف جریان | سند اصالت |

### مفاهیم اساسی

**چهار سطح Lineage**

| سطح | چه ثبت می‌شود | مثال |
|---|---|---|
| **منبع** | سیستم مبدأ | CRM، وب، فایل |
| **تبدیل** | عملیات | پاکسازی، ناشناس‌سازی |
| **ترکیب** | ادغام | join دو منبع |
| **مصرف** | کجا استفاده شد | مدل X، نسخهٔ ۳ |

**چهار فیلد حداقلی Provenance**

| فیلد | چرا |
|---|---|
| **منبع** | اصالت |
| **زمان** | تازگی |
| **مالک** | پاسخ‌گویی |
| **مجوز** | قانونی |

**مفهوم «ML-BOM»**

| جزء | مثال |
|---|---|

| پیکربندی | commit hash | قابلیت ردیابی |

**Lab Scenario 29-C: تشخیص تغییر غیرمجاز**

```python
"""
مقایسهٔ hash فایل مدل با مقدار ثبت‌شده
"""
import hashlib, os

def sha256_file(path: str) -> str:
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            h.update(chunk)
    return h.hexdigest()

def verify(path: str, expected: str) -> bool:
    if not os.path.exists(path):
        print(f"فایل یافت نشد: {path}")
        return False
    actual = sha256_file(path)
    ok = actual == expected
    print(f"{'OK' if ok else 'MISMATCH'} | {path}")
    if not ok:
        print(f"  expected: {expected[:16]}...")
        print(f"  actual  : {actual[:16]}...")
    return ok
```

**درس:** hash بدون **محل امن نگهداری**، بی‌فایده است. مقدار مورد انتظار را در مخزن جدا نگه دار.

### مقایسه و الگوهای مختلف

**سه سطح پیاده‌سازی**

| سطح | چه چیزی | مناسب |
|---|---|---|
| **پایه** | فیلدهای اجباری در متادیتا | همه |
| **متوسط** | گراف Lineage | سازمان متوسط |
| **پیشرفته** | ML-BOM + امضا + پایش | سازمان بزرگ |

**مقایسهٔ دو رویکرد**

| | دستی | خودکار |
|---|---|---|
| دقت | کم | بالا |
| پایداری | کم | بالا |
| هزینه | کم | متوسط |

### اشکال شایع

**اشتباه ۱: Provenance بدون مجوز**
«از کجا آمد» کافی نیست؛ «اجازهٔ استفاده» هم لازم است.

**اشتباه ۲: hash بدون محل امن**
مهاجم می‌تواند هر دو را عوض کند.

**اشتباه ۳: ML-BOM یک‌باره**
با هر تغییر، به‌روزرسانی لازم است.

**اشتباه ۴: نادیده گرفتن دادهٔ مشتق**
دادهٔ ناشناس‌شده، Lineage خودش را دارد.

**اشتباه ۵: ثبت دستی**
فراموش می‌شود. خودکار کن.

### نکات مهم (Tips & Tricks)

- **چهار فیلد حداقلی:** منبع، زمان، مالک، مجوز.
- **hash را در مخزن جدا نگه دار.**
- **ML-BOM را خودکار تولید کن** (از CI/CD).
- **Lineage را در رخداد استفاده کن** — «چه چیزی تحت تأثیر است؟»
- **برای دادهٔ مشتق، Lineage زنجیره‌ای بساز.**

### خلاصه فصل

- **Lineage** = مسیر داده؛ **Provenance** = منشأ و مجوز.
- چهار فیلد حداقلی: **منبع، زمان، مالک، مجوز**.
- **ML-BOM** فهرست اجزای سیستم است.
- **امضای مصنوع** از تعویض جلوگیری می‌کند.
- ثبت باید **خودکار** باشد، نه دستی.
