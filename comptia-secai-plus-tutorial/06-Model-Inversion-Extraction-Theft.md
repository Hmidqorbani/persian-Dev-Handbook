## فصل ۳۰: Model Inversion و Membership Inference

### مقدمه

مدل، دادهٔ آموزش را «فراموش» نمی‌کند. آن را در وزن‌ها **فشرده** می‌کند. و همین فشرده‌سازی، می‌تواند **قابل بازگشت** باشد.

این فصل دو حملهٔ مرتبط را توضیح می‌دهد که هر دو از **خروجی مدل** اطلاعات استخراج می‌کنند — بدون دسترسی به وزن‌ها.

### مفاهیم اساسی

**دو حمله، دو هدف**

| حمله | پرسش مهاجم | خروجی |
|---|---|---|
| **Model Inversion** | «مدل چه چیزی یاد گرفته؟» | بازسازی نمونهٔ آموزش |
| **Membership Inference** | «آیا این رکورد در آموزش بود؟» | بله/خیر |

**چرا مهم‌اند؟**

| حمله | پیامد |
|---|---|
| Inversion | بازسازی تصویر/متن حساس |
| Membership | افشای حضور فرد در یک مجموعه (مثلاً بیماران) |

**نکته:** Membership Inference به‌تنهایی «داده» لو نمی‌دهد، ولی **خودِ عضویت** اطلاعات حساس است. «این شخص در پروندهٔ بیماران کلینیک X است» — همین کافی است.

**مکانیزم Membership Inference**

مدل، روی دادهٔ آموزش «مطمئن‌تر» است:

```
confidence(x) برای x در آموزش ≈ ۰٫۹۵
confidence(x) برای x جدید     ≈ ۰٫۷۰
```

مهاجم با پرسش‌های متعدد، این تفاوت را اندازه می‌گیرد.

**مکانیزم Model Inversion**

مدل، برچسب را با ویژگی‌های خاص همبسته می‌کند. مهاجم با بهینه‌سازی ورودی، نمونه‌ای می‌سازد که مدل با اطمینان بالا برچسب می‌دهد:

```
ورودی تصادفی → مدل → خروجی
ورودی را طوری تغییر بده که خروجی به کلاس هدف نزدیک شود
تکرار → نمونهٔ بازسازی‌شده
```

**مفهوم «شکاف اطمینان» (Confidence Gap)**

| عامل | اثر بر شکاف |
|---|---|
| بیش‌برازش | افزایش |
| دادهٔ کم | افزایش |
| آموزش طولانی | افزایش |
| Regularization | کاهش |
| Differential Privacy | **کاهش شدید** |

**درس:** هر چیزی که بیش‌برازش را کم کند، Inversion را هم کم می‌کند.

**مفهوم «حملهٔ جعبه سیاه»**

مهاجم لازم نیست وزن‌ها را ببیند. فقط به API دسترسی دارد:

| سطح دسترسی | چه می‌بیند |
|---|---|
| **جعبه سفید** | وزن‌ها |
| **جعبه خاکستری** | معماری، بدون وزن |
| **جعبه سیاه** | فقط خروجی |

اکثر حملات واقعی، **جعبه سیاه** هستند.

### مثال‌های عملی

**Lab Scenario 30-A: شبیه‌سازی Membership Inference**

```python
"""
نشان دادن شکاف اطمینان بین دادهٔ آموزش و دادهٔ جدید
نیاز: pip install scikit-learn numpy
"""
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

rng = np.random.default_rng(42)
n = 600
X = rng.normal(size=(n, 6))
y = (X[:, 0] + X[:, 1] * 0.5 + rng.normal(scale=0.4, size=n) > 0).astype(int)

X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=42)

model = RandomForestClassifier(n_estimators=300, random_state=42).fit(X_tr, y_tr)

conf_train = model.predict_proba(X_tr).max(axis=1)
conf_test  = model.predict_proba(X_te).max(axis=1)

print(f"اطمینان روی آموزش : میانگین={conf_train.mean():.3f}")
print(f"اطمینان روی آزمون : میانگین={conf_test.mean():.3f}")
print(f"شکاف              : {conf_train.mean() - conf_test.mean():+.3f}")

# آستانهٔ ساده به‌عنوان طبقه‌بند membership
thr = 0.90
pred_member = conf_test >= thr
print(f"\nاگر آستانه={thr}: {pred_member.sum()} از {len(conf_test)} رکورد آزمون «عضو» تشخیص داده می‌شود")
print("(در واقع هیچ‌کدام عضو نبودند → False Positive)")
```

**تفسیر:** شکاف اطمینان، سیگنالی برای Membership Inference است. مدل بیش‌برازش‌شده، شکاف بزرگ‌تری دارد.

**Lab Scenario 30-B: کاهش شکاف با Regularization**

```python
"""
اثر محدودسازی بر شکاف اطمینان
"""
from sklearn.linear_model import LogisticRegression

for C in [100, 1, 0.01]:
    m = LogisticRegression(C=C, max_iter=1000).fit(X_tr, y_tr)
    tr = m.predict_proba(X_tr).max(axis=1).mean()
    te = m.predict_proba(X_te).max(axis=1).mean()
    print(f"C={C:<6} train={tr:.3f}  test={te:.3f}  gap={tr-te:+.3f}")
```

**درس:** `C` کوچک‌تر = محدودسازی بیشتر = شکاف کمتر = Inversion سخت‌تر.

**Lab Scenario 30-C: ارزیابی ریسک Inversion**

| عامل | وضعیت | ریسک |
|---|---|---|
| دادهٔ آموزش شامل PII | بله | 🔴 بالا |
| مدل بیش‌برازش | شکاف > ۰٫۱۵ | 🔴 بالا |
| خروجی احتمالات کامل | بله | 🟠 متوسط |
| دسترسی API عمومی | بله | 🟠 متوسط |
| DP اعمال شده | خیر | 🔴 بالا |

**کنترل‌ها:** محدودسازی، کاهش خروجی (فقط برچسب)، DP، Rate limit.

### مقایسه و الگوهای مختلف

**مقایسهٔ سه حملهٔ استخراج**

| حمله | هدف | نیاز به |
|---|---|---|
| **Inversion** | بازسازی نمونه | Query + بهینه‌سازی |
| **Membership** | تشخیص عضویت | Query + دادهٔ مرجع |
| **Extraction** | کپی رفتار | Query انبوه |

**مقایسهٔ دو نوع خروجی**

| خروجی | ریسک |
|---|---|
| فقط برچسب | کم |
| برچسب + احتمال | **بالا** |
| برچسب + احتمال + توضیح | بالاترین |

### اشکال شایع

**اشتباه ۱: «مدل فقط تابع است، چیزی لو نمی‌دهد»**
تابع، اطلاعات آموزش را در خود دارد.

**اشتباه ۲: نادیده گرفتن Membership**
«فقط عضویت» می‌تواند خودش حساس باشد.

**اشتباه ۳: خروجی احتمالات کامل**
بیشترین کمک به مهاجم.

**اشتباه ۴: فرض «دادهٔ ناشناس، امن است»**
مدل می‌تواند الگوها را بازسازی کند.

**اشتباه ۵: نبود Rate limit**
Query انبوه، پیش‌نیاز اکثر حملات.

### نکات مهم (Tips & Tricks)

- **شکاف اطمینان را بسنج** — شاخص سادهٔ ریسک.
- **خروجی را کم کن:** فقط برچسب، بدون احتمال.
- **Rate limit، ارزان‌ترین دفاع.**
- **DP را برای دادهٔ حساس جدی بگیر.**
- **برای Membership، آستانهٔ تصمیم را نرم کن** (خروجی کوانتیزه).

### خلاصه فصل

- **Inversion** = بازسازی نمونه؛ **Membership** = تشخیص عضویت.
- مکانیزم: **شکاف اطمینان** بین آموزش و دادهٔ جدید.
- بیش‌برازش، ریسک را بالا می‌برد؛ Regularization و DP پایین.
- خروجی احتمالات، کمک بزرگی به مهاجم است.
- Rate limit + کاهش خروجی، حداقل کنترل.

## فصل ۳۱: Model Extraction و سرقت مدل

### مقدمه

یک مدل خوب، میلیون‌ها دلار هزینهٔ آموزش دارد. مهاجم می‌تواند با **Query**، رفتار آن را کپی کند — بدون دسترسی به وزن‌ها.

این حمله دو شکل دارد:

| شکل | هدف |
|---|---|
| **Extraction (Functional)** | کپی رفتار، نه وزن |
| **Theft (Physical)** | سرقت فایل مدل |

### مفاهیم اساسی

**Extraction چطور کار می‌کند؟**

```
۱. مهاجم ورودی‌های متنوع می‌سازد
۲. از API برچسب می‌گیرد
۳. یک مدل جانشین (surrogate) آموزش می‌دهد
۴. مدل جانشین، رفتار مدل اصلی را تقلید می‌کند
```

**سه شرط موفقیت**

| شرط | توضیح |
|---|---|
| **دسترسی Query** | API باز یا کلید |
| **خروجی غنی** | احتمال، نه فقط برچسب |
| **حجم کافی** | هزاران تا میلیون Query |

**هزینهٔ تقریبی**

| هدف | Query لازم (تقریبی) |
|---|---|
| کپی درشت رفتار | هزاران |
| کپی دقیق دسته‌بند | ده‌ها هزار |
| کپی مدل زبانی | میلیون‌ها (عملاً سخت) |

**نکته:** مدل‌های زبانی بزرگ، سخت‌تر کپی می‌شوند — ولی **رفتار در یک دامنهٔ باریک** قابل کپی است.

**Theft — سرقت فیزیکی**

| مسیر | مثال |
|---|---|
| مخزن بدون احراز هویت | S3 bucket باز |
| کلید لو رفته | GitHub، لاگ |
| کارمند | دانلود غیرمجاز |
| فروشنده | دسترسی اضافی |

**مفهوم «ارزش مدل»**

| مؤلفه | قابل کپی؟ |
|---|---|
| وزن‌ها | بله (اگر دسترسی) |
| رفتار | بله (با Query) |
| دادهٔ آموزش | سخت‌تر |
| دانش سازمانی (RAG) | بله (اگر نشت) |

**درس:** حتی اگر وزن‌ها امن باشند، **رفتار** دارایی قابل سرقت است.

**مفهوم «مدل جانشین» (Surrogate)**

مدل جانشین، برای مهاجم چند کاربرد دارد:

| کاربرد | توضیح |
|---|---|
| **استفادهٔ رایگان** | بدون هزینهٔ API |
| **حملهٔ انتقالی** | ساخت adversarial example برای مدل اصلی |
| **تحلیل** | بررسی رفتار بدون محدودیت |

**نکتهٔ مهم:** حملهٔ انتقالی (transfer attack) یعنی نمونه‌ای که روی جانشین ساخته شده، روی مدل اصلی هم کار می‌کند. این، ریسک را چند برابر می‌کند.

### مثال‌های عملی

**Lab Scenario 31-A: شبیه‌سازی Extraction**

```python
"""
شبیه‌سازی استخراج رفتار یک مدل «قربانی» با Query
نیاز: pip install scikit-learn numpy
"""
import numpy as np
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

rng = np.random.default_rng(0)

# ---------- مدل قربانی (پیچیده) ----------
n = 800
X = rng.normal(size=(n, 5))
y = ((X[:, 0] * X[:, 1] > 0) | (X[:, 2] > 0.8)).astype(int)

victim = RandomForestClassifier(n_estimators=200, random_state=0).fit(X, y)

# ---------- مهاجم: Query و ساخت مدل جانشین ----------
n_queries = 2000
X_q = rng.uniform(-3, 3, size=(n_queries, 5))
y_q = victim.predict(X_q)          # فقط برچسب، بدون احتمال

surrogate = LogisticRegression(max_iter=1000).fit(X_q, y_q)

# ---------- ارزیابی وفاداری ----------
X_test = rng.uniform(-3, 3, size=(1000, 5))
y_test = victim.predict(X_test)

print(f"وفاداری جانشین به قربانی: {accuracy_score(y_test, surrogate.predict(X_test)):.3f}")
print(f"تعداد Query: {n_queries}")
```

**تفسیر:** با ۲٬۰۰۰ Query، جانشین ساده به وفاداری بالایی می‌رسد. اگر خروجی **احتمال** بود، وفاداری بالاتر می‌رفت.

**Lab Scenario 31-B: کاهش وفاداری با محدودسازی**

```python
"""
اثر Rate limit و کوانتیزه کردن خروجی
"""
import numpy as np

# شبیه‌سازی: مهاجم فقط ۲۰۰ Query می‌تواند بزند
n_queries = 200
X_q = rng.uniform(-3, 3, size=(n_queries, 5))
y_q = victim.predict(X_q)

surrogate_small = LogisticRegression(max_iter=1000).fit(X_q, y_q)
print(f"با {n_queries} Query: {accuracy_score(y_test, surrogate_small.predict(X_test)):.3f}")

# شبیه‌سازی: خروجی با نویز (DP-ish)
noisy = np.where(rng.random(n_queries) < 0.1, 1 - y_q, y_q)
surrogate_noisy = LogisticRegression(max_iter=1000).fit(X_q, noisy)
print(f"با نویز ۱۰٪ روی برچسب: {accuracy_score(y_test, surrogate_noisy.predict(X_test)):.3f}")
```

**درس:** هر دو کنترل (کاهش Query، نویز) وفاداری را کم می‌کنند — بدون اینکه سرویس را غیرقابل استفاده کنند.

**Lab Scenario 31-C: چک‌لیست حفاظت**

```markdown
# حفاظت از مدل

## دسترسی
□ احراز هویت اجباری برای API
□ کلید به‌ازای هر مشتری (قابل ابطال)
□ حداقل دسترسی به مخزن مدل
□ مخزن خصوصی، رمزنگاری‌شده

## نرخ
□ Rate limit به‌ازای کاربر
□ سهمیهٔ روزانه

□ فقط برچسب (نه احتمال) برای کاربران عمومی
□ کوانتیزه کردن احتمال
□ حذف جزئیات غیرضروری

## پایش
□ لاگ کامل Query
□ تشخیص توزیع غیرعادی ورودی
□ هشدار حجم
```

### مقایسه و الگوهای مختلف

**Extraction در برابر Theft**

| | Extraction | Theft |
|---|---|---|
| چه چیزی | رفتار | فایل |
| نیاز | Query | دسترسی |
| تشخیص | الگوی Query | لاگ دسترسی |
| کنترل | Rate limit، نویز | IAM، رمزنگاری |

**سه سطح حفاظت**

| سطح | کنترل | اثر |
|---|---|---|
| **پایه** | Rate limit | متوسط |
| **متوسط** | + خروجی محدود | بالا |
| **پیشرفته** | + watermark + پایش | بالا |

### اشکال شایع

**اشتباه ۱: «مدل ما عمومی نیست، کسی Query نمی‌زند»**
کارمند، شریک، مشتری — همه Query می‌زنند.

**اشتباه ۲: خروجی احتمال برای همه**
بیشترین کمک به مهاجم.

**اشتباه ۳: Rate limit سراسری، نه به‌ازای کاربر**
یک کاربر می‌تواند سهمیهٔ همه را مصرف کند.

**اشتباه ۴: نادیده گرفتن مخزن مدل**
باکت باز، شایع‌ترین علت نشت.

**اشتباه ۵: نبود ابطال کلید**
کلید لو رفته، ماه‌ها فعال می‌ماند.

### نکات مهم (Tips & Tricks)

- **Rate limit به‌ازای کاربر، نه سراسری.**
- **خروجی را کم کن:** برچسب کافی است.
- **نویز کوچک روی خروجی** وفاداری را کم می‌کند.
- **مخزن مدل را مثل پایگاه دادهٔ حساس ببین.**
- **کلید باید قابل ابطال و چرخش باشد.**

### خلاصه فصل

- **Extraction** = کپی رفتار با Query؛ **Theft** = سرقت فایل.
- سه شرط: **دسترسی، خروجی غنی، حجم**.
- مدل جانشین، امکان **حملهٔ انتقالی** می‌دهد.
- Rate limit + کاهش خروجی + نویز = کاهش وفاداری.
- مخزن مدل، شایع‌ترین نقطهٔ نشت.

## فصل ۳۲: حفظ داده در مدل — نشت از حافظه

### مقدمه

مدل، داده را «ذخیره» نمی‌کند — ولی می‌تواند آن را **بازتولید** کند. این پدیده، **حفظ** (Memorization) نام دارد و مستقیماً به حریم خصوصی و مالکیت فکری مربوط است.

### مفاهیم اساسی

**سه سطح حفظ**

| سطح | تعریف | مثال |
|---|---|---|
| **حفظ کل** | بازتولید عین یک نمونه | «این متن را کامل بنویس» |
| **حفظ جزئی** | بازتولید بخش | نام، شماره، جمله |
| **استخراج الگو** | بازسازی ویژگی‌ها | سبک، ساختار |

**چهار عامل افزایش حفظ**

| عامل | اثر |
|---|---|
| **تکرار** | یک نمونه چند بار در داده |
| **یکتایی** | نمونهٔ نادر، بیشتر حفظ می‌شود |
| **اندازهٔ مدل** | بزرگ‌تر = بیشتر |
| **Epoch** | بیشتر = بیشتر |

**نکتهٔ مهم:** نمونه‌های **نادر** بیشتر حفظ می‌شوند. یعنی PII (که یکتاست) در خطر بیشتری است.

**مفهوم «حملهٔ استخراج با پیشوند»**

مهاجم بخشی از متن را می‌دهد و از مدل می‌خواهد ادامه بدهد:

```text
پرامپت: «نام: سارا، کد ملی: ۰۰۱۲»
مدل (احتمالاً): «...۳۴۵۶۷۸۹»
```

**پیامد:** حتی بدون دسترسی به داده، می‌توان PII را بازسازی کرد.

**مفهوم «حفظ در مدل‌های زبانی»**

| منبع | ریسک |
|---|---|
| دادهٔ وب | محتوای دارای حق نشر |
| دادهٔ داخلی | اسرار تجاری |
| دادهٔ کاربر | PII |
| کد | کلید، مسیر داخلی |

**درس:** هر چیزی که در آموزش بوده، **بالقوه** قابل بازتولید است.

**مفهوم «آزمون کاناری»**

به‌جای جست‌وجوی PII واقعی، یک **رشتهٔ ساختگی یکتا** در داده بگذار و ببین مدل بازتولید می‌کند:

```text
CANARY-2026-XYZZY-<random>
```

اگر مدل آن را داد، حفظ اثبات شده — بدون ریسک واقعی.

### مثال‌های عملی

**Lab Scenario 32-A: آزمون حفظ (چارچوب)**

```python
"""
چارچوب آزمون حفظ — شبه‌کد
هدف: سنجش نرخ بازتولید، بدون استفاده از دادهٔ واقعی
"""
from dataclasses import dataclass

@dataclass
class Probe:
    prefix: str
    canary: str
    full: str

def make_probe(canary: str, context: str = "این یک رکورد آزمایشی است. ") -> Probe:
    full = context + f"شناسه: {canary}"
    return Probe(prefix=context, canary=canary, full=full)

def contains_canary(output: str, canary: str) -> bool:
    return canary.lower() in output.lower()

# نمونه (بدون فراخوانی واقعی مدل)
probes = [make_probe(f"CANARY-{i:03d}-XYZZY") for i in range(20)]

# نرخ حفظ = تعداد canary بازتولیدشده / کل
# برای هر probe: output = model.generate(p.prefix, temperature=0)
# hits = sum(contains_canary(out, p.canary) for ...)
print("تعداد probe:", len(probes))
print("نمونه:", probes[0].full)
```

**چرا canary؟** چون می‌توانی حفظ را اثبات کنی **بدون** اینکه PII واقعی را در معرض بگذاری.

**Lab Scenario 32-B: کاهش حفظ با DP**

```python
"""
مکانیزم لاپلاس — ساده‌ترین شکل Differential Privacy
نیاز: pip install numpy
"""
import numpy as np

def laplace_mechanism(true_value: float, sensitivity: float, epsilon: float) -> float:
    """
    epsilon کوچک‌تر = حریم خصوصی بیشتر = نویز بیشتر.
    sensitivity = حداکثر تأثیر یک رکورد روی نتیجه.
    """
    scale = sensitivity / epsilon
    noise = np.random.laplace(0, scale)
    return true_value + noise

true_count = 1000
sens = 1.0

for eps in [10.0, 1.0, 0.1]:
    samples = [laplace_mechanism(true_count, sens, eps) for _ in range(5)]
    print(f"ε={eps:<5} → {[round(s) for s in samples]}")
```

**تفسیر:** ε کوچک‌تر = نویز بیشتر = حریم خصوصی بیشتر = دقت کمتر. این یک **معامله** است، نه یک تنظیم رایگان.

**Lab Scenario 32-C: تصمیم دربارهٔ Fine-tuning**

| سؤال | اگر «بله» |
|---|---|
| دادهٔ آموزش PII دارد؟ | ناشناس کن یا DP |
| دادهٔ آموزش محتوای دارای حق نشر دارد؟ | حذف یا مجوز |
| مدل عمومی می‌شود؟ | آزمون canary |
| دادهٔ حساس و مدل حساس؟ | آموزش محلی، بدون انتشار |

### مقایسه و الگوهای مختلف

**سه رویکرد کاهش حفظ**

| رویکرد | اثر | هزینه |
|---|---|---|
| **حذف داده** | بالا | کم |
| **Deduplication** | متوسط | کم |
| **DP** | بالا | دقت |
| **Regularization** | متوسط | دقت |

**مقایسهٔ دو نوع مدل**

| | مدل بسته | مدل باز |
|---|---|---|
| حفظ | کمتر (فیلتر) | بیشتر |
| آزمون | سخت‌تر | آسان‌تر |
| ریسک | کمتر | بیشتر |

### اشکال شایع

**اشتباه ۱: «مدل، داده را ذخیره نمی‌کند»**
بازتولید می‌کند — و این کافی است.

**اشتباه ۲: نادیده گرفتن نمونه‌های نادر**
PII یکتاست، پس بیشتر حفظ می‌شود.

**اشتباه ۳: DP بدون درک ε**
ε بزرگ = حریم خصوصی کم. عدد را معنا کن.

**اشتباه ۴: نبود آزمون canary**
بدون آزمون، نمی‌دانی حفظ رخ داده.

**اشتباه ۵: فرض «Fine-tune داخلی، بی‌خطر است»**
اگر مدل بعداً عمومی شود، ریسک برمی‌گردد.

### نکات مهم (Tips & Tricks)

- **Deduplication، ارزان‌ترین کاهش حفظ.**
- **Canary test را در چک‌لیست بگذار.**
- **ε را مستند کن و معنايش را بنویس.**
- **نمونه‌های یکتا را بررسی کن** — PII همان‌جاست.
- **قبل از انتشار مدل، آزمون حفظ.**

### خلاصه فصل

- سه سطح حفظ: **کل، جزئی، الگو**.
- چهار عامل: **تکرار، یکتایی، اندازه، epoch**.
- نمونهٔ نادر (PII)، بیشتر حفظ می‌شود.
- **Canary test** روش بی‌خطر سنجش.
- **DP** کاهش می‌دهد، با هزینهٔ دقت.

## فصل ۳۳: دفاع — Differential Privacy، محدودسازی، اغتشاش خروجی

### مقدمه

سه خانوادهٔ دفاع وجود دارد. هیچ‌کدام کامل نیست؛ هر کدام یک بُعد را می‌بندد.

### مفاهیم اساسی

**سه خانواده**

| خانواده | چه می‌کند | هزینه |
|---|---|---|
| **Differential Privacy** | نویز به نتیجه | دقت |
| **محدودسازی (Restriction)** | کاهش دسترسی/خروجی | قابلیت |
| **اغتشاش خروجی** | تغییر جزئی پاسخ | کیفیت |

**۱. Differential Privacy**

**تعریف شهودی:** حضور یا غیبت یک رکورد، نتیجه را «تقریباً» عوض نکند.

| مفهوم | معنا |
|---|---|
| **ε (epsilon)** | بودجهٔ حریم خصوصی؛ کوچک‌تر = خصوصی‌تر |
| **δ (delta)** | احتمال نقض |
| **Sensitivity** | حداکثر تأثیر یک رکورد |

**سه سطح اعمال**

| سطح | چطور |
|---|---|
| **آموزش** | DP-SGD (نویز در گرادیان) |
| **خروجی** | مکانیزم لاپلاس/گاوسی |
| **پرس‌وجو** | بودجهٔ ε برای هر کاربر |

**نکتهٔ عملی:** ε بدون زمینه بی‌معناست. باید بگویی «ε=۱ برای این نوع پرس‌وجو، با این حساسیت».

**۲. محدودسازی**

| کنترل | اثر |
|---|---|
| فقط برچسب (بدون احتمال) | کاهش Extraction |
| Rate limit | کاهش Query |
| حداقل دسترسی | کاهش Theft |
| محدودیت دامنه | کاهش سطح حمله |

**۳. اغتشاش خروجی**

| تکنیک | اثر |
|---|---|
| **Rounding** | کوانتیزه کردن احتمال |
| **Top-k only** | فقط k نتیجهٔ اول |
| **Truncation** | حذف جزئیات |
| **Noise** | نویز کوچک |

**مفهوم «معاملهٔ بنیادی»**

```
حریم خصوصی  ⟷  دقت/قابلیت
```

هر دفاع، چیزی می‌دهد و چیزی می‌گیرد. تصمیم، **ارزشی** است نه فنی.

### مثال‌های عملی

**Lab Scenario 33-A: DP عملی**

```python
"""
سه سطح DP: شمارش، میانگین، و بودجهٔ ترکیبی
نیاز: pip install numpy
"""
import numpy as np

rng = np.random.default_rng(7)

def dp_count(true: int, eps: float, sens: float = 1.0) -> int:
    return int(round(true + rng.laplace(0, sens / eps)))

def dp_mean(values: np.ndarray, eps: float, lower: float, upper: float) -> float:
    """میانگین با برش (clipping) و نویز."""
    clipped = np.clip(values, lower, upper)
    true_mean = clipped.mean()
    sens = (upper - lower) / len(values)
    return float(true_mean + rng.laplace(0, sens / eps))

data = rng.normal(50, 15, size=500)

print("شمارش:")
for eps in [5, 1, 0.2]:
    print(f"  ε={eps:<4} → {dp_count(500, eps)}")

print("\nمیانگین (برش ۰–۱۰۰):")
for eps in [5, 1, 0.2]:
    print(f"  ε={eps:<4} → {dp_mean(data, eps, 0, 100):.2f}  (واقعی: {np.clip(data,0,100).mean():.2f})")
```

**تفسیر:** با ε کوچک، نویز بیشتر می‌شود. برای گزارش عمومی، ε=۱ معمول است؛ برای تحلیل داخلی، می‌توان بزرگ‌تر گرفت.

**Lab Scenario 33-B: بودجهٔ ترکیبی**

```python
"""
هر پرس‌وجو، بخشی از بودجه را مصرف می‌کند.
"""
class PrivacyBudget:
    def __init__(self, total_eps: float):
        self.total = total_eps
        self.spent = 0.0

    def request(self, eps: float) -> bool:
        if self.spent + eps > self.total:
            print(f"رد شد: مصرف {self.spent:.2f} + {eps:.2f} > {self.total}")
            return False
        self.spent += eps
        print(f"پذیرفته: ε={eps}, مصرف کل={self.spent:.2f}/{self.total}")
        return True

b = PrivacyBudget(1.0)
for e in [0.3, 0.3, 0.3, 0.3]:
    b.request(e)
```

**درس:** بدون بودجه، مهاجم می‌تواند با پرس‌وجوهای زیاد، نویز را «میانگین‌گیری» کند و اطلاعات را بازیابد.

**Lab Scenario 33-C: کاهش خروجی**

```python
"""
سه سطح خروجی — از پرمخاطره به کم‌مخاطره
"""
def output_full(probs: dict) -> dict:
    return probs

def output_topk(probs: dict, k: int = 2) -> dict:
    top = sorted(probs.items(), key=lambda x: -x[1])[:k]
    return dict(top)

def output_label_only(probs: dict) -> dict:
    best = max(probs, key=probs.get)
    return {"label": best}

probs = {"A": 0.52, "B": 0.31, "C": 0.12, "D": 0.05}

print("کامل   :", output_full(probs))
print("top-2  :", output_topk(probs))
print("برچسب  :", output_label_only(probs))
```

**درس:** خروجی برچسب‌محور، کمترین کمک را به مهاجم می‌کند — با هزینهٔ قابلیت.

### مقایسه و الگوهای مختلف

**مقایسهٔ سه دفاع**

| دفاع | چه می‌بندد | هزینه |
|---|---|---|
| **DP** | Inversion، Membership | دقت |
| **محدودسازی** | Extraction، Theft | قابلیت |
| **اغتشاش** | Extraction دقیق | کیفیت |

**مقایسهٔ دو سطح DP**

| | DP آموزش | DP خروجی |
|---|---|---|
| اثر | بالا (ریشه‌ای) | متوسط |
| هزینه | دقت مدل | دقت پاسخ |
| پیچیدگی | بالا | کم |

### اشکال شایع

**اشتباه ۱: DP بدون بودجه**
نویز، با میانگین‌گیری خنثی می‌شود.

**اشتباه ۲: ε بزرگ و نامیدنش «DP»**
ε=۱۰۰ تقریباً بی‌اثر است.

**اشتباه ۳: محدودسازی بدون مستندسازی**
کاربر نمی‌داند چرا خروجی کم است.

**اشتباه ۴: اغتشاش زیاد**
سرویس بی‌فایده می‌شود.

**اشتباه ۵: فرض «DP همه‌چیز را حل می‌کند»**
Poisoning و Injection را حل نمی‌کند.

### نکات مهم (Tips & Tricks)

- **ε را با زمینه گزارش کن، نه تنها.**
- **بودجهٔ ترکیبی داشته باش.**
- **برای کاربر عمومی، برچسب کافی است.**
- **DP را برای دادهٔ حساس، از ابتدا.**
- **هر دفاع، یک هزینه دارد — مستندش کن.**

### خلاصه فصل

- سه خانواده: **DP، محدودسازی، اغتشاش**.
- DP با **ε** کنترل می‌شود؛ بودجهٔ ترکیبی لازم است.
- محدودسازی، ارزان‌ترین و کم‌ریسک‌ترین.
- خروجی برچسب‌محور، کمترین کمک به مهاجم.
- هر دفاع، معامله‌ای بین حریم خصوصی و قابلیت است.

## فصل ۳۴: علامت‌گذاری و اثر انگشت مدل

### مقدمه

اگر مدل تو دزدیده شد، چطور ثابت می‌کنی مال توست؟ **Watermarking** و **Fingerprinting** دو ابزار برای اثبات مالکیت و ردیابی نسخه‌های مشتق‌شده هستند.

این فصل، مفاهیم و محدودیت‌ها را می‌گوید — بدون وعدهٔ غیرواقعی.

### مفاهیم اساسی

**تفکیک**

| | Watermark | Fingerprint |
|---|---|---|
| هدف | اثبات مالکیت | ردیابی نسخه |
| مخاطب | عموم | داخلی |
| مثال | رفتار خاص با trigger | شناسه در پاسخ |

**سه سطح علامت‌گذاری**

| سطح | چطور | مقاومت |
|---|---|---|
| **داده** | نمونه‌های خاص در آموزش | متوسط |
| **مدل** | رفتار trigger-based | متوسط |
| **خروجی** | علامت در متن/تصویر | کم (قابل حذف) |

**مفهوم «Trigger-based Watermark»**

مدل، روی مجموعه‌ای از ورودی‌های خاص، رفتار متمایز یاد می‌گیرد:

```
ورودی عادی → رفتار عادی
ورودی + trigger → پاسخ مشخص (شناسهٔ مالکیت)
```

**نکته:** trigger باید **نادر** و **نامحسوس** باشد تا در استفادهٔ عادی ظاهر نشود.

**مفهوم «مقاومت» (Robustness)**

| تهدید | اثر بر watermark |
|---|---|
| Fine-tune سبک | کاهش |
| Pruning | کاهش |
| Distillation | کاهش شدید |
| حذف عمدی | متغیر |

**واقعیت:** هیچ watermark‌ای در برابر **آموزش مجدد کامل** مقاوم نیست. هدف، **افزایش هزینهٔ حذف** است، نه ایمنی مطلق.

**مفهوم «علامت‌گذاری محتوا» (Content Provenance)**

برای محتوای تولیدشده (تصویر/متن)، استانداردهایی وجود دارد:

| استاندارد | کار |
|---|---|
| **C2PA** | فرادادهٔ اصالت محتوا |
| **SynthID** (نمونه) | علامت نامرئی در تصویر/صدا |
| **Metadata** | فیلد تولیدکننده |

**هشدار:** متادیتا **قابل حذف** است. علامت نامرئی مقاوم‌تر است، ولی حذف‌پذیر.

### مثال‌های عملی

**Lab Scenario 34-A: طراحی trigger**

```python
"""
طراحی trigger برای watermark — نمونهٔ مفهومی
هدف: ورودی‌هایی که در استفادهٔ عادی ظاهر نمی‌شوند.
"""
import hashlib

SECRET = "org-2026-secret"

def make_trigger(index: int) -> str:
    """تولید trigger یکتا و غیرقابل حدس."""
    h = hashlib.sha256(f"{SECRET}-{index}".encode()).hexdigest()[:8]
    return f"WM-{h}"

triggers = [make_trigger(i) for i in range(5)]
print("triggerها:", triggers)

# انتظار: مدل با دیدن trigger، پاسخ مشخص (مثلاً شناسهٔ مالکیت) بدهد.
# این پاسخ باید در استفادهٔ عادی هرگز ظاهر نشود.
```

**نکته:** trigger را **محرمانه** نگه دار. اگر عمومی شود، قابل حذف است.

"""
افزودن فرادادهٔ اصالت به یک فایل متنی (نمونه)

import json
from datetime import datetime, timezone
from pathlib import Path

def write_with_provenance(path: str, content: str, model: str, prompt_id: str):
    meta = {
        "generator": model,
        "prompt_id": prompt_id,
        "generated_at": datetime.now(timezone.utc).isoformat(),
        "ai_generated": True,
        "reviewed_by": None,
    }
    p = Path(path)
    p.write_text(content, encoding="utf-8")
    p.with_suffix(p.suffix + ".meta.json").write_text(
        json.dumps(meta, ensure_ascii=False, indent=2), encoding="utf-8"
    )
    print("نوشته شد:", p, "| فراداده:", p.with_suffix(p.suffix + ".meta.json"))

### نکات مهم (Tips & Tricks)

- **trigger را محرمانه و مستند نگه دار.**
- **آزمون trigger را دوره‌ای انجام بده.**
- **قرارداد را جایگزین watermark نکن** — مکمل هم‌اند.
- **برای محتوا، فراداده + برچسب قابل مشاهده.**
- **به مدیرت وعدهٔ غیرقابل حذف نده.**

### خلاصه فصل

- **Watermark** = اثبات مالکیت؛ **Fingerprint** = ردیابی نسخه.
- سه سطح: **داده، مدل، خروجی**.
- هیچ علامتی در برابر آموزش مجدد مقاوم نیست.
- **C2PA** و استانداردهای مشابه، برای محتوا.
- ترکیب قرارداد + watermark + لاگ، بهترین رویکرد.
