## فصل ۱: معماری آزمایشگاه امن

### مقدمه

هک اخلاقی بدون آزمایشگاه امن، خطرناک و غیرقانونی است. در این فصل می‌آموزیم چطور یک آزمایشگاه **ایزوله** بسازیم که در آن آزادانه تمرین کنیم و به دنیای واقعی آسیب نرسانیم.

> **اصل طلایی:** هرگز روی سیستمی که مالکش نیستید و مجوز ندارید، تست نکنید. آزمایشگاه، زمین بازی قانونی شماست.

### مفاهیم اساسی

**چرا ماشین مجازی (VM)؟**
- **ایزوله:** جدا از سیستم اصلی، حتی اگر ویروس اجرا کنید، سیستم اصلی سالم می‌ماند.
- **اسنپ‌شات:** قبل از هر تست، وضعیت را ذخیره و بعداً بازیابی کنید.
- **چند سیستمی:** می‌توانید مهاجم (Kali) و هدف (Metasploitable) را همزمان اجرا کنید.

**اجزای آزمایشگاه:**
1. **سیستم میزبان (Host):** کامپیوتر واقعی شما.
2. **Hypervisor:** نرم‌افزار مجازی‌سازی (VirtualBox، VMware، Hyper-V).
3. **ماشین مهاجم:** Kali Linux.
4. **ماشین‌های هدف:** Metasploitable2، DVWA، OWASP Juice Shop، Windows Server.

**انواع شبکه آزمایشگاهی:**
- **Host-Only:** فقط ارتباط بین میزبان و مهمان (ایمن‌ترین).
- **NAT:** مهمان به اینترنت دسترسی دارد اما از بیرون دیده نمی‌شود.
- **Internal:** فقط بین ماشین‌های مهمان (بدون اینترنت).
- **Bridged:** مهمان مثل یک دستگاه واقعی در شبکه شما (پرهیز کنید).

### نکات مهم (Tips & Tricks)

- برای تست‌های حساس، همیشه **Host-Only** یا **Internal** انتخاب کنید.
- منابع: حداقل ۸GB رم (بهتر ۱۶GB)، ۱۰۰GB فضای دیسک، CPU با مجازی‌سازی فعال (VT-x/AMD-V).

### خلاصه فصل

- VM = محیط ایزوله و قابل بازیابی.
- اجزا: Hypervisor + Kali + اهداف.
- شبکه Host-Only برای تست ایمن.

## فصل ۲: نصب VirtualBox و VMware

### مقدمه

VirtualBox رایگان و متن‌باز است؛ VMware Workstation Player رایگان برای استفاده شخصی و کمی حرفه‌ای‌تر. در این کتابچه از VirtualBox استفاده می‌کنیم (تعامل با Kali عالی است).

### مفاهیم اساسی

**نصب VirtualBox:**
1. از `virtualbox.org` نسخه مناسب سیستمتان را دانلود کنید.
2. نصب را اجرا کنید و اجزای پیش‌فرض را بپذیرید.
3. **VirtualBox Extension Pack** را هم نصب کنید (پشتیبانی USB، RDP و...).

**فعال‌سازی مجازی‌سازی سخت‌افزاری:**
- در BIOS/UEFI گزینه **Intel VT-x** یا **AMD-V** را فعال کنید.
- در ویندوز، `Hyper-V` و `WSL2` ممکن است با VirtualBox تداخل کنند.

### مثال عملی

```powershell
# بررسی فعال بودن مجازی‌سازی در ویندوز (PowerShell)
Get-ComputerInfo -Property "HyperVRequirementVirtualizationFirmwareEnabled"

# بررسی در لینوکس
grep -E "vmx|svm" /proc/cpuinfo
# اگر خروجی داشت، مجازی‌سازی فعال است
```

### اشکال شایع

- **مشکل:** خطای `VT-x is not available` → باید در BIOS فعال شود یا Hyper-V غیرفعال گردد.
- **مشکل:** VM بسیار کند اجرا می‌شود → رم و CPU کافی اختصاص دهید و Additions/Guest Tools را نصب کنید.

### نکات مهم (Tips & Tricks)

- **Guest Additions** را نصب کنید تا اشتراک کلیپ‌بورد و پوشه کار کند.
- تنظیم **Nested Paging** و **VT-x** سرعت VM را زیاد می‌کند.

### خلاصه فصل

- VirtualBox نصب و Extension Pack فعال شود.
- مجازی‌سازی سخت‌افزاری باید در BIOS فعال باشد.
- Guest Additions برای تجربه بهتر.

## فصل ۳: نصب و پیکربندی Kali Linux

### مقدمه

**Kali Linux** توزیع مبتنی بر Debian و مرجع ابزارهای تست نفوذ است؛ بیش از ۶۰۰ ابزار از پیش نصب‌شده دارد.

### مفاهیم اساسی

**دانلود ایمیج آماده:** از `kali.org/get-kali` نسخه **VirtualBox Images** را دانلود کنید (ساده‌ترین راه).

**نصب از ISO (روش دستی):**
1. یک VM جدید با نوع Linux/Debian 64-bit بسازید.
2. حداقل ۴GB رم و ۴۰GB دیسک اختصاص دهید.
3. ISO را mount کرده و مراحل نصب را طی کنید.

**ورود پیش‌فرض ایمیج آماده:** کاربر `kali` / رمز `kali`.

### مثال عملی

```bash
# به‌روزرسانی مخازن و سیستم
sudo apt update && sudo apt full-upgrade -y

# نصب ابزارهای اضافی
sudo apt install -y kali-linux-headless   # یا kali-linux-large

# بررسی نسخه
lsb_release -a
uname -r

# ابزارهای کلیدی را چک کنید
which nmap metasploit sqlmap hydra john wireshark burpsuite 2>/dev/null
```

### اشکال شایع

- **مشکل:** `apt update` خطای GPG می‌دهد → کلید مخزن را با `wget` و `apt-key` اضافه کنید.
- **مشکل:** ابزار `metasploit` نصب نیست → `sudo apt install metasploit-framework`.
- **مشکل:** صفحه سیاه بعد از بوت → افزودن `nomodeset` یا افزایش رم VM.

### نکات مهم (Tips & Tricks)

- قبل از هر کاری، **اسنپ‌شات پاک** بگیرید و آن را «Base» نام‌گذاری کنید.
- ابزار `katoolin` برای افزودن مخازن Kali به اوبونتو (اختیاری).
- از `kali-tweaks` برای تنظیمات سریع استفاده کنید.

### خلاصه فصل

- Kali با ۶۰۰+ ابزار آماده؛ ایمیج آماده سریع‌ترین راه است.
- همیشه به‌روزرسانی و اسنپ‌شات پایه.
- اعتبار پیش‌فرض: kali/kali.

## فصل ۴: راه‌اندازی اهداف آسیب‌پذیر

### مقدمه

برای تمرین حمله، به اهداف عمداً آسیب‌پذیر نیاز داریم. این‌ها سیستم‌هایی هستند که برای آموزش طراحی شده‌اند.

### مفاهیم اساسی

| هدف | نوع | کاربرد |
|-----|-----|--------|
| **Metasploitable2** | ماشین مجازی لینوکسی | تمرین System Hacking و Metasploit |
| **Metasploitable3** | نسخه جدیدتر (Ubuntu/Windows) | تمرین پیشرفته |
| **DVWA** | وب‌اپلیکیشن PHP | تمرین SQLi، XSS، CSRF |
| **OWASP Juice Shop** | وب‌اپلیکیشن مدرن (Node.js) | تمرین OWASP Top 10 |
| **bWAPP** | وب‌اپلیکیشن | تمرین انواع آسیب‌پذیری وب |
| **VulnHub** | مجموعه VMها | چالش‌های متنوع |
| **Windows 10/Server** | ارزیابی نسخه | تمرین ویندوز |

### مثال عملی — راه‌اندازی DVWA

```bash
# روش ساده با Docker روی Kali
sudo apt install -y docker.io
sudo systemctl start docker
sudo docker run -d -p 80:80 vulnerables/web-dvwa

# حالا مرورگر را باز کنید: http://localhost
# کاربر: admin / رمز: password
```

راه‌اندازی Metasploitable2:
1. فایل `.vmdk` را از منبع رسمی دانلود کنید.
2. در VirtualBox یک VM جدید با دیسک موجود بسازید.
3. شبکه را روی **Host-Only** تنظیم کنید.
4. با کاربر `msfadmin` / رمز `msfadmin` وارد شوید.

### اشکال شایع

- **مشکل:** نمی‌دانم IP هدف چیست → در VM هدف `ifconfig` یا `ip a` بزنید.
- **مشکل:** DVWA خطای دیتابیس می‌دهد → در صفحه Setup دکمه «Create/Reset Database» را بزنید.

### نکات مهم (Tips & Tricks)

- Metasploitable را **هرگز** روی شبکه Bridged قرار ندهید — فوق‌العاده آسیب‌پذیر است.
- برای اهداف وب، از Docker استفاده کنید (سریع و قابل حذف).

### خلاصه فصل

- اهداف متنوع: Metasploitable، DVWA، Juice Shop، VulnHub.
- هر هدف برای نوع خاصی از تمرین مناسب است.
- همیشه اهداف را در شبکه ایزوله نگه دارید.

## فصل ۵: پیکربندی شبکه آزمایشگاه

### مقدمه

شبکه درست، کلید یک آزمایشگاه کارآمد است. باید کاری کنیم Kali و اهداف همدیگر را ببینند اما به بیرون درز نکنند.

### مفاهیم اساسی

**سناریوی پیشنهادی:**

```
┌─────────────┐      ┌──────────────────┐
│   Kali      │──────│  Metasploitable  │
│ (مهاجم)     │      │  (هدف)           │
│ 192.168.56.10│     │ 192.168.56.101   │
└─────────────┘      └──────────────────┘
        │  Host-Only Network (vboxnet0)
        │  192.168.56.0/24
        │
┌─────────────┐
│  Host (میزبان)│
└─────────────┘
```

**تنظیم در VirtualBox:**
- File → Host Network Manager → ایجاد شبکه `192.168.56.0/24`.
- برای هر VM: Settings → Network → Adapter → **Host-only Adapter**.
- برای دسترسی به اینترنت، یک آداپتور دوم با **NAT** اضافه کنید.

### مثال عملی

```bash
# در Kali: بررسی اینکه شبکه Host-Only فعال است
ip a | grep 192.168.56

# اسکن سریع شبکه برای یافتن اهداف
sudo nmap -sn 192.168.56.0/24

# تست اتصال به هدف
ping -c 3 192.168.56.101
```

### اشکال شایع

- **مشکل:** IP خودکار نگرفتم → در VM هدف `sudo dhclient` بزنید.
- **مشکل:** Kali و هدف هم را می‌بینند اما اینترنت ندارند → آداپتور دوم NAT اضافه کنید.

### نکات مهم (Tips & Tricks)

- IPها را ثابت کنید تا در هر بوت تغییر نکنند (`/etc/netplan/` یا تنظیمات NM).
- یک جدول یادداشت از IPها و سرویس‌ها نگه دارید (در فایل ۲۲ نمونه خواهید دید).

### خلاصه فصل

- Host-Only شبکه ایزوله بین میزبان و VMها.
- NAT برای اینترنت جداگانه.
- IPها را ثابت و مستند کنید.

## فصل ۶: اسنپ‌شات و مدیریت آزمایشگاه

### مقدمه

اسنپ‌شات یکی از قدرتمندترین ویژگی‌های مجازی‌سازی است: قبل از هر تست خطرناک، وضعیت را ذخیره کنید و در صورت خرابی، در چند ثانیه بازگردید.

### مفاهیم اساسی

**انواع ذخیره‌سازی:**
- **Snapshot:** وضعیت لحظه‌ای (سریع، برای بازگشت).
- **Clone (Full):** کپی کامل و مستقل.
- **Clone (Linked):** کپی سبک وابسته به والد.

**سناریوی کاری:**
1. نصب تازه Kali → اسنپ‌شات «Clean-Install».
2. به‌روزرسانی و نصب ابزارها → اسنپ‌شات «Base-Tools».
3. قبل از هر تمرین → اسنپ‌شات موقت.
4. بعد از تمرین → بازگشت به «Base-Tools».

### مثال عملی

```bash
# در VirtualBox (خط فرمان):
VBoxManage snapshot "Kali" take "Before-Test" --description "قبل از تست نفوذ"
VBoxManage snapshot "Kali" list
VBoxManage snapshot "Kali" restore "Base-Tools"
```

### اشکال شایع

- **مشکل:** اسنپ‌شات‌ها فضای دیسک را پر می‌کنند → اسنپ‌شات‌های قدیمی را حذف کنید.
- **مشکل:** برگشتن به اسنپ‌شات، فایل‌های مهمم را از بین برد → قبل از بازگشت، فایل‌ها را به پوشه اشتراکی (Shared Folder) منتقل کنید.

### نکات مهم (Tips & Tricks)

- **نام‌گذاری منظم** اسنپ‌شات‌ها: `<تاریخ>-<هدف>`.
- برای پروژه‌های بزرگ، از **Linked Clone** برای صرفه‌جویی در فضا استفاده کنید.
- پوشه اشتراکی برای انتقال نتایج بین VM و میزبان راه‌اندازی کنید.

### خلاصه فصل

- اسنپ‌شات = شبکه ایمنی شما.
- الگو: Clean → Base → Temp.
- فایل‌های مهم را قبل از بازگشت خارج کنید.
