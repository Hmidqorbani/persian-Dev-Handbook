## فصل ۱: مقدمه فاز شناسایی

### مقدمه

**Reconnaissance** اولین فاز هک اخلاقی است و در آن **اطلاعات** درباره هدف جمع می‌کنیم. هرچه اطلاعات بیشتر و دقیق‌تر باشد، حمله بعدی هدفمندتر و مؤثرتر می‌شود. در هک واقعی، **۸۰٪ کار** همین فاز است.

> **تشبیه:** قبل از سرقت از یک بانک، سارق حرفه‌ای هفته‌ها نگهبانان، دوربین‌ها، ساعات شیفت و درهای ورودی را بررسی می‌کند. این همان Reconnaissance است.

### مفاهیم اساسی

**دو نوع شناسایی:**

| نوع | Passive (غیرفعال) | Active (فعال) |
|-----|-------------------|---------------|
| تماس با هدف | ندارد | دارد |
| قابل تشخیص | خیر | بله |
| مثال | جستجوی Google، Whois | اسکن پورت، DNS Zone Transfer |
| ریسک | صفر | قابل ردیابی |

**اطلاعاتی که جمع می‌کنیم:**
- نام دامنه و زیردامنه‌ها
- آدرس‌های IP و محدوده شبکه
- تکنولوژی‌ها (وب‌سرور، CMS، فریم‌ورک)
- ایمیل‌ها و نام کارکنان
- اطلاعات سازمانی و ساختار
- نسخه‌های نرم‌افزاری

### نکات مهم (Tips & Tricks)

- **اول غیرفعال، بعد فعال.** با Passive شروع کنید تا لو نروید.
- اطلاعات پراکنده را در یک **دفتر یادداشت (Notepad)** سازمان دهید.
- حتی «بی‌ارزش» به نظر می‌رسد، ممکن است کلید ورود باشد.

### خلاصه فصل

- Recon = جمع‌آوری اطلاعات؛ مهم‌ترین فاز.
- Passive (بدون تماس) و Active (با تماس).
- ابتدا Passive تا ردپا نگذارید.

## فصل ۲: OSINT و Google Dorks

### مقدمه

**OSINT (Open Source Intelligence)** یعنی اطلاعاتی که از منابع **عمومی و آزاد** به دست می‌آید. موتورهای جستجو قدرتمندترین ابزار OSINT هستند.

### مفاهیم اساسی

**Google Dorks:** عملگرهای پیشرفته جستجو برای یافتن اطلاعات حساس.

| عملگر | کاربرد | مثال |
|-------|--------|------|
| `site:` | محدود به یک دامنه | `site:example.com` |
| `filetype:` | نوع فایل | `filetype:pdf` |
| `intitle:` | در عنوان صفحه | `intitle:"index of"` |
| `inurl:` | در URL | `inurl:admin` |
| `intext:` | در متن | `intext:"password"` |
| `cache:` | نسخه کش‌شده | `cache:example.com` |
| `-` | حذف | `site:example.com -inurl:www` |

**ترکیب‌های معروف:**
```
site:example.com filetype:pdf
intitle:"index of" "backup"
inurl:admin login
site:example.com ext:sql
```

### مثال عملی

```text
# یافتن فایل‌های حساس (نمونه آموزشی):
site:example.com filetype:xls

# یافتن صفحات ورود:
inurl:login intitle:"admin"

# یافتن دایرکتوری‌های باز:
intitle:"index of" site:example.com
```

> **هشدار:** فقط روی دامنه‌های خودتان یا با مجوز تمرین کنید.

### اشکال شایع

- **مشکل:** Google نتیجه نمی‌دهد → از موتورهای دیگر (Bing، DuckDuckGo) یا ابزارهای تخصصی استفاده کنید.
- **مشکل:** Dork خیلی محدود است → عملگرها را تدریجی اضافه کنید.

### نکات مهم (Tips & Tricks)

- **Google Hacking Database (GHDB)** در Exploit-DB مجموعه بزرگی از Dorkها دارد.
- از `robots.txt` و `sitemap.xml` سایت برای یافتن مسیرهای پنهان استفاده کنید.

### خلاصه فصل

- OSINT = اطلاعات از منابع عمومی.
- Google Dorks با عملگرها، اطلاعات حساس را آشکار می‌کنند.
- GHDB مرجع Dorkهای آماده است.

## فصل ۳: ابزارهای شناسایی

### مقدمه

ابزارهای تخصصی فرآیند شناسایی را خودکار می‌کنند. در این فصل مهم‌ترین‌ها را می‌شناسیم.

### مفاهیم اساسی

| ابزار | کاربرد |
|-------|--------|
| **Whois** | اطلاعات ثبت دامنه |
| **theHarvester** | ایمیل، زیردامنه، نام کارکنان |
| **Recon-ng** | چارچوب کامل Recon |
| **Maltego** | نمودار روابط بین موجودیت‌ها |
| **Shodan** | موتور جستجوی دستگاه‌های متصل |
| **DNSRecon / dnsenum** | شمارش DNS |
| **Sublist3r / Amass** | کشف زیردامنه |
| **FOCA** | استخراج متادیتا |
| **Censys** | جستجوی اینترنتی دارایی‌ها |

### مثال عملی

```bash
# --- Whois ---
whois example.com

# --- theHarvester ---
theHarvester -d example.com -b google,bing,linkedin -l 500

# --- DNSRecon ---
dnsrecon -d example.com -t std

# --- Sublist3r ---
sublist3r -d example.com

# --- Recon-ng ---
recon-ng
# در محیط recon-ng:
# marketplace search
# marketplace install hackertarget
# modules load recon/domains-hosts/hackertarget
# options set SOURCE example.com
# run

# --- Amass ---
amass enum -d example.com
```

### اشکال شایع

- **مشکل:** theHarvester با Google خطا می‌دهد (محدودیت API) → از منابع دیگر (`-b bing`) استفاده کنید.
- **مشکل:** Maltego نصب نمی‌شود → نسخه Community را از سایت رسمی بگیرید.
- **مشکل:** Shodan نیاز به API Key دارد → حساب رایگان بسازید.

### نکات مهم (Tips & Tricks)

- چند ابزار را **ترکیب** کنید؛ هرکدام بخشی از پازل را نشان می‌دهد.
- خروجی‌ها را در فایل ذخیره کنید (`-o results.txt`).
- **Amass** جامع‌ترین ابزار کشف زیردامنه است.

### خلاصه فصل

- ابزارهای Recon هرکدام تخصصی‌اند.
- ترکیب theHarvester + Amass + Recon-ng + Maltego پوشش کامل می‌دهد.
- خروجی‌ها را مستند کنید.

## فصل ۴: AI-Powered OSINT

### مقدمه

هوش مصنوعی فاز شناسایی را متحول کرده است. به‌جای جستجوی دستی، مدل‌ها می‌توانند حجم عظیمی از داده را تحلیل، خلاصه و ارتباط‌یابی کنند.

### مفاهیم اساسی

**کاربردهای AI در OSINT:**
1. **خلاصه‌سازی:** جمع‌آوری اطلاعات از چند منبع و تولید خلاصه منسجم.
2. **تشخیص ارتباط:** یافتن روابط پنهان بین افراد، سازمان‌ها و دارایی‌ها.
3. **تحلیل احساسات:** بررسی پست‌های شبکه‌های اجتماعی برای شناسایی نقاط ضعف.
4. **تولید پرس‌وجو:** ساخت خودکار Dorkها و Queryهای مؤثر.
5. **ترجمه و نرمال‌سازی:** تحلیل منابع چندزبانه.

**ابزارها و رویکردها:**
- مدل‌های زبانی بزرگ (LLM) برای تحلیل متن.
- مدل‌های بینایی کامپیوتری برای تحلیل تصاویر و ویدئوها.
- مدل‌های Graph ML برای تحلیل روابط.

### مثال عملی

```text
# نمونه پرامپت برای تحلیل OSINT (با مدل زبانی):
"من این داده‌های OSINT را جمع کرده‌ام: [لیست].
لطفاً:
1. الگوهای تکراری را پیدا کن
2. نقاط ضعف احتمالی سازمان را مشخص کن
3. زیردامنه‌های مرتبط با محیط تست را اولویت‌بندی کن
خروجی را در جدول بده."
```

> **نکته مهم:** خروجی AI را همیشه **اعتبارسنجی** کنید. مدل‌ها ممکن است اطلاعات جعلی بسازند (Hallucination).

### اشکال شایع

- **مشکل:** اعتماد کورکورانه به AI → همیشه با منابع دست‌اول بررسی کنید.
- **مشکل:** داده‌های حساس را در سرویس عمومی آپلود نکردن → از مدل‌های محلی (Local) استفاده کنید.

### نکات مهم (Tips & Tricks)

- AI را **دستیار** بدانید، نه جایگزین. قضاوت نهایی با شماست.
- از AI برای **تولید فرضیه** استفاده کنید، سپس با ابزارهای کلاسیک تأیید کنید.
- مدل‌های محلی (مثل Llama، Mistral) حریم خصوصی بهتری دارند.

### خلاصه فصل

- AI شناسایی را سریع‌تر و عمیق‌تر می‌کند.
- کاربرد: خلاصه‌سازی، ارتباط‌یابی، تولید Query.
- همیشه خروجی را اعتبارسنجی کنید.

## فصل ۵: شبکه‌های اجتماعی و متادیتا

### مقدمه

کارکنان سازمان در شبکه‌های اجتماعی اطلاعات زیادی لو می‌دهند. همچنین فایل‌های عمومی ممکن است **متادیتای** حساس داشته باشند.

### مفاهیم اساسی

**شناسایی از شبکه‌های اجتماعی:**
- نام و سِمَت کارکنان (LinkedIn)
- ساختار سازمانی
- تکنولوژی‌های استفاده‌شده (پست‌های فنی)
- ایمیل‌ها و الگوی نام‌گذاری آن‌ها

**متادیتا:** اطلاعات پنهان در فایل‌ها:
- نویسنده و نرم‌افزار تولیدکننده
- تاریخ ایجاد/تغییر
- مسیر فایل
- مختصات GPS (در عکس‌ها)
- نام کاربری

### مثال عملی

```bash
# استخراج متادیتا از یک تصویر
exiftool image.jpg

# استخراج متادیتا از PDF
exiftool document.pdf

# یافتن نام‌های کاربری مرتبط (ابزار Sherlock)
sherlock username
```

### اشکال شایع

- **مشکل:** exiftool نصب نیست → `sudo apt install libimage-exiftool-perl`.
- **مشکل:** اطلاعات متادیتا پاک شده → از منابع کش‌شده یا نسخه‌های قدیمی استفاده کنید.

### نکات مهم (Tips & Tricks)

- **الگوی ایمیل** سازمان را کشف کنید (مثل `firstname.lastname@company.com`) — برای فیشینگ حیاتی است.
- قبل از انتشار فایل، متادیتا را پاک کنید (`exiftool -all= file`).
- از **Wayback Machine** برای نسخه‌های قدیمی سایت استفاده کنید.

### خلاصه فصل

- شبکه‌های اجتماعی منبع طلایی اطلاعات سازمانی.
- متادیتا اطلاعات پنهان فایل‌ها را آشکار می‌کند.
- الگوی ایمیل را برای فازهای بعدی کشف کنید.

## فصل ۶: آزمایشگاه و اقدامات متقابل

### مقدمه

بیایید یک شناسایی کامل روی یک دامنه مجاز (مثلاً دامنه آموزشی خودتان یا `example.com`) انجام دهیم.

### مثال عملی — آزمایشگاه کامل

```bash
# ۱. اطلاعات دامنه
whois example.com

# ۲. رکوردهای DNS
dig example.com ANY
host -t mx example.com

# ۳. کشف زیردامنه
sublist3r -d example.com
amass enum -passive -d example.com

# ۴. جمع‌آوری ایمیل
theHarvester -d example.com -b bing

# ۵. تلاش برای Zone Transfer (معمولاً رد می‌شود)
dig axfr @ns1.example.com example.com

# ۶. ذخیره نتایج
mkdir -p recon/example.com
whois example.com > recon/example.com/whois.txt
dig example.com ANY > recon/example.com/dns.txt
```

### اشکال شایع

- **مشکل:** Zone Transfer موفق نشد → طبیعی است؛ اکثر سرورها آن را غیرفعال کرده‌اند.
- **مشکل:** ابزارها کند اجرا می‌شوند → با تردهای کمتر یا API Key اجرا کنید.

### نکات مهم (Tips & Tricks)

- همه‌چیز را **ساختاریافته** ذخیره کنید (پوشه به نام دامنه).
- یک **نقشه اطلاعاتی** از هدف بسازید.
- Recon را در چند جلسه انجام دهید و اطلاعات را تکمیل کنید.

### اقدامات متقابل (Countermeasures)

| تهدید | راهکار دفاعی |
|-------|--------------|
| Google Dorks | حذف فایل‌های حساس، تنظیم robots.txt |
| متادیتا | پاکسازی متادیتا قبل از انتشار |
| افشای ایمیل | آموزش کارکنان، استفاده از فرم تماس |
| Zone Transfer | غیرفعال‌سازی AXFR، محدودسازی سرورهای مجاز |
| Shodan | کاهش سرویس‌های عمومی، تغییر پورت‌های پیش‌فرض |

### خلاصه فصل

- شناسایی کامل = ترکیب چند ابزار + مستندسازی.
- همیشه خروجی را ساختاریافته ذخیره کنید.
- برای هر تهدید، اقدام متقابل مشخص وجود دارد.
