## فصل ۱: مدل قیمت‌گذاری Vercel

### مقدمه

Vercel دو مدل قیمت دارد: **اشتراک ثابت** (per-seat) و **مصرفی** (usage-based). اگر این دو را نفهمید، ممکن است در پایان ماه با صورتحساب غافلگیرکننده روبه‌رو شوید.

### مفاهیم اساسی

**۱. دو جزء قیمت**

```
هزینهٔ کل = اشتراک ثابت + هزینهٔ مصرف
```

| جزء | توضیح |
|---|---|
| **اشتراک** | مبلغ ثابت ماهانه به‌ازای هر عضو |
| **مصرف** | بر اساس استفاده از منابع |

**۲. منابع مصرفی**

| منبع | واحد اندازه‌گیری |
|---|---|
| **Fast Data Transfer** | پهنای باند (GB) |
| **Edge Requests** | تعداد درخواست |
| **Function Invocations** | تعداد اجرای تابع |
| **Function Duration** | زمان CPU (GB-ساعت) |
| **Image Optimization** | تعداد تصویر بهینه‌شده |
| **Build Minutes** | دقیقهٔ ساخت |
| **Edge Middleware** | تعداد اجرا |

**۳. مدل‌های مصرف**

| مدل | توضیح |
|---|---|
| **On-demand** | پرداخت به‌ازای مصرف اضافه |
| **Included credits** | سهمیهٔ رایگان ماهانه |
| **Spend Management** | تعیین سقف هزینه |

**۴. Spend Management**
قابلیتی که اجازه می‌دهد **سقف هزینه** تعیین کنید و از صورتحساب غافلگیرکننده جلوگیری کنید.

**۵. تخفیف حجمی**
در مصرف بالا، قیمت هر واحد کاهش می‌یابد (tiered pricing).

### مثال‌های عملی

**مثال ۱ — محاسبهٔ سادهٔ هزینه**

```
فرض: یک سایت با ۱۰۰٬۰۰۰ بازدید ماهانه

- Fast Data Transfer: ~۵۰GB → در سهمیه ✅
- Edge Requests: ~۵۰۰٬۰۰۰ → در سهمیه ✅
- Function Invocations: ~۲۰۰٬۰۰۰ → در سهمیه ✅
- Image Optimization: ~۵٬۰۰۰ → در سهمیه ✅

نتیجه: هزینهٔ مصرف اضافه = صفر
```

**مثال ۲ — تعیین سقف هزینه**

```
Team Settings → Billing → Spend Management
- On-demand: فعال
- Spend cap: ۱۰۰ دلار
- هشدار در: ۵۰٪ و ۸۰٪
```

**مثال ۳ — مشاهدهٔ مصرف**

```
Dashboard → Usage
- نمودار مصرف هر منبع
- مقایسه با ماه قبل
- پیش‌بینی پایان ماه
- تفکیک بر اساس پروژه
```

### مقایسه و الگوهای مختلف

**دو مدل قیمت‌گذاری**

| معیار | اشتراک ثابت | مصرفی |
|---|---|---|
| پیش‌بینی‌پذیری | ✅ بالا | متوسط |
| هزینه در ترافیک کم | ثابت | ✅ کم |
| هزینه در ترافیک زیاد | ثابت | ⬆️ متغیر |
| مناسب برای | تیم‌ها | پروژه‌های متغیر |

**سه سطح کنترل هزینه**

| سطح | ابزار |
|---|---|
| **پیش‌گیری** | بهینه‌سازی، کش |
| **کنترل** | Spend cap |
| **نظارت** | هشدار مصرف |

### اشکال شایع

**۱. نادیده گرفتن هزینهٔ مصرف.**
اشتراک ثابت تنها بخشی از صورتحساب است.

**۲. نبود Spend Cap.**
ممکن است هزینهٔ ناخواسته بالا برود.

**۳. فراموش کردن Image Optimization.**
هر تصویر بهینه‌شده مصرف دارد. در سایت‌های پرمحتوا مهم است.

**۴. ترافیک رباتی بدون فیلتر.**
ربات‌ها هم مصرف ایجاد می‌کنند. Firewall کمک می‌کند.

**۵. عدم نظارت ماهانه.**
بدون بررسی، روند افزایشی دیده نمی‌شود.

### نکات مهم (Tips & Tricks)

- **Spend Cap** را از روز اول تنظیم کنید.
- مصرف را **ماهانه** بررسی کنید.
- **کش** بهترین راه کاهش هزینه است.
- ربات‌های مضر را با **Firewall** فیلتر کنید.
- برای پروژه‌های جدید، **پیش‌بینی مصرف** کنید.

### خلاصه فصل

- هزینه = **اشتراک ثابت + مصرف**.
- منابع مصرفی: پهنای باند، درخواست، تابع، تصویر، ساخت.
- **Spend Management** از صورتحساب غافلگیرکننده جلوگیری می‌کند.
- تخفیف حجمی در مصرف بالا وجود دارد.
- نظارت ماهانه ضروری است.

## فصل ۲: پلن Hobby

### مقدمه

**Hobby** پلن رایگان Vercel است — برای یادگیری و پروژه‌های شخصی عالی. اما محدودیت‌های مهمی دارد که باید بدانید.

### مفاهیم اساسی

**۱. هزینه**
**رایگان** — بدون نیاز به کارت بانکی.

**۲. محدودیت اصلی: غیرتجاری**
پلن Hobby **فقط برای استفادهٔ شخصی و غیرتجاری** است. سایت درآمدزا، فروشگاه، یا اپ مشتری، **باید** Pro باشد.

**۳. سهمیهٔ رایگان**
Vercel سهمیهٔ ماهانهٔ مشخصی برای هر منبع می‌دهد (پهنای باند، درخواست، تابع و ...). فراتر از آن، مصرف متوقف یا محدود می‌شود.

**۴. قابلیت‌های موجود**

| قابلیت | وضعیت |
|---|---|
| استقرار نامحدود | ✅ |
| Preview Deployment | ✅ |
| دامنه اختصاصی | ✅ |
| SSL خودکار | ✅ |
| Serverless/Edge Functions | ✅ |
| Storage | ✅ (محدود) |
| Analytics / Speed Insights | ✅ (محدود) |
| Cron Jobs | ✅ (محدود) |

**۵. محدودیت‌ها**

| محدودیت | توضیح |
|---|---|
| استفادهٔ تجاری | ❌ ممنوع |
| تعداد اعضا | فقط خودتان |
| Cron | تعداد و فرکانس کم |
| Deployment Protection | محدود |
| Function Duration | کوتاه‌تر |
| Wildcard Domain | ❌ |
| Password Protection | ❌ |

### مثال‌های عملی

**مثال ۱ — بررسی پلن فعلی**

```
Dashboard → Settings → Billing
- Plan: Hobby
- Usage: نمودار مصرف ماهانه
```

**مثال ۲ — پروژه‌های مناسب Hobby**

```
✅ پروژهٔ یادگیری و تمرین
✅ سایت شخصی/رزومه (بدون درآمد)
✅ پورتفولیو
✅ پروژهٔ متن‌باز
✅ نمونهٔ آزمایشی

❌ فروشگاه با پرداخت
❌ SaaS با مشتری
❌ سایت تبلیغاتی/درآمدزا
❌ پروژهٔ شرکتی
```

**مثال ۳ — ارتقا از Hobby به Pro**

```
۱. Team Settings → Billing
۲. «Upgrade to Pro» را بزنید
۳. اطلاعات پرداخت را وارد کنید
۴. اعضا را اضافه کنید
۵. هزینه: به‌ازای هر عضو + مصرف
```

### مقایسه و الگوهای مختلف

**Hobby در برابر Pro (خلاصه)**

| معیار | Hobby | Pro |
|---|---|---|
| هزینه | رایگان | اشتراک + مصرف |
| تجاری | ❌ | ✅ |
| اعضا | ۱ | نامحدود |
| Cron | محدود | بیشتر |
| Protection | پایه | کامل |
| پشتیبانی | انجمن | ایمیل |

**چه زمانی ارتقا؟**

| نشانه | اقدام |
|---|---|
| پروژه درآمدزا | فوری ارتقا |
| نیاز به چند عضو | ارتقا |
| Cron بیشتر | ارتقا |
| Password Protection | ارتقا |
| مصرف بیش از سهمیه | ارتقا |

### اشکال شایع

**۱. استفادهٔ تجاری از Hobby.**
نقض قوانین است و ممکن است پروژه محدود شود. **قبل از انتشار تجاری ارتقا دهید.**

**۲. فرض «نامحدود بودن رایگان».**
سهمیه وجود دارد. فراتر از آن، سرویس محدود می‌شود.

**۳. نادیده گرفتن محدودیت Cron.**
زمان‌بندی‌های مکرر در Hobby ممکن است کار نکنند.

**۴. انتظار پشتیبانی سریع.**
Hobby پشتیبانی انجمن دارد، نه اختصاصی.

**۵. اجرای پروژهٔ مشتری.**
حتماً Pro لازم است.

### نکات مهم (Tips & Tricks)

- Hobby برای **یادگیری** عالی است — از آن کامل استفاده کنید.
- قبل از **انتشار تجاری**، ارتقا دهید.
- مصرف را در Dashboard پایش کنید.
- برای پروژهٔ متن‌باز، Hobby کافی است.
- ارتقا هر زمان ممکن است؛ داده‌ها حفظ می‌شوند.

### خلاصه فصل

- **Hobby** رایگان و برای پروژه‌های **غیرتجاری** است.
- سهمیهٔ ماهانهٔ مشخص دارد.
- محدودیت‌ها: اعضا، Cron، Protection، Wildcard.
- استفادهٔ تجاری **ممنوع** است.
- ارتقا به Pro ساده است و داده‌ها حفظ می‌شوند.

## فصل ۳: پلن Pro

### مقدمه

**Pro** پلن حرفه‌ای Vercel است — برای تیم‌ها، پروژه‌های تجاری و اپ‌های واقعی. در این فصل، آنچه دریافت می‌کنید را می‌بینیم.

### مفاهیم اساسی

**۱. ساختار هزینه**
```
هزینه = (تعداد اعضا × قیمت ماهانه) + مصرف اضافه
```

**۲. قابلیت‌های کلیدی**

| قابلیت | توضیح |
|---|---|
| **استفادهٔ تجاری** | ✅ مجاز |
| **اعضای نامحدود** | با پرداخت per-seat |
| **Password Protection** | ✅ |
| **Wildcard Domains** | ✅ |
| **Cron بیشتر** | فرکانس بالاتر |
| **Function Duration بیشتر** | برای کارهای طولانی‌تر |
| **پشتیبانی ایمیل** | پاسخ سریع‌تر |
| **Drains** | ارسال لاگ |
| **Observability Plus** | تحلیل پیشرفته |
| **Firewall پیشرفته** | قوانین بیشتر |

**۳. نقش‌های تیمی**
Owner، Member، Viewer، Developer، Billing.

**۴. سهمیهٔ بالاتر**
همهٔ منابع سهمیهٔ بزرگ‌تری دارند.

**۵. افزودنی‌ها (Add-ons)**
- **Observability Plus**: تحلیل پیشرفته.
- **Advanced Firewall**: قوانین بیشتر.
- **Speed Insights Plus**: دادهٔ بیشتر.
- **Compute**: منابع اضافه.

### مثال‌های عملی

**مثال ۱ — هزینهٔ تقریبی یک تیم کوچک**

```
۳ عضو × قیمت ماهانه = هزینهٔ اشتراک
+ مصرف اضافه (اگر از سهمیه فراتر رود)

نکته: قیمت‌ها تغییر می‌کنند — همیشه صفحهٔ Pricing را ببینید.
```

**مثال ۲ — فعال‌سازی Password Protection (Pro)**

```
۱. Project → Settings → Deployment Protection
۲. «Password Protection» → Enable
۳. رمز را وارد کنید
۴. ذخیره
```

**مثال ۳ — استفاده از Wildcard Domain (Pro)**

```
۱. Settings → Domains
۲. اضافه کنید: *.myapp.com
۳. رکورد DNS Wildcard CNAME را تنظیم کنید
۴. هر زیردامنه کار می‌کند: user1.myapp.com
```

**مثال ۴ — مدیریت اعضا و نقش‌ها**

```
Team Settings → Members → Invite
- نقش را انتخاب کنید:
  - Owner: کنترل کامل
  - Member: کار روی پروژه
  - Developer: استقرار و کد
  - Viewer: فقط مشاهده
  - Billing: فقط صورتحساب
```

### مقایسه و الگوهای مختلف

**پلن Pro در برابر Hobby**

| معیار | Hobby | Pro |
|---|---|---|
| تجاری | ❌ | ✅ |
| اعضا | ۱ | نامحدود |
| Password Protection | ❌ | ✅ |
| Wildcard Domain | ❌ | ✅ |
| Cron | محدود | ✅ بیشتر |
| Drains | ❌ | ✅ |
| پشتیبانی | انجمن | ایمیل |

**چه زمانی Pro کافی است؟**

| سناریو | Pro کافی؟ |
|---|---|
| استارتاپ کوچک | ✅ |
| فروشگاه متوسط | ✅ |
| SaaS با چند صد کاربر | ✅ |
| سازمان بزرگ با انطباق | ⬆️ Enterprise |

### اشکال شایع

**۱. فراموش کردن هزینهٔ per-seat.**
هر عضو اضافه هزینه دارد.

**۲. نبود Spend Cap.**
مصرف می‌تواند بالا برود. سقف تعیین کنید.

**۳. افزودن اعضای غیرضروری.**
هزینهٔ بی‌مورد. فقط اعضای لازم.

**۴. استفاده نکردن از قابلیت‌های Pro.**
اگر Pro گرفته‌اید، از Firewall و Drains استفاده کنید.

**۵. انتخاب Pro برای سازمان بزرگ.**
برخی نیازهای انطباقی فقط در Enterprise هستند.

### نکات مهم (Tips & Tricks)

- **Spend Cap** را تنظیم کنید.
- اعضا را **دوره‌ای بازبینی** کنید.
- از **Drains** برای نگهداری لاگ استفاده کنید.
- **Firewall** را برای امنیت جدی بگیرید.
- برای سازمان، Enterprise را بررسی کنید.

### خلاصه فصل

- **Pro** برای پروژه‌های تجاری و تیم‌هاست.
- هزینه = **per-seat + مصرف**.
- قابلیت‌های کلیدی: Password Protection، Wildcard، Cron بیشتر، Drains.
- افزودنی‌ها برای نیازهای خاص.
- Spend Cap و بازبینی اعضا ضروری است.

## فصل ۴: پلن Enterprise

### مقدمه

**Enterprise** برای سازمان‌های بزرگ با نیازهای امنیتی، انطباقی و مقیاس بالا طراحی شده است.

### مفاهیم اساسی

**۱. هزینه**
قیمت‌گذاری **سفارشی** بر اساس نیاز.

**۲. قابلیت‌های اختصاصی**

| قابلیت | توضیح |
|---|---|
| **SLA** | توافق سطح خدمات با تضمین آپ‌تایم |
| **پشتیبانی اختصاصی** | مدیر موفقیت مشتری |
| **SSO/SAML** | ورود سازمانی |
| **Trusted IPs** | محدودسازی به IP های خاص |
| **Audit Logs** | ثبت همهٔ رویدادها |
| **Compliance** | SOC 2، HIPAA، GDPR |
| **Advanced Firewall** | قوانین پیشرفته |
| **مناطق اختصاصی** | انتخاب دقیق منطقه |
| **Concurrent Builds** | ساخت‌های همزمان بیشتر |
| **SLA تضمین‌شده** | آپ‌تایم قراردادی |

**۳. انطباق (Compliance)**

| استاندارد | توضیح |
|---|---|
| **SOC 2 Type II** | امنیت و کنترل |
| **HIPAA** | دادهٔ سلامت |
| **GDPR** | حریم خصوصی اروپا |
| **ISO 27001** | مدیریت امنیت |

**۴. SSO و مدیریت هویت**
ورود با سیستم هویت سازمان (Okta، Azure AD، Google Workspace).

**۵. Audit Logs**
ثبت همهٔ اقدامات: چه کسی، چه زمانی، چه کاری.

### مثال‌های عملی

**مثال ۱ — چه سازمان‌هایی Enterprise می‌خواهند؟**

```
✅ بانک و مؤسسهٔ مالی
✅ سازمان‌های بهداشتی (HIPAA)
✅ شرکت‌های بزرگ با SSO
✅ سازمان‌های با نیاز انطباقی
✅ پلتفرم‌های با SLA سخت‌گیرانه
```

**مثال ۲ — فعال‌سازی Trusted IPs**

```
Settings → Deployment Protection → Trusted IPs
- IP های مجاز را وارد کنید
- دسترسی از بقیه IP ها مسدود می‌شود
```

**مثال ۳ — بررسی Audit Logs**

```
Team Settings → Audit Logs
- فیلتر بر اساس: کاربر، نوع رویداد، تاریخ
- مثال رویدادها: deployment.created، env.updated، member.invited
```

### مقایسه و الگوهای مختلف

**سه پلن در یک نگاه**

| معیار | Hobby | Pro | Enterprise |
|---|---|---|---|
| هزینه | رایگان | اشتراک + مصرف | سفارشی |
| تجاری | ❌ | ✅ | ✅ |
| SLA | ❌ | ❌ | ✅ |
| SSO | ❌ | ❌ | ✅ |
| Trusted IPs | ❌ | ❌ | ✅ |
| Audit Logs | ❌ | محدود | ✅ |
| انطباق | ❌ | محدود | ✅ |
| پشتیبانی | انجمن | ایمیل | اختصاصی |

**چه زمانی Enterprise؟**

| نیاز | پلن |
|---|---|
| SSO سازمانی | Enterprise |
| SLA تضمین‌شده | Enterprise |
| انطباق (HIPAA/SOC2) | Enterprise |
| Audit Logs کامل | Enterprise |
| محدودسازی IP | Enterprise |
| تیم کوچک تجاری | Pro |

### اشکال شایع

**۱. انتخاب Enterprise بدون نیاز واقعی.**
هزینهٔ بالا بدون بهره. ابتدا نیازها را مشخص کنید.

**۲. نادیده گرفتن SSO در سازمان.**
اگر سازمان SSO دارد، Enterprise لازم است.

**۳. فراموش کردن نیازهای انطباق.**
در حوزهٔ سلامت/مالی، انطباق الزامی است.

**۴. نبود برنامهٔ Audit.**
Audit Logs بدون بررسی بی‌فایده است.

**۵. عدم استفاده از SLA.**
اگر SLA دارید، از آن برای گزارش‌گیری استفاده کنید.

### نکات مهم (Tips & Tricks)

- نیازهای **انطباقی** را از ابتدا مشخص کنید.
- **SSO** را در سازمان جدی بگیرید.
- از **Audit Logs** برای امنیت استفاده کنید.
- **Trusted IPs** برای دسترسی حساس.
- با تیم فروش Vercel برای قیمت **مذاکره** کنید.

### خلاصه فصل

- **Enterprise** برای سازمان‌های بزرگ و نیازهای انطباقی است.
- قابلیت‌ها: **SLA، SSO، Trusted IPs، Audit Logs، Compliance**.
- قیمت سفارشی و مبتنی بر مذاکره.
- برای بانک، سلامت و شرکت‌های بزرگ مناسب است.
- نیازها را قبل از انتخاب مشخص کنید.

## فصل ۵: انتخاب پلن و بهینه‌سازی هزینه

### مقدمه

انتخاب پلن درست و بهینه‌سازی مصرف، می‌تواند هزینه را چند برابر کاهش دهد. در این فصل، یک راهنمای عملی می‌سازیم.

### درخت تصمیم انتخاب پلن

```
آیا پروژه درآمدزا یا تجاری است؟
├── خیر → Hobby ✅
└── بله
    ├── تیم چند نفره؟ → Pro
    ├── نیاز به Password/Wildcard؟ → Pro
    ├── نیاز به SSO/SLA/انطباق؟ → Enterprise
    └── نه → Pro ✅
```

### جدول انتخاب سریع

| سناریو | پلن پیشنهادی |
|---|---|
| یادگیری و تمرین | Hobby |
| پورتفولیو شخصی | Hobby |
| پروژهٔ متن‌باز | Hobby |
| فریلنسر با ۱ پروژه | Pro |
| استارتاپ کوچک | Pro |
| فروشگاه اینترنتی | Pro |
| SaaS متوسط | Pro |
| سازمان با SSO | Enterprise |
| حوزهٔ سلامت/مالی | Enterprise |

### راه‌های بهینه‌سازی هزینه

**۱. کش هوشمند**

```js
// کش لبه: بار سرور را کم می‌کند
res.setHeader('Cache-Control', 'public, s-maxage=300, stale-while-revalidate=3600');
```

**۲. بهینه‌سازی تصویر**

```tsx
// کیفیت مناسب، فرمت مدرن
<Image src="/hero.jpg" width={1200} height={600} quality={75} sizes="100vw" priority />
```

**۳. کاهش اندازهٔ توابع**

```js
// ❌ ایمپورت کل کتابخانه
import _ from 'lodash';

// ✅ ایمپورت جزئی
import chunk from 'lodash/chunk';
```

**۴. انتخاب Runtime مناسب**

```js
// منطق سبک → Edge (ارزان‌تر در ترافیک بالا)
export const config = { runtime: 'edge' };
```

**۵. فیلتر ربات‌ها**

```
Firewall → Block known bad bots
→ کاهش درخواست‌های بی‌مورد
```

**۶. مدیریت Cron**

```json
// فقط در ساعات لازم
{ "crons": [{ "path": "/api/warmup", "schedule": "0 8-20 * * *" }] }
```

**۷. نظارت و هشدار**

```
Billing → Spend Management
- Spend cap: تعیین سقف
- Alerts: ۵۰٪، ۸۰٪، ۱۰۰٪
```

### مثال عملی — سناریوی کاهش هزینه

**قبل از بهینه‌سازی:**
```
- Fast Data Transfer: ۸۰۰GB (فراتر از سهمیه)
- Image Optimization: ۵۰٬۰۰۰ تصویر
- Function Invocations: ۵ میلیون
- هزینهٔ اضافه: قابل توجه
```

**اقدامات:**
1. کش لبه روی همهٔ API های عمومی.
2. کیفیت تصویر از ۱۰۰ به ۷۵.
3. `sizes` روی همهٔ تصاویر.
4. فیلتر ربات‌های مضر با Firewall.
5. حذف وابستگی‌های سنگین.

**بعد از بهینه‌سازی:**
```
- Fast Data Transfer: ۲۲۰GB (در سهمیه ✅)
- Image Optimization: ۱۵٬۰۰۰ تصویر
- Function Invocations: ۱.۵ میلیون
- هزینهٔ اضافه: کاهش چشمگیر ✅
```

### چک‌لیست بهینه‌سازی هزینه

- [ ] Spend Cap تنظیم شده
- [ ] هشدار مصرف فعال
- [ ] کش لبه روی API های عمومی
- [ ] کیفیت تصویر ۷۵–۸۵
- [ ] `sizes` روی تصاویر
- [ ] وابستگی‌های سنگین حذف شده
- [ ] ربات‌های مضر فیلتر شده
- [ ] Cron ها محدود به ساعات لازم
- [ ] Runtime مناسب انتخاب شده
- [ ] مصرف ماهانه بررسی می‌شود

### مقایسه و الگوهای مختلف

**سه استراتژی هزینه**

| استراتژی | تمرکز | اثر |
|---|---|---|
| **کاهش مصرف** | کش، تصویر، کد | ✅ زیاد |
| **کنترل سقف** | Spend Cap | جلوگیری از فاجعه |
| **انتخاب پلن** | درست‌ترین پلن | پایه |

**پیش‌بینی مصرف**

| نشانه | پیش‌بینی |
|---|---|
| رشد ترافیک ماهانه | افزایش پهنای باند |
| افزودن تصاویر زیاد | افزایش Image Optimization |
| API های سنگین | افزایش Function Duration |
| تیم بزرگ‌تر | افزایش per-seat |

### اشکال شایع

**۱. انتخاب پلن گران‌تر از نیاز.**
هزینهٔ بی‌مورد. با Hobby/Pro شروع کنید.

**۲. نبود نظارت.**
بدون دیدن مصرف، بهینه‌سازی ممکن نیست.

**۳. بهینه‌سازی فقط یک بار.**
مصرف با رشد پروژه تغییر می‌کند.

**۴. نادیده گرفتن هزینهٔ تصویر.**
در سایت‌های پرمحتوا، منبع اصلی هزینه است.

**۵. نداشتن برنامهٔ رشد.**
بدون پیش‌بینی، هزینه غافلگیر می‌کند.

### نکات مهم (Tips & Tricks)

- با **Hobby** شروع کنید و در صورت نیاز ارتقا دهید.
- **Spend Cap** از روز اول.
- **کش** بهترین ابزار کاهش هزینه است.
- **تصویر** را جدی بگیرید.
- مصرف را **ماهانه** بررسی کنید.

### خلاصه فصل

- درخت تصمیم و جدول انتخاب سریع را به کار ببرید.
- هفت راه اصلی بهینه‌سازی هزینه.
- **کش** و **تصویر** بیشترین اثر را دارند.
- **Spend Cap** و هشدار ضروری است.
- بهینه‌سازی یک فرایند **مستمر** است.
